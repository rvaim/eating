# Eating

Eating 是一个独立管理应用，用于连接通讯平台和用户选择的 AI 运行程序（Harness）。同一个 AI 共享核心人格，由主 Agent 决定是否行动，并将具体任务交给受限子代理。Eating 负责连接、运行、授权和可靠交接，不另建一套认知循环。

当前已实现 QQ OneBot v11 与独立 DeepSeek Harness 适配。应用仍在开发，尚未发布。

**除非用户明确要求，否则默认不兼容旧版本；即使以后发布也遵循此规则。** 当前代码不提供旧 API、配置或数据库的自动迁移、字段补齐、旧入口别名或回退分支。旧格式会明确报错，原数据不会被自动覆盖或删除。已有旧数据时，请先选择全新数据目录；任何转换或清理都须另行明确要求。

## 已实现功能

- **QQ 连接与工具**：使用已登录的 OneBot v11 服务，接收私聊／群聊消息，提供完整39项标准工具与手动功能测试。支持多个主人／管理员和按私聊、群聊类型配置工具权限。
- **分层代理**：主／子代理使用各自系统提示词并共享当前人格。按账号、联系人／群和类型复用原生会话，后台限制实际工具和目标范围，向主代理返回真实动作回执。
- **提示词与人格**：通用前置、主 Agent、子代理前置、插件说明和角色提示词分别编辑；支持变量补全、诊断、草稿、版本冲突保护及已保存组合预览。一次最多启用一个人格，也可停用全部人格。
- **模型配置**：保存服务地址、模型和 Key 后，可获取模型列表、选择填入草稿并测试模型连接。不支持列表的服务可手动填写模型名称。
- **会话看板**：手动查看当前 Harness 的原生主／子会话层级与已保存内容，按需分页；离开或隐藏后清空页面内容，不另建聊天档案，不后台轮询。
- **可靠投递**：有界消息聚合，可选本地暂存或内存队列；可靠接管后删除队列正文，外部动作使用稳定请求 ID 防重，结果未知时不自动重做。
- **中英文界面**：语言切换保留草稿、选区和撤销历史，白绿界面支持独立滚动及窄屏操作。

当前工具授权属于逻辑执行边界，不是 OS 沙箱。其他 Harness、跨 Harness 无损迁移、长期记忆、Tauri 桌面壳和三平台完整运行仍未完成验证。

## 环境

- 普通 Node.js **>=24.9.0**，本轮使用24.22.0。
- pnpm **11.28.5**，以仓库 [package.json](package.json) 为准。
- QQ 接入需单独运行已登录的 OneBot v11 协议服务；Eating 不实现 QQ 登录。
- AI 接入需支持 OpenAI 接口的模型服务，以及在 Eating 内独立安装的 DSH 运行时。不能借用用户主 DSH 的 Profile、会话或凭据。

## 从全新数据目录启动

先克隆仓库、安装依赖和构建：

```bash
git clone https://github.com/rvaim/eating.git
cd eating
pnpm install --frozen-lockfile
pnpm build
```

为 `EATING_HOME` 选择一个**尚未使用的新目录**。以下路径仅是示例；新数据根会产生新的账号实例与会话，不会继承旧数据。

```bash
export EATING_HOME="$HOME/.eating-current"
pnpm plugin install plugins/communication/qq/dist
pnpm plugin install plugins/harness/dsh/dist
pnpm dev
```

打开 <http://127.0.0.1:5180/>，Host 使用5181。插件安装／升级／卸载前须停止 Host，代码按已安装产物加载，不直接扫描插件源码。

需要只运行已构建应用时，在同一个 `EATING_HOME` 下执行：

```bash
pnpm start
```

Host 默认在 <http://127.0.0.1:5181/> 同源提供界面、API、插件资源和 MCP，可通过 `EATING_HOST_PORT` 修改端口。开发模式的 Vite 不能单独替代 Host。

### 连接 QQ

1. 打开“机器人 → QQ → 连接配置”，填写统一的 `ws://` 或 `wss://` OneBot 地址、访问令牌和连接设置，保存后连接。
2. 在“代理与权限”配置多个主人／管理员 QQ，并分别选择私聊和群聊子代理可用的工具。保存权限不重连 QQ；后台仍会逐次核对账号、目标与引用。
3. “功能测试”用于主人主动执行真实工具；副作用操作需要确认。自动开发测试只向本地协议夹具发送，不向真人试发。

### 配置 AI

1. 打开“Harness → DeepSeek Harness”，保存 API 基础地址、模型名称和 Key。Key 不会回显。
2. 可获取模型列表；选择只写入草稿，保存才生效。测试模型连接会向已保存的服务发出一次最小真实请求，可能产生提供商费用。
3. 安装 Eating 专属运行时后启动 Harness。模型 API 测试、运行时就绪和实际任务成功是不同状态。
4. 在“提示词管理”和“人格管理”调整 AI 规则。主系统使用通用前置、主规则、启用插件说明和统一人格；子代理使用通用前置、子代理前置、类型规则和同一人格。
5. 切换到“会话看板”，手动刷新并选择会话查看内容。运行中的最新活动可能尚未写入原生记录。

## 开发与验证

```bash
pnpm build
pnpm test
pnpm exec playwright test
```

原生 SDK 集成需要已准备好的**独立测试运行时**，并显式提供目录：

```bash
EATING_DSH_TEST_RUNTIME="<独立测试运行时目录>" pnpm exec vitest run --maxWorkers=4
```

该目录内应有当前安装器准备的 `runtime` 子目录。未提供时5项原生用例会跳过，不能当作全套实跑。测试使用全新临时数据目录、回环模型和 OneBot，不读取真实账号配置或向真人发送。

本轮完整结果、截图及未覆盖范围见[删除旧版兼容验证报告](docs/reports/2026-10-29-删除旧版兼容验证报告.md)。不支持的旧格式有负向测试，当前格式下的重启、可靠 ACK、幂等和独立安装仍有正向验证。

## 仓库结构

```text
apps/host                 Node／SQLite Host、安装器与受控API
apps/web                  React 管理界面
packages/plugin-core      当前注册器与共享配置类型
packages/plugin-sdk       公开后台与代理契约
packages/ui-sdk           公开面板、API客户端与共享国际化
plugins/communication/qq  QQ OneBot v11 插件
plugins/harness/dsh       独立 DSH 适配插件
docs                      当前规范、决策与历史验证
```

主应用／Host／Web当前0.9.0，三个共享包2.0.0，QQ0.9.0、DSH0.4.0，插件唯一 API2。各自的存储 schema 独立版本化，不能通过统一改版本号或自动转换让旧格式继续运行。
