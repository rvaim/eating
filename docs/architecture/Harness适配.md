# Eating Harness 适配设计

结论：**认知与行动交给用户选定的 Harness，Eating 提供稳定运行和统一接入边界，不永久绑定 DSH，也不重写 Harness。** 唯一 AI 身份保持不变。

状态：可替换原则已确认；适配契约、最小能力集、选择/切换与迁移流程 Proposed，未实现。对应 [ADR-0006](../decisions/ADR-0006-可替换Harness与认知边界.md)。

## 现状与变化

v0.3 曾将 DSH 定为唯一引擎；负责人本轮明确改为用户可以选择 DSH、Codex、Claude Code 或其他 Harness。DSH 保留为首个具体源码核对和集成验证对象，原 SDK 结论不再作为通用 Host API。

Codex/Claude Code 是候选运行时名称，不代表已经验证其官方 SDK、进程协议、长期会话、工具、调度、记忆或再分发条件。模型提供商/API 与完整 Harness 是不同层级，不能仅替换模型名称就宣称完成运行时适配。

## 依赖方向

UI、通讯、队列、主人授权依赖 Eating 的运行时契约；DSH 适配器将契约映射到 DSH SDK/配置，其他适配器映射各自真实接口。通用 Host 不导入 DSH Session、Preset、事件枚举或内部插件对象。

适配器可以管理外部进程，无需运行时本身采用 Cordis，也不应与 Host 共享同一个 Cordis Context。DSH 原生插件、Eating 扩展和其他 Harness 插件是不同生态，不默认通用二进制或配置兼容。

## 候选职责

| 职责 | 契约需要表达 | 差异处理 |
| --- | --- | --- |
| 启动/连接/健康/停止 | 真实就绪、版本、错误、独立数据与退出 | 外部服务/进程形态与关闭语义由适配器实现 |
| 人格与已授权能力配置 | 核心人格的可应用性、工具与权限边界 | DSH Profile/Preset 不是通用字段 |
| 主运行脉络 | 创建/恢复、原生身份关联、工作区与数据根 | 使用包含 Harness/配置身份的映射，不能跨引擎复用裸 ID |
| 输入投递与事件 | 受理、持久/消费证据、关联 ID、错误和终止 | 无证据则未知，不能伪造已读或成功 |
| 可选续行/中途输入/暂停 | 能力、约束与实际行为 | 不用 Host 第二套 Agent Loop 补出“支持” |
| 工具、子 Agent、调度、记忆 | 运行时真实能力与来源 | 独立声明；缺失不能偷偷声称等价 |
| 管理界面 | 运行时自有配置/诊断入口 | 通过页面贡献注册，不改通用导航 |

这是职责草案，不是已发布的方法名/schema。通用最小契约只包含当前实际需要的操作，避免为所有未来运行时预建万能框架。

## 能力与结果

能力认知区分“已支持”“明确不支持”“尚未核实”；本次探测/调用是否失败是另一维度。失败可能发生在未知能力的探测中，也可能发生在已支持功能的执行中，不能由 error 推导 unsupported。具体字段名与协议尚未冻结。能力声明是版本和运行环境相关证据，不是插件作者任意填写即可成立的保证。

例如没有消息中途注入时应返回明确不支持，不能将普通排队伪装成 steer；没有持久恢复时不能把新会话称为恢复；调度、记忆或受控工具不满足自主生活需求时，在 UI 明确显示限制，并限制依赖这些能力的功能。通用适配成功不等于满足 Eating 全部产品需求。

## 唯一身份与选择边界

可以安装多个 Harness 适配模块，用户选择实际使用者。初始验证范围是同一 AI 数据集一个活跃主认知控制者；子 Agent 属于其授权的执行能力，不因有多个候选而创建多个独立人格。

切换运行时不自动保证旧会话、上下文压缩、记忆插件、工具授权或未完成工作无损延续。运行中热切换、跨运行时会话转换、长期记忆迁移和多运行时并行均未承诺。

需要切换时，候选流程是停止新投递 → 核对在途动作/停旧主控 → 验证目标能力与配置 → 明确历史/记忆兼容限制 → 用户确认涉及的数据转换或信息披露 → 启动目标并更新映射。原生记录保留；不静默丢历史、复制凭据或启动第二主控。精确流程需后续决定。

## 长期记忆与自主性

主人选择所选 Harness 可用且已授权的记忆插件/机制。Eating 保存运行状态与主身份配置，不新建人生记忆引擎。不同运行时能否使用相同记忆服务、如何隔离和迁移需各自验证；不可用必须报告。

自主活动与休息仍由选定 Harness 中的主 Agent 决定。若某候选没有所需续行/调度能力，应记录产品缺口，不在 Host 增加第二套意图生成器绕过。

## 验证

先用模拟 Harness 验证契约、能力差异和自注册，再用 DSH 做真实隔离/会话/事件实验。第二种真实 Harness 接入时，检验是否无需修改通讯模块和通用管理页，才有证据支持可替换性。

所有 Harness 运行验证未开始；本轮已运行的前端平台目录/组件验证不是模拟或真实 Harness 适配。DSH 专属事实见[DSH 集成](DSH集成.md)与[源码核对](../research/DSH源码核对.md)，计划见[路线图](../plans/路线图与PoC计划.md)。
