# Eating 主会话模型

状态：单主实现 Proposed，唯一身份与可替换 Harness 的产品边界已确认。来源：v0.3 §7、本轮负责人确认；见 [ADR-0006](../decisions/ADR-0006-可替换Harness与认知边界.md)与[Harness 适配](Harness适配.md)。[ADR-0003](../decisions/ADR-0003-唯一主会话.md)保留为原 DSH 单主 Session 方案的历史背景，不代表所有 Harness 的共同接口。

## 标识与认知控制者

- Eating 逻辑身份/主会话别名：产品用于持续识别同一 AI，不等同任何 Harness 的内部 ID。
- Harness 适配器、实例与运行句柄：标明当前选择的实现、数据集和恢复目标；只有接口支持时才映射为其 Session ID。
- 外部 conversationId：QQ 私聊/群、飞书、微信等平台会话，用于来源、取历史和发送路由。

v0.3 推荐 `eating-main` 作为别名，尚无持久化使用。新产品名称为 Eating；最终内部别名尚待确认，不为统一名称直接重命名已有数据。

同一 Eating 数据集只允许一个当前活跃的主要认知控制者，由用户选定的 Harness 承担认知与行动；子 Agent 是受委派的执行者，不能默认形成多个独立人格。唯一身份不等于所有 Harness 都支持一个永久技术 Session。Eating 管理准入、授权和恢复，不建设第二套 Agent Loop 或人格决策器。

## 通用生命周期边界

适配器需声明创建/恢复、持久化、忙碌与排队、取消、事件观测等 capabilities，并标注版本与证据；不能把 DSH 接口当作其他 Harness 的默认能力。`unsupported` 表示明确不支持，`unknown` 表示未核或证据不足，`error` 表示本次探测/调用失败，不能据此推断不支持。状态与字段均为候选，见[接口契约](../technical/接口契约.md)。必要能力未满足时不能宣称主会话就绪。

恢复目标缺失、损坏、占用或不兼容必须报告，不能静默创建新会话掩盖历史丢失。切换 Harness 前须停止旧控制者的新任务并确认其活动与未决动作；无法确认旧控制者已停止时不得激活第二个。跨 Harness 会话、插件、记忆无损迁移和运行中热切换均未承诺，实际 Codex/Claude Code 接口未核。

## DSH 适配器：SDK 实际行为（源码分析）

DSH 是首个具体技术验证对象。以下仅适用于已核固定版本，未进行 Eating 运行验证。

`session(id?)` 返回惰性句柄，不发生 wire 请求；省略 ID 时客户端生成 `session-` 加 UUID。首个 prompt 或相关工作目录操作才会创建 Agent。这里存在客户端显式 ID 参数，但参数校验、命名冲突和持久化行为仍须实验，不能承诺任意字符串都可用。

`run()` 不带 Session ID 会获得新的会话句柄，不适合直接用作每条平台消息的长期主会话入口。应明确复用同一句柄/ID。

重启后调用 `resumeSession(savedId)` 恢复；仅把相同 ID 再传给 prompt 不等同 resume。

恢复依赖实际装配的 sessionPersistence。官方 base 组合配置 JSONL 到 DSH home 下 sessions，但手动 Server 并非自动具备此能力。API 受理和实时事件通知不等于落盘屏障。SDK 不自动挂 Preset，因此映射存在不代表人格/工具配置已经正确恢复。固定源码引用见[研究矩阵](../research/DSH源码核对.md)。

## 主要认知上下文

仅投递必要新事件并保留来源/权限；聊天历史按外部会话授权范围读取；长期经历交给所选 Harness 可用且主人授权的记忆插件/机制；上下文压缩与子 Agent 仅按该 Harness 的实际能力使用。不要把所有平台全部历史塞进主要上下文，也不由 Eating 建立第二套人生记忆。

共享上下文有隐私风险：单一 Session 本身不隔离联系人信息。输出工具的目标授权、历史读取范围和记忆披露都需要验证；若单主 Session 实现无法满足隐私与规模要求，需提出替代技术方案，不能改变唯一身份和单一活跃主要控制者要求。

## 恢复映射

候选记录逻辑主身份、适配器/实例与数据集标识、真实恢复句柄（如支持）、Harness/协议版本、所需配置版本和能力证据。字段名与持久化结构未冻结；运行映射不冒充长期记忆。

创建、映射提交与首次事件落盘之间存在崩溃窗口；具体事务和补救方式需在各适配器中验证，防止生成两个活跃“主会话”。DSH 首轮实验见 Phase 1，不能代替其他 Harness 的验证。

子 Agent 的身份、工具权限和结果汇总服从主要认知控制者与真实执行边界；主 Session 等待/通知不自动涵盖所有外部执行进程。停用 Harness 模块须停止新投递、撤销能力与界面注册、核对在途活动，并按保留策略保存恢复映射和未决动作证据，见[插槽式扩展](插槽式扩展.md)。
