# Eating 插件与能力系统

结论：区分 Eating 宿主扩展、具体 Harness 原生扩展和 MCP 服务；通过明确契约连接，不把某个运行时的插件框架当作整个产品的唯一入口。

状态：模块独立注册、主人审批及单仓独立包/公开 SDK 原则已确认。正式 QQ 已有实现，本轮本地产物安装与加载已于 2026-10-27 完成验证，见[重组报告](../reports/2026-10-26-单仓独立包重组报告.md)；任意第三方市场、自动下载、完整安装授权与 OS 执行隔离仍未完成。交付边界见[工程结构与插件发布](工程结构与插件发布.md)与 [ADR-0012](../decisions/ADR-0012-单仓独立包与插件加载.md)。

## 扩展类别与归属

| 类别 | 管理内容 | 兼容边界 |
| --- | --- | --- |
| Eating 模块 | 通讯连接器、Harness 适配器、模块自有后台和页面贡献 | 遵循 Eating 契约；Cordis 为后台候选实现 |
| Harness 原生扩展 | 所选运行时的工具、记忆、技能或其他插件 | DSH 插件由 DSH 适配管理，不默认适配 Codex/Claude Code |
| MCP 服务 | 已启用且connected的功能型capability／direct全部工具默认开放给所有Agent | 通讯／资源scope独立，协议兼容不代表OS隔离或全部业务可用 |

Host 通过各适配器管理具体 Profile/Preset/工具/插件配置，不把这些 DSH 名称写成通用接口。已批准普通操作保持自主使用，付款、重要删除等动作单独制定保护，不默认每一步审批。

## 注册不是安装或授权

模块声明来源、稳定 ID、契约/模块版本、能力、依赖及前后端入口，由宿主验证。后台和管理面板分别注册并关联生命周期，通用页面从目录发现平台，不导入所有实现。

发现 manifest、读取元数据、安装代码、激活模块、连接账号、暴露工具和显示页面各有真实状态。未经批准不能为“验证声明”先执行任意模块代码；新增可执行 UI 入口也属于扩展范围。

## 当前功能默认开放

主人最新授权按[ADR-0034](../decisions/ADR-0034-主Agent自主决策与功能能力默认开放.md)执行：主Agent自主选择行动和执行者，已启用且connected的功能型capability／direct MCP全部当前及新增工具自动对main、现有及后续类型可用。不维护按类型／工具保存的功能授权，删除save-grants和勾选UI；McpServiceSummary.grant仅当前目录动态摘要。

通讯来源继续permissionsManagedByPlugin，调用按真实账号／对象／类型／消息与资源范围核验，群子不取得私聊通讯权。功能默认开放不生成资源引用；连接成功和业务已配置／动作成功分开。main全部原生全局工具及所有Agent功能型native Profile MCP／新增工具自动开放，排除Eating／QQ受控通讯；其他子非MCP原生工具仍精确名称／指纹选择。目录automaticAccess只读，tools/change更新native.restrict。

安装仍验证固定来源／版本／封存快照并经正式安装入口，启用、连接、工具挂载和删除数据各自报告；不因功能默认开放跳过产物校验或自动清资料，也不重新申请已获授权的逐工具许可。

## 独立停用与卸载

来源新增／连接／断开、工具目录变化及能力插件生命周期变更使用一次性重挂事务：撤lease并停受影响Harness，await来源／目录变更完成，仅对原connected、同一实例且仍启用的Harness恢复一次。原stopped／error不启动，owner stop／disable优先，失败不重试、不重放unknown；harnessRemounts返回reconnected／failed／cancelled。

暂停本模块新操作，核对在途动作，停止其连接/进程并撤销所属注册和页面，释放监听/定时器。删除飞书不删除 QQ 账号、事件、公共依赖或通用管理壳；全部平台移除后管理系统仍可用。停用/卸载程序/清理历史数据分开，未确认操作不得随模块移除而消失。

本轮代码安装、升级与卸载明确要求先停止 Host、完成后重启，索引提交前失败保旧，卸载保留数据；索引提交后的目录同步失败返回 unknown 并保留已激活版本；运行中热卸载与其他故障回滚仍需后续实验；本模块失败不应通过全局吞异常伪装成功。功能隔离和进程/权限隔离分别验证，见[插槽设计](插槽式扩展.md)。

## 具体运行时安装服务不是主人边界

DSH plugin-manager 源码显示 build 批准参数不验证 Eating 主人同意，许可可持久化，安装脚本可能按宿主用户权限执行。此为 [DSH 专属证据](../research/DSH源码核对.md)，其他 Harness 也需核查实际安装/更新/执行旁路，不能假设相同 API。

Cordis scope和注册表不是OS权限保护。新main原生feature按平台默认开，Eating官方permission默认danger-full-access／approval never；这是主人当前选择，不把尚未验证的OS隔离当作再次阻止已授权功能的理由。保持Eating数据根与主人主DSH分离，报告实际进程、凭据和文件访问边界。
