# Eating 插件与能力系统

结论：区分 Eating 宿主扩展、具体 Harness 原生扩展和 MCP 服务；通过明确契约连接，不把某个运行时的插件框架当作整个产品的唯一入口。

状态：模块独立注册与主人审批原则已确认；具体安装/执行方案 Proposed，未实现。来源：v0.3 有效安全要求及本轮架构修订。

## 扩展类别与归属

| 类别 | 管理内容 | 兼容边界 |
| --- | --- | --- |
| Eating 模块 | 通讯连接器、Harness 适配器、模块自有后台和页面贡献 | 遵循 Eating 契约；Cordis 为后台候选实现 |
| Harness 原生扩展 | 所选运行时的工具、记忆、技能或其他插件 | DSH 插件由 DSH 适配管理，不默认适配 Codex/Claude Code |
| MCP 服务 | 显式授予的工具/服务 | 协议兼容不代表权限隔离或全部功能等价 |

Host 通过各适配器管理具体 Profile/Preset/工具/插件配置，不把这些 DSH 名称写成通用接口。已批准普通操作保持自主使用，付款、重要删除等动作单独制定保护，不默认每一步审批。

## 注册不是安装或授权

模块声明来源、稳定 ID、契约/模块版本、能力、依赖及前后端入口，由宿主验证。后台和管理面板分别注册并关联生命周期，通用页面从目录发现平台，不导入所有实现。

发现 manifest、读取元数据、安装代码、激活模块、连接账号、暴露工具和显示页面各有真实状态。未经批准不能为“验证声明”先执行任意模块代码；新增可执行 UI 入口也属于扩展范围。

## 新能力授权

候选流程：Agent 申请 → Host 固定来源/版本/校验/操作与权限 → 可信主人批准/拒绝 → Host 验证 → 受控安装/激活 → 健康检查 → 注册后台/页面/工具 → 必要时恢复选定运行时。

审批绑定请求、精确版本或 commit、实际操作、数据身份、状态及有效期。歧义“可以”、重放或目标变更不得放行。安装新模块、启用未授权预装能力、新 MCP/远端执行及升级范围仍按[权限规则](../security/权限与授权.md)具体确认。

同一已批准模块在批准范围内启动后台、注册声明过的页面或重复挂载界面，不逐次申请安装批准；新增下载执行、声明外入口或权限扩大须另行核对授权。

## 独立停用与卸载

暂停本模块新操作，核对在途动作，停止其连接/进程并撤销所属注册和页面，释放监听/定时器。删除飞书不删除 QQ 账号、事件、公共依赖或通用管理壳；全部平台移除后管理系统仍可用。停用/卸载程序/清理历史数据分开，未确认操作不得随模块移除而消失。

具体顺序、超时、热卸载和失败回滚尚需实验；本模块失败不应通过全局吞异常伪装成功。功能隔离和进程/权限隔离分别验证，见[插槽设计](插槽式扩展.md)。

## 具体运行时安装服务不是主人边界

DSH plugin-manager 源码显示 build 批准参数不验证 Eating 主人同意，许可可持久化，安装脚本可能按宿主用户权限执行。此为 [DSH 专属证据](../research/DSH源码核对.md)，其他 Harness 也需核查实际安装/更新/执行旁路，不能假设相同 API。

Cordis scope 和注册表同样不是 OS 权限保护。限制安装目录、配置/凭据、Shell、文件写入、包管理器、动态代码与远端执行入口；保留广泛执行能力时先做真实安全 PoC。
