# Eating 数据归属与隔离

状态：归属原则与可替换 Harness 边界已确认；目录、schema、保留策略 Proposed。来源：v0.3 §2.4、§6.1、§11、本轮负责人确认。

| 数据 | 责任方 | 约束 |
| --- | --- | --- |
| 固定核心人格 | Eating 主人受保护配置 | Agent 不可自行写；保留变更版本和来源 |
| 兴趣/关系/经历等长期记忆 | 所选 Harness 可用且主人授权的插件/机制 | 不复制成 Host 人生记忆库；说明本地/远端存储和故障 |
| 会话、上下文、Agent 事件 | 所选 Harness 的实际持久化机制 | 不由 Host 手改内部格式；恢复能力需实测，不假设可跨 Harness 导入 |
| 事件队列、逻辑身份与运行映射 | Eating | 运行可靠性数据，不冒充 AI 记忆；记录适配器和未决投递归属 |
| 授权记录、操作账本、安装清单 | Eating | 可信执行者写入；敏感信息脱敏 |
| 模块配置、注册与资源归属记录 | 各模块通过 Eating 受控接口管理 | 按模块命名空间划分；不得越权删除其他模块数据或全局注册 |
| 平台历史/附件 | 平台与通讯模块 | 按需读取、来源标记、最小保留、联系人范围保护 |
| 模型/平台凭据 | 受控配置或系统凭据设施 | 具体存储方案未定；不得放到代码、报告、日志 |

## 根目录原则

使用各 OS 标准应用数据目录，不依赖项目目录或安装目录可写。精确路径和应用标识待最终打包方案决定。

每个 Harness 适配器须声明并核对其配置、用户数据、会话、工作区、插件、缓存和凭据的实际解析范围，不能套用 DSH 环境变量。模块后台与前端的注册契约由 Eating 定义，见[插槽式扩展](插槽式扩展.md)；Cordis 仅为 Proposed 的 Node/TS 插件底座，作用域只表示逻辑资源管理，不是 OS/进程隔离。

路径隔离不等于 OS 权限隔离，也不保证记忆插件使用独立远端命名空间。插件自己的存储、账号与备份需单独验证；能力声明与一次健康查询都不能代替实际权限核对。

## DSH 适配器：专属根目录（源码分析）

必须单独核对 `DSH_HOME`、`DSH_AGENTS_HOME`、Profile、工作区、插件、Session、缓存与凭据的真实解析方式。官方源码显示 agents home 独立于 DSH home；同一 home 下切换 Profile 还会继承 home 级 patch。只改一个变量不能宣称完全隔离，见[源码研究](../research/DSH源码核对.md)。这些变量和路径规则只属于已核 DSH 版本，不是通用 Harness 契约；不得影响用户主 DSH 数据和配置。

## 单实例与迁移

对同一数据集取得跨进程排他运行权后才能激活主要认知控制者；锁实现、失效恢复和休眠行为未定。用户选择的 Harness 可替换，但同一时刻只允许一个活跃的主要认知控制者。

未来迁移必须在源实例停止后验证数据与凭据兼容；无法确认旧控制者已停止时不得激活新控制者。不支持多设备同时运行或自动切换，不承诺跨 Harness 会话/插件/记忆无损迁移或运行中热切换；实际 Codex/Claude Code 数据接口未核。详见[Harness 适配](Harness适配.md)。

升级先识别用户数据与安装资源边界，保留人格、记忆、会话、授权、队列与未确认操作；制定快照/迁移/回退。插件远端记忆不能假设可用本地目录备份完成，停用记忆机制也不能改用 Eating 运行日志冒充长期记忆。

## 停用、保留与删除

模块停用须停止其新工作和运行准入、撤销后台能力与界面注册，释放归属资源，并保留配置、队列、游标、恢复映射、授权审计和未决动作等必要证据。未能取消的在途或远端动作仍需对账；不能因卸载模块就清除这些不确定性。清理仅作用于自身资源，不影响 QQ、飞书等其他模块及通用管理页。

停用、移除可执行包与删除用户数据是不同操作。长期凭据保留/吊销、本地配置删除及远端记忆删除须有明确策略和主人授权范围，不能默认为一并清空；保留审计记录也不表示旧运行授权继续有效。记忆机制不可用或被移除必须可见。

队列、日志、附件和操作账本的保留期限、脱敏、导出/删除策略尚待负责人讨论。运行恢复确需内容时限制用途和范围；不能因不做第二份记忆而删掉恢复所需证据，也不能无限保存所有私人聊天。
