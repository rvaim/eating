# Eating 消息与可靠投递

更新：2026-11-03。当前Host已有有界未交接队列与可靠回执实现；本轮空闲整批及统一会话身份按[ADR-0038](../decisions/ADR-0038-空闲整批交接与统一会话身份.md)整合，源码修复与隔离验证已完成、未部署，运行证据见[本轮报告](../reports/2026-11-03-空闲整批交接与统一会话身份验证报告.md)。历史ADR-0013和报告保留当时事实，其中逐会话批次及硬切规则由0038替代。

## 接收与信任

持续接收平台事件的通讯模块由Eating管理，独立于Harness的运行状态。流程为：平台→模块验证来源→Host队列准入→等待主要接收者就绪及聚合触发→一次交接全部可交接前缀→主Agent自主安排→绑定子Agent独立理解及执行→核对平台真实回执。本地暂存可恢复未交接正文，仅内存模式在Host退出时丢失，不能笼统将收到称为已持久化。

QQ、飞书等模块分别注册后台收发能力与自己的管理界面，通用管理页按 Eating 定义的注册契约发现模块，不硬编码具体平台。新增或移除一个模块主要局限自身，不要求改写其他通讯模块，见[插槽式扩展](插槽式扩展.md)。

只有成功持久化后才能记录“Eating 已保存”。平台确认机制因模块不同而异；不支持可靠补收的平台不能承诺 Host 离线期间不丢消息。

Eating 区分内部、已验证主人、好友、群聊、公开内容、未知来源。身份来自模块验证和绑定记录，不能来自正文中的“我是主人”。主人的普通聊天也不自动等于批准某个安装。

## 当前事件与整批边界

公开HarnessEvent包含protocolVersion、稳定eventId、pluginId／instanceId／accountId／conversationId、发送者、接收时间、content／text及external来源；角色、目标、消息与资源引用来自后台核验并经队列保存。只保存未交接规范化信封，不另存原始OneBot包或终态历史。

Host以pluginId／instanceId／accountId／conversationId／source.kind／targetId完整身份计算每组静默、最长等待和冷却。maxBatchMessages／batchTargetBytes只提前触发；任一身份ready即汇总所有身份无冷却前缀，按global sequence一次deliverBatch，不逐会话或按阈值硬切。同身份冷却项挡住其后续，其他身份继续。batch.conversationId单一完整身份为其ID，多身份为null；SDK groupHarnessEvents用于一致分组。忙时isReady=false不交接、不耗attempts，wake重新读取全部当前候选。

外部会话标识只用于路由和隐私范围，不直接当作 Harness 的内部会话 ID。内容按来源标注并作为外部资料输入，不能伪装 system role；适配器必须说明来源表达、受理、持久化、消费观测和取消等 capabilities 的真实边界，见[接口契约](../technical/接口契约.md)。`unsupported`、`unknown` 与 `error` 不等于消息已处理，也不能转成虚构回执。

## 各阶段证据

| 阶段 | 可采信证据 | 不能推导 |
| --- | --- | --- |
| 已收到 | 通讯模块收到平台事件 | 已落盘 |
| 已保存 | Eating 事务提交并可重读 | Harness 已接受 |
| Harness 已接受 | 适配器对应的真实接口回执与关联 ID | Agent 已感知或处理 |
| Agent 已感知 | 可关联的持久事件/消费证据，若接口真实提供 | 必然回复 |
| 已尝试动作 | 工具调用和操作账本 | 平台成功 |
| 平台确认成功 | 平台回执或真实状态查询 | 永不会重复 |

上述是证据分层，不是已经冻结的一条线性状态机。一个事件可以不产生动作，动作也可能有多个。无法观测某层时记录“未知”，不能伪造“已读”。模型结束轮次也不等于平台动作成功。

## 去重、重试与恢复

Host使用SQLite及可选内存队列，保留稳定eventId去重、状态和attempts，外部动作账本独立。只有accepted=true、durable=true、非空receiptId及本地确认才能删除正文；DSH凭据要求原生flush成功与匹配原子ACK，不能用idle代替耐久证据。ACK本地保存失败只重试本地提交，不再次调用接收端。输入去重不等于模型／外部动作幂等，不能声称exactly-once。

只有明确拒收才有限冷却重试；超时、异常、中断、缺少耐久证据或耗尽尝试转uncertain保留正文，不自动补投。原生ACK重建须匹配当前持久记录；detach、存储失败和同版恢复不等于放开未知重放。外部动作使用稳定request_id，结果未知先核对，不换ID重复执行。

同一时刻只向一个活跃主要认知控制者投递。更换 Harness 时保留旧投递归属和未决回执，不把未知结果事件直接重放到新 Harness，不承诺跨 Harness 无损迁移或运行中热切换。

## 模块停用与失败隔离

停用模块须停止其新事件准入、新投递与新外部动作，撤销后台能力和管理界面注册；已开始的调用按真实取消能力处理，不能把撤销注册当作已经取消平台动作。保留待处理事件、游标、授权审计与未决动作，重新启用前先对账；删除模块不默认删除这些数据或远端聊天/记忆，具体保留策略见[数据归属](数据归属.md)。

某模块断线、注册或界面加载失败应限制在自身并显示原因，不清空全局注册表或让 QQ 故障停掉飞书。共享存储、Host 或同进程崩溃仍可能影响整体；逻辑作用域不提供 OS/进程隔离保证，须另行验证实际故障边界。

## DSH上下文与真实空闲

一个主信封保留全部有序events，context.conversations提供逐组引用及可信绑定。原生准入核对nonce／session／batch／digest和owner policy后激活contexts；主Agent可按各组context_ref选择处理，子只取得对应组events和scope。所属主turn结束清理当前正文，首次委派不提前清；SDK user来源不代表可信主人，外部来源仍须后台核验并由当前桥标记。

原生运行时以当前root Agent的真实idle状态及nextTurn／nextStep入箱为空报告受认证、递增且有界有效的状态，idle唤醒Host；SDK run结束、turn/end或运输ACK均不能独立证明可交下一批。普通／主动联系按同对象身份复用后续child UUID，保留已有重复历史；记忆逐组scope召回与采集，不复制混合协调输出。完整边界见[Harness适配](Harness适配.md)和[接口契约](../technical/接口契约.md)。

本轮自动验证限独立临时目录、模拟通讯及本地模型夹具；最终命令和实数以本轮报告为准，不将旧阶段或默认跳过写为本轮实跑。其他Harness、真实模型行为与真实外部平台仍须独立核对；[主动行为方案](../plans/2026-11-03-主动活动行为改进方案.md)尚未实施。
