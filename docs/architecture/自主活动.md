# Eating 自主活动与唤醒

状态：产品目标与可替换 Harness 边界已确认，实现 Proposed；可行性未验证。来源：v0.3 §9、本轮负责人确认。

## 认知边界

模型一次请求结束后不会凭空开始下一轮。需要续行、调度或事件提供新的思考机会，但新活动、是否继续、委派、停止与休息必须由用户选定 Harness 的当前主要认知控制者决定。只有一个自主身份、一个当前活跃的主要认知控制者；子 Agent 是执行者，不默认为独立人格。

Eating 不调用另一套模型来生成生活计划，不用固定任务池或每日配额制造自主性，也不自建第二套 Agent Loop。Host 仅在已核能力和授权范围内提供事件、机械唤醒及运行约束；唤醒只提供机会，可以没有新任务或外部回复。认知边界见[Harness 适配](Harness适配.md)与 [ADR-0006](../decisions/ADR-0006-可替换Harness与认知边界.md)。

## Harness 能力前提

适配器需说明续行、后台运行、调度、忙碌排队、子 Agent、暂停/取消、生命周期观测以及记忆机制等 capabilities。不能从 DSH 行为推断 Codex/Claude Code 的接口；后两者尚未核对。

`unsupported` 是明确不支持，`unknown` 是未核或证据不足，`error` 是本次探测/调用失败；必要能力缺失或未知须明确显示限制，失败不能被称为 AI 自愿休息。能力声明不等于能力已获主人授权，也不保证调用成功；状态和字段名均为候选，见[接口契约](../technical/接口契约.md)。长期记忆仅来自所选 Harness 可用且主人授权的插件/机制，Eating 不建第二套人生记忆。

## DSH 适配器：优先验证路径（源码分析）

DSH 是首个具体技术验证对象，优先复用其 Agent Loop、followup、Schedule、子 Agent 和生命周期事件。SDK 暴露与进程内 API 的差异见[源码调查](../research/DSH源码核对.md)。只有公开接口不足才研究 DSH 薄桥，不能因为需要持续运行而重写 Harness。

DSH Schedule 是需要正确装配的服务/工具，不是仅引入 SDK 包就必然可用。源码表明它涉及独立的 inbox/session 持久化与任务记录写入，存在重复窗口，详见[研究](../research/DSH源码核对.md)。定时提醒送达不等于自主行动成功。这些是 DSH 固定版本源码结论，尚非 Eating 运行保证，也不是其他 Harness 的共同调度协议。

## 休息、暂停与模块停用

主要认知控制者可按实际能力安排未来唤醒、等外部事件或休息。是否设置低频兜底唤醒尚未决定；必须区分意外失去续行机会、明确长期休息和人工暂停。不能以保底定时器反复打断已经明确的休息。

设备休眠/关机不能保证实时触发。漏发合并、时区、恢复补发和取消语义需在实际组合下验证，不承诺精确时刻或精确一次。

停用相关模块须停止新唤醒与新任务、撤销能力和管理界面注册，并核对已登记调度与在途执行；本地撤销注册不能证明远端调度或工具已经取消。保留未决记录，单一可选模块故障应局限自身；主要认知控制者失效时停止新的认知投递，不自动再启动另一 Harness 接管。切换前须确认旧控制者停止，跨 Harness 无损迁移及运行中热切换均未承诺。

## 资源保护

Host 管理资源上限与人工暂停，不决定兴趣。候选约束：单活动调用量、Token/成本统计、并行上限、有限失败重试、重复无进展检测、暂停后不再开始新轮次。实际阈值由成本实验和负责人决定，不凭空填数。

预算耗尽、模型错误或记忆不可用应显示真实原因，不能把异常停止称为 AI 自愿休息。已开始的工具取消能力和暂停边界也要按适配器测试；新增插件、MCP 或其他可执行扩展能力仍须可信主人的明确批准。

## 可行性观察

在没有主人任务的条件下记录是否产生有意义的自发行动、能否自然停止、人格一致性、真实记忆使用、合理休息、子 Agent 委派、重启连续性与成本。评价规则和观察时长在实验前确定，保留负面结果。

“长期持续”不能靠一次演示证明；首先完成有预算的短实验，再按证据扩展，见[Phase 3](../plans/路线图与PoC计划.md)。DSH 实验不能替代其他 Harness 的能力与自主活动验证。
