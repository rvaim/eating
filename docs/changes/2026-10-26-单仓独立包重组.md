## 修改原因

原 QQ 已有独立后台与面板注册，但源码目录直接装配和 Web 私有导入仍将插件绑定主程序。只移动路径不足以满足单独安装、升级和发布，需要把公开 SDK、应用源码和插件产物三个边界落到实际包与加载流程。

## 修改内容

1. Host 从旧服务目录迁到 [apps/host](../../apps/host/)，[Web](../../apps/web/)继续作为独立应用；根 pnpm workspace 聚合开发、构建和测试，应用分别拥有包配置。
2. 通用后台契约迁为 [plugin-sdk](../../packages/plugin-sdk/src/index.ts)；前端契约和受控 API 客户端迁为 [ui-sdk](../../packages/ui-sdk/src/index.ts)。公开包分别为 `@eating/plugin-sdk`、`@eating/ui-sdk`，当前 `1.0.0`，契约 `apiVersion` 为 `1`。[plugin-core](../../packages/plugin-core/)保留纯注册与旧持久化测试。
3. QQ 迁为 [communication/qq](../../plugins/communication/qq/) 下独立 `@eating/plugin-qq` 包，当前 `0.2.0`。后台、界面和 [OneBot 配置](../../plugins/communication/qq/src/config.ts)由插件管理；不再导入应用私有源码，通用 SDK 不含 QQ 专有配置。
4. QQ 构建独立后台 ESM、界面 JS/CSS 和使用 `schemaVersion`、`apiVersion`、`id`、`version`、`backend`、`frontend`、`integrity` 的清单，其中 integrity 保存各文件 SHA-256。Host 从已安装产物加载，Web 动态导入 Host 提供的插件资源，界面 SDK 与 React 共享宿主实例。
5. 本地安装 CLI 负责校验兼容/哈希、暂存发布和切换激活索引；代码存于 `EATING_HOME/plugins/<pluginId>/versions/<version>`，通过安装索引选择激活版本。安装、升级、卸载需 Host 停止，完成后重启；升级只改目标插件，卸载撤入口并保留账号数据。
6. 新增 [ADR-0012](../decisions/ADR-0012-单仓独立包与插件加载.md) 与[工程结构说明](../architecture/工程结构与插件发布.md)，同步索引、状态、交接、受影响架构与有效 Markdown 本地链接。旧目录不留转发 shim。

详细旧到新映射统一见[工程结构说明](../architecture/工程结构与插件发布.md#迁移映射)。包名、版本、清单和安装布局是本轮实现选择；负责人确认的是仓库、发布与公开接口原则，不把所有细节表述为逐项确认。

## 影响与兼容

源码路径和包引用需要随迁移更新；不能继续依赖旧路径或通过 shim 隐藏未改的导入。主程序不捆入 QQ，运行时不要求仓库源码存在；本轮已用仓库外安装、删除构建源后重启和浏览器产物加载验证这一点。

既有 `~/.eating/bot/qq-bot/accounts/<稳定 UUID>/config.json`、账号索引、Host 锁与 SQLite 保持位置。新增插件目录只管理代码版本，不迁移或清空用户账号数据。消息、幂等、MCP 和 Harness 预留继续沿用正式 QQ 的实际语义；当前仍只一个默认账号，没有真实 Harness 或真人 QQ 联调结论。

本轮不实现运行中热更新、任意第三方市场下载、真实 npm 发布、完整恶意插件 OS 沙箱或新的平台能力。SHA-256 与兼容检查不代替主人批准。
