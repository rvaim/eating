# QQ 按需实时日志

日期：2026-10-27，Asia/Shanghai。单仓独立包重组已按用户明确要求提交为 `68031fc`；本轮实时日志改动未提交、未推送。

## 修改原因与确认结论

QQ 的正常 WebSocket 已会主动接收消息并写入 Host SQLite；“消息记录”的读取与刷新不是 QQ 收消息的前提。本轮增加独立的实时诊断视图，帮助主人查看新消息到达和日志通道状态。

用户最新纠正明确：不建设日志持久化或后台缓存。只有“实时日志”页签打开且页面可见时才订阅，离开即停止并清空；浏览器默认保留最近 100 条，可选数量。QQ 正常连接、消息保存与 Harness 待投递流程保持原逻辑。

## 修改内容与接口边界

- QQ 新增第 5 个“实时日志”页签，复用已有浅色、中文表单和细分隔列表，不增加演示消息或假造 QQ 在线状态。
- 公开 `@eating/plugin-sdk`、`@eating/ui-sdk` 为 1.1.0，`apiVersion` 保持 1；QQ 为 0.3.0，Host 自身包版本不变。MCP 工具仍为 10 项，DSH 插件及实际 Harness 适配仍未实现。
- 后台公开 `PluginLogEntry`，界面仅通过公开 `subscribePluginLogs(pluginId, handlers)` 订阅；Host 工作区提供每插件 `logsSupported`，面板据此判断能力。插件不引用应用私有源码；前端面板不直连 OneBot，不读取浏览器 localStorage。
- Host 提供泛型 SSE，订阅前由公开客户端完成会话鉴权，Host 核对 ownerSession 与 Host/Origin；最多 8 个查看者，背压时断开并由客户端自动重连。每个打开的查看流每 15 秒注释心跳，关闭即清理。
- 没有查看者时，不执行日志源 factory、不启动日志定时器；不缓存后台日志、不写日志文件、不输出 console 日志。没有日志快照、历史接口或重连补发。

## 生命周期与显示规则

只有页签激活、插件启用、日志能力可用且 `!document.hidden` 时创建订阅。隐藏页面、离开页签、pagehide、关闭页面、停用或卸载组件都会退订并清空；回到可见页签时从 0 开始接收新事件。SDK cleanup 停止迟到的初始化、连接和重试；组件以代次和清理状态过滤迟到回调，取消待显示帧和增量公告定时器。

“保留条数”默认 100，可选 50 / 100 / 200 / 500 / 1000，仅存于浏览器组件内存。同 ID 去重，收到事件立即裁剪到上限；调小即时裁剪，调大不补历史。选择不写后台配置或浏览器持久存储。“清空显示”只清前端列表并继续监听，不删除已保存的 QQ 消息，日志通道错误仍保留可见。

面板明确：“仅在此页签打开且页面可见时显示新消息。离开即停止并清空；日志不保存到磁盘。”四态“正在连接日志流 / 实时接收中 / 连接中断，正在重连 / 已停止”只描述日志通道，不代替 QQ 连接状态。空列表等待真实新消息，不放演示数据。

日志使用 `id / timestamp / level / event / message`；`message.received` 显示为“收到消息”。metadata 仅使用已验证的 `accountId / instanceId / conversationId / senderId / messageId`、`kind` 与群聊显式 `groupId`；群号不从会话字符串猜测，会话 ID 原样显示。正文为最多 500 字预览，不记录认证字段，正文中出现当前 OneBot 令牌时会替换，全部按纯文本渲染；不承诺识别任意消息里的所有秘密。列表限制高度并滚动，长正文和 ID 折行；辅助技术使用独立增量提示，避免每次播读整个列表。

正常 QQ WebSocket、SQLite 消息持久化和 Harness `pending / accepted / uncertain` 与日志视图独立。关闭日志页签不会停止 QQ 收消息或消息入库；`accepted` 仍不表示 Agent 已读或已回复。
