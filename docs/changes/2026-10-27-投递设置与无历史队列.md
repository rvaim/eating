# 2026-10-27 投递设置与无历史队列

状态：负责人已明确批准“不需要聊天历史”和可选队列设置。本轮完整构建/严格类型、Vitest 387/387、浏览器 13/13 与 Gateway 本地提交故障新增回归通过；真实库迁移、QQ 0.4.0 安装、connected/设置 200 API 核验和 4 张设置截图读图检查已完成。当前未提交、未推送，基线仍为 `68031fc`。决策见 [ADR-0013](../decisions/ADR-0013-无历史消息与可配置投递队列.md)，证据汇总见[验证报告](../reports/2026-10-27-投递设置与无历史队列验证报告.md)。

## 修改原因与目标

旧接收表同时承担聊天历史、去重和 Harness 待投递，可靠交接后仍保存正文，并重复保存原始 OneBot 事件与 text。负责人明确历史体积不必要，要求只为未交接消息临时保留内容，并能在全局设置里配置存储方式、容量、聚合等待和重试。

本轮将长期保留责任留给选定 Harness 的已授权机制。Eating 仅管理来源、准入、有限暂存与可靠交接；不因删除历史而删除外发防重复账本，不把接收端确认伪装为模型消费。

## 界面、版本与工具

新增全局“设置”侧栏入口，二级分类为“消息投递”“队列与存储”。两个分类共用草稿，统一保存/校验并带 revision；409 冲突保留草稿，重新读取需确认放弃未保存内容。清空队列为单独确认操作，需勾选后执行，不把清空前的草稿顺带保存。

QQ 删除本地历史页签和已收消息 MCP；当前页签为“连接配置 / 实时日志 / 功能测试 / MCP 能力”，工具目录从 10 减为 9，保留 OneBot 标准 `get_msg` 单条查询，可查询范围由协议端决定。发送/撤回仍用稳定请求 ID，功能测试仍需逐次确认。

版本调整为 Host/Web/根应用 **0.3.0**、公开 plugin-sdk/ui-sdk **1.2.0**、QQ **0.4.0**，`apiVersion` 保持 **1**。按独立包构建/安装，不恢复源码扫描或旧路径 shim。已完整构建，停旧 Host 后于锁内迁移并安装新 QQ，重启后的实际版本、连接和设置 API 均通过核验。

## 投递与可靠交接

Gateway 按 `conversationId` 分组，不跨会话。静默从同会话末条重置，最长等待从首条固定，达到条数或目标字节提前。单条超过目标时独立、不拆分，仍受队列硬限制。接收端有 `deliverBatch` 时传结构化批次，旧 `deliver` 按事件逐条调用，不能承诺一次模型请求。

只有接收端同时返回 `accepted === true`、`durable === true` 和非空 `receiptId`，且本地确认事务成功，才删除对应正文并累计可靠交接数。该数表示接收端接管，不是模型已读、任务成功或外部动作完成。

明确拒收才按间隔有限重试，耗尽保留 uncertain；超时、抛错、缺凭据、注销/停止中断均保留待核对，不自动补投。唯一主 sink 和迟到结果边界保持。当前无 DSH 插件或真实 Harness 接收者，自动验证使用独立测试 sink。

## 数据保留、容量与故障

新 `delivery_queue` 只持有 outstanding 的规范化 Harness JSON 一份和元数据，不保存原 OneBot raw、额外 text 列、未转交正文或终态历史。persistent 临时放 SQLite、重启可恢复；memory 只在 RAM，Host 退出/重启丢失未交接正文。运行中切换迁移全部存活信封，准备后原子提交；写失败保留原模式、revision 与内容。

`event_dedup` 只存哈希标识、时间、短状态与回执哈希，24 小时、常态合计不超过 10000 个。SQLite 连清理也持续失败时，磁盘旧标识最多 10000，加内存故障后备最多 10000，合计最多 20000 个小标识，无正文；后备 RAM 无法保证跨重启。队列仍保留的 event_id 不因去重过期再次准入。

reject-new 满时新正文不保存，返回 `inserted: true / queued: false / admission: rejected`，计 rejected、最近队列错误，并允许可见实时日志记录这次接收准入。drop-oldest 仅移最旧 pending，保护 delivering/uncertain；单条超总容量先拒，不能先删空原队列。缩容预计算，保护状态仍超限时整次 409，不部分删除后失败。

清空需用户勾选不可恢复提示；存在 delivering 则 409。成功清除其余正文、计 discarded，保留短期哈希、账号配置与 `actions` 发送防重复账本。发送执行、锁、持久结果与 unknown 语义不变。队列状态提供总条数/字节、分状态计数、拒绝/丢弃、超容量与最近错误，持久模式以 SQL 聚合元数据，不为工作区周期查询读取大正文。

## 旧库迁移与回退边界

同一事务保全旧 pending/delivering/uncertain 的有效 Harness 信封，顺序和尝试数保持，启动 delivering 转 uncertain。终态只可留未过期的小哈希，旧正文、raw/text 副本和 `incoming_events` 表删除，schema 更新后在原数据库一次 VACUUM/checkpoint，不生成聊天全量备份。待投递损坏或事务失败则取消迁移、保留原表，不跳过丢弃。

旧 backlog 超过新默认容量全部保留，显示 overCapacity 并拒绝新消息，不启动即隐式裁剪。账号索引/配置、MCP 令牌、安装信息、锁路径与发送账本不迁移或清空。新库启用 incremental auto_vacuum 与 secure_delete，正常删除后增量回收和 checkpoint，避免每次全库重建。

已按要求删除的历史和内存退出丢失的正文不承诺恢复。旧 Host 依赖旧表，不可直接降级后假设新队列仍可见；回退需先安全交接或明确反向迁移，不能恢复聊天历史作为兼容修复。

## 实时日志保持的原则

日志仍只在 QQ 可见页签打开且插件支持时订阅，默认 100 条，可选 50/100/200/500/1000，全部浏览器内存。隐藏、离开、关闭、pagehide 或停用立即退订清空，Host viewer 归零，不落盘、不补发、后台无日志缓存；无查看者不执行 factory/计时器。正常 QQ WebSocket 和队列准入独立运行。

只在查看期间展示最多 500 字纯文本预览与已验证标识，新增 `queueAdmission` 表明 queued/not-forwarded/rejected。原 token 隐藏与 SSE ownerSession/Host/Origin、8 viewer、背压和心跳清理边界保持。上一轮[变更](2026-10-27-QQ按需实时日志.md)和[报告](../reports/2026-10-27-QQ实时日志验证报告.md)保留当时 321/10 与历史功能，不重写。
