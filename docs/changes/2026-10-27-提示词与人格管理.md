人格初始 `personas=[]`、`activePersonaId=null`。可创建、改名、编辑正文、启用、停用和删除，最多 100 份；创建不自动启用。启用另一份原子替换当前选择，允许全部停用；活跃人格删除返回 `409 ACTIVE_PERSONA`，先停用或切换才可删除。

## 编辑体验

编辑器使用本地打包的 CodeMirror 6。输入 `{{` 在光标处提供当前范围变量；上下键选择、回车/Tab 插入、Esc 关闭，也可触屏选择或用“插入变量”按钮。合法变量绿色标记，非法变量红色标记，诊断可定位到正文精确范围。切换文档创建独立编辑状态，撤销不会恢复其他文档内容。

页面内按文档保存内存草稿；保存时提交原文档 revision，冲突保留原草稿及保存版本，要求显式重新读取核对。重读有未保存修改时先确认放弃，不自动用新版本覆盖草稿；草稿不承诺跨刷新恢复。

## 变量与模板规则

变量目录以[公开 SDK 实现](../../packages/plugin-sdk/src/authoring.ts)为准。主提示词和人格正文各 2 项，群聊与私聊各 11 项；后九项虽部分是批次元数据，统一标记 external，不能插入主提示词或人格正文。

| 变量名称 | 适用范围 | 来源 | 值的定义 |
| --- | --- | --- | --- |
| 当前时间 | 主提示词、群聊、私聊、人格 | runtime | 渲染时当前时间 |
| 人格名称 | 主提示词、群聊、私聊、人格 | persona | 当前启用的人格名称；未启用时调用方明确提供空值 |
| 平台 | 群聊、私聊 | external | 实际 platform id |
| 机器人账号 | 群聊、私聊 | external | 本批实际机器人账号标识 |
| 会话编号 | 群聊、私聊 | external | 实际 conversationId |
| 会话类型 | 群聊、私聊 | external | group 或 private |
| 发送者列表 | 群聊、私聊 | external | 本批唯一发送者 ID JSON 列表 |
| 消息列表 | 群聊、私聊 | external | 带逐条来源的完整本批 JSON |
| 消息内容 | 群聊、私聊 | external | 本批最新一条文本 |
| 消息数量 | 群聊、私聊 | external | 本批消息条数 |
| 批次编号 | 群聊、私聊 | external | 稳定 batchId |

支持 `{{ 当前时间 }}` 形式的外围空白，按规范化名称识别。未知变量、越作用域、未闭合与嵌套/畸形变量分别诊断，范围使用 JavaScript UTF-16 `[from,to)`。嵌套的内层合法变量不会掩盖外层错误；孤立 `}}` 作为普通正文。采用线性扫描，正文上限 50000 个 UTF-16 代码单元，避免回溯扫描。

分析空正文合法，保存服务另行要求正文非空。渲染先验证整份模板及所有 own-property 字符串绑定，再单次替换；不 eval，替换值中的 `{{…}}` 不二次解释。`__proto__` 等原型 key 不可绕过目录或绑定校验。不提供人格正文自引用，也不提供群名称、昵称、工作目录等当前无稳定字段的变量。

## 持久化与并发保护

[Host 领域服务](../../apps/host/src/authoring.ts)通过现有同步 `getSetting/setSetting`，在单实例 Host 下完成读校验、CAS 检查与单条 SQLite setting 写入，中间无 await。主人配置独立保存在 `host:authoring` 单 JSON，带 `schemaVersion: 1`、全局 revision、三份提示词、人格文档和唯一 activePersonaId；总 UTF-8 JSON 上限 5 MiB。目录快照只含人格摘要，正文每次读取单个人格。

人格名称 trim 后 1 至 80 个字符，每份正文非空、合法且最多 50000 个 UTF-16 代码单元。创建人格文档版本从 1 开始；每次真实修改全局版本加一，正文/名称修改才增加对应文档版本。完全相同保存或非活跃停用在版本一致时幂等，不产生额外写入。

| 操作 | CAS 使用的版本 | 特别规则 |
| --- | --- | --- |
| 修改提示词 | 对应提示词 revision | 独立于其他文档编辑 |
| 修改人格 | 对应人格 revision | 保持当前启用关系和其他数据 |
| 删除人格 | 对应人格 revision | 活跃人格拒绝删除，接口需明确确认 |
| 启用/停用人格 | 全局 revision | 先核版本，再判断幂等；启用原子切换唯一选择 |

冲突统一返回 `409 AUTHORING_REVISION_CONFLICT`，未知文档 404，非法模板 `400 INVALID_TEMPLATE`，只返回固定中文说明，不回显整份正文。API 沿用 owner session、Host/Origin 与 CSRF 边界，创建成功 201，其他成功 200；不提供模型/MCP 修改固定人格的接口。返回对象深拷贝，调用方修改不能污染后端。

构造服务不读取配置，普通 GET 只返回默认或校验过的已存数据，不初始化写库。schema、内容或容量损坏返回 `AUTHORING_STORAGE_CORRUPTED` 并拒绝覆盖原文档；故障只影响管理页读取，不阻止 Host 与 QQ 服务。此文档仅保存主人配置，不存聊天历史、批次正文或运行轨迹。

## 关闭连接的根因与修正

完整浏览器回归暴露了真实 Host 关闭问题：页面正文断言约 3.1 秒完成后，既有每 3 秒的 `/workspace` 轮询在 `Host.close()` 期间仍收到允许 keep-alive 的 503 响应，继续延长连接寿命，使清理拖到 45 秒。根因是已关闭路由分支没有要求连接关闭。[Host 路由](../../apps/host/src/app.ts)现先设置 `Connection: close` 再返回 503；未修改测试清理或增大超时。

新增[真实 TCP 回归](../../apps/host/src/app.test.ts)使用 `Expect: 100-continue` 建立已接收但尚在处理的活动请求，再在关闭期间发送 pipeline 请求，确定性验证 503 带关闭连接响应头。该项计入 Host API 第 15 项；修复后完整 19 项浏览器回归通过，首项清理正常结束。
