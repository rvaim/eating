# 管理面板独立滚动修复

日期：2026-10-28，Asia/Shanghai。基线dfc6beb。用户反馈面板、二级侧栏和顶部Tab一起滚动；本轮修复视口与滚动职责，不改变QQ工具、数据、授权或模型行为。应用／Host／Web与QQ补丁为0.7.1；SDK1.5.0／1.6.0、DSH0.2.0和apiVersion1保持。

## 根因与修正

原应用只有min-height:100vh，工作区同样只有最小高度。真实浏览器在900px高视口中量得文档5110px、主区和二级栏均4991px；滚轮650后文档scrollTop=650、二级栏从y119移到y-531。实际滚动发生在文档，QQ页签又是普通流元素，因此一起离开视口。

[共享布局](../../apps/web/src/styles.css)现采用受100dvh约束的网格、可收缩的纵向主框架和独立overflow区域。页面头部保留；右侧主区、二级长列表和全局栏各自滚动，移动分类仍横排。概览和插件目录有各自的滚动边界，目录展开时工作区保留有界可操作高度，避免短窗口正文被挤没。

[QQ样式](../../plugins/communication/qq/src/web/panel.css)让Tab贴在主区顶部，以通用内容间距变量抵消滚动容器顶部内边距；正文控件有滚动余量，键盘聚焦不会落在页签后面。页签本身不套正文聚焦余量，箭头切换不会带来额外滚动。

首次边界检查发现：1280×420展开目录时，主区被挤到112px，QQ包装盒结束于宿主停用区域之前，sticky被末端推出117px。修正让纯展示包装使用display:contents，保留直接子项1050px宽度限制，使固定范围覆盖完整宿主article；主工作区至少保留min(220px,50%)，让目录自行收缩滚动。没有增加第二层QQ正文滚动、跨插件选择器或React重挂。

实际读图又发现macOS Chromium的边界回弹会移动合成画面：Tab的DOM坐标仍正确，画面却被裁。对照三个新页面，contain仍裁切，修改顶部间距也仍裁切，overscroll-behavior-y:none完整显示；因此主区与概览禁用边界回弹，同时保留独立滚动。没有以等待或放松坐标断言掩盖。
