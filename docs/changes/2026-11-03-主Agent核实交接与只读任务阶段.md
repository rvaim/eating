# 主Agent核实交接与只读任务阶段

日期：2026-11-03，Asia/Shanghai。状态：源码已实现，隔离验证及实际 Eating 部署完成；未提交或 push。主人“修复问题”已授权修复并部署；最终验证、运行版本与现场保留证据见[本轮报告](../reports/2026-11-03-主Agent核实交接与实际部署验证报告.md)。

## 修改原因

仅传 `context_ref` 无法把主 Agent 已核实的可披露事实交给原会话子；仅用任务文字要求“只核实不发言”，仍保留发送和写入工具，不能形成实际约束。本轮把主先理解／判断事实、显式阶段及事实交接落到严格契约与工具守卫，子继续自主组织回复。

## 修改内容

- `eating_handle_conversation` 必填 `{context_ref,mode:'reply'|'verify'}`，可选 `context_notes` 最长8000字符；缺 mode 或未知字段拒绝。notes 只传可披露事实、来源和未知，不预写全文，不改变授权。子信封新增 `coordination:{mode,context_notes}`，保原始 context／events。
- `eating_contact_target` 必填 `{target_id,task,mode}`；跨目标核实选 verify，不向被查询会话发公告。`eating_delegate_task` schema 保持 `type_id/context_ref/task`，内部固定 reply，用于明确执行任务或用户明确逐字内容。
- verify 临时只读范围贯穿控制层、Host 通讯和功能 MCP；目录与调用守卫仅允许 `tool.readOnly === true`，direct 未知 metadata 不放行。零只读工具允许空 MCP；`AgentMcpConnection.toolNames` 必填并返回实际过滤集合。
- verify 子不挂任何原生 feature／全局工具，本阶段也不额外挂 time。后续 reply 在同 canonical UUID 上从原普通授权重新取 scope／工具并撤旧 lease；临时 scope／policy／readOnly 只在 RAM，不改持久 schema 或主人配置。
- 主子必需规则进入各自唯一 complete，主先理解请求和判断事实，再选 mode；必要时协调对应会话只读核实，将可披露事实交原子自然表达。主不写每句文案，语义是否需要核实仍由 LLM 判断，只保证显式 verify 阶段不能通过受控路径发／写，不承诺事实绝对正确。

当前决策见[ADR-0040](../decisions/ADR-0040-主Agent核实交接与只读任务阶段.md)，定向替代 ADR-0035／ADR-0039 的仅 context 旧交接契约及纯文字核实约束；旧历史正文和数字保持。接口、架构和提示词操作入口同步，不增加旧格式兼容或第二 Loop。
