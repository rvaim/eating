## 背景与决策

Eating 需要持续身份与自主行为，但外围再实现 Agent Loop 会产生两个互相竞争的认知控制器。决定将模型推理、意图形成、行动选择、子 Agent、上下文和记忆插件使用统一交给 DSH。

Eating 只提供运行、事件、能力、授权、故障恢复与管理界面。事件分发与资源限制不是 AI 生活决策。

## 原因与备选

复用官方能力，避免重复维护 Harness。未采用 Host 自行调用模型规划人生、外部规则生成兴趣和独立长期记忆库，这些会违反唯一核心目标。

## 影响

自主生活的可行性取决于 DSH 的真实续行、调度和记忆能力，不能靠第二套决策引擎绕开验证。发现接口不足先考虑薄插件和上游扩展。

## 证据与后续

产品依据见[需求 R-05](../product/需求基线.md)。官方接口只读核对见[研究](../research/DSH源码核对.md)。通过后续自主性 PoC 验证可持续性；尚无运行结果。
