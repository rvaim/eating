# ADR-0002：Eating Host 与 DSH 的职责边界

## 背景与决策

DSH 可能重启，通讯、事件与主人授权仍需可靠管理。Eating Host 负责 DSH 生命周期、独立环境、能力清单、插件管理、来源验证、持久投递、恢复与 UI 接口；DSH 主 Agent 决定如何行动。

安装授权必须在 DSH 之外实施。固定人格配置和安装权不能依赖模型遵守提示词。前端只使用 Host 受控入口。

## 原因与备选

该边界允许运行环境独立恢复，并避免 AI 自授权限。未采用前端直接调用 DSH 内部高权限服务，也不让 DSH 自己审批新增能力。Host 使用 Node 还是 Rust、进程是否拆分均未在本 ADR 冻结。

## 影响

需要跨进程契约、可信主人绑定、执行权限隔离和结果未知的操作恢复。与主 Agent 同 OS 用户且有广泛 Shell 权限时，隔离目标不能默认成立。

## 证据与后续

[需求](../product/需求基线.md)、[总体架构](../architecture/总体架构.md)、[权限](../security/权限与授权.md)。源码分析已发现插件安装服务自身不验证对话批准；运行保护必须做独立安全 PoC。
