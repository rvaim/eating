# ADR-0005：持续收消息的连接器独立于 DSH

- 状态：Proposed
- 日期：2026-10-26
- 来源：v0.3 §8.1、§11
- 2026-10-26 范围补充：结合 [ADR-0006](ADR-0006-可替换Harness与认知边界.md)与 [ADR-0007](ADR-0007-插槽式模块与界面注册.md)，连接器应独立于选定 Harness 的生命周期，并可独立注册后台/管理界面；下文 DSH 为最初案例，独立进程和故障隔离仍需单独验证。

## 背景与决策提议

DSH 崩溃或升级时仍可能收到外部消息。建议有持续接收需求的平台由 Eating 管理的常驻连接器收消息，先持久化，再向主 Session 投递。工具型 MCP/DSH 插件仍可保留在 DSH 中使用。

“独立”首先指生命周期和故障边界，不预先规定每个平台必须单独 OS 进程。

## 原因与备选

仅把监听器装入 DSH 难以保证它离线期间继续接收。平台若有可靠历史补收，内置插件也可能满足部分场景，需按实际插件验证，不能一概宣称都不支持。

## 影响

需要来源认证、断线重连、事件唯一键、离线保留、隐私处理、凭据隔离和发送结果核对。平台不支持补收时，Host 离线的缺口只能明确报告，不能承诺无丢失。

## 证据与后续

[消息设计](../architecture/消息与投递.md)、[恢复](../operations/故障恢复.md)。Phase 2 先用模拟连接器验证 DSH 离线积压、重启补投和重复事件；真实平台待负责人选择并验证。尚无运行结果。
