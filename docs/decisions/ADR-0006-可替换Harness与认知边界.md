# ADR-0006：可替换 Harness 与认知边界

- 状态：Accepted（架构原则；不代表适配器实现或运行验证通过）
- 日期：2026-10-26
- 依据：负责人明确要求用户可选择 DSH、Codex、Claude Code 或其他 Harness，并于本轮授权写入文档。
- 替代：[ADR-0001](ADR-0001-DSH唯一认知核心.md)、[ADR-0002](ADR-0002-Host职责边界.md)。

## 背景

v0.3 绑定 DSH，不符合负责人进一步明确的插槽式设计。需要保留唯一 AI 身份和不重写 Harness 的目标，同时允许独立替换运行时实现。

## 决策

Eating 的认知与行动交给用户选定的 Harness；宿主管理进程、能力、授权、通讯、事件、资源和恢复。通过 Eating 自己的运行时接入约定连接具体适配模块。DSH 作为首个具体验证对象，不是不可替换依赖。

同一 AI 数据集初期仅一个活跃主认知控制者；不因安装多个适配器产生多个自主身份。Host 不实现第二套 Agent Loop、意图/人格决策器或人生记忆引擎。

长期记忆使用所选运行时兼容且主人授权的插件/机制。不可用必须报告；不能承诺不同 Harness 的记忆、会话、工具和插件通用兼容。

## 原因与备选

模块边界应稳定，不让通讯和 UI 随具体 SDK 改动。继续锁 DSH 会违反负责人新方向；从头自建通用 Agent 引擎会破坏复用与单一认知控制边界，均不采用。

## 影响与风险

需要能力声明、版本协商和运行时专属错误/数据映射。跨 Harness 无损迁移、运行中热切换、多运行时并行未承诺；不能将 DSH 的 Preset/Session/Schedule 语义当统一事实。

## 证据与后续

产品确认来自本轮对话；[DSH 源码](../research/DSH源码核对.md)仅支持 DSH 适配分析。Codex/Claude Code 具体接口未核对，所有适配运行实验未开始。先用模拟运行时验证边界，再做 DSH 真实实验，见[Harness 适配](../architecture/Harness适配.md)。

## 替代关系

旧 ADR 保留原内容并标 Superseded；其中不重复实现 Harness、Host 管理环境、外部授权等有效原则在本决策中延续。
