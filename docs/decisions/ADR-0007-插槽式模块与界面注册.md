# ADR-0007：插槽式模块与界面注册

- 状态：Accepted（架构原则；接口和实现未冻结）
- 日期：2026-10-26
- 依据：负责人以 QQ/飞书独立增删、微信面板注册、Harness 可替换明确设计要求，并授权写入文档。

## 背景

若宿主和通用管理页显式枚举所有平台，每新增一个模块都需要改核心；移除一个平台也会影响其他模块，违背功能解耦。

## 决策

Eating 提供按类别定义的扩展约定。通讯平台、Harness 和其他确有需求的扩展通过独立实现注册后台能力与管理界面贡献。通用管理页读取目录，不硬编码 QQ、飞书、微信或某个 Harness。

同类实现互不直接依赖；依赖公共契约和声明的共享服务。模块包可以同时含后台/前端入口，通过同一身份与生命周期关联，不让后台直接引用 UI 框架。

停用/卸载撤销本模块资源和注册，保护其他模块、共享依赖和数据。面板可安装/注册已经实现的平台模块，不因填写一个名称自动生成平台能力。

## 原因与备选

把增删改动集中在模块自身，并支持平台自有配置/登录页。未采用通用页持续扩大的平台条件分支；也不为每个未知未来功能预建抽象插槽。

## 影响与风险

需定义契约版本、能力、注册归属、前后端握手、清理、缺依赖和失败状态。功能隔离、数据隔离、进程故障隔离、权限隔离分别验证。新增可执行模块和管理界面仍受主人授权控制。

## 验证与后续

使用两个模拟通讯模块和一个模拟 Harness 测独立注册、页面出现、移除一个不影响另一个、重复启停、迟到响应与部分失败。未验证热装卸、零中断升级或 OS 隔离，见[插槽设计](../architecture/插槽式扩展.md)。
