# ADR-0009：首版采用 React 本地网页验证

- 状态：Accepted（本轮验证工程范围，不冻结最终桌面/后台选型）
- 日期：2026-10-26
- 确认依据：负责人明确“开始写第一个验证版本”，要求概览/机器人与平台分类、自有插件面板，随后选择“React 本地网页验证”。

## 背景

原项目只有架构文档。需要首先让负责人看到并操作平台宿主结构，验证模块注册带动分类和配置面板变化，不立即承担真实通讯、Harness 或三平台桌面分发复杂度。

## 决策

使用 React + TypeScript + Vite、pnpm 实现独立本地网页。纯业务插件注册和持久化不依赖 React；前端贡献通过独立契约关联 React 配置组件；构建期发现随附模块入口，宿主通用页面不枚举平台实现。

提供 QQ/飞书/微信本地示例，保存至当前浏览器；所有平台明确未连接。界面使用负责人选定的“浅色标签”，两层导航固定、中文按钮与反馈。普通 CSS 足够，不提前引 Tailwind/shadcn/全局状态库。

## 原因与备选

优先验证可见、可操作的模块边界和配置流程。未选本轮直接 Tauri，因为负责人选择先网页；Cordis 是后台候选，当前业务目录不冒充其插件生命周期或安全验收，也不因 UI 原型永久否决后续采用。

## 影响

浏览器配置不是正式运行数据库/凭据仓库，无真实发送/模型/长期记忆。仅组件渲染错误可局部承载，进程与权限隔离未实现。构建期自动发现不等于任意第三方动态安装。

## 验证与后续

实际构建、65项业务单元和5项浏览器流程已通过；桌面/窄屏截图与独立设计复核在[验证账本](../research/PoC验证结果.md)记录。本决定只覆盖首版前端，Phase 0B 后台/Harness 仍需后续实验。
