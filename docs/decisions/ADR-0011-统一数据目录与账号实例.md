# ADR-0011：统一数据目录与账号实例

- 状态：Accepted（目录/身份设计；当前仅一个默认账号运行）
- 日期：2026-10-26
- 确认来源：负责人要求Eating_home默认~/.eating、bot内部按插件目录管理；随后明确不能只保存一份配置，设计多账号但本轮只做一个账号。

## 背景与决定

统一环境变量 `EATING_HOME`，默认 `~/.eating`；Host公共锁/SQLite/授权位于host子目录。插件声明合法独立的bot子目录，QQ为qq-bot。

QQ用accounts.json保存版本化实例索引和defaultInstanceId，每实例 `accounts/<稳定UUID>/config.json` 保存连接配置与令牌。插件种类、配置实例、真实平台账号分别标识；实际QQ号只在真实连接核验后获得，不用作初始目录名。

当前只创建/操作一个默认实例，无添加第二账号、选择切换或并行连接管理。现有插件API是当前默认实例入口；工具可显式instance_id，未知/非默认拒绝，不能静默发到另一账号。

## 原因与备选

单root config.json无法扩展多账号；以QQ号命名则未连接时无法建配置且换号需迁移。采用稳定local UUID，保留目录归属与后续扩展，不提前建设多账号调度系统。

## 影响

消息与Harness信封带instanceId，消息去重/筛选按实例；发送幂等含实例与真实账号，防止键跨账号混用。索引与配置原子替换、POSIX0700/0600，不回显令牌；停用保留文件/消息。

旧单文件真实配置若存在且无索引，明确提示迁移需求并保留原文，不猜测或覆写；旧prototype浏览器记录不自动转换成真实账号。此前暂定标准OS应用数据根由本次明确位置要求取代，无已有正式数据被删除。

[数据规范](../technical/数据目录与账号实例.md)、[账号/配置测试](../../plugins/qq/backend/accounts.test.ts)覆盖稳定实例、索引多条结构、非法路径、损坏保护、权限与独立文件。第二账号实际连接、切换和权限范围需后续实现和测试。
