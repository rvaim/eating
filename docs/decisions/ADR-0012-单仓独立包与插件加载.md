# ADR-0012：单仓独立包与插件加载

- 状态：Accepted（负责人已确认仓库、独立发包与公开接口原则；实现细节及验证范围见下文）
- 日期：2026-10-26
- 确认来源：负责人确认“一个仓库，主程序/SDK/插件独立发包，主程序按产物加载，插件仅依赖公开 SDK”，并要求先提交当前版本再改目录。
- 前置提交：`2532469`（实现正式 QQ 插件并建立中文提交说明规范），已完成中文修改原因与内容；更早的 `6da6044` 保留。

## 背景

独立注册面板只能证明逻辑解耦。如果 Host 直接导入仓库插件源码、前端通过构建期扫描打包插件，插件仍跟随主程序一起构建，不能形成可单独交付、安装和升级的包。QQ 面板引用 Web 应用内部契约或 API 客户端，也会使插件依赖宿主私有源码。

单仓协作本身不应要求主程序、SDK 与插件锁步发版，也不应让 QQ 协议配置成为所有插件共享的通用类型。

## 已确认的决定

1. 保留一个仓库管理源码、文档、锁文件和联合验证。
2. 主程序、公开 SDK 与具体插件具有独立包和发布边界，可分别构建和发版。
3. 主程序根据已安装插件的构建产物加载后台和界面；运行不依赖仓库插件源码，也不把 QQ 实现捆入主程序来完成加载。
4. 插件对 Eating 的依赖通过公开 SDK，禁止引用应用私有源码或同类插件实现。

`Accepted` 表示上述原则已确认，不表示所有具体目录、包名、清单字段、安装路径或本轮验收结果均由负责人逐项确认。

## 本轮实现选择

为落实原则，本轮将 Host 放在 [apps/host](../../apps/host/)，Web 保留在 [apps/web](../../apps/web/)；公开 [plugin-sdk](../../packages/plugin-sdk/src/index.ts) 与 [ui-sdk](../../packages/ui-sdk/src/index.ts) 分别使用 `@eating/plugin-sdk`、`@eating/ui-sdk`，当前包版本 `1.0.0`，契约 `apiVersion` 为 `1`。保留 [plugin-core](../../packages/plugin-core/) 中已有的纯注册与旧持久化测试。

QQ 作为 [communication/qq](../../plugins/communication/qq/) 下的 `@eating/plugin-qq` 独立包，当前版本 `0.2.0`；`OneBotConfig` 属于插件[配置类型](../../plugins/communication/qq/src/config.ts)，不进入通用 SDK。根 pnpm workspace 聚合开发、构建和测试。

QQ 独立交付后台 ESM、界面 JS/CSS 与清单。Host 从 `EATING_HOME/plugins/<pluginId>/versions/<version>` 和激活索引加载，先检查 SDK/API 兼容与 SHA-256，再执行入口。Web 动态加载 Host 提供的界面资源，公开界面 SDK 与 React 共享宿主实例。

首期使用本地产物目录安装；安装、升级和卸载要求 Host 停止后重启。通过暂存与原子发布保护激活状态，升级只针对目标插件，卸载撤销入口并保留账号数据。具体产物文件、迁移映射与职责见[工程结构与插件发布](../architecture/工程结构与插件发布.md)，已确定的本地构建与安装命令见[QQ 操作说明](../operations/QQ配置与功能测试.md)，实际结果见[重组报告](../reports/2026-10-26-单仓独立包重组报告.md)。

## 原因与备选

- 单仓独立包保留跨 SDK/Host/插件协作和联合回归的便利，避免为本轮单插件场景引入多仓协调；多仓并非独立发布的前提。
- 只移动文件而继续相互引用源码，无法验证交付边界，不能满足本次决定。
- 把 QQ 静态编入主程序虽方便开发，但插件升级仍要求重建主程序，不符合独立交付目标。
- 本地产物安装先覆盖确定的交付路径；第三方市场、自动下载、真实 npm 发布与运行中热更新另行设计和验证。

## 影响与边界

旧目录删除后不留转发 shim；现行文档链接迁移，旧路径仅作迁移或 Git 历史记录。插件代码目录与账号数据目录分开，既有 `bot/qq-bot/accounts/<instanceId>/config.json`、Host 锁与 SQLite 不迁移。插件版本变化不等于账号身份或真实 QQ 号变化。

安装与激活记录、运行中停用/恢复、实际 OneBot 连接是不同状态；安装成功不代表在线。哈希与 API 检查不是发布者认证或恶意插件 OS 沙箱。新增未知可执行能力仍需主人批准；本轮不放宽原授权边界。

QQ 工具/MCP、当前单默认账号、消息投递状态和未接真实 Harness 的事实保持原范围；不承诺热更新、零中断升级、真人联调、多账号并行或桌面跨平台完成。
