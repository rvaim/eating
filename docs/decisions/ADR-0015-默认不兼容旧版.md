# ADR-0015 默认不兼容旧版

状态：Accepted。

日期：2026-10-29，Asia/Shanghai。

确认来源：负责人明确要求“先提交代码，然后把之前写的旧版兼容删除”，并说明项目尚未发布，即使以后发布，未明确要求时默认也不兼容旧版；要求写入工程规则、更新README和相关文档，最后提交并push。

## 决策

1. 默认只实现当前契约。旧API、配置、数据库或功能不自动兼容，发布与否不改变该原则；例外必须来自用户明确指令。
2. 删除旧格式读取／转换、字段补齐、默认种类推断、旧别名入口、转发模块、缺接口回退和新旧双路。当前调用方与测试一起更新，不为通过旧用例保留兼容。
3. 当前格式严格校验；不支持版本、缺字段、旧表或不合法形状明确报错，不偷偷采用默认值或写成新格式。
4. 删除代码不授权处置真实数据。不自动擦除、重置或转换用户数据；新实例才生成默认配置。需要使用当前版本时可显式选择新的EATING_HOME，这会产生新实例／会话，不冒充迁移成功。
5. 当前接口规定的PATCH／空Key保持、当前格式下的正常重连与故障恢复、可靠flush／ACK重建、幂等和unknown保护继续存在，它们不是旧版兼容。
6. OneBot正式参数别名／消息形态、OpenAI接口等外部正式协议仍属于当前功能，不因其名称含“兼容”而删除。
7. README、工程规则、规范、状态、交接和验收统一当前契约；历史报告保留原数字和当时事实，并明确不再作为兼容要求。

## 影响

当前插件只接受API2；后台入口、实际插件与清单种类一致。作者只接受schema2，移除旧群私输入模板；Host只用deliverBatch和当前数据库结构；QQ配置只接受完整当前wrapper schema2；DSH代理绑定只收schema2和完整taskId／taskRefs。具体目录和每项存储版本见[数据规范](../technical/数据目录与账号实例.md)。

旧数据默认会被明确拒绝。不会提供自动迁移脚本，也不会先按新格式失败再尝试旧格式。若用户后续需要某项旧数据处理，应在那次明确指令范围内另外设计、实现和验证。

## 原因与备选

尚未发布的旧实现没有默认向后兼容要求；自动保留历史路径会扩大状态空间、维护成本与权限旁路，违背负责人明确偏好。保留所有迁移或只隐藏旧界面均不满足本次要求，因此直接删除实现并将现有调用方迁到当前契约。

## 替代关系与证据

本决策替代[ADR-0014](ADR-0014-分层提示词与受控子代理.md)中旧作者迁移／旧入口保留及旧任务兼容策略，以及其他规范中默认支持旧格式的条款；不替代其同AI身份、分层代理、后台权限、可靠交接和手动原生读取原则。早期历史报告不重写。

实施顺序、删除范围、当前负向拒绝测试、同版恢复与最终构建／浏览器／原生结果见[本轮报告](../reports/2026-10-29-删除旧版兼容验证报告.md)。
