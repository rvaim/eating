# ADR-0018：复用系统 DSH Web 并移除自有会话看板

状态：Accepted。日期：2026-10-30，Asia/Shanghai。确认来源：用户要求“dshharness 插件里面的看板去掉，然后加一个按钮打开 web 页面”，并在确认无需额外安装后明确“继续”。

## 背景

Eating 已使用系统安装的 DSH 启动独立 SDK 实例，不再下载单独运行时。系统安装自带官方 Web 前端及服务模块。Eating 自有离线看板依赖 Host 直接加载原生会话包，在打包应用的 asar 安装方式下不可用；继续维护另一份会话投影与页面也不符合当前需求。

## 决策

- 删除 DSH 插件自有的会话看板、记录组件、离线读取实现，以及 list-sessions／read-session 管理入口，不保留旧入口或备用看板。
- 插件配置页只提供“打开 DSH Web”按钮。SDK 与 Web 在同一 Eating 专属 DSH 进程中运行，读取同一份原生主子会话。
- 使用系统安装已有的官方模块和前端，运行时不另下载 DSH 或 Web 包。普通 Node 的 SDK 客户端仍通过插件已有启动资产转交系统 dsh。
- 官方 Web 服务监听 127.0.0.1 随机端口。Web 不向 SDK stdout 打印 URL，也不在启动时自动打开浏览器。普通公开状态仅含 nativeWeb.ready；用户点击时通过主人管理接口按需取得当前鉴权 URL 和 rootSessionId。
- 按钮在可信用户点击时同步预留页签，请求失败、隐藏或离开页面时取消请求并关闭未使用的页签；鉴权 URL 不存入 UI 状态、普通日志、模型上下文或本地存储。
- 保持官方界面、主题、侧栏、消息组件与正常操作；不注入 Eating 客户端，不增加只读访问层或命令白名单。
- Web 模块配置位于 Eating Profile 自身可写层，保留已有主题、欢迎提示等用户设置。SDK/provider/QQ bridge 保持在调用层，不将 Web 设置锁在 CLI overlay 中。
- Eating 的 DSH_HOME、DSH_AGENTS_HOME、runtime-home 和工作区保持独立；保留会话 UUID、配置、密钥和代理绑定，不启动第二个进程共享写入同一数据目录，不改用户主 DSH 或系统安装文件。

## 影响与验收

DSH 插件升级到 0.7.0，平台 API3 和共享 SDK 版本不变。插件交付的额外资产仍只有系统命令启动文件。现有 QQ 主子工具授权、可靠 ACK、原生时间上下文及模型限流诊断保持。

验收必须覆盖实际系统 dsh 的 SDK 回合、官方 Web 会话读写、设置持久化与重启、普通会话创建、SDK 与 Web 对应同一根会话、按钮生命周期及明暗界面。自动验证只使用临时数据、本地模型与 OneBot；生产现场更新单独备份与核验。具体结果记录于[本轮报告](../reports/2026-10-30-系统DSH原生Web入口验证.md)，未运行的验证不得标为通过。

## 替代关系

承接 ADR-0017 的官方原样 Web 接入原则，并用系统安装替代其专属 npm 运行时假设；移除 ADR-0014／0016／0017 中 Eating 自有离线会话看板的当前实现要求。旧 ADR 与报告保留当时事实，不重写历史验证结果。
