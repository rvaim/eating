# ADR-0022：服务声明模型能力与就地展示

状态：Accepted。日期：2026-11-01，Asia/Shanghai。用户指出模型能力应从服务读取，必要的补充配置也应放在模型名称及“获取模型列表／测试模型连接”附近。

## 根因与决定

当前真实模型服务的/models已经返回modalities.input/output、tool_call、reasoning、context_window/context_length和max_output_tokens等字段。原解析仅保留id/name，丢弃了能力元数据，前端只能展示页面底部的人工图片声明。此次修复数据链路和页面归属。

- 模型列表保留经过白名单归一化的能力事实：图片输入、工具调用、推理、输入/输出模态、上下文和输出上限。缺失、格式不合法或矛盾的字段明确未知，不从模型名称猜测，不把列表获取当成真实识图测试。
- 进入已保存模型的配置区域自动通过/models读取信息，使用已保存地址与Key；不发送chat/completions或付费视觉探测。刷新和模型列表使用同一归一化链路。语言切换不重新请求，草稿模型可预览已获取列表中的能力，保存前不影响运行。
- 服务明确声明的图片输入和上下文/输出容量自动传给DSH原生模型元数据。每次请求的maxTokens仍保留主人原设置，不被服务最大输出自动扩大。工具/推理支持仅作为服务声明显示，不擅自更改运行策略。
- 新增独立model-information.json/schema1，保存白名单目录和读取时间，以服务地址和Key的摘要绑定来源；模型按精确id选择。换服务或Key不能借用旧报告。既有model-capabilities.json/schema1保留当前合同与资料，无旧格式迁移/字段补齐。
- 服务未声明图片能力时，才在同一模型区域提供折叠的手动补充，仍独立CAS保存、要求停止Harness，不保存连接草稿。服务已声明时不再要求重复勾选，后台也拒绝没有实际作用的重复人工声明。
- 运行中的实例保留启动时输入能力；新报告改变输入能力时提示重启应用。已读取、服务声明、已应用与真实业务成功分别表示。

## 界面与范围

“模型能力”就地位于模型名称、列表选择及两个模型按钮下方、API Key字段之前。使用现有白绿语义令牌、紧凑dl和普通表单，明确标注服务声明和未声明，不新建页面底部独立配置区。未知项的人工补充在当前位置展开，刷新不丢已展开的草稿，隐藏取消读取，locale不进入网络effect。

DSH插件0.9.2，Eating/SDK/API4不变。主DSH和官方Web不改；原网页Fake-IP问题不属于本决定，也没有通过本次调整放宽网络策略。原实例更新前备份，保连接Key、图片人工声明、原生能力授权、人格、UUID和历史。

验收覆盖真实服务字段、未知/矛盾、Key/服务切换、元数据自动进入DSH、每次输出上限保持、就地布局、模型草稿预览、双语无请求、手动补充CAS及运行中禁保存。结果见[本轮报告](../reports/2026-11-01-模型能力自动读取与就地展示验证.md)。本决定替代此前“无论服务是否声明都由主人重复确认图片能力”的当前策略；权限和图片来源控制继续保留。
