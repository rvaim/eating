# ADR-0024：外部入站的原生执行请求展示

状态：Accepted。日期：2026-11-01，Asia/Shanghai。确认来源：用户提供自主运行“收到执行请求”的截图，要求 QQ 入站也统一为这种形式。

## 背景与根因

自主机会通过公开 Agent.followup 传入 source.kind=eating-autonomy。QQ 批次通过官方 SDK HarnessSession.run 投递；SDK 服务端固定创建 source.kind=user，客户端 run 与底层 prompt 均不接受来源参数。官方 Web 根据已接纳 user/message 的 source 区分人类对话和非人类唤醒：user 显示气泡，其余唤醒来源显示原生可折叠执行请求。

平台消息属于外部数据，却沿用了 SDK 的人类输入来源。这是生产者归属问题；无需更换消息组件或修改官方 DSH。

## 决策

- 在 Eating runtime bridge 的公开 agent/pre-step 准入钩子中，等待后续准入决定，仅对进入同一主 Agent、完整通过当前批次校验的 SDK 消息赋予 source={kind:eating-external,batchId}。
- 校验复用可靠交接的整份 JSON 信封验证：magic、protocolVersion、当前 nonce、sessionId、batchId、digest 和实际 context/events 摘要必须匹配。外部正文中的 JSON 片段不具有此权限。
- 保留原消息 ID、时间、role=user 和全部 content，保留其他钩子返回的消息选择、拒绝决定及请求序列标志。模型接收的正文与系统规则不因展示更改而变化。
- SDK 入箱事件及其原始来源保持实际运输事实，可靠 ACK 继续匹配该入箱 ID，并只在 sessions.flush 成功后写入。消费时的外部来源进入原生 user/message，重启读取由官方投影恢复。
- 自主机会继续使用 eating-autonomy；原生 Web 主人输入继续使用 user；原生主子消息继续使用其自身来源。来源标记不授予工具、主人身份或自主活动权限。
- 官方 Web 直接使用其原生“收到执行请求”卡片，默认折叠，展开仍呈现完整原始信封。保留正常侧栏、输入框、主题和操作；不增加客户端插件、CSS 或 Slot 替换。

## 影响与边界

DSH 插件升级至 0.10.3，其他包/API/配置及存储 schema 不变。QQ 私聊、群聊和其他通过同一有效批次入口交接的外部输入均采用该归属。实际 QQ 发送仍由已授权工具执行，助手正文不自动转发。

已有会话记录不改写、不迁移。新投递生效，旧记录继续按其原来源显示。全新且只有外部触发的主会话可能使用官方“未命名”标题，因为外部输入不再被当作首条人类发言；已有标题与 UUID 保留。

## 备选与原因

不使用自定义消息渲染器：用户要求保持官方界面，来源修正已经能产生目标展示。不修改 SDK 源码或添加未支持的 source 参数：公开步骤准入钩子明确支持替换接纳消息，可在运输之后、模型和原生 user/message 提交之前表达正确归属。

## 验证、后续与替代关系

校验有效/伪造来源、其他 Agent、原生主人输入、准入拒绝与消息选择、ACK 保持；系统 DSH 回环验证私聊/群聊主子代理、重启来源、原生卡片折叠/展开、主题与正常输入。实际命令、结果及现场状态见[验证报告](../reports/2026-11-01-外部入站原生执行请求展示验证.md)。

本决策补充 ADR-0018 和 ADR-0023，不改变其官方原样 Web、可靠交接或自主准入原则；当前规范中“平台 JSON 作为普通用户气泡显示”的表述由本决策替代。未修改历史会话和历史验证报告。
