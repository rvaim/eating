# ADR-0029：持续记忆会话与记录保留

状态：Accepted。日期：2026-11-02，Asia/Shanghai。确认来源：主人指出同一个聊天每批Session ID/路径不同、Session立即被删除，明确要求“不要删除会话记录，留着有用”“设置的自动启动都没生效”，并要求改好push。本决策替代ADR-0028的每批临时Session和提取后删除策略，其他范围、全局、名单、授权及自动采集保持。

## 根因

0.1.0把任务UUID直接用作Session ID；每批创建新根，提交结束后调用deleteSession，连同该根的历史与memory_diff都被删除。即使该批没有产生长期记忆，也执行删除。这是生命周期设计错误，不是连接或OpenViking缓存故障。另一本地自动启动问题来自开发命令EATING_AUTO_CONNECT=false，覆盖用户保存的开关，正常启动路径无需改造。

## 当前决策

1. 任务ID和Session ID独立。相同platform/account/private或group/target的Peer，默认固定Session为eating-<peer>；自主为eating-self。每次复用服务现有Session，只有404时创建；各次提交由服务在同根生成archive_001/002等，不再每批随机根目录。
2. 不自动删除任何Session、原始消息或归档。成功、零条记忆、失败/取消、重启和断开都保留。长期记忆仍存原全局/Peer位置，不把归档当成记忆提取成功。
3. 当前公开Session API不能更新memory_policy。全局关闭使用同Peer的固定eating-<peer>-local会话，全局开启使用无后缀会话；最多两个显式策略根，切回原模式继续原根。不能为修改提取策略而删除/重建已有Session，也不能通过私有文件写接口篡改服务元数据。
4. 同一服务/账号/用户/Session串行写入、commit和终态确认。遇到unknown或无法确认的已有未提交消息，保留远端内容并阻止同Session追加，不能重放或盲目清空；不同Session独立继续。
5. 当前任务状态仍保存服务返回的真实sessionId/taskId/archiveUri，不从任务ID推断Session路径。原有有效摘要继续保留，不删除/迁移用户数据，不导入或重放DSH历史，不能声称已被0.1.0删除的归档已恢复。
6. 本地服务改为不带EATING_AUTO_CONNECT=false启动，让已保存autoConnect生效；不擅自打开用户关闭的开关。正常重启应保留配置、权限、人格和原生会话。

## 验证边界

仅做针对性官方SDK回环验证：同Peer多次提交与重启保持Session、archive递增；不同Peer隔离；同Session无并行commit；unknown阻塞不重发；零变化/失败任务保留记录；实际系统DSH自动采集链路不变。构建及必要页面核验后更新本地0.1.1、提交推送main，不重复完整历史测试矩阵，不向真人试发或为验收调用付费提取。
