# ADR-0030：增量记忆提取与历史分段解耦

状态：Accepted。日期：2026-11-02，Asia/Shanghai。确认来源：主人指出“一句话一个archive”造成碎片，否定等待大量消息或长时间后才提交，要求参考AstrBot和官方Agent插件；核对源码并说明需要服务端能力后，主人批准实现并要求提交push。随后明确只写好插件与配套代码供审查，不处理其服务器部署、不替换现有安装。

本决策替代ADR-0029中每批commit提取及归档的组合路径，保留固定会话、原记录保留、授权和未知不盲重放原则。

## 事实与根因

Eating0.1.1虽已固定Session并取消删除，但capture遇到任何工具动作都会立即commit，QQ回复本身需要工具，实际绕过批量设置。OpenViking0.5.2.1把commit的Phase1归档与Phase2记忆提取绑定，不能用keep_recent_count或StreamingMemoryUpdater参数实现逐轮提取而不归档。

AstrBot0.2.0逐条写Session，默认20消息/4096估算Token/空闲1800秒commit；官方DSH插件0.5.26逐条捕获、20000 pending tokens或压缩/退出commit。官方通用Agent Plugins只有MCP/Skill，无自动生命周期，remember仍创建一次性Session并commit。没有可直接复制的“每轮提取无archive”公开协议；本轮复用官方内核而补明确版本扩展，不伪造现有接口。

## 组件与职责

- Eating能力插件0.2.0：每个获准主回合立即入有界队列并同步原始增量，查询服务持久回执，展示实际提取结果。工具名/真实结果摘要合并进对应助手消息，不增加独立触发器，不调用commit或deleteSession。
- 配套eating-openviking-incremental：精确依赖openviking==0.5.2.1，扩展官方ASGI应用，继承其认证、账号/用户命名空间、存储和模型配置。复用官方ExtractLoop、MemoryIsolationHandler、StreamingMemoryUpdater与MemoryUpdater，不引入第二认知循环或客户端提取模型。
- 原文持续保存在同一个服务Session内；已处理前缀达到archiveMaxMiB才用官方历史格式分段。默认8MiB，可设置1–64MiB。不因回合、工具、闲置时间、手动同步或记忆零变化创建archive。

## 协议与恢复

协议v1提供capabilities、Session提取游标、原子追加/增量任务入口和按request_id查询持久回执。账号/用户从官方认证取得，Body不能选择身份；Session写入遵循官方会话权限，Actor-Peer不是额外的Session ACL。

追加携带expected_sequence和稳定request_id，消息区间为[from_sequence,to_sequence)，相同ID/相同负载返回原回执，冲突拒绝。服务侧在官方分布式Session锁下保存带校验的日志、追加意图与消息顺序；每Session只有一个提取工作者。上传与提取不共用长时间占用的客户端任务槽，上一轮提取中仍能持久追加后续记录。

提取只将本次增量作为新事实来源，少量已处理前文作为只读背景，不重新提取或移动旧游标。已确认完成才推进extracted_sequence。写入前持久apply-start，若崩溃落在无法证明官方记忆应用结果的窗口，回执为unknown并阻止该Session继续提取，等待核对；不宣称模型/文件系统跨事务的永久exactly-once。准备阶段失败不推进游标，原文仍完整。

客户端在POST回执丢失后只GET原request_id，不盲目重新发送正文。持久回执独立于官方TaskTracker短期TTL；远端回执缺失显示未知，同Session后续写入阻塞、其他Session可继续。配置撤销只取消本地请求，不删除已接受远端工作。

分段先写并校验完整archive/messages.jsonl、元数据与.done，再截断已确认处理的live前缀。服务持久记录分段意图，崩溃可留重叠原文，但不能丢掉唯一副本。分段不调用commit、不再次运行提取，未处理尾部仍在live区。

## 当前格式和旧记录

Eating配置/状态均为严格schema2，移除submissionMode、batchMessages、batchChars、idleSeconds、tokenThreshold，新增archiveMaxMiB。服务端扩展日志为其独立schema1。旧格式明确拒绝，不自动迁移、改写版本或清空原文件。源码更新不等于真实实例已经切换。

增量模式使用固定eating-live-<peer>，全局关闭用同Peer固定-local后缀；会话提取策略经官方get/create验证。新标识避免静默接管0.1.x含未处理原文的会话，旧Session和归档全部保留，不回放、不自动合并。用户审查部署时须显式选择当前格式配置/状态；既有远端记忆可以继续读取，原始记录不因新模式删除。

## 交付与验证

所有实现和针对性测试提交至Eating main，服务端扩展源码位于integrations/openviking-incremental。测试采用固定版本官方内核、独立存储和合成模型回执；Node客户端采用真实官方SDK与协议夹具，DSH采用独立模型/OneBot回环。不得为验收向真人试发、访问用户远端记录或调用付费提取模型。

主人已明确不处理远端部署；不继续探测SSH、不上传代码、不升级用户服务或自动安装新插件。配套README给出安装与原有配置/数据保留步骤；未安装扩展时连接明确报MEMORY_INCREMENTAL_UNSUPPORTED，不回退旧commit路径，也不把只有health可达显示成已支持。
