# ADR-0031：自主运行状态、活动时长与可选能力降级

状态：Accepted。日期：2026-11-02，Asia/Shanghai。确认来源：主人报告机器人声称没有主动联系权限，实际设置已有权限，先要求在独立工作树修复、暂不合并，随后明确授权合并主分支、提交并 push。合并时主分支已有增量记忆 ADR-0030，本决策改用 ADR-0031，补充 ADR-0023、ADR-0025，不改变其目标、权限边界或存储格式。

## 根因

1. `eating_activity_state` 把 `autonomy.json` 的旧字段 `configuration.targets` 原样返回给模型。该字段在统一主动联系策略后不再是联系人授权来源，当前为 `[]`；真正策略在 `proactive-contact-policy.json`。模型因此把“旧字段为空”误报成“没有主动联系权限”，且历史对话中的错误结论继续被沿用。
2. `maxRunMinutes` 的检查使用 `now - startedAt`。`startedAt` 在主人恢复时设置，AI 登记 `sleeping`/`waiting` 后没有结束当前活动段；01:13 睡眠到 09:00 被算成约 467 分钟连续运行，超过 120 分钟，09:00 第一次重新申请轮次时直接触发 `AUTONOMY_RUN_LIMIT` 并暂停。
3. `CapabilityAccess.connections` 对任何已授权但未连接的 MCP 直接抛 `MCP_SERVICE_NOT_READY`。OpenViking 记忆服务掉线时，整个 QQ 子代理任务无法准备，通讯发送被无关的可选能力阻断。

## 当前决策

1. 模型可见的自主状态不再包含 `configuration.targets`。`eating_activity_state` 和 `eating_plan_activity` 返回 `contactPolicy` 摘要（模式、revision、保存对象数）；实际联系人及其工具必须通过 `eating_list_contact_targets` 读取。历史对话中的权限结论不得复用。
2. `maxRunMinutes` 只累计实际自主活动段。AI 进入 `sleeping` 或 `waiting` 时结束当前活动段，下一次准入开启新活动段；状态和准入结果提供 `runRemainingMs`，供 AI 和界面判断剩余额度。睡眠、等待和重启停机不计入该额度。
3. 可选 capability 未连接时，从当前子任务的 capability MCP 集合中省略，并在 MCP 目录保留真实的 disconnected/error 状态供主人修复；不阻断通讯 MCP 或其他已连接能力。已连接但工具目录与授权不一致仍明确报 `MCP_GRANTED_TOOL_MISSING`，不降级成默认成功。
4. 不迁移、不重写 `autonomy.json`、`proactive-contact-policy.json`、联系人、代理绑定或历史；当前已有的 `AUTONOMY_RUN_LIMIT` 仍需主人点一次“恢复”。不因为部署代码自动恢复暂停状态或发起模型费用。

## 影响

- 机器人读取主动联系权限时看到真实策略摘要，不再把旧 `targets` 当作授权；实际发送仍由 `eating_list_contact_targets` 和 Host scope 核验。
- AI 安排跨夜睡眠不会因为睡眠时间耗尽连续活动额度；长时间无实际模型活动的等待也不会被误判成连续运行。
- 记忆等可选能力离线只影响对应工具，不影响 QQ 通讯；其掉线仍可在 MCP 页面看到。
- `AUTONOMY_RUN_LIMIT` 对真实连续活动仍有效；只有实际活动段累计达到主人设置上限时才暂停。

## 验证边界

需覆盖：状态输出不含旧 targets 且含 contactPolicy；历史错误权限结论不再被系统提示确认；120 分钟上限下睡眠 8 小时后仍可准入；实际连续活动仍会触发上限；已授权记忆 MCP 断开时 QQ 子代理准备成功且 MCP 工具缺失，不重放未知动作。真实 QQ/付费模型不自动试发，现有真实数据不自动迁移。
