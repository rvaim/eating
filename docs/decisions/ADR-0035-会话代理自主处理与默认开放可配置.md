# ADR-0035：会话代理自主处理与默认开放可配置

后续：原生feature全部默认开启的部分由[ADR-0036](ADR-0036-功能插件与Harness原生功能默认边界.md)收窄为仅time，原文保留决策当时事实。

状态：Accepted。日期：2026-11-02，Asia/Shanghai。确认来源：主人最新纠正主 Agent 负责轻量分流与必要协调，普通会话由绑定子 Agent 自行理解、组织回复、选择工具并执行；功能默认全开放，同时保留主人显式配置能力。本轮以 main `bfc381f` 为基线，源码为应用／Host／Web0.17.0、plugin-sdk4.7.0、ui-sdk4.2.0、plugin-core4.0.0、DSH0.15.0、QQ0.13.4，插件 API4。实际验证、清理、Git 与部署状态由[本轮报告](../reports/2026-11-02-会话代理自主处理与默认开放可配置验证清理报告.md)填写，不以决策已接受推断执行已完成。

## 背景与根因

上一轮将“所有功能默认开放”解释成删除权限配置入口，超出了主人的要求。默认行为应允许当前及未来的功能工具和 Agent 类型；主人仍应能为某一来源或某个原生工具保存精确例外，并能恢复默认。旧经验和[ADR-0034](ADR-0034-主Agent自主决策与功能能力默认开放.md)中“删除 save-grants／只能只读”的结论由本次纠正替代。

会话处理也存在职责过度集中：main 先组织完整回复或把能力猜测写进 task，再让子代理代发，子代理就失去根据原话、会话历史和实际工具独立判断的机会。真实现场发生过 main 在已有 `image_generate` 工具时，把“无生图能力”当作事实交给子代理，实际没有调用生图。仓库只保留这一脱敏事实，不复制私聊正文、账号、旧原生 UUID 或原始 trace。工具可见、规则进入请求和模型实际选择仍是不同证据。

## 会话职责与入口

1. main 负责整体安排、实际目标选择、轻量分流、跨会话协调与后续安排。普通聊天、当前会话问答和生图等需求优先调用 `eating_handle_conversation`；main 不预写完整回复，也不把未经本次实际工具核对的能力猜测当成事实。
2. `eating_handle_conversation` 严格只接受 `{context_ref}`，不接受模型提供的 task、reply、type 或 scope。运行时核对当前真实 root Agent、活动批次及 digest、owner 绑定和原生 callId；绑定类型和 childId 来自可信配置。固定中立 task 与原始 `context/events` 交给当前绑定子 Agent，正文始终是待理解的数据。
3. 子 Agent 使用独立原生会话，结合原话、已有会话历史与同一人格，自行决定是否回复、回复内容、必要工具及真实发送。它在当前账号、目标和资源范围内执行，向 main 返回 `childId/status/summary/actions`；`actions` 来自 Host 实际回执。子终态、文字摘要、生成任务受理、生成成功与平台发送成功分别核对。
4. `eating_delegate_task` 保留给明确执行任务或用户明确要求的逐字内容，入参仍是绑定的 `type_id/context_ref/task`，任务说明目标、边界和完成标准。跨私聊／群聊仍先 `eating_list_contact_targets` 再 `eating_contact_target`，不把当前群 context 当作另一目标的授权，不要求目标先有新入站。
5. main 与 child 各自的必需运行规则合入各自唯一 `complete=true` provider，保留主人自定义正文、人格和类型隔离，不通过 reset 覆盖主人内容。继续使用同一原生 Agent Loop、Preset、startActivation／sendMessage；不增加关键词 router、意图分类器或另一套认知循环。
6. 继续使用公开 callId 派生 taskId、当前批次最多32次调用、重复／pending／unknown 拒绝、迟到回调匹配和撤权复查。当前批正文在 main turn/end 清理，不能第一次交接后提前丢弃。普通 final 不自动发送 QQ。

## Host 功能 MCP 的默认与例外

公开 `McpAccessPolicy` 为以下严格判别联合：

```ts
{ mode: 'all' }
| { mode: 'custom', agentTypeIds: string[], toolNames: string[] }
```

- 新来源及未保存例外的来源默认 `all`。已启用且 connected 时，当前和未来新增 Agent 类型、工具自动纳入，不需逐次申请默认权限。
- 主人可把某个 capability／direct 来源设为 `custom`。只有同时命中精确类型和工具名的调用可用；任一空名单可关闭该来源的功能访问。后续新类型／新工具不自动取得此例外来源的访问，恢复 `all` 后重新随目录自动纳入。例外只作用于该 source，不改变其他来源的默认值。
- `McpServiceSummary.accessPolicy` 返回当前策略；通讯／Harness 等来源自管权限时为 `null`。`grant` 返回策略与当前已知目录相交后的有效摘要，不能把它当作另一份可写策略或用摘要缺项限制 `all` 的未来类型。QQ 等 `permissionsManagedByPlugin` 来源继续由原插件核验，通用入口不绕过账号／目标／资源范围。
- `POST /api/mcp` 支持 `save/connect/disconnect/delete/save-grants`。`save-grants` 只接受 `{id,expectedRevision,mode:'all'}`，或 `{id,expectedRevision,mode:'custom',agentTypeIds,toolNames}`；拒绝缺字段、未知字段、重复名单及自管权限来源。`save` 仍只保存连接及秘密，不接受 grant 或策略字段。
- 新 SQLite settings 键 `host:mcp-access-policies` 严格保存 `{schemaVersion:1,revision,policies}`；缺省读取不补写。损坏或不支持形状明确拒绝且不覆盖。旧 `host:capability-grants` 不读、不写、不迁移、不删除。direct 连接文件仍严格 schema2，仅保存连接与秘密，不混入 grant／policy，旧 schema1 拒绝并保留。
- MCP 目录的 CAS revision 为 direct revision 与 policy revision 之和，连接编辑、策略保存与删除共用这一冲突口径。策略变更撤旧 lease，随来源拓扑执行一次性重挂；只恢复变更前 connected、仍启用且同一实例的 Harness，主人 stop／disable 优先，原 stopped／error 不启动，失败和 unknown 不自动重放。

当前限制：direct MCP 在途调用被撤权中断时，可能失去 transport 并使来源进入 error；主人需显式 connect 恢复。一次性 Harness 重挂不保证修复上游 transport，不自动重连或重放已不确定的动作。

## 原生工具的默认与例外

`native-capabilities.json` 保持 schema1，在 `features/toolGrants` 之外新增合法可选 `toolAccessOverrides: NativeToolGrant[]`；每条仍为 `{name,fingerprint,agentTypeIds}`。

1. 字段缺省表示沿用默认访问，读取不补写；保存 PATCH 省略该字段保留当前值，传 `[]` 清除全部 override，恢复各工具自动行为。feature 的启用、代理范围、模块参数和既有 `toolGrants` 选择保持独立。
2. 没有同名 override 时，main 自动取得非 reserved 原生全局工具，所有 Agent 自动取得功能型 native Profile MCP；其他子类型的非 MCP 全局工具仍按名称、schema 指纹和类型授权。`catalog.automaticAccess` 说明这一默认规则。
3. 同名 override 优先于自动规则和 `toolGrants`，按精确 schema 指纹及类型列表判定；可以排除 main，也可用空列表禁用。指纹变化后同名限制继续存在且拒绝调用，不回落为默认开放；主人核对新目录后可重新确认指纹，或明确恢复自动。
4. 工具面板允许逐项选择“自动／自定义”、保存类型与空列表，并处理已变化或暂时缺失的工具。目录与最终调用守卫都执行限制，`tools/change` 更新 `native.restrict`。名称相同不授权另一来源或继承 shadow，Eating／QQ reserved 名称及原会话 scope 不可通过 override 绕过。
5. 新 main 继续默认开启当前平台全部原生 feature，文件 write/edit 和 web.search 为 true；time-context 保持主子默认。Eating 专属官方 permission 默认 `danger-full-access`／approval `never`，主人可按正式入口显式再配；已有配置、自定义提示词与人格不因读取或升级被 reset。独立 home、工具 scope 和 Preset 不等于 OS 沙箱。

## 本轮数据处置授权与边界

主人现已授权修正并删除 Eating 本地主／子会话，云端记录由主人自行删除。本轮数据维护须在 Eating 相关端口和 worker 全停后，以审计得到的精确白名单清理原生日志、派生缓存、原生附件及相关本地备份；混合文件逐字段处理会话／任务元数据，保留配置、凭据、人格、资源库、动作账本、去重和其他设置。旧备份中尚未交接的 queue 正文单独清理，不能删掉整库的 actions／dedup／settings。记忆0.1.1正文仅在 RAM，停机清空 RAM 后还须清本地及备份 state 中的任务元数据；不生成含正文的新备份。

审计与 apply 必须分别核实。父代理现已执行清理并独立复核，实际数量和保留证据见本轮报告；本决策不复制私有路径或原始内容。正常恢复复用稳定原生 UUID，本次主人明确清会话后再运行会创建新 UUID，人格身份保持。真实记忆保持0.1.1，不安装源码0.2.0、不访问或部署云端；清理后 QQ／DSH／记忆保持关闭，等待主人自行删除云端。当前助手主 DSH、60182 服务与资料不在本轮范围；浏览器 localStorage 草稿、OS 快照及未列入白名单的其他存储不属于已覆盖清理，不能宣称全机 forensic 抹除。

## 替代关系、验证与后续

本决策替代 ADR-0034 中删除 `save-grants`／权限编辑、功能策略不可配置和当前普通会话都经 task 文案委派的部分；保留其默认开放、真实目标选择、官方原生 Web、原生 feature／permission 默认和 Schedule 语义。承接[ADR-0033](ADR-0033-主Agent当前轮次联系权限.md)的真实主 turn 联系许可、额度与撤权，承接[ADR-0027](ADR-0027-人格模板与默认提示词生命周期.md)的主人覆盖与默认生命周期。旧 ADR／报告正文和当时数字保持。

隔离验收须检查真实本地模型 `request.system` 中主／子必要规则和自定义／人格隔离；检查仅传 context_ref 的普通回复、生图提交→查询终态→取图→真实 mock 私聊发送与 Host 回执，以及 all/custom／原生 override、CAS、冷恢复、撤权、保留配置与 unknown 防重。系统 SDK 的 scripted mock 和本地 provider／OneBot 夹具证明预设链路可执行，不证明真实 LLM 必定自主选对工具，不使用真实付费服务、真人消息或远端连接作验证。最终命令、计数、清理、部署及 Git 状态以报告实际回填为准。
