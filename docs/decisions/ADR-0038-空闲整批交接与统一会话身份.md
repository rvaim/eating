# ADR-0038 空闲整批交接与统一会话身份

状态：Accepted；源码修复与隔离验证完成，尚未部署，验证证据见本轮报告。

日期：2026-11-03，Asia/Shanghai。

确认来源：主人要求入站先排队，主 Agent 忙时不交接，空闲时一次取得所有可交接队列并自行分配，不能按会话逐批或按 maxBatch 硬切；普通入站和主动联系同一真实对象应延续同一子会话。主动活动行为优化本轮只写方案，不修改其行为、配置或调度。

## 背景与根因

Host 既有选择器按 conversationId 分桶，并在条数或体积达到阈值时停止取消息；flush 每次只交一个已就绪会话。主 Agent 因而只能逐块取得已知输入，无法在空闲时统一安排当前全部可交接来源。仅 conversationId 也不足以区分不同插件、实例、账号、私聊／群聊与目标。

DSH 的普通入站与主动联系原先分别选择子会话 UUID；同一真实对象可能落到两份原生历史。接收端 SDK 的单次 run 结束、运输 ACK 和原生 Agent 真正空闲是不同事实，不能据其中一个推断另一个。

## 决策

### Host 空闲整批交接

1. 入站先经当前队列准入，正文和来源校验、持久或内存模式、条数／字节硬容量及溢出策略保持。未成功入队不伪装已保存。
2. 排队身份为完整六元组：pluginId、instanceId、accountId、conversationId、source.kind、targetId。SDK 导出 groupHarnessEvents，分组保留首见组顺序及各组原始事件相对顺序；身份键采用无歧义结构化序列化。
3. 每身份独立计算静默和最长等待。maxBatchMessages 与 batchTargetBytes 只作为提前触发阈值，不能截断批次，也不把超目标单条另切一批。静默从该身份可交接末条计时，最长等待从首条固定。
4. 任一身份达到静默、最长等待、条数或字节条件，且接收端就绪时，取所有身份当前无冷却的可交接前缀，按 Host 全局 sequence 排序，一次调用 deliverBatch。其他身份不必再单独等待静默。
5. 同身份遇到冷却项即停止，后续项不得越过；该阻塞不传染其他身份。明确拒收冷却结束后重新选择全队列，不保留旧切片。
6. HarnessDeliveryBatch.conversationId 改为 string | null：仅单一完整身份时为该 conversationId，多身份时为 null；不能因多个完整身份恰好具有同名 conversationId 就伪装成单会话。batchId 仍由全局有序 eventId 派生。
7. isReady=false 时不交接、不消耗 attempts，不为等待忙碌轮询 Host 队列；接收端 wake 时重新取当前全部候选，不使用忙碌前缓存的选择。

### DSH 多上下文与原生就绪反馈

适配器将整批作为一个受信运输信封送入同一主 Agent，保留全局有序 events；context.conversations 列出各完整身份的 contextRef、真实来源与绑定类型。可用组与owner policy.bindings一一对应，不能绑定的组保留独立路由错误。单组 contextRef 可沿用 batchId，多组由 batchId 与完整组身份派生独立引用；主 Agent 通过当前组引用选择普通处理或明确委派。

原生桥在真正准入该输入时核对 nonce、root session、batchId、digest 与 policy，激活整批 contexts 映射。每个 contextRef 只携带所属组 events 与精确消息／资源 scope，不能取其他组引用；即使同一真实对象映射到同一 child UUID，各组上下文仍保持独立。任务临时授权保留本批全部引用，Host每类最多100000项、两类引用合计UTF-8不超过100MiB，超限明确拒绝、不静默截断；DSH持久binding仍为严格schema2且只保各256项历史尾部，不能将持久尾项上限套到本批临时权限。上下文保留至所属主 turn 结束，不在第一次委派后清掉，也不让旧 turn 的结束清掉尚未准入的新批次。

绑定容量仍为100；某组类型不可用或绑定容量不足时，以该context的routingError标记unavailable并保留其原事件，让主看见全部输入并处理其他可用组，不能将整批当作全部不可交接。同一child的任务先reserve并经本地flight gate，再执行drain／激活，避免并发调用在pending检查前取消首个任务；同对象不同context仍保精确scope。

运行时通过受认证控制通道报告当前 root Agent 的原生状态与入箱状态，使用递增 sequence、500ms反馈和3s有效期；观察到当前Agent为idle、nextTurn／nextStep入箱均空且适配器其他条件满足，才允许尝试新交接。状态变化触发反馈，idle通知唤醒Host。缺失、过期、倒序或不匹配身份的报告不能放行；单次SDK run结束、turn/end或收到ACK都不能单独视为空闲证明。状态检查与SDK enqueue仍非原子；其间发生的竞争输入由原生串行Inbox承接，不能声称严格原子idle-only enqueue。反馈只协调交接，不创建第二个Agent Loop。

ACK后尚未claim的持久输入在冷恢复时，可能因root Inbox非空而持续busy。恢复必须按既有持久messageId／digest精确核对、恢复existing bindings及受控路由，不能将旧nonce外部信封误当self记忆。原生send／remove无正文sentinel只唤醒原已有输入，不重新prompt同一正文、不自动重放unknown；缺匹配证据仍保留待核对。

### 同对象普通／主动会话共用 UUID

子会话身份使用 parent root、pluginId、instanceId、accountId、agentTypeId、kind、targetId。外部 conversationId 仍用于消息分组与当前 scope，不能因普通入站和联系入口采用不同表示就另建一份同对象原生会话。

优先复用已存在的普通绑定 UUID；没有普通绑定时复用同身份联系绑定，均不存在才创建新 UUID。任务仍逐次取得最新授权，普通和联系任务共享同 child 的在途互斥。联系任务不继承旧入站 message/resource 权限；来源、目标、类型、工具、额度与撤权检查保持。

本轮不合并、不删除、不搬运已经存在的重复历史或原生日志，不转换已有存储格式，不把统一后续路由描述为已经合并历史。旧任务防重和 unknown 索引保留，原未知动作不自动重放；更改后续选择不授权覆盖真实数据。

### 记忆按实际来源隔离

Host 根据完整组身份逐组复核通讯来源、真实账号／目标、主人身份与成员规则，分别召回，返回内容附可信 scope 标签。一个组的主人权限不能传播给整批其他组。

memory context使用三态：单一scope返回实际context，混合来源返回null并让主Agent记忆MCP明确报MEMORY_CONTEXT_AMBIGUOUS，无活动flight返回undefined并保持原语义；不能把null降成self授权，也不能将首组当全轮权限。对应会话子代理仍以真实scope使用记忆。

捕获按序列化messages的UTF-8 JSON体积计预算，包含转义与metadata，每段最多200条且不超过256KiB减1KiB预留。多来源，或单外部来源加主输出后需要分段时，仅将各组原始user消息写入各自Peer，不把主协调摘要或整轮actions灌入每段。原生主人追加输入独立按self处理，不借用外部私聊／群聊scope。记忆故障不撤销已成立的原生运输ACK。

当前外部记忆插件的固定会话、增量提取、未知回执和主人明确配置继续遵循 ADR-0029／0030；本轮不升级真实安装的记忆插件，不远端访问或部署。

## 替代关系与保持范围

本决策仅替代 [ADR-0013](ADR-0013-无历史消息与可配置投递队列.md) 中不跨会话、单批硬切及超目标单条独立批次的部分，并补足 [ADR-0014](ADR-0014-分层提示词与受控子代理.md)、[ADR-0033](ADR-0033-主Agent当前轮次联系权限.md)、[ADR-0035](ADR-0035-会话代理自主处理与默认开放可配置.md) 的当前上下文及同对象会话身份。旧 ADR 和历史报告正文保留当时事实。

可靠接管仍要求原生 sessions.flush 成功与匹配原子 ACK，Host 本地确认后才删除队列正文；接纳不表示模型已读、任务完成或平台成功。明确拒收才有限冷却重试；unknown、超时、异常、detach 和尝试耗尽继续保留待核对。本地结果保存失败只重试本地，不重复调用 sink；同版恢复与 ACK 重建保持。

功能型 MCP 默认 all／主人 custom、原生 feature 新实例仅 time、现有主人配置、唯一 complete 规则、人格、权限边界、动作账本和官方 Web 正常操作均保持。Eating 不建设聊天历史库，不修改主人主 DSH 或本次会话服务。

## 原因与备选

按会话逐批或在 maxBatch 处继续硬切，会把运输边界误当成主 Agent 的安排边界，不能满足一次取得全部待办输入的要求。取消队列容量或忙时直接注入则混淆准入与执行，并破坏已保存设置。本方案保留有界队列，把阈值限定为交接时机，由同一主 Agent 自行组织和委派。

对已有普通／联系历史做自动合并无法证明消息顺序、任务防重和许可来源可无损重建，也没有真实数据处置授权，因此只统一后续 UUID 选择。记忆按首组或整轮复制会扩大来源 scope，故逐组召回与采集并明确拒绝含糊范围。
