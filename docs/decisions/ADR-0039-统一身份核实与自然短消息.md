# ADR-0039：统一身份核实与自然短消息

状态：Accepted；源码实现与隔离验证完成，未部署。决策已接受不代表实际实例已经使用新规则。

日期：2026-11-03，Asia/Shanghai。

确认来源：主人要求同一 AI 在群聊和私聊保持同一身份，不能因为局部会话没有记录就否认参与；主 Agent 先协调核实，查询另一会话只核实回报，核实后由原会话子 Agent 自然回答。平时聊天使用按意思组织的少量独立短消息，保留复杂说明、逐字原文、代码与链接的完整性。

## 背景与根因

独立原生会话只拥有各自历史和当前获准来源。若把“当前私聊没有看到群记录”解释成“我没有在群里说话”，就把信息缺口误当成身份或经历的否定；先让当前子代理发送这种否认，再由另一任务补充核实结果，还会造成同一问题的矛盾或重复回复。

普通会话由子代理自主处理，不意味着主 Agent 可以省略跨会话事实协调。已有记录、获准记忆或对应会话事实需要由有实际范围的执行者核实，再判断哪些信息可以向原对象披露。同一身份不自动扩大读取与披露权限，也不等于各原生会话拥有全部历史。

自然聊天还包含真实发送边界。一次发送内的换行或多个消息段仍是一条平台消息；仅改文本排版不能产生独立气泡。固定字数、逐句拆分或固定条数也不能表达按意思组织的聊天节奏。

## 身份与事实核实

- 主、子 Agent 是同一 AI 身份的内部协作分工，使用当前统一人格的第一人称。真实记录证明的自身参与是自己的经历，不能冒认他人的发言或经历；不以“我只是私聊子代理”“群里的另一个 Agent”向用户解释信息缺口。
- 当前会话缺记录只表示尚未核实。先看当前可信上下文、真实子回报与获准记忆；不能据缺失推断未参与，也不能反向编造参与或声称自动共享历史。
- 涉及其他群或私聊时，主 Agent 负责必要协调。需要对应会话补充事实时，按当前真实账号、对象与工具选择执行者；使用 `eating_list_contact_targets`／`eating_contact_target` 时，任务明确“只核实并回报，不向该会话发言”。查询联系目标不是要求向该目标广播。
- 执行者只利用已有会话记录或实际获准的读取工具，回报事实、来源、时间范围及未知部分。没有记录或权限就保留未知，交回主 Agent；不自行跨目标读取，不增加任意历史读取接口或绕过记忆、成员、主人设置。
- 取得记录与允许披露分别核对。主 Agent 把可向当前对象披露的事实、来源和不确定范围交回原会话，以当前 `context_ref` 与绑定类型委派明确任务；原会话子 Agent 根据人格与会话历史自然组织回答。核实任务提供事实与完成标准，不预写普通聊天全文。
- 原会话子 Agent 缺依据时先回报待核实问题、缺失来源和尚未发送，不抢先发送未经核实的否认。已经有发送时，主 Agent 先核对真实 `actions`，再判断是否需要更正，避免重复回答；未核实的旧结论不能在核实后继续沿用。

普通聊天仍优先 `eating_handle_conversation`，严格只传 `{context_ref}`；明确执行任务或用户要求逐字内容使用 `eating_delegate_task`。跨会话事实核实属于主 Agent 的必要协调，继续使用同一原生 Agent Loop，不增加意图路由器或第二套认知循环。

## 自然短消息与真实气泡

2026-11-03补充纠正：主人明确“一条消息可以有几句话，一次回复也可以连续发多条”，撤回此前“一条讲清一个意思”的机械表述。连贯的话可以同条说，适合另一个语气或补充时实际另发；句数、字数、条数都无固定配额。普通短聊两句话之间不插大空行，不把回答和追问排成上下两段；想分开发就调用真实发送工具另发。提问按真实好奇或需要，不把每条末尾的“你呢”“怎么突然问这个”当固定格式。不连续刷屏，不默认长篇报告、标题编号或总结，也不把内部任务摘要直接发给用户。

不按固定字数、每个句号或每句话机械切分。复杂需求、必要详细说明、用户要求的逐字原文、代码与链接保持完整，不能为了短而遗漏内容或拆坏结构。该规则约束普通对外聊天，内部任务回报仍可结构化。

需要 QQ 等平台上的独立气泡时，分别调用实际发送工具。每条使用不同且稳定的 `request_id`，按顺序核对真实回执后继续；同一次调用的换行或消息段数组仍是一条。结果未知时停止自动续发与重发，先核对原回执，不靠换 ID 重做。未发送、失败、受理、成功与未知分别报告。

自然表达不依赖伪造经历、假装正在输入或人为等待；本轮不添加等待、打字模拟或消息切分发送器。

## 规则送达与主人内容保留

DSH 在 [conversation-policy.ts](../../plugins/harness/dsh/src/backend/conversation-policy.ts) 集中维护共享身份／表达规则与主、子协调规则，由 [runtime-agents.ts](../../plugins/harness/dsh/src/backend/runtime-agents.ts) 分别合入主、子各自唯一 `complete=true` provider。共享层供主子使用，主层负责核实协调，子层负责范围内核实回报与原会话表达；保留 owner、人格及类型隔离。

主人即使完全替换公共、主／子或 QQ 默认正文，运行时必需规则仍须进入实际模型 `request.system`，不能只存在于会被 complete 抑制的普通 section、编辑器预览或工具说明中。这里的必需规则不修改主人保存的正文，也不通过恢复默认覆盖自定义内容。

[Host 默认](../../apps/host/src/authoring-defaults.ts)、[QQ 角色及使用说明](../../plugins/communication/qq/src/backend/agent-policy.ts)和[人格模板草稿](../../apps/web/src/persona-templates.ts)同步自然表达约定。默认生命周期继续按 [ADR-0027](ADR-0027-人格模板与默认提示词生命周期.md)：跟随默认的文档在采用新代码后使用当前默认，自定义正文保持；人格模板只填新增草稿，不自动保存、启用或改写真实已保存人格。

## 替代关系、备选与边界

本决策补足 [ADR-0014](ADR-0014-分层提示词与受控子代理.md)、[ADR-0035](ADR-0035-会话代理自主处理与默认开放可配置.md)的同一身份、必要协调和唯一 complete 规则，以及 [ADR-0027](ADR-0027-人格模板与默认提示词生命周期.md)的表达约定。它不改变 [ADR-0038](ADR-0038-空闲整批交接与统一会话身份.md)的后续 UUID 选择或实际 scope 记忆隔离；旧 ADR 与历史报告保留当时事实。

不采用自动共享全部历史、先否认后更正、把核实任务当作群发任务，或固定条数／字数拆分。这些做法分别扩大权限、产生事实矛盾、误发消息或破坏完整表达。

本轮不写真实已保存人格，不 reset 自定义提示词，不清理或迁移真实会话、配置、资源和动作账本。功能 MCP 的 all／custom、Harness 新实例仅 time 默认、主人既存原生选择、联系额度、unknown 防重和官方原生 Web 保持。前轮[主动活动行为改进方案](../plans/2026-11-03-主动活动行为改进方案.md)仍仅供审查，不实施其自主行为、额度或 sleeping／waiting 调度修改。

## 验证与后续

本轮源码实现与隔离验证完成，未部署。父代理统一在[本轮验证报告](../reports/2026-11-03-统一身份核实与自然短消息验证报告.md)记录严格类型、构建、相关回归及系统 DSH 隔离回环的实际命令、实数和限制；本决策不预填测试数量或通过结论。验收须捕获主、子实际本地模型 `request.system`，覆盖主人正文完全自定义时的规则送达与人格／类型隔离，并检查“核实另一会话不发送→回报→原会话自然回复”和独立发送的顺序回执、稳定不同 ID、unknown 停止续发。

脚本模型与本地 OneBot 回环只能证明预设链路可执行及规则实际送达，不能保证真实 LLM 已经学会或每次自主选择同一路径。真实实例须在另行获准部署相应应用／插件并加载新规则后才生效；现有主人保存正文与人格保留。未向真人或付费模型试发，不部署、不提交或 push；最终交付状态由父代理据实际证据回填。
