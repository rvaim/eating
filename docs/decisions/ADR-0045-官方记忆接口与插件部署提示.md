# ADR-0045：官方记忆接口与插件部署提示

状态：Accepted。日期：2026-11-04，Asia/Shanghai。依据：负责人明确授权重做官方 OpenViking connector、修复插件部署提示并更新云端 Eating，不再强制安装 Eating 服务端扩展。当前源码已实现，整体验证进行中，服务器尚未更新；实际验证、Git 发布与部署结果由[本轮报告](../reports/2026-11-04-官方记忆与插件能力更新验证报告.md)收口，报告由父代理创建。

## 背景与根因

记忆0.2.x把配套增量扩展作为连接前提，使用私有能力探测、持久回执和独立历史分段；这使正常官方 OpenViking 服务无法接入。删除探测守卫无法改变后续私有请求，增加两套协议回退也不能提供清晰的状态与恢复语义。因此改用完整的官方 Session／Task API 链路，并同步配置、任务状态、生命周期与说明。

插件面板还需要解释实际部署环境：系统 DSH 检测发生在运行 Eating 的机器，浏览器所在操作系统不能用来推断服务器安装状态；QQ 登录由 OneBot 协议端承担；生图服务地址、模型与可选 Key 的缺失也应按真实配置报告。

## 官方记忆链路

Eating只负责可信来源、范围、传输与真实回执，提取和合并由 OpenViking 官方机制完成。每个获准回合通过官方 `POST /api/v1/sessions/{id}/messages/batch` 追加新消息；追加成功是 `synced`，表示记录已同步、尚未提取。不得将同步回执、服务健康或工具函数返回写成记忆提取完成。

官方 `commit` 同时归档原始记录并异步提取。接纳提交后保存实际 `taskId` 与 `archiveUri`，通过官方 `GET /api/v1/tasks/{taskId}` 查询；`processing` 尚未完成，`completed` 才表示已知官方任务完成。官方 Task API 不提供 Eating 私有持久回执或可信的逐项记忆增删改数量，界面不得伪造这些承诺。

配置与状态均严格使用 schema3。settings 移除 `archiveMaxMiB`，新增 `autoCommit`，默认 `true`；`commitTokenThreshold` 为1至1000000的整数，默认20000。达到服务报告的待处理 Token 阈值、会话压缩及正常会话结束时，只有 `autoCommit` 开启才请求提交；主人显式“提交待处理记录”不受该开关限制。普通回合只及时同步，不因发生 QQ 回复工具就强制逐轮 commit。

固定 Session 使用 `eating-standard-<peer>`，全局记忆关闭时使用同 Peer 固定 `-local` 后缀。创建时明确关闭服务自动提交，核验真实用户、Account与记忆策略。新根不接管扩展管理的 `eating-live-<peer>` 或旧 Session；既有远端记忆和原始记录保留，不删除、不回放、不自动合并。

## 未知与恢复

同 Session 串行处理写操作。追加或提交结果未知时保留原标识与元数据，阻塞该 Session 的后续写入，不换号重发、不尝试另一协议。已保存 `taskId` 的提交只查询原任务恢复；任务不存在、过期或无法证明结果时继续报告未知，不能重做 commit。一个 Peer 的未知不会授权丢弃原任务或影响其他独立 Peer 的正常处理。

界面移除扩展“重试提取”、私有 durable receipt、服务序列与 diff counts 文案。保持 `queued / syncing / synced / committing / processing / completed / failed / unknown` 的事实区别；本地正文仍仅在有界 RAM 中，状态只保存任务、身份、范围、幂等摘要和恢复元数据。退出或故障不能把未同步正文伪称已持久保存。

自动采集／召回与模型保存工具相互独立，Host／DSH公开生命周期增加压缩、正常结束的 flush 原因。可信 Peer、真实群成员名单、混合拒绝成员时只采集允许成员原文、主人显式跨会话以及原生 DSH Web 来源隔离继续执行。功能 MCP 默认 all 与主人 custom 例外不绕过这些范围。

## 当前格式与一次性部署转换

应用只读取严格 schema3，拒绝旧格式并保留原文件，不在启动或正常读取时迁移。用户已明确授权本轮云端 Eating 更新；此前“不处理云端”是历史范围，不撤回这次授权。本机已安装记忆0.1.1不替换，不配置、安装或重启真实 OpenViking 服务端。

本轮云端只读预检的旧 state 为 schema2、jobs 与 scopes 为空。部署时先停止目标 Eating 并备份原字节，再由独立[一次性转换工具](../../scripts/server-memory-transition.mjs)执行显式变更；工具与应用运行路径分开。项目外 `EATING_MEMORY_TRANSITION_CONFIG` 指定数据根、备份根、两份旧文件 SHA-256 与明确确认值；存在 Host 锁、哈希不符或 jobs／scopes 非空就停止核对，不能丢弃旧任务。

配置只把 schema 改为3、revision加1，settings只移除 `archiveMaxMiB` 并加入当前提交默认值；保留 Key、endpoint、Account、用户、规则及其他现有设置。空 state 只把 schema2改为3，保留其余元数据。该工具只执行本轮已批准的精确转换，不成为生产自动迁移层。最终操作与保留证据记入本轮报告，不凭预检宣称已部署。

## 部署提示

- DSH面板顶部区分尚未检测、服务器未找到 DSH、已找到但版本号为 `null`、实际运行错误。找到命令但无版本号不能判为未安装；显示官方安装说明与“重新检测”，不自动执行安装，不用浏览器 OS 拼出服务器结论。
- QQ明确要求协议端已登录真实 QQ 并启用 OneBot v11，Eating不实现登录，也不自动安装协议端。
- 生图明确提示 Base URL 或模型尚未配置；Key可选，允许提供商不要求 Key 的服务，不能仅凭 Key 为空判定不可用。保存／连接只检查配置，不触发付费生成。

## 版本与验证

应用／Host／Web0.18.0、plugin-sdk4.8.0；ui-sdk4.2.1与plugin-core4.0.0保持。QQ0.14.0、DSH0.16.0、image-generation0.3.0、openviking-memory0.3.0、stickers0.2.0，各插件 package／清单／前端入口／后台实例四处版本一致，插件 API4保持。共享产物字节改变按封存不可变规则升级，不原地改写已安装旧版本；无新依赖，锁文件 workspace links 应保持零差异。

验收须覆盖真实官方协议夹具、严格 schema3拒旧、同步与提取区别、阈值及三种 flush 原因、已知任务 GET恢复、未知追加／提交不重发、名单和跨会话隔离，以及部署提示的各状态。完整构建、类型、测试与浏览器读图由父代理统一执行，当前不填写未实跑数字或完成结论。真实 OpenViking 提取质量、付费模型与真实 QQ／OneBot 业务按实际证据分别报告。

云端仍先本地验证、commit／push，再从 GitHub 拉取确认提交构建；真实连接值、SSH别名、路径、Key及映射只留项目外。缺少额外依赖先说明并询问安装，不增加 TLS、网关或防火墙配置。
