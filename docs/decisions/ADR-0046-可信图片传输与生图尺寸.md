# ADR-0046：可信图片传输与生图尺寸

状态：Accepted，已实现并完成本地及云端验证与部署。日期：2026-11-04，Asia/Shanghai。依据：负责人授权修复生图／表情资源到 QQ 的传输，并让单次生图尺寸覆盖保存默认值。完整证据见[本轮报告](../reports/2026-11-04-官方记忆与插件能力更新验证报告.md)。

## 背景与根因

插件图片原先通过 Base64 预览接口交接，发送前已经展开整图，无法表达同机或共享挂载中的可信文件能力；简单把模型传入路径改成 OneBot 文件路径会绕开来源、资源权限与真实字节验证。不同机器或容器中的绝对路径也不能因为名字相同就认定指向同一图片。

生图服务的尺寸集合属于具体提供商与模型。把尺寸固化成客户端预设、只读保存默认值，或在服务拒绝后自动换尺寸重试，都会掩盖真实请求参数，并可能造成重复付费。尺寸应保留清晰优先级和服务裁决。

## 公开图片资产契约

plugin-sdk4.8.0公开 `PluginImageAsset`：`mimeType`、`byteLength`、`sha256`、`readBytes()`，以及可选 `localFile()`。来源插件只为自身固定 blobs 内的资源提供该对象，每次读取自验证真实文件、大小、SHA-256及MIME，不接受模型给出的任意路径或 URL。共享后台契约变化不增加 UI SDK API，ui-sdk继续4.2.1。

公开资源服务 `getAsset(reference, scope)` 返回 Host 持有的 `ImageAssetLease`。Host在读取前后核对同一个来源实例、调用者 lease、当前 scope 与 AbortSignal，验证大小、哈希、MIME和真实字节；撤权、停用、换实例或资源变化后不可继续使用旧对象。`localFile()` 只给可信后台，不进入模型输出、普通执行记录或可公开下载的路由。

模型预览仍使用 Base64 图片读取及标准 MCP image 块；发送通过 `getAsset` 获取字节与可选文件能力，不先为了发送调用 Base64 预览。生图与表情只暴露 opaque `eating-asset://<plugin>/<assetId>` 引用。AI不得注入或选择宿主路径、共享目录和传输模式。

## QQ 传输选择与共享目录

QQ使用独立 `media-transport.json`，严格 schema1、revision／CAS，保存于本账号数据目录，与封存代码包分开。仅主人管理入口可读取／保存；模型工具不接收这些字段。模式为 `auto` 或 `shared-directory`，映射字段为 `sourceRoot`、`hostMappingRoot`、`onebotRoot`、`ownerConfirmed`，确认绑定当前 OneBot endpoint 与真实账号。

后台优先尝试经过验证的文件映射：来源 `localFile()` 位于受信源根，Host可见映射文件须是无路径越界／符号链接的普通文件，逐图读取并核对与来源相同的字节数、SHA-256及MIME；全部条件满足才构造 OneBot标准 `file://`。无法取得或验证映射时，在发送前选择 Base64。该过程不先尝试一次真实发送，也不在失败或 unknown 后换另一传输再发一次。

`ownerConfirmed` 表示主人已确认目录共享关系；本地逐图一致性不等于 OneBot 已自动实测远端可读。标准 `get_image` 不能探测任意 `localfile`，本轮不伪造这种验证，不自动挂载或修改容器／远端文件系统。真正 OneBot 可读性与最终发送成功由实际部署及动作回执分别证明。

用户手工使用 OneBot标准 file／URL／Base64消息段的协议语义保持。插件资源单图5MiB、最多4张／合计10MiB，Base64展开只对后台验证后的资源计算额外发送预算：普通 wire 扣该字节后≤1MiB，额外≤14MiB，总JSON≤15MiB；普通JSON、模型入参、入站／响应／WebSocket仍1MiB。原动作账本与稳定 `request_id` 防重，unknown不换号重发。

不新增公开图片 URL、无认证媒体服务或任意路径读取入口；权限、来源和真实发送前复查保持。图片进入Harness后仍可按原生附件机制持久化，浏览器 Blob 清理不代表全链路删除。

## 生图尺寸与部署提示

`image_generate.size` 单次传入时优先于已保存默认值；省略该字段使用保存的 size；显式空串表示省略提供商请求中的 size，让服务选择默认。配置默认值和单次参数使用同一校验，接受正整数 `WIDTHxHEIGHT` 或服务原生尺寸标识（包括 `auto`）。客户端只保证形状合法，最终是否受模型支持由提供商判定。

尺寸校验在请求前完成；请求失败后不自动更换尺寸、模型或 `request_id` 重试付费操作。无参考图使用 `/images/generations`，单图编辑使用 `/images/edits`，不增加聊天／Responses回退。稳定请求 ID 与参考图哈希幂等继续执行。

面板提示缺少 Base URL／模型时应保存实际服务配置。Key可选，允许服务不需要 Key；保存或连接不真实生成，也不能当作认证、余额或模型尺寸能力验证。生图成功、图片取得和 QQ发送成功分别核对。

## 版本、验证与边界

应用／Host／Web0.18.0、plugin-sdk4.8.0、QQ0.14.0、DSH0.16.0、image-generation0.3.0、openviking-memory0.3.0、stickers0.2.0；ui-sdk4.2.1、plugin-core4.0.0、插件API4保持。五插件 package／清单／前端／后台版本同步，按封存不可变规则生成新版本，不覆盖旧产物；无新增依赖，锁文件 workspace links 零差异。

媒体专项14文件221项通过、1项条件跳过，另补多源异步读取后的同步最终撤权检查；媒体面板2项浏览器通过并实读390英文／1440中文截图。最终与记忆15项、HTTP插件及提示／尺寸7项组成24项相关浏览器通过；本地完整构建／类型通过，最终全量1824项通过／8跳过（122.16秒）。验收覆盖资产哈希／大小／MIME、来源替换与lease撤销、发送不先展开预览、同机／共享映射验证与Base64选择、路径及模型参数拒绝、unknown零重发，以及JSON和multipart中的尺寸优先级／空串省略／服务原生标识。

云端已按[ADR-0045](ADR-0045-官方记忆接口与插件部署提示.md)同批部署：QQ0.14.0、DSH0.16.0、image-generation0.3.0、openviking-memory0.3.0、stickers0.2.0全部connected，DSH ready／nativeWeb ready、gateway idle／queue0、service active／enabled、异常restart0；四plugin面板可见、pageerror0、无意外mutation／测试发送／真实生图。媒体当前为默认auto且没有主人confirmed mapping，实际发送仍选Base64；以后由主人按服务器实际挂载一次配置sourceRoot／hostMappingRoot／onebotRoot并确认，才可能使用标准file。本地逐图校验不等于OneBot已能读取远端路径，未真人probe；不得写成远端file已验证。

真实服务器值、映射、目录和凭据只保存在项目外，不安装额外依赖、不配置／重启真实OpenViking服务，不增加TLS、网关或防火墙。本地协议夹具不能证明付费提供商支持所有合法尺寸或真实语义质量。
