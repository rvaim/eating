# ADR-0047：图片消息结构提示

状态：Accepted，**本地验证及云端发布部署完成**。日期：2026-11-04，Asia/Shanghai。确认来源：用户初期“先修改提示词吧”仅本地修复，随后明确“push 发到服务器上”，授权本轮Git发布与云端Eating更新，替代此前云端只读限制。源码 `f8b0d51` 已commit／push并由云端GitHub拉取同提交构建、验证及同data部署；完整证据见父代理维护的本轮报告。未真实QQ试发／付费生图。

## 背景与根因

现场 AI 已取得正确的 image 消息段，却把消息段数组序列化成 `message` 字符串。NapCat 实际成功发送文字，成功消息回执随后被误解为图片发送成功。`eating-asset` 是现有受控资源引用，本轮没有删除或替换它的需求。

## 决策与示例

QQ 共享图片规则同时进入默认私聊／群聊提示及主插件说明；消息 schema 只补 description／examples，不改校验结构。生图 `server.agentInstructions` 与 `image_get.description` 同步说明已有图片的使用方式。子 Agent 不自动继承主插件说明，实际可见的类型提示和工具描述都要明确结构要求；主人已保存的自定义正文及人格保持。

`message` 直接接收 image 段对象或数组，`sendable` 是可直接使用的消息段对象；不能 `JSON.stringify`，也不能把 URI／图片 JSON 放进普通字符串或 text 段。下例仅展示 message 字段，其他参数遵循现有工具 schema；`<assetId>` 是占位符，实际应使用已有资源的真实引用。

正确数组：

```json
{"message":[{"type":"image","data":{"file":"eating-asset://image-generation/<assetId>"}}]}
```

正确单段对象：

```json
{"message":{"type":"image","data":{"file":"eating-asset://image-generation/<assetId>"}}}
```

错误字符串：

```json
{"message":"[{\"type\":\"image\",\"data\":{\"file\":\"eating-asset://image-generation/<assetId>\"}}]"}
```

复用已有图片及引用，不为补发再次调用 `image_generate`。生成成功、文字发送成功与图片发送分别核对；只有实际 image 调用及其成功回执才能称图片发送成功，unknown 保原请求标识核对，不重发。

## 原因、取舍与影响

此次选择补齐模型调用指引与正反例，保留现有工具名、URI、参数校验、权限、幂等和 file／Base64传输选择。标准 OneBot 字符串仍用于普通文字；本轮不增加新图片工具、后端强制拦截、自动JSON解析、回执字段或环境自动检测。提示词改进不能宣称为强制代码防漏保证，也不承诺真实 LLM 每次选择正确。

仅 QQ0.14.1、生图0.3.1各四处版本同步；应用／Host／Web0.18.0、DSH／SDK及其余版本保持。源码 `f8b0d51` 已本地commit／push，云端GitHub拉取同提交完整构建／严格类型及Linux11文件363项42.56秒通过；只停Eating，私有全data／服务配置／unit备份后同data正式安装QQ0.14.1／生图0.3.1。五插件connected、DSH／nativeWeb ready、service active／enabled、异常restart0、队列0／busyfalse。正式四提示、主bridge及QQ发送描述／真实数组examples／image_get描述已更新，公网GET实读通过、pageerror0／意外写入0并已脱敏读图；保存配置／人格、受保护业务文件、Host设置及表、原生UUID与3日志前缀、记忆8任务identity与scopes、ownerToken及原系统服务保持。
