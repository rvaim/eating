# ADR-0050：自主思考休息上限

状态：Accepted；实现、可行性验证、Git发布与云端保留数据部署完成，证据见本轮报告。日期：2026-11-09，Asia/Shanghai。

## 根因与目标

主人反馈自主行为仍有问题，现场AI在21:22结束一轮后将sleeping安排到次日10:00。旧代码允许睡眠时间到未来一年，waiting没有普通定时机会；minIntervalSeconds只约束active续行，没有主人可控的休息／等待思考上限。ADR-0049只改提示词，不能强制限制这些安排。

主人同意修改调度边界，并要求先完成实现，再给出实际可行性。目标是在既有原生DSH主Agent中提供有界的重新考虑机会，不增加第二Agent Loop、不强制对外发言、不绕过主人暂停或运行额度。

## 当前契约

1. AutonomyConfiguration新增必填maxRestMinutes，默认15，整数范围1～1440；minIntervalSeconds不得大于maxRestMinutes×60。设置→自主运行→运行设置提供“最长休息或等待（分钟）”，中英文文案明确只保证在运行条件允许时重新考虑，不要求消息或联系。
2. sleeping的有效wakeAt取AI请求与本次安排时间＋主人上限的较早值；waiting仍以wake_at=null请求，但后台保存本次安排时间＋主人上限作为wakeAt，到期可获得普通自主机会。两者均由同一1秒机械检查及原生Agent.followup执行，重新考虑仍由同一主Agent判断。
3. 工具回执提供真实state.wakeAt／state.nextWakeAt，模型与UI须以实际回执为准。limits和configuration均提供maxRestMinutes，必需提示词与主人默认统一新语义；不假装成功安排了被缩短的长休息。
4. 更早到期的AI任务仍可提前触发机会。概览nextWakeAt取安排／最近任务的较早值，再受小时轮次窗口限制；主人关闭、暂停、错误或运行时未就绪时不展示为可执行时间。DSH忙、外部消息、其他Inbox与原生目标仍优先，额度不足可推迟，休息上限不承诺强制打断或忽略配额。
5. 配置保存仍暂停并撤旧许可。主人缩短上限时，同步缩短已保存的休息／等待时间，但不自动恢复运行。正常重启保留绝对wakeAt；中断或未知周期仍暂停且不重放。联系策略、每小时联系任务数、单轮时长和失败规则保持。
6. 自主存储autonomy.json改为严格schema2；新字段缺失或旧schema1明确拒绝并保原文件。公开snapshot.protocolVersion仍为1，agenda、contact-policy、proactive-bindings及其他数据schema不变。应用不自动迁移或给旧数据补默认。
7. 本次已授权服务器更新使用独立GitHub工具server-autonomy-transition.mjs显式转换schema1→2。完全停Eating且host.lock不存在，核对原文件SHA256、私有原文件备份后，新增指定maxRestMinutes、配置及活动revision各递增1，并缩短旧长休息／为旧waiting记录有限时间；保主人开关／暂停／自动恢复、既有额度、note、历史、计数、联系人和错误／未知状态。活动中、格式不符或摘要变化拒绝，生产读取不调用此工具。

## 可行性与限制

默认15分钟休息对应空闲且每次选择最长休息时约4轮／小时；模型可选择更早继续，因此仍由主人每小时轮次上限约束。新增模型轮次可能增加实际费用，不用“只是后台检查”掩盖真正重新思考调用模型；每秒机械检查本身不调用模型。

该边界强制约束安排时间，不能证明活人感、兴趣质量或每轮都有值得做的事。程序提供机会，AI仍可选择安静、继续探索或在当前授权内联系。真实暂停、忙碌和配额导致的等待明确显示，不能视为边界未执行而偷偷增加第二条唤醒链。
