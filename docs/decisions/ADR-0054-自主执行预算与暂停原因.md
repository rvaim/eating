# ADR-0054：自主执行预算与暂停原因

状态：Accepted，2026-11-10。主人要求修复自主暂停、按钮文案及执行计时，提交／push并部署服务器。诊断见[只读记录](../reports/2026-11-10-自主暂停与按钮文案只读诊断.md)，本轮结果见[验证报告](../reports/2026-11-10-自主执行预算修复部署报告.md)。

## 已确认根因

旧maxRunMinutes以active状态开始至当前的经过时间计算，小时额度等待与轮次间隔也消耗预算。24轮各3秒的隔离复现仅执行72秒，两个小时后仍触发AUTONOMY_RUN_LIMIT。准入拒绝并不新增失败周期，所以现场连续失败0、最近结果completed与暂停同时存在。

前端把所有非空errorCode都显示为通用错误，缺少独立预算暂停原因；恢复按钮引用resumeAfterReview，但两种语言都缺失资源，直接显示内部键名。

## 当前计时契约

自主存储严格schema3，删除state.startedAt，改为runUsedMs记录当前活动段已结算的执行毫秒。每轮从Host准入至结算计时，包含该轮模型／工具／I/O及交接，最多计至该轮deadline；不宣称CPU时间或仅Token生成时间。轮次之间、额度等待、外部事件等待和停机不累加。

snapshot在已结算值上加当前轮的有界经过时间，派生runRemainingMs，读取不写盘、也不推进revision。claim使用剩余额度与单轮超时的较早边界，明确返回budgetLimited；运行时按真实边界区分执行预算耗尽与单轮超时。预算中止仍保留unknown及动作账本的不确定性，不伪造成成功，也不计入模型连续失败。

正常完成后耗尽预算立即暂停，保持该轮completed。真实故障的连续失败阈值、unknown防重、scope撤销、主人暂停和小时额度继续生效。明确sleeping／waiting的活动段边界在当前轮结算后重置预算；主人正式resume／wake也重新开始预算。已结算用时跨重启保留，重启不额外计入停机时间，也不凭重启解除暂停。

## 界面与数据更新

AUTONOMY_RUN_LIMIT派生reason=run-limit，显示“已达连续执行时长上限，已暂停”，直接解释分钟上限并展示代码及累计执行时间；真实故障保持故障提示。成功轮次历史保持成功。两种语言都补齐“核对后恢复”和“恢复自主运行”，unknown仍要求核对。

旧active经过时间无法准确换算实际执行时长。独立离线工具scripts/server-autonomy-transition.mjs仅接受schema2→3，在停止Host、原SHA核对及私有备份后显式启动新预算runUsedMs=0；配置／活动revision各加1，其余配置、安排、note、历史、计数、暂停和错误保持。生产不自动迁移、不读取旧格式。当前已有暂停须由主人通过正式按钮恢复，本次部署保留该状态。

应用／Host／Web0.22.0、DSH0.19.0，plugin-sdk4.11.0／ui-sdk4.3.0／plugin-core4.0.0／API4保持。其余五插件及外部依赖不改，锁文件不变。此决策替代ADR-0031中以活动段经过时间代表执行时长的实现，保留休息／等待边界和未知动作规则。
