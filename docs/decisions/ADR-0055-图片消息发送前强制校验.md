# ADR-0055：图片消息发送前强制校验

状态：Accepted。日期：2026-11-13，Asia/Shanghai。用户在截图中再次指出图片JSON被发成文字，明确要求立即修复；延续本会话提交、push及云端保留数据部署授权。

## 根因与决定

既有提示词要求 image 对象／数组，但 OneBot 正式 message 支持字符串。模型将正确图片段序列化为字符串后，旧校验接受该字符串，内部图片解析不触发，最终当文字发送并拿到 message_id。ADR-0047 当时仅提示词的处理不能阻止这条错误路径；本决策新增发送边界强制约束，替代其“不增加后端拦截”的阶段范围。

QQ 的 prepareOneBotCall 在有界JSON Schema校验后、Host动作账本和OneBot调用前检查 outgoing message 及快速操作的 operation.reply。拒绝：

- 普通字符串／text 段中出现 eating-asset 内部图片引用。
- 普通字符串／text 段本身是序列化的 image 消息段对象、数组或包含 image 的结构化 node 内容。
- 内部图片引用放在 record、video、share 等非 image.data.file 字段。

递归检查真实 node.content；快速操作的原始 context 属于入站数据，不检查或转换其消息正文。正确 image.data.file 继续走原资源解析、scope、lease、大小和真实字节校验。普通聊天、非图片JSON、正常CQ码和OneBot的其他正式能力保留。

错误为 QQ_IMAGE_MESSAGE_REQUIRED、HTTP400、outcome=not-sent，通过原MCP错误通道返回模型，同时明确对象／数组用法、复用已有图片、不重新生图。此次拒绝不登记发送动作，因此修正后可复用本次request_id。既往已成功或unknown请求的幂等与参数冲突规则保持。

只为识别并拒绝而解析序列化图片段，不将错误字符串转换为消息并发送，不引入兼容分支或自动重试。无需添加工具或修改SDK／存储schema；QQ升级0.16.1，四处版本同步。

## 验证与边界

回环覆盖各发送入口、text／node／错误段字段、纯文本／JSON／CQ与正确图片保留，以及拒绝时OneBot请求数0、账本调用0、资源读取0。格式修正后同request_id实际发送原图一次，重复调用不二次发送。

使用独立系统DSH、Host、MCP、回环模型、生图服务及OneBot验证：模型首先故意传错误字符串，真实工具返回not-sent；模型收到纠正信息后以同request_id提交真正image数组，只生成一次、发送一次且源PNG字节相同。真实model request中的system和工具描述包含新规则。

这证明错误通道与正确发送路径可执行，不证明任意真实LLM必然自我纠正；强制保证范围是已定义的错误格式不能作为文字发出。没有真实付费生成或真人QQ试发。版本、执行结果与部署证据见[报告](../reports/2026-11-13-图片JSON文字误发强制修复报告.md)。
