# ADR-0059：多协议语音合成与受控语音识别

状态：Accepted；实现及发布已获主人授权，实际验证与部署结果见[报告](../reports/2026-11-14-多协议语音与识别部署报告.md)。日期：2026-11-14，Asia/Shanghai。

## 需求与根因

主人要求在语音合成中增加 DeepSeek 接口，新增独立语音识别插件，并让两者以后都可扩展其他协议；明确不兼容旧版，允许重建旧语音合成数据。授权使用独立工作树，完成后合入 main、删除工作树，再 push、由云端 GitHub 拉取构建部署。

旧合成实现把配置、全局音色枚举、WebSocket 事件及完成转写都绑定 OpenAI Realtime，不能通过替换 endpoint 接入 DeepSeek。QQ 的标准 get_record 只返回协议端转换结果，不能把远端路径当成 Host 本机文件读取；已有受控音频资源只支持发送用的 24kHz／60秒 WAV，不能据此限制所有识别输入。

官方依据：[DeepSeek TTS](https://api-docs.deepseek.com/zh-cn/guides/tts/)、[DeepSeek ASR](https://api-docs.deepseek.com/zh-cn/guides/asr/)、[NapCat 文件处理](https://napneko.github.io/develop/file)。服务声明与真实音质、识别准确率、实际协议端可用性分别验证。

## 独立插件与协议配置

保留 text-to-speech，新增 capability speech-to-text；二者不导入彼此实现。各自负责有界任务、状态、防重、管理面板与生命周期；协议适配器只处理提供商参数、传输与响应。共享 SDK 只定义资源、校验与权限契约，不建立第二个 Agent Loop 或通用工具框架。

合成配置／任务严格 schema2。公共配置包含 revision、endpoint、timeoutMs 和私有 apiKey；provider 为严格区分的联合：

- openai-realtime：model、voice，支持每次 delivery。音色由主人保存，语气仍由会话 AI 按次选择。
- deepseek-tts：voice（stella／tide）、filterMarkdown；没有 model、delivery、语速或音色克隆参数。未知字段拒绝，不悄悄忽略语气。

识别配置／任务严格 schema1，provider 当前只有 deepseek-asr；没有伪造的 model 或 language 字段。以后增加协议时新增对应类型与适配器，不根据域名、模型名猜协议，不做失败后换协议重试。协议格式与音频编码分开。

更换服务地址或合成协议时，不把旧服务的密钥自动带到新服务；没有明确提供新 Key 就清空该连接的 Key。空 Key 在同服务的普通保存中仍表示保持，显式 clear 仍表示清除。保存和连接不调用付费服务。

合成的工具 schema 和说明按已保存协议生成。声明 configurationChangesTools 的能力插件在启用状态下保存配置，Host 走现有来源撤权、停止并一次性恢复原已连接 Harness 的拓扑事务；主人 stop 优先，未连接的 Harness 不自动启动。停用插件保存配置不触发重挂。识别也声明此能力，以在从未配置变为就绪时刷新来源目录。

## 合成协议与成功证据

OpenAI 适配保留单次 Realtime response、原文转写核对和未知不重放。DeepSeek 使用 WebSocket 一次提交 text 与 finish_text，显式选择 PCM；收到 finish/code=success 且收齐合法 PCM 后才封装标准 WAV。音频中途断线、缺少成功终结、超长或协议无效不释放资源。

公共输出仍是最多1000字符／60秒、24kHz单声道PCM16 WAV；继续通过 eating-audio:// 和 Host lease 交 QQ record 发送。任务记录 protocol 和 verification：OpenAI 为 provider-transcript，DeepSeek 为 provider-completion。DeepSeek 没有提供朗读转写，不伪造核对、不额外付费调用 ASR 验证。合成完成与 QQ 发送成功分别核对。

## 受控识别输入与结果

SDK 新增 ReceivedAudioReference、ReceivedAudioAsset、ReceivedAudioLease 和 readReceivedAudio，独立于发送音频。WAV 按 RIFF／fmt／data 检查真实 PCM16、采样率、声道与时长；Ogg Opus 核对容器、头、序列、流标识、CRC、结束页与时长。最多8MiB／120秒；双声道只识别左声道是服务行为，界面明确说明。

ASR 提供 asr_transcribe、asr_job_get、asr_jobs。Agent 只能提供当前消息 messageId 与真实 record.file 作为 audioId，不接受任意 URL、路径、Base64 或伪造 scope。QQ 重新查询原消息，核对账号、类型、发送者、消息与资源配对；核验当前 qq_get_message／qq_get_record 权限，再请求 out_format=wav。

转换结果有 HTTP(S) 下载地址时按系统网络栈取得有界字节，禁止重定向、认证头传播与任意模型 URL；只有路径时必须使用主人确认的专用音频缓存映射。audio-input.json 为账号目录独立 schema1／revision，绑定实际 endpoint 与 accountId，不复用图片发送映射。限制文件在确认的缓存根内，拒绝路径穿越、符号链接、文件身份变化和过期 revision；读前、读后及上传前复核授权。协议端不能转换或没有可读结果时明确失败，不自行安装 ffmpeg、不猜下载端点。

ASR 通过 multipart/file 一次上传，仅服务明确成功并返回有效 text／duration_ms／request_id 才完成。服务端 request_id 是回执，不是客户端幂等承诺。Host 持久接收回执先于付费请求；相同请求返回原任务，参数或配置变化拒绝，unknown 不自动换号重试。停用或进程中断保 unknown；普通会话结束不自动重复已提交上传。

任务绑定真实账号／会话及消息资源范围；其他会话和主人面板上传的任务不能通过本会话工具读取。转写始终是原消息的外部内容，不升级为系统规则或主人授权。任务最多100项；列表仅有界元数据和160字符预览，完整转写最多32000字符，按需单独读取。原始识别音频只在处理期间保留于 RAM，不新增语音聊天库。

## 面板、数据与部署

两个插件均有独立双语配置与任务界面，继承现有白绿样式和固定滚动区域。上传由内容校验决定格式；付费测试须确认，保存和语言切换不提交音频。隐藏／离页停止轮询和在途 UI 请求，清未保存 Key、上传音频和临时预览；已提交后台任务按插件生命周期管理。

识别的主人上传管理接口声明独立输入上限，仅管理入口容纳8MiB音频的Base64 JSON；不随图片大小设置缩减，不扩大模型参数、普通消息或 OneBot WebSocket 的1MiB上限。

生产读取不迁移、不重置旧数据。部署先停 Eating 并核对全量私有备份，再显式运行 server-speech-reset.mjs：完整旧语音目录的 manifest 必须匹配，Host 锁必须消失，旧目录移动至应用外新的私有备份，再建立空语音目录。只处理 capabilities/text-to-speech，Host动作账本及其他配置／资源／会话保持。旧请求ID不因清空插件任务而重新计费。新 speech-to-text 使用独立目录。

版本：应用0.23.0、plugin-sdk4.12.0、QQ0.17.0、TTS0.2.0、ASR0.1.0。其余 SDK 消费产物按封存不可变规则补丁升级；无新外部依赖，锁文件仅新增 workspace importer。最终合并后的版本、构建、回归和部署实数以报告为准。
