# ADR-0060：QQ 消息格式统一发送校验

日期：2026-11-14。状态：已采纳。替代 ADR-0055 的图片专用发送格式入口；保留其资源授权、回执与幂等原则。

2026-11-14补充：发送已有语音的明确audio_ref参数见[ADR-0061](ADR-0061-QQ语音引用直传.md)；原格式防漏、授权、幂等与当前标准OneBot消息能力保留。

## 已证实根因

服务器原生日志及实际模型请求确认，新群聊第一轮和已有私聊已经收到图片与语音的系统规则。模型仍将 text／record 消息段序列化为 message 字符串；原生 assistant 调用参数与 QQ 接收参数一致，Host 没有把正确对象转成字符串。原图片校验只识别图片 JSON 与图片内部引用，文字段 JSON、语音段 JSON 和内部语音 CQ 包装绕过了校验；语音解析器不把普通字符串当作音频对象，因此 OneBot 将其作为文字处理。主 Agent 的 QQ 说明还缺少语音规则，工具 message 描述也主要覆盖图片，纠错信息不足。

这与缺少音频文件、服务器完全没加载提示词无关。既有音频任务和实际 WAV 均已存在；只有真实调用参数与发送回执能证明走过语音发送路径。

## 当前契约

- 在 schema／有界输入校验之后、动作账本登记与媒体资源读取之前，所有发送入口统一调用 assertQQMessage；包括私聊、群聊、通用发送及快速操作的 operation.reply，不校验或改写入站 context 正文。
- 普通文字保持字符串；真实 OneBot 消息段保持对象或数组。根据唯一 OneBot 段 schema 识别整段序列化字符串，覆盖 text、image、record 和其他当前正式段类型，也拒绝双重编码及 text／转发节点正文中的同类错误。
- 字符串解析仅用于识别并拒绝，不自动转换、不猜类型、不执行兼容修复。普通业务 JSON、标准外部 CQ 和当前结构化消息段仍按 OneBot 契约处理；明确的 json 段内容仍是业务数据。
- 内部 eating-asset／eating-audio 引用只能处在相应 image.data.file／record.data.file 且符合 SDK 的原引用格式；放进文字、错误段字段、内部 CQ 包装或无效引用均在发送前拒绝。语音必须是单个顶层 record 或单元素 record 数组，配文另发；快速操作不承接内部语音。
- 格式错误统一返回 QQ_MESSAGE_FORMAT_INVALID、HTTP 400、outcome=not-sent，指出字段、正确结构、复用现有资源和当前 request_id。此拒绝没有登记动作，修正后可复用同号；成功／unknown 不因此重发。资源撤权、损坏、真实传输失败仍保留各自错误与回执。
- 主／私聊／群聊共享普通文字、消息段、图片及语音规则；主规则补全语音。工具 schema 提供正确文字、text 数组、image 数组和 record 对象示例。正常聊天发送自然正文；参数、日志和回执没有证明的原因不能编造。
- 面板用中英文说明统一错误；不新增按钮或改变请求编号生命周期。QQ 从 0.17.0 升至 0.17.1，其余应用、SDK、插件版本、依赖与锁文件保持。

## 验证与部署边界

公共发送入口回归覆盖全部当前发送段、各发送 action、auto_escape 开关、节点正文、原始业务 JSON 与有界深层字符串。后台集成确认错误先于 ledger／resource／OneBot；修正同 request_id 后仅一次真实字节发送。

系统 DSH 以全新临时数据、脚本模型和回环 OneBot 验证主及私聊／群聊模型 request.system、工具描述、错误回传、同资源同号纠正；图片与语音各只生成一次。这验证真实运行链路，不保证任意真实模型永不产生错误参数。

部署须先本地提交并 push，云端从 GitHub 拉取同提交构建；同版本封存产物逐一核对。空闲时只停 Eating，全量私有备份核对后原目录更新，不做格式迁移或清空资料、不覆盖人格与自定义提示词。检查实际安装后台、生成规则、服务就绪及公网双语桌面／手机。没有真人试发或真实付费调用。实际结果见[本轮报告](../reports/2026-11-14-QQ文字图片语音格式修复部署报告.md)。
