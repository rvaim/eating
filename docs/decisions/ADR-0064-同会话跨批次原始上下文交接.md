# ADR-0064：同会话跨批次原始上下文交接

日期：2026-11-14。状态：已采纳。修复图片先发、文字随后落入另一聚合窗口时，绑定子Agent丢失原图引用的问题。

## 现场根因

正式原生日志显示：主Agent先收到一个仅图片批次，未委派便结束该轮；活动批次按既有契约退休。约15秒后另一批文字到达，主Agent只将该批events与文字context_notes交给绑定子。子Agent原始输入没有上一批的图片消息／资源配对，随后未调用取图工具便称只收到文字。原图不是下载失败：正式qq_view_received_image只读成功，JPEG725148字节。生产read-model-information的imageInput与appliedImageInput均为true；model-capabilities.json的false只是未生效的手动补充，不能据此判断实际能力关闭。

上轮ADR-0063解决另一张JPEG的尾部字节误拒绝，本轮是独立的跨批次交接缺口。现场正文、账号、消息引用、URL及原始日志仅存项目外私人诊断目录。

## 决定与当前契约

DSH在验证外部批次进入主原生会话时，保留一个有界RAM投影：每个真实会话最多32条规范化信封／256KiB，最多100会话、总计4MiB，按eventId去重；超出范围明确truncated。它不存图片字节、不建立Eating聊天历史库，也不新增持久化文件。重启时复用已有原生日志扫描，只从当前root中来源为eating-external且运输身份、batchId及正文digest匹配的user/message重建。

主Agent选择普通会话处理、明确委派或给运行任务追加context_ref时，运行时在当前events之外补充history:{events,truncated}。只选择当前批次之前、同plugin／platform／instance／account／conversation／kind／target／agentType的原始消息，并与后台签发的当前messageIds／resourceIds相交；图片的messageId、resourceIds与原始消息段一同保留。当前批之后的新消息不会提前混入，其他会话、账号或已失效引用不补充。

prepare-task与append-task返回不含signal或凭据的historyScope；该scope只供原生运行时筛选，不由模型填写，不修改许可。当前只读verify、运行任务互斥、租约增量扩展、真实动作回执、unknown不重放及双确认批次退休保持。历史是话题上下文，不是新请求，不自动重新执行旧任务。主Agent仍决定是否启动、追加或中断子；Host不按正文推断图文关系，不自动触发子Agent或网络请求。

主子唯一complete系统层说明history.events的含义及有界限制。子Agent针对当前图片话题使用实际获准取图工具，不凭当前events只有文字断言用户没发图；不自动抓取所有图片或伪造视觉理解。

## 发布与验证

只升DSH四处版本至0.21.1。应用0.25.0、SDK4.14.0、QQ0.18.1与其他六插件保持；不加依赖，不迁移数据、不覆盖主人模型选择、人格或自定义提示词，不修改主DSH或官方Web。

隔离系统DSH回归必须覆盖：图片先到但主沉默、批次退休、原生重启、随后文字交绑定子、原图片引用进入history、真实MCP取图后模型请求包含图片。另验证忙碌任务追加、同会话筛选、撤权过滤、未来批次隔离、容量、伪造原生来源与digest拒绝。正式原图只读，实际安装包使用独立模型／OneBot回环，不向真人试发或调用付费模型。完整构建、类型、回归、发布与保留数据部署结果见[报告](../reports/2026-11-14-跨批次图片上下文修复部署报告.md)。
