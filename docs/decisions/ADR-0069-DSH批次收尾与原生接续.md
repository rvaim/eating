# ADR-0069：DSH 批次收尾与原生接续

日期：2026-11-21。状态：已采纳。补充 [ADR-0058](ADR-0058-固定聚合窗口与主Agent异步协调.md) 的批次双确认和重启恢复。

## 原因

旧版将所有批次的收尾挂在整个进程的子任务和通知状态上。任一普通子任务运行中，或其结果仍未登记为已读，其他已结束批次也无法退出登记。重启只校验原生 Inbox 的接收回执，随后恢复所有登记并等待下一次主轮结束。32 个登记占满时，Host 已无名额交接新消息，且旧批次的结束事件不会由 DSH 重发。

系统 DSH 的 Inbox 还会先持久记录取出操作，随后才写入原生 `user/message`。若在两步之间中断，恢复后的原生 Inbox 已无此消息，单靠检查 Inbox 会漏掉这条已由 Host 确认接收的批次。

## 当前契约

- 主轮对已写入原生会话的批次，按对应的 `turn/end` 收尾。子任务保留启动协调时可用的上下文，以及主 Agent 之后明确追加的批次。独立执行任务与后来已结束的无关批次可以并行。任务结果以原生会话实际写入并结束的轮次确认，原生显式取消保留其取消语义。
- 收尾前调用公开的 `sessions.flush`。Host 的持久 ACK 和主轮收尾两项均成立后，释放登记和短期引用。回执或收尾响应丢失时仅核对或重试登记，保留原生会话和动作账本。
- 冷启动按顺序核对原生 Inbox 记录、批次 ID、原消息 ID、摘要和会话。已进入原生会话的批次可在无待接续工作时直接收尾。未取出的原生 Inbox 继续由 DSH 处理。已取出且没有原生消息记录的批次，用原 ID 接回同一 Inbox，排在尚未取出的原生输入之前。明确取消或原生拒绝的工作不重放。
- Host 继续用持久队列的接收序号和原子回执交接 backlog。已交接、结果未知及已按设置移除的记录保留各自语义。接收与收尾都不代表模型已回复或外部动作已成功。

DSH 升至 0.25.1。沿用当前严格存储形状、协议及 32 批上限，无数据迁移。现场与回归见[验证报告](../reports/2026-11-21-DSH批次收尾与QQ边距修复报告.md)。
