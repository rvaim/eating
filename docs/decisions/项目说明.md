当前共 15 份 ADR。Accepted 可表示已确认原则或当前实施选择，具体确认范围、源码分析与运行证据分别记录。0012 的目录、包名／版本、产物与安装布局是实现细节，不概括为负责人逐项确认。0014 补充 0006／0007／0013；0015 替代其中旧作者迁移和旧入口保留策略，其他主子权限、统一人格与可靠性原则保持。历史文件保留当时理由和结果，不将新实现反写成旧阶段已经完成。

正式 Host／QQ／MCP 在重组前已有本地协议／持久化／浏览器证据；0012 于 2026-10-27 完成构建／严格类型、280 项单元集成、8 项浏览器、四包 pack 与仓库外产物回归，见[重组历史报告](../reports/2026-10-26-单仓独立包重组报告.md)。0013 阶段为 387 项／13 浏览器，见[队列历史报告](../reports/2026-10-27-投递设置与无历史队列验证报告.md)。0014 阶段的 855 项与 53 浏览器及当时旧产物迁移证据保留在[多代理历史报告](../reports/2026-10-28-多代理与会话看板验证报告.md)，旧版本支持不延续到当前契约。

0015 本轮完整构建／严格类型通过，41 文件 983/983（37.03 秒），含 5 项实际 SDK 验证（多代理 3、源码／独立产物 2）；浏览器 53/53（18.5 秒），见[当前报告](../reports/2026-10-29-删除旧版兼容验证报告.md)。实际 SDK 测试须显式设置独立 EATING_DSH_TEST_RUNTIME，默认跳过 5 项不能当完整实跑，不再要求旧插件目录或旧迁移测试。自动模型／OneBot 都是临时目录与回环夹具，未向真人测试、未代测付费提供商，也未部署或处置真实数据。三平台、OS 隔离、其他 Harness 与 Host 最终 Cordis 选型仍需分别验证。

## 模板与维护

新增 ADR 连续编号，包含状态（Proposed／Accepted／Superseded）、日期／确认来源、背景、决策、原因、备选、影响、证据、后续和替代关系。

替代旧方案时新增 ADR，旧文件标明全部或部分替代范围并双向关联，不删除或无记录重写历史。产品基线变更由负责人决定；已明确授权的原则不重复请示。技术候选须有实际证据后再决定是否 Accepted。证据分级见[文档索引](../项目说明.md)。
