当前 14 份 ADR，Accepted 可表示已确认原则或当前实施选择，具体确认范围、源码分析与运行证据分别记录。0012 的目录、包名/版本、产物与安装布局是本轮实现细节，不把它们概括成负责人逐项确认。0014 补充 0006／0007／0013；旧 ADR 状态和当时的验证结论保留，不将新实现反写成旧阶段已经完成。

正式 Host／QQ／MCP 在重组前已有本地协议／持久化／浏览器证据；0012 于 2026-10-27 完成构建／严格 TS、280 项单元集成、8 项浏览器、四包 pack 与仓库外产物回归，详情见[重组报告](../reports/2026-10-26-单仓独立包重组报告.md)。当时真实 Harness 与 Host 最终 Cordis 底座尚未接入。0013 阶段无历史队列与设置的 387 项／13 浏览器及真实未交接数据保持证据见[历史报告](../reports/2026-10-27-投递设置与无历史队列验证报告.md)，原数字不随新阶段修改。

0014 已完成官方 SDK 源码组合、独立产物与原生多代理的本地验证，包括主委派、子会话授权、稳定 UUID、统一人格更新和停机原生会话只读。精确测试数字和实际部署见[本轮报告](../reports/2026-10-28-多代理与会话看板验证报告.md)。自动模型／OneBot 均为回环夹具，不向真人发测试消息，也不证明正式付费提供商、三平台或 OS 沙箱已认证。Host 最终 Cordis 底座仍未选定；0001／0002 与旧阶段结果保留历史，Accepted 不等于全部环境验证通过。

## 模板与维护

新增 ADR 连续编号，包含状态（Proposed/Accepted/Superseded）、日期/确认来源、背景、决策、原因、备选、影响、证据、后续和替代关系。

替代旧方案时新增 ADR，旧文件标明 Superseded 并双向关联，不删除或无记录重写历史。产品基线变更由负责人决定；本轮已明确授权的原则不重复请示。技术候选须有实际证据后再决定是否 Accepted。证据分级见[文档索引](../项目说明.md)。
