# Eating 产品上下文

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

前端为 React／TypeScript／Vite、普通 CSS、lucide-react、pnpm；后台为普通 Node.js >=24.9.0、TypeScript、SQLite、ws 与官方 MCP SDK。Host／Web／根应用 `0.6.0`，plugin-sdk `1.4.0`、ui-sdk `1.5.0`，QQ `0.6.0`、DSH `0.2.0`，apiVersion 仍 1。公开 UI SDK 以精确 `i18next 26.5.11` 提供共享国际化。`pnpm dev` 联合 Host 5181／Vite 5180，生产由 Host 同源提供构建产物与独立插件资源。最小真实 DSH 已实现，Cordis、Tauri、Windows/Linux 尚未完成；不修改用户主 DSH 或当前 GUI。

## Users

Eating 主人在个人电脑上管理同一个 AI 的通讯、模型、提示词、人格和待处理消息。当前可连接真实 OneBot，查看按需实时日志、手动测试 9 项 QQ 工具并配置独立 DSH。自动验证使用本地模型／OneBot 协议夹具，不向真人发送消息；当前实际 QQ 已连接，DSH 未配真实模型、未启动。

## Product Purpose

为拥有持续身份的 AI 提供稳定、可扩展、可恢复的生活环境。认知与行动由用户选择的 Harness 承担，Eating 管理能力、通讯、授权、状态和恢复，不建立第二套 Agent Loop 或人生记忆引擎。

## Positioning

通讯和 Harness 通过插槽接入，各插件独立注册后台与面板，通用目录只读契约和已安装清单。插件依赖公开 SDK、自带双语资源，不依赖宿主私有实现；增加插件不需要硬编码语言链或修改其他插件。

## Operating Context

全局导航“概览 / 机器人 / Harness / 提示词管理 / 人格管理 / 设置”。中文“机器人”保留，英文“Connections”；各插件分类仍来自目录。QQ 四页签为“连接配置 / 实时日志 / 功能测试 / MCP 能力”，不再有消息历史页或历史工具。DSH 在 Harness 分类配置独立模型与运行时，提示词页使用“通用提示词”。

桌面为主要场景，390px 窄屏仍须可读可操作。侧栏底部提供原生“简体中文 / English”选择，默认中文；刷新保留、跨标签页同步，即时更新文档语言／标题／说明与面板，不重挂、不丢草稿／选区／undo，不引发保存、重启或发送。`eating.locale` 仅语言偏好，无凭据。

## Capabilities and Constraints

- QQ 支持 OneBot v11 正向统一 WebSocket，实际账号／服务状态符合要求后才显示连接成功；不支持反向或 API/event 分离。令牌只写不回显，留空保留，清除需显式保存；保存断开旧连接。
- 功能测试与 MCP 共用 Host 单 catalog 的 9 项工具；工具名称和参数描述按 ID 在 QQ 自有资源本地化，schema／执行来源不变，未知 metadata 原样回退。手动发送／撤回逐次确认，稳定请求 ID 防重复，未知先核对。
- 消息不建 Eating 聊天历史，只暂存有界未交接信封；可选保存到本机或仅内存。可靠送达不等于 AI 已处理，内存关闭丢失、丢弃／清空不可恢复等后果须明确。
- 实时日志只在可见页签订阅、浏览器内存有界，离开／隐藏／停用清空停止，不补发，不建后台日志缓存。
- DSH 使用专属运行时、双 home、工作区和固定原生会话；通用策略／当前人格为可信 system、外部消息为 user，策略更新下次请求生效。模型自行调用 QQ MCP 回复，Host 不代发普通输出。
- `sessions.flush` 成功并原子 ACK 后才可靠交接删 Host 正文，忙时暂停不耗重试；恢复同会话，不重发未知批次、不承诺 exactly-once。当前实际 DSH runtime installed、模型空配置未启动，不代表提供商认证。
- 数据统一 `EATING_HOME`；插件代码在 plugins，QQ 账号在 bot/qq-bot，DSH 在 harness/dsh。停用保留数据，删除另需授权。本版仅一个默认 QQ 实例，多账号目录不等于多账号并行。
- 主人新增未知可执行扩展须批准，固定人格写入口不开放给模型。Host 的回环／会话／CSRF／scope／锁与工具收窄不等于 OS 沙箱。
- QQ 空间发布／评论不属于当前 OneBot 标准能力。其他 Harness、跨 Harness 无损迁移、长期记忆、自主活动、Tauri、Windows/Linux 与多账号并行未完成。

## Brand Commitments

名称统一 Eating，保留白绿“浅色标签”视觉令牌，不因双语重设计。界面支持简体中文与 English，面向阅读的仓库文档继续中文唯一正文。UI 说清当前状态、下一步、后果，不把实现约束当主叙述；“添加／启用／停用”对应真实动作，诊断和路径保留折叠入口。

用户名称、模型名、URL、Key、消息、JSON、canonical 中文变量 token 和默认提示词正文保持原样；主人内容／AI 策略不随 UI locale 翻译。完整句、插值、复数、aria、错误及日期数值统一走资源和公开 SDK。结构化错误按 code 映射，未知后端原文作为可选详情。

## Product Principles

1. 唯一身份、一个活跃主认知控制者，主人新增能力授权和来源验证保持。
2. 通用页面只读注册契约，插件自带面板和资源，后台不依赖浏览器。
3. 保存、连接、可靠接收和 AI 处理完成分别表达，状态未知不能伪装成功。
4. 文案面向用户任务，必要风险和确认清楚，技术详情可展开。
5. 切换语言仅改变展示，不改主人内容、协议数据或执行行为。
6. 可访问性、稳定草稿与窄屏可操作优先于装饰，保留既有白绿方向。
