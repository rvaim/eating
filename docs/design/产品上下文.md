# Eating 产品上下文

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

负责人于 2026-10-26 明确选择 React + TypeScript + Vite 本地网页验证。最终产品目标为 Windows/macOS/Linux 独立桌面应用，本轮不搭 Tauri、不接真实通讯或 Harness。运行于独立本地预览服务，不修改 DSH Web GUI。

## Users

Eating 主人及项目负责人在个人电脑上管理同一个 AI 的运行环境与通讯扩展。本次用于验证导航、插件注册和模块自有配置面板。

## Product Purpose

为拥有持续身份的 AI 提供稳定、可扩展、可恢复的生活环境。认知与行动由用户选择的 Harness 承担，Eating 管理能力、通讯、权限、状态和恢复。

## Positioning

模块插槽式接入：通讯平台与 Harness 可替换，模块注册自己的后台能力和管理界面。新增/移除飞书不要求修改 QQ 或通用管理页。

## Operating Context

用户已确定全局侧栏第一项“概览”、第二项“机器人”；机器人页内另有左侧分类栏。分类名称来自已注册插件，例如 QQ。QQ 配置面板由 QQ 插件实现，宿主负责通用导航、挂载和状态。

首版在本地浏览器运行，桌面窗口为主要使用场景，窄屏仍须能浏览和操作。无需真实账号即可验证示例模块注册/移除与配置保留。

## Capabilities and Constraints

- 用户已授权开始首个验证版本及必要前端开发，不再受上一轮“只写文档”限制；范围仅当前前端 PoC。
- 示例平台明确标注未接入，不伪造在线、消息数量、模型活动或长期记忆。
- 自有配置面板、保存/校验和分类变化需真实可操作，模拟配置仅保存在本地浏览器；不保存真实认证令牌。
- 新增可执行扩展仍需主人批准。本轮注册仅限随代码提供的本地示例，不实现任意下载执行或真实插件市场。
- Cordis 为后续 Host 候选，前端业务注册目录不冒充后台插件生命周期或安全隔离验证。
- 唯一身份、一个活跃主认知控制者、人格保护、来源验证和联系人隐私保持。

## Brand Commitments

名称统一 Eating；界面和面向阅读的文档使用中文。全局“概览/机器人”及机器人页内分类栏为用户固定结构。没有现成标志、配色、视觉实现或图片可继承。

## Evidence on Hand

[需求基线](../product/需求基线.md)、[插槽设计](../architecture/插槽式扩展.md)、[Harness 设计](../architecture/Harness适配.md)提供产品事实。当前代码工程此前为空；所有真实平台、Harness、后端隔离和桌面打包均未验证。

## Product Principles

1. 通用页面只读取注册契约，不枚举 QQ/飞书/微信条件分支。
2. 状态真实，配置成功与外部连接成功分开。
3. 移除模块保留其他模块和本模块已保存配置，不静默删除数据。
4. 操作简单，模块自有内容与宿主通用交互边界清晰。
5. 可访问性与稳定行为优先于装饰。
