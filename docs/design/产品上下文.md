# Eating 产品上下文

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

前端为React／TypeScript／Vite、普通CSS、lucide-react、pnpm；后台为普通Node.js>=24.9.0、TypeScript、SQLite、ws与官方MCP SDK。Host／Web／根应用0.9.1，三个共享包2.0.0，QQ0.9.1、DSH0.4.1，插件API2。公开ui-sdk以精确i18next26.5.11共享国际化。pnpm dev联合Host5181／Vite5180，构建后Host同源提供Web和插件资源。默认不兼容旧格式，不修改主DSH或借其Profile／凭据。

## Users

Eating主人在个人电脑上管理同一个AI的通讯、模型、提示词、人格和待处理消息。当前支持OneBot、多主人与工具权限、分层原生DSH子代理和手动会话看板。自动验证使用本地模型／OneBot夹具，不向真人发送；实际连接与提供商认证以当前受控API和用户主动测试为准。

## Product Purpose

为拥有持续身份的 AI 提供稳定、可扩展、可恢复的生活环境。认知与行动由用户选择的 Harness 承担，Eating 管理能力、通讯、授权、状态和恢复，不建立第二套 Agent Loop 或人生记忆引擎。

## Positioning

通讯和 Harness 通过插槽接入，各插件独立注册后台与面板，通用目录只读契约和已安装清单。插件依赖公开 SDK、自带双语资源，不依赖宿主私有实现；增加插件不需要硬编码语言链或修改其他插件。

## Operating Context

全局导航为概览／机器人／Harness／提示词管理／人格管理／设置；平台分类来自目录。QQ五页签为连接配置／代理与权限／实时日志／功能测试／MCP能力，DSH含配置／会话看板。提示词保留公共和主层，各平台说明及角色合入一个可折叠条目；展开／折叠保持编辑内容、草稿和路由。会话正文滚动时导航留在页签下方，长列表自行滚动。

桌面为主要场景，390px 窄屏仍须可读可操作。侧栏底部提供原生“简体中文 / English”选择，默认中文；刷新保留、跨标签页同步，即时更新文档语言／标题／说明与面板，不重挂、不丢草稿／选区／undo，不引发保存、重启或发送。`eating.locale` 仅语言偏好，无凭据。

## Capabilities and Constraints

- QQ 支持 OneBot v11 正向统一 WebSocket，实际账号／服务状态符合要求后才显示连接成功；不支持反向或 API/event 分离。令牌只写不回显，留空保留，清除需显式保存；保存断开旧连接。
- 功能测试与 MCP 共用 Host单catalog的39项工具；工具名称和参数描述按 ID 在 QQ 自有资源本地化，schema／执行来源不变，未知 metadata 原样回退。手动副作用操作逐次确认，稳定请求 ID 防重复，未知先核对。
- 消息不建 Eating 聊天历史，只暂存有界未交接信封；可选保存到本机或仅内存。可靠送达不等于 AI 已处理，内存关闭丢失、丢弃／清空不可恢复等后果须明确。
- 实时日志只在可见页签订阅、浏览器内存有界，离开／隐藏／停用清空停止，不补发，不建后台日志缓存。
- DSH使用专属运行时、双home、工作区与固定原生会话；主与子使用各自可信分层system并共享人格，外部事件只在user。主仅列类型／委派，子按真实账号与目标使用已选QQ工具；主根据真实回执再判断，Host不代发普通输出。
- sessions.flush成功并原子ACK后才可靠交接删Host正文，忙时暂停不耗重试；当前同版会话正常恢复，不重放unknown，不承诺exactly-once。模型API连通、运行时就绪、实际任务完成和外部动作成功分别表达。
- 数据统一 `EATING_HOME`；插件代码在 plugins，QQ 账号在 bot/qq-bot，DSH 在 harness/dsh。停用保留数据，删除另需授权。本版仅一个默认 QQ 实例，多账号目录不等于多账号并行。
- 主人新增未知可执行扩展须批准，固定人格写入口不开放给模型。Host 的回环／会话／CSRF／scope／锁与工具收窄不等于 OS 沙箱。
- QQ已接入官方38公开API＋1框架quick操作，19发送段／文本／数组／单对象支持；空间／评论等未实现占位删除。复杂参数、默认值、确认及凭据清理保持用户可操作，CSP不放宽。其他 Harness、跨 Harness 无损迁移、长期记忆、自主活动、Tauri、Windows/Linux 与多账号并行未完成。

## Brand Commitments

名称统一 Eating，保留白绿“浅色标签”视觉令牌，不因双语重设计。界面支持简体中文与 English，面向阅读的仓库文档继续中文唯一正文。UI 说清当前状态、下一步、后果，不把实现约束当主叙述；“添加／启用／停用”对应真实动作，诊断和路径保留折叠入口。

用户名称、模型名、URL、Key、消息、JSON、canonical 中文变量 token 和默认提示词正文保持原样；主人内容／AI 策略不随 UI locale 翻译。完整句、插值、复数、aria、错误及日期数值统一走资源和公开 SDK。结构化错误按 code 映射，未知后端原文作为可选详情。

## Evidence on Hand

当前界面与根因见[平台折叠和固定布局记录](../changes/2026-10-29-平台提示词折叠与面板滚动修复.md)；完整构建／严格类型、984项与60项浏览器通过，包含5项当前实际SDK及双平台折叠、长会话导航、页脚末端、键盘和390／短窗绘制。原OneBot39、默认不兼容、数据与权限的证据保留在对应报告与[项目状态](../项目状态.md)。

本轮未自动部署到真实数据根、转换旧数据或执行真人／付费模型试发；历史653／855等数字及早期实际连接记录保留为当时事实，不作为当前运行状态。

## Product Principles

1. 唯一身份、一个活跃主认知控制者，主人新增能力授权和来源验证保持。
2. 通用页面只读注册契约，插件自带面板和资源，后台不依赖浏览器。
3. 保存、连接、可靠接收和 AI 处理完成分别表达，状态未知不能伪装成功。
4. 文案面向用户任务，必要风险和确认清楚，技术详情可展开。
5. 切换语言仅改变展示，不改主人内容、协议数据或执行行为。
6. 可访问性、稳定草稿与窄屏可操作优先于装饰，保留既有白绿方向。
