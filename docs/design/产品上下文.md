# Eating 产品上下文

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

负责人于 2026-10-26 从 React + TypeScript + Vite 本地网页验证进入正式开发。当前前端使用普通 CSS、lucide-react、pnpm，后台使用普通 Node.js >=24.9.0、TypeScript、内置 SQLite、ws 与官方 MCP SDK。开发 `pnpm dev` 联合运行 Host 5181 + Vite 5180，前端代理 `/api`；执行 `pnpm build` 后，以 `node apps/host/dist/main.mjs` 启动 Host 5181，同源提供 Web 构建产物、已安装插件界面资源、API 和 MCP，安装顺序见[操作说明](../operations/QQ配置与功能测试.md)。目标仍为 Windows/macOS/Linux 独立桌面应用，Tauri、真实 Harness 和 Cordis 底座尚未实现；不修改 DSH Web GUI。

## Users

Eating 主人及项目负责人在个人电脑上管理同一个 AI 的运行环境与通讯扩展。当前可配置真实 OneBot 服务、核验 QQ 连接、查看 Host 收到的消息并手动测试已支持能力；开发自动验证使用独立协议夹具，尚未验证真人 QQ 账号。

## Product Purpose

为拥有持续身份的 AI 提供稳定、可扩展、可恢复的生活环境。认知与行动由用户选择的 Harness 承担，Eating 管理能力、通讯、权限、状态和恢复。

## Positioning

模块插槽式接入：通讯平台与 Harness 可替换，模块注册自己的后台能力和管理界面。通用管理页读取注册契约，平台面板自行表达协议、配置与能力边界；新增/移除平台不应要求改其他平台或通用页面。

## Operating Context

用户已确定全局侧栏第一项“概览”、第二项“机器人”；机器人页内另有左侧分类栏，名称来自已注册插件。当前产品只有 QQ 真实插件，飞书/微信占位入口已移除。QQ 自有“连接配置 / 功能测试 / 消息记录 / MCP 能力”四页签，宿主负责通用导航、挂载和状态。

当前在独立本地浏览器中使用，桌面为主要场景，窄屏仍须能浏览和操作。保存配置与连接为两个动作，停用保留配置和数据，恢复不代表外部已在线。消息持久化与 Harness 消费分别呈现，不能把等待投递显示为 Agent 已读。

## Capabilities and Constraints

- 用户已授权正式 Host、QQ OneBot v11、预留 Harness 接口、每插件 MCP、可扩展功能测试面板与必要依赖；不再提供产品 demo，协议夹具仅用于测试目录。
- QQ 连接仅支持正向统一 WebSocket，不支持反向或 API/event 分离。实际登录与 `online/good` 核验成功后才显示已连接，支持有限重连。
- OneBot Bearer 令牌仅写入、不回显，留空保留、显式清除；原子保存后断开旧连接，再由用户手动连接。
- 功能测试从后台工具 schema 动态生成，与 MCP 共用 10 项工具目录。UI 手测发送/撤回逐次确认，保留稳定请求 ID；未知结果不自动重试。MCP 日常调用不逐次人工审批。
- 消息记录仅覆盖 Host SQLite 实际收到的消息，按实例归属去重，面板读取最近50条，工具接口另支持before游标；不是 QQ 全平台历史。
- QQ 专属 Streamable HTTP `/mcp/qq` 使用独立 Bearer，官方 SDK 握手/工具/调用已验证；仅显式查看配置才显示 MCP 令牌，尚未自动注册到 Harness。
- `EATING_HOME` 默认 `~/.eating`；QQ 自管 `bot/qq-bot`，版本化 `accounts.json` 与 `accounts/<稳定本地实例 UUID>/config.json` 保存账号结构。真实 QQ 号由登录获取，不作目录名；本版仅一个账号实例，未实现第二账号添加、切换或并行 UI，旧浏览器原型配置不自动导入。
- `HarnessGateway` 提供唯一主 sink 与持久 inbox，区分 `pending / accepted / uncertain`；当前没有实际 sink，消息等待投递，`accepted` 只表示准入。
- 新增未知可执行扩展仍需主人批准。Host 已有回环/Host/Origin 校验、HttpOnly session + CSRF、插件独立 scope、进程锁和损坏配置局部报错，不等于完整恶意插件 OS 沙箱。
- QQ 空间发布/评论不属 OneBot v11 标准，本版明确 `unsupported`，后续研究显式扩展；长期记忆、自主活动、真实 Harness、Tauri 和 Windows/Linux 验证仍未完成。
- 唯一身份、一个活跃主认知控制者、人格保护、来源验证和联系人隐私保持。Eating 不增加第二套 Agent Loop 或人生记忆引擎。

## Brand Commitments

名称统一 Eating；界面和面向阅读的文档使用中文。全局“概览/机器人”及机器人页内分类栏为用户固定结构，延续已选浅色标签方向与[界面设计规范](界面设计规范.md)。状态、错误和真实副作用须清楚，不能用占位内容暗示已接入认知或通讯。

## Product Principles

1. 通用页面只读取注册契约，不枚举平台条件分支；后台入口和前端面板分别注册。
2. 状态真实，保存成功、连接成功、消息持久化和 Agent 消费分别呈现。
3. 停用模块保留其他模块和本模块已保存配置、消息；删除数据需要另有授权。
4. 操作简单，模块自有内容与宿主通用交互边界清晰；功能测试与 MCP 共用工具实现。
5. 可访问性与稳定行为优先于装饰，敏感令牌按需显示，真实发送/撤回的手动测试明确确认。
