# DSH 原生能力与插件

适用：DSH 插件 0.9.0、Eating API4。入口：**Harness → DeepSeek Harness → 原生能力与插件**。

## 原生功能

点击“读取当前目录”检查本机系统 DSH 实际提供的模块。未配置模型时也可以读取和保存原生能力；停止状态使用短生命周期管理进程，不调用模型或创建会话。运行中直接读取当前实例。

功能可搜索，展开目标条目后：

1. 选择“启用”。首次启用的默认选择是主 Agent，随后可以改成当前目录里的任意主/子代理类型。
2. 勾选允许使用的代理。不能把启用功能保存为没有任何代理；不同类型的选择分别生效。
3. 根据需要修改原生模块 JSON。每个模块条目下是该模块的完整配置，依赖服务的配置也在同一对象内。`<stored-secret>` 表示保持原秘密；删除字段表示明确清除。保存前系统 DSH 校验模块、平台、依赖与原生配置。
4. 停止 Harness 后点击“保存原生能力与授权”，再启动 Harness。

时间上下文默认保留主/子代理、上海时区和 600000ms 间隔。其他功能初始关闭。文件能力默认开启文本/图片读取，写入和编辑初始关闭；需要时修改 `tool-fs` 的 `write`、`edit` 参数。Bash/PowerShell、文件搜索、工作目录、后台任务、网页、技能、提醒、目标、待办、结构化提问和文件交付都使用官方原生模块。

模块存在不代表远端服务已经配置。网页搜索需要此 Eating 实例自己的原生搜索提供商和鉴权，未配置会返回真实错误；不会借用主 DSH 的账号或环境密钥。网页获取与关键词搜索是不同工具，当前默认fetch=true/search=false。若网页获取报non-public IP且DNS返回198.18/15，属于原生HTTP公网地址策略与TUN/Fake-IP的冲突；普通网络可通也可能在请求前被拒绝，原生参数没有allowFakeIp开关，详见[现场诊断](../reports/2026-11-01-原生网页Fake-IP拦截与图片声明诊断.md)。终端和文件能力使用实际 DSH 权限与沙箱策略，代理范围选择不构成 OS 沙箱。

“草稿未保存”“已保存，待启动”“等待代理创建”和“已挂载”是不同状态。页首同时显示已保存版本与运行中应用版本。子代理尚未创建时没有实际挂载记录，不会为了检查状态唤醒模型。运行中修改按钮禁用，请先停止 Harness。

## DSH 插件

“DSH 插件”同时显示真实 Bundle 和 Loader 模块。来源包括系统安装、Eating 专属 Profile，以及官方目录中尚未安装的条目。搜索只过滤目录；“显示基础组件”展开不可移除的内核、Eating 桥和官方 Web 组件，并说明原因。

插件作用于整个 DSH 实例。可以分别启用/停用 Bundle，以及实际可管理的模块。禁用不会卸载，卸载也不会删除插件资料。Bundle 和模块可能受依赖或更高优先级设置影响，读取当前目录可以查看真实结果，不以保存成功代替已运行。

模块配置不回显原值或密钥。配置编辑器初始空白：留空保持；填写 JSON 对象并“保存此模块配置”会完整替换原配置，`{}` 表示明确清空。失败或结果未知时先重新读取目录核对，不重复写入。

## 检查并安装

安装区接受 DSH 原生管理器支持的 npm 包及版本、本机绝对目录、Git 地址或 tarball：

1. 输入“插件来源”，点击“检查来源”，核对返回的包名、版本和接受状态。
2. 勾选信任该来源代码，再点击“确认安装插件”。检查本身不等于安装。
3. 安装由官方 PluginManager 和 pnpm 完成，安装后保持停用。不要把包下载/安装结果当成已挂载成功。
4. 若原生管理器报告依赖需要安装脚本，页面列出确切包名；只有主人再勾选脚本许可才会重试安装。
5. 核对目录后单独启用插件，再到“插件工具授权”分配工具。

安装、启停、配置、卸载都要求 Harness 完全停止；其他页面也不能在管理进程活动时启动同一实例。安装失败只显示原生结构化原因，不回显 pnpm 原始输出或秘密。结果未知时重新读取目录，不自动重做。卸载需要先停用并再次确认，仅删除插件代码，保留资料。

## 插件工具授权和 MCP

实例级插件可能注册工具。插件启用不会把工具自动授给所有代理；在“插件工具授权”展开精确工具名，选择允许使用的代理，再保存。

授权同时记录工具名称与 schema 指纹。插件新增工具不会自动开放；工具结构变化后显示“需重新授权”。消失的工具显示过期记录，可移除旧授权。实际模型可见集合和最终调用守卫都检查当前授权，不能只靠隐藏按钮限制执行。

运行区展示真实代理挂载过的 MCP 工具数量。Eating MCP 仍在“MCP”页面管理，不在 DSH 面板维护第二份权限。QQ 通讯工具仍受账号、会话、目标和消息/图片引用范围控制。

## 草稿、隐藏和错误

语言切换保留功能 JSON、代理选择和草稿，不触发重新读取或保存。功能配置与连接配置独立保存。切换页签或离开时停止本页读取，清理插件配置输入和安装来源；已向后台提交的写操作不会因关闭页面而伪称未发生。

遇到版本冲突或未知结果，先点“读取当前目录”。草稿仍保留；若已保存版本变化，点击“放弃草稿并载入已保存配置”后重新编辑。原文件损坏或版本不支持时明确报错，不自动转换、补字段或覆盖。

本功能使用 Eating 自己的数据和系统 DSH 安装，不修改主人主 DSH、当前 DSH GUI、主 Profile 或凭据。实现决策见[ADR-0021](../decisions/ADR-0021-DSH原生能力与插件管理.md)，实际验证范围见[本轮报告](../reports/2026-11-01-DSH原生能力与插件管理验证.md)。
