# MCP、插件与表情包使用说明

适用：Eating0.18.0／plugin-sdk4.8.0／stickers0.2.0，插件API4；默认开放与主人例外以[ADR-0035](../decisions/ADR-0035-会话代理自主处理与默认开放可配置.md)为准。当前可信图片传输按[ADR-0046](../decisions/ADR-0046-可信图片传输与生图尺寸.md)实现，整体验证进行中、服务器尚未更新；最终证据见父代理创建的[本轮报告](../reports/2026-11-04-官方记忆与插件能力更新验证报告.md)。

## 插件管理

侧栏“插件”汇总通讯、Harness和能力三类插件。QQ是通讯插件，DSH是Harness插件，表情包是能力插件。机器人和Harness仍保留各自业务入口；插件列表可进入每项自己的配置面板。

当前支持从本机可信的已构建插件目录安装。点击“安装插件”，填含 eating-plugin.json 的产物目录，先预览名称、类型、版本、体积和摘要，再确认安装。预览不会运行插件；确认会加载该插件代码。当前不提供在线市场或任意仓库自动安装。

同ID的新版本可通过同样流程更新，包版本内容不可原地替换。启用／停用、连接／断开和卸载含义不同；卸载移除代码激活记录和工具注册，保留数据，重装同一插件可继续使用。

## 直接接入 MCP

侧栏“MCP”中选择“添加直接接入”。

- 本地 stdio：填写命令，每行填写一个参数；参数按原样传递，不经 shell。需要的环境变量逐项填写。保存只保存配置，点击连接才会启动进程。
- 远程 Streamable HTTP：填写完整服务地址及需要的请求头。认证建议放请求头；已保存的环境变量、请求头值和URL查询值不回显，编辑留空保留，明确删除才移除。

连接成功后显示服务发现的真实工具。新功能来源默认“全部开放”（all），已启用且connected时全部当前及未来工具／Agent类型自动可用。主人可编辑为“自定义”（custom），选择精确代理类型与工具并保存；新增工具／类型不会自动取得该例外source的权限，任一空名单关闭访问。恢复“全部开放”后重新跟随目录；其他新source仍默认all。accessPolicy显示当前策略，grant为当前目录的有效摘要。

直接服务和插件来源都显示在同一目录。QQ等通讯插件已有专门会话权限，需在来源插件面板设置，不能通过MCP页获取不受范围约束的QQ工具。插件提供的MCP不能单独删除，应到插件页停用或卸载来源插件。

策略保存、来源新增／连接／断开、工具目录变化及能力插件生命周期变更使用一次性重挂事务：撤lease并停受影响Harness，await来源／目录变更完成，仅对原connected、同一实例且仍启用的Harness恢复一次。原stopped／error不启动，owner stop／disable优先，失败不重试、不重放unknown；harnessRemounts返回reconnected／failed／cancelled。连接成功不代表所有工具业务动作已经验证，手机ADB／浏览器的具体服务、设备和权限由用户自己配置，Eating不会自动安装或连接未指定的第三方服务。

直接连接保存只收连接与秘密，不接受grant／policy；文件保持严格schema2，旧schema1拒绝且保留。权限单独用严格save-grants保存{id,expectedRevision,mode:all}或{id,expectedRevision,mode:custom,agentTypeIds,toolNames}，目录CAS为direct＋policy revision。策略在host:mcp-access-policies严格schema1／revision／policies保存，旧host:capability-grants不读／写／迁移／删。目录变化／版本冲突先保草稿再重读核对，不隐式推进CAS。direct在途撤权可能失去transport并使source error，需主人显式connect；不自动重放未知动作。

## 管理表情包

进入“插件 → 表情包”独立面板。可从本机选择PNG、JPEG、GIF或WebP，单图最多5MiB，填写描述和标签后添加。

描述建议包含画面内容、情绪和使用场景，例如“猫咪举起前爪，开心打招呼，适合问好或轻松回应”。标签可写“开心”“招呼”“猫”，同义标签尽量统一。列表按描述关键词和多标签筛选，标签采用同时匹配。每页默认20条、最多50条；列表只读元数据，不逐张加载图片。点击单项预览时才取图。

支持编辑描述和标签、确认删除。同图按文件内容去重，重复添加不会覆盖原描述和标签。发生版本冲突时保留草稿，先显式刷新再决定是否修改。清空Host消息队列不删除表情库，卸载插件也保留收藏。

当前资源库上限1000项、总图片256MiB、2048种标签；每项最多32标签、每标签32字符、描述最多1000字符。达到上限会明确拒绝写入而不淘汰已有资料。

## 让 AI 使用表情包

启用并连接表情包后，默认all下全部功能工具自动供main及所有Agent类型使用；主人保存custom例外后按当前类型／工具名单生效，也可恢复all。AI工具包括：

| 工具 | 用途 |
| --- | --- |
| sticker_list | 按描述／标签筛选分页元数据 |
| sticker_list_tags | 查看标签及条目数量 |
| sticker_get | 获取单张预览和可发送引用 |
| sticker_add | 把当前获准会话消息中的图片收藏，填写描述／标签 |
| sticker_update | 使用当前revision修改描述／标签 |
| sticker_delete | 使用当前revision删除收藏 |

QQ执行代理需同时拥有对应QQ发送工具；收藏收到图片还需保留“查看本会话图片”权限。主Agent没有QQ当前消息范围，不能凭任意URL或路径调用收藏；它可以直接使用已连接表情服务的列表与预览工具。功能默认开放不生成消息／图片引用。

AI可以先看描述和标签列表决定候选，需要确认时再取图。图片内容通过get的原生image块送给模型，因此要查看原图仍需模型支持图像输入；模型图片能力与功能MCP可用性分别判断。AI是否使用表情取决于主人提示词、当前上下文和模型决策，安装插件不保证每次聊天都会发图。

取图返回 `eating-asset://stickers/<assetId>` 引用，AI将工具实际返回的sendable消息段交给QQ发送工具。AI预览仍使用Base64及标准image块；发送通过公开getAsset取得当前授权的图片lease，来源插件自验证固定blobs，Host复查来源实例、调用者lease、scope、signal与实际字节／SHA-256／MIME。QQ优先使用主人确认且逐图本地验证通过的共享文件映射，否则发送前选Base64；不自动证明OneBot已读取远端文件，不在unknown后换传输再发。模型只提供opaque资源引用，不能传入任意路径、URL或映射设置；具体配置见[QQ说明](QQ配置与功能测试.md)。表情包收藏在本插件库，和QQ账号自带的“收藏表情”不同，不依赖OneBot提供收藏接口。

写入和发送是独立动作，均需核对工具回执。调用需要稳定request_id；超时或未知结果不要换一个ID盲目重发。任务结束、断开／停用／卸载或工具拓扑变化后，旧连接和在途资源须重新检查有效许可，不能继续用旧scope发送／收藏。
