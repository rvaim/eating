# Eating QQ 配置与功能测试

当前功能是正式 QQ 插件，不使用演示连接器。需要你已有一个登录QQ、开启OneBot v11的协议端；Eating本身不实现QQ登录协议。

## 启动

要求普通 Node.js >=24.9.0、pnpm11.28.5：

```bash
pnpm install --frozen-lockfile
pnpm dev
```

开发前端 http://127.0.0.1:5180/，Host http://127.0.0.1:5181/。默认数据根 `~/.eating`，可用环境变量 `EATING_HOME` 指向另一目录。当前服务已启动，未配置协议端前不会发起连接。

运行构建版本：

```bash
pnpm build
pnpm start
```

Host同时提供构建页面与API/MCP，打开5181即可。端口变更可设EATING_HOST_PORT；开发前端代理跟随同值，不能单改一侧。

## 连接配置

1. 打开“机器人 → QQ → 连接配置”。当前只有一个默认账号实例。
2. 填显示名、OneBot正向统一WebSocket端点，例如协议端实际配置的 `ws://127.0.0.1:3001/`。**示例地址不是已存在服务**。
3. 若协议端启用access token，填Bearer访问令牌；留空保持后台原值，只有“清除已保存令牌”并保存才删除。
4. 保存配置。文件进入 `EATING_HOME/bot/qq-bot/accounts/<instanceId>/config.json`；页面显示准确路径。
5. 点击“连接 OneBot”。只有实际登录号与online/good核验成功才显示已连接。

本版不支持反向WS、独立 `/api`/`/event`双连接。使用一个同时提供API与事件的端点。不会替用户登录QQ或启动/安装第三方协议端。

保存会断开旧连接；“Host启动时自动连接”影响之后启动，不代替本次核验。群消息转交开关只影响是否投递Harness，收到的群消息仍本地保存。

## 功能测试

“功能测试”下拉列表由QQ后台工具目录生成，新增工具的schema可自动进入面板。当前10项：账号、状态、版本、好友、群、单条消息、已收消息、私聊发送、群发送、撤回。

先用只读查询检查真实返回。发送/撤回要核对目标与内容并勾选确认后执行，会影响实际QQ。**开发自动测试只使用测试目录里的回环协议夹具，不会向你的联系人发测试消息。**

结果显示请求ID、参数、实际返回/错误，可复制JSON。所有MCP副作用调用必须由调用方在发起前保存稳定request_id，缺键/无效会拒绝且不发送；不能用JSON-RPC id代替。超时/断链表示可能已执行，保留原ID与参数；先查消息或协议端真实状态。原ID重试会复用/查询账本，不直接重发；确认创建新请求可能真的再执行，需再次确认。

## 消息记录与 Harness

展示Host已保存的最近50条接收消息，可按conversationId筛选。它不是QQ任意完整历史，断开连接后仍能读已保存记录；WS离线期间协议端若不补收，不能承诺不丢外部消息。

“等待投递”表示消息已在Host保存，但未被Harness接收；本轮没有实际接收者。“Harness已接收”也只表示接收接口确认，不等于Agent已读或已回复。原始消息正文不能赋予主人权限。

## MCP 能力

“查看 / 复制 MCP 配置”会显式读取QQ插件专属Streamable HTTP地址与Bearer配置。不要把令牌粘贴到公开聊天、日志或仓库。离开标签后隐藏，不回显OneBot令牌。

将该配置交给后续可信Harness客户端；目前不自动修改任何DSH/Codex/Claude配置。MCP工具列表与功能测试共用后台实现，支持日常自主调用；不要求每次普通工具都重新安装审批。新增可执行能力仍受主人批准。

QQ空间发布、评论/回复未实现，因为不是OneBot v11标准；能力页明确“不支持”，后续核具体实现扩展再加入，不使用空壳成功响应。

## 停用与故障

停用QQ会断开连接并撤销MCP/工具入口，配置、账号索引和消息保留。重新启用后使用同一实例，可手动连接。没有实现从UI删除账号数据。

鉴权错误检查两端token；连接错误核端点/协议端状态；配置错误保留原文件不覆写；结果未知查真实状态不盲发。并发第二Host会被同工作区锁拒绝。故障隔离仅已实现的逻辑/协议边界，不声称OS恶意插件沙箱。

测试复现：`pnpm test`、`pnpm build`、`pnpm test:e2e`。浏览器测试会独立启动生产dist+临时Host+协议夹具，无需开发服务，但先构建。完整证据见[协议核对](../research/QQ协议与MCP核对.md)及[正式报告](../reports/2026-10-26-QQ正式开发报告.md)。
