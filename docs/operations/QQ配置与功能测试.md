# Eating QQ 配置与功能测试

Eating 使用正式 QQ OneBot v11 插件，需要已有登录 QQ、开启 OneBot v11 的协议端；Eating 不实现 QQ 登录协议。当前为应用 0.3.0、公开 SDK 1.2.0、QQ 0.4.0，`apiVersion: 1`。本轮真实迁移与安装已完成，实际 API 确认 QQ connected、日志能力可用、9 个工具且无历史工具，设置读取 200。

## 构建、安装与启动

要求普通 Node.js >=24.9.0、pnpm 11.28.5。Host 按已安装产物加载插件，不扫描仓库源码自动提供 QQ。新增公开契约后先完整构建 SDK、QQ、Host 与 Web：

```bash
pnpm install --frozen-lockfile
pnpm build
```

**停止使用目标数据根的 Host**，再安装并检查：

```bash
pnpm plugin install plugins/communication/qq/dist
pnpm plugin list
```

安装 CLI 与 Host 必须使用同一个 `EATING_HOME`，默认 `~/.eating`。安装器校验 SDK/API 和资源哈希，通过暂存发布、激活索引选版本；索引提交前失败保留旧版本，提交后的目录 fsync 失败返回 unknown 并保留已激活版本，需核对实际索引。插件代码与账号配置分开，见[工程结构](../architecture/工程结构与插件发布.md)。本轮不从第三方市场下载或发布 npm。

开发联合启动：

```bash
pnpm dev
```

开发页面 [Eating](http://127.0.0.1:5180/)与 [Host](http://127.0.0.1:5181/)分别在 5180/5181。生产运行：

```bash
node apps/host/dist/main.mjs
```

Host 同源提供 Web、API/MCP 和插件界面资源。端口由 `EATING_HOST_PORT` 指定，开发代理跟随同值；纯 Vite 预览不提供 Host 能力。本轮已停旧服务，在锁内迁移并安装 QQ 0.4.0，新开发 job 为 `bash-3a6f5eac4f134a3f`。实际 API 确认 connected、logsSupported=true、工具 9 且无历史工具，设置接口 200；未交接信封和账号配置/发送账本标识保持，见[本轮报告](../reports/2026-10-27-投递设置与无历史队列验证报告.md)。

## 升级与卸载

本轮涉及 Host/Web、两个 SDK 与 QQ，应执行完整 `pnpm build`，停止 Host 后安装 QQ 产物再启动，不能只替换界面。之后仅改 QQ 且已有相容 SDK 产物时，可用 `pnpm build:plugin`。版本代码位于 `plugins/<pluginId>/versions/<version>`，由 `plugins/installed.json` 激活；不支持运行中热更新或零中断升级。

首次使用新 Host 打开旧库会保全所有未交接信封，清除旧聊天正文及原始事件副本，原库压缩，不另外备份聊天。旧积压超过默认上限仍保留、提示超容量并拒新。发送防重复账本和账号配置保留；已清除的历史不会因回退代码恢复，旧 Host 也不能直接操作迁移后的新表。详细边界见[数据规范](../technical/数据目录与账号实例.md)。

卸载先停止 Host，再执行：

```bash
pnpm plugin uninstall qq
pnpm plugin list
```

重启后撤销 QQ 后台、页面和工具/MCP 入口，保留账号配置、未决动作及本地暂存模式的未交接队列。仅内存队列在 Host 退出时丢失，不能承诺卸载停机后恢复。UI“停用/恢复”只控制插件运行，与安装/卸载、清空队列分别处理。

## 连接配置

1. 打开“机器人 → QQ → 连接配置”。本版只有一个默认账号实例。
2. 填显示名、OneBot 正向统一 WebSocket 端点，例如协议端实际配置的 `ws://127.0.0.1:3001/`；示例地址不表示已有服务。
3. 若协议端启用 access token，填 Bearer 访问令牌。留空保留后台原值，勾选“清除已保存令牌”并保存才删除；公共配置不回显令牌。
4. 保存配置，文件进入 `EATING_HOME/bot/qq-bot/accounts/<instanceId>/config.json`，页面显示实际路径。
5. 点击“连接 OneBot”。实际登录号与 `online/good` 核验成功后才显示已连接。

保存会断开旧连接，“Host 启动时自动连接”影响之后启动，不代替本次核验。本版只支持一个同时承载 API/事件的正向统一端点，不支持反向 WS 或 `/api`、`/event` 双连接，不替用户安装协议端或登录 QQ。

转交选项决定收到的私聊/群消息是否加入 Harness 队列。关闭转交不会停止 OneBot 接收；未转交消息不保存正文。日志页可见时仍可观察实时接收事件，离开即清空。

## 全局设置：消息投递

从全局侧栏进入“设置 → 消息投递”。这些是 Host 全局设置，与 QQ 账号配置分开，两个设置分类的草稿一起保存。

| 页面字段 | 默认值 | 行为 |
| --- | --- | --- |
| 聚合静默时间 | 500 ms | 同会话新消息到达后重新计时；0 表示不等静默 |
| 最长聚合等待时间 | 2000 ms | 从同会话首条入队固定计时，不能小于静默时间 |
| 单批消息上限 | 10 条 | 达到即提前投递，不能超过队列消息上限 |
| 批次目标大小 | 32 KB | 页面 1 KB = 1024 字节，即默认 32 KiB；不能超过队列容量 |
| 投递超时 | 15000 ms | 等接收端确认的时限，超时转结果待核对 |
| 拒收重试间隔 | 10000 ms | 仅对接收端明确拒收进行有限重试 |
| 最大投递尝试次数 | 5 次 | 包含首次；耗尽后保留正文待核对 |

只在同一 `conversationId` 聚合，不跨会话混批。静默、最长等待、条数或字节任一条件达到时投递；连续新消息不会无限推迟首条的最长等待。批次目标是软阈值，单条超过目标时独立投递、不拆分，仍受队列总容量约束；它不是模型 token 数、模型请求次数或上下文长度。只提供旧单条交接接口的接收端仍按批内消息逐条调用。

只有接收端同时返回 `accepted: true`、`durable: true` 与非空 `receiptId`，并完成本地确认，才计为“已可靠交接”并删除正文。它表示接收端接管，不表示模型已读或动作完成。超时、异常、凭据不足、进程中断均保留“结果待核对”，不自动补投；明确拒收才按设置重试。当前没有真实 Harness 或 DSH 插件，测试只使用独立接收端。

## 全局设置：队列与存储

打开“设置 → 队列与存储”：

| 页面字段 | 默认值 | 可选项或说明 |
| --- | --- | --- |
| 队列存储方式 | 本地暂存（重启恢复） | 可改为“仅内存（重启丢失）” |
| 队列消息上限 | 1000 条 | 计算全部尚未交接消息，包含投递中和结果待核对 |
| 队列容量上限 | 10 MB | 页面 1 MB = 1 MiB = 1048576 字节，默认 10 MiB |
| 队列溢出处理 | 拒绝新消息，保留现有队列 | 可改为“丢弃最旧待投递消息” |

本地暂存只保存当前未交接的规范化信封，可在重启后恢复；仅内存模式的正文不进 SQLite，Host 退出或重启就丢失未交接内容。运行中切换会迁移现有队列；保存失败保留原模式、设置和正文。

队列容量按信封 UTF-8 JSON 实际字节，**不是整个 SQLite 文件大小上限**。数据库还保存去重小元数据、设置、令牌与动作账本。原始 OneBot raw、额外 text 副本、未转交正文和终态聊天历史均不保存。

拒新时，新消息正文不入队，页面“已拒绝入队”和“最近队列错误”显示实际结果；可见实时日志带 `queueAdmission` 区分 queued / not-forwarded / rejected。收到不等于排队成功。丢旧只允许移除最旧 pending；正在投递、结果待核对受保护，没有可移除消息时仍拒新。单条大于总容量直接拒绝，不先删空原队列。

保存缩容时，拒新策略若当前不满足则 409；丢旧策略可原子裁剪 pending，但保护状态仍超容量时整次 409，不先删除一部分再报错。旧库积压超默认容量不会启动时自动裁剪，可先可靠交接或按明确策略处理。

“队列状态”显示待投递、正在投递、结果待核对、消息总数、字节占用、已可靠交接、已拒绝入队、已丢弃、短期去重标识、超容量与最近错误。这是最近一次读取的实际快照，点击“重新读取设置”更新。

保存冲突返回 409 时，原草稿保留。先核对提示，再点击“重新读取设置”，确认放弃两个分类未保存更改后载入最新值；“放弃更改”只恢复最近读取的草稿，不修改后台。

清空步骤：

1. 在“队列与存储”点击“清空队列”，阅读正文不可恢复提示。
2. 勾选“我已了解，确认清除这些正文”，再点“确认清空队列”。
3. 若存在正在投递消息，后台返回 409，重新读取状态后处理。成功则清除尚未交接及待核对正文、累计丢弃数；账号配置、发送账本与短期哈希保留，不把前端未保存草稿顺带保存。

## 功能测试与 MCP

QQ“功能测试”下拉从后台目录生成，当前 **9 项**：获取登录账号、检查协议端状态、获取协议端版本、读取好友列表、读取群列表、读取一条消息、发送私聊消息、发送群消息、撤回消息。“读取一条消息”调用 OneBot 标准 `get_msg`，是否可查由协议端保存范围决定，不从 Eating 历史库查询。

先用只读工具检查真实返回。发送/撤回需核对目标、正文并勾选确认，会影响实际 QQ；开发自动测试仅用独立回环协议夹具，不向联系人发测试消息。结果包含请求 ID、参数和实际返回/错误，可复制 JSON。

所有 MCP 副作用调用必须事先保存稳定 `request_id`；缺键/无效键拒绝且不发送，JSON-RPC id 不能替代。超时/断链表示可能已执行，应保留原 ID 与参数，先查协议端真实状态。原 ID 同参数重用账本结果或返回 unknown，不直接重发；创建新请求可能再次执行。

“查看 / 复制 MCP 配置”显式读取 QQ 专属 Streamable HTTP 地址与独立 Bearer，离开页签隐藏；不回显 OneBot 令牌，不自动修改 DSH/Codex/Claude 配置。已批准工具的普通调用不要求每次重新审批，新增可执行能力仍需主人批准。QQ 空间发布、评论/回复非 OneBot v11 标准，当前明确不支持。

## 实时日志

QQ 四页签中的“实时日志”仅在页签打开、插件启用且支持日志、页面可见时订阅 Host SSE。默认最近 100 条，可选 50/100/200/500/1000，只留浏览器组件内存；缩小立即裁剪，增大不补发，选择不写浏览器持久存储或后台配置。

隐藏、离开、pagehide、关页或停用时停止订阅并清空，回到可见后从新事件开始。后台无日志缓存、文件或历史快照，无查看者不执行日志源 factory 或日志定时器。“清空显示”只清前端列表并继续监听，与全局“清空队列”不同。

行内显示时间、级别、私聊/群聊、账号/实例、会话、发送者、消息 ID 与最多 500 字纯文本预览；群号仅取明确 groupId。元数据的准入结果表明消息是否入队，不把拒收写成排队。认证字段不进入日志，预览中的当前 OneBot 令牌会替换，不承诺识别正文里所有秘密；日志通道“实时接收中”不等于 QQ 账号在线。

手动核验顺序：保持日志页签可见，使用另一个 QQ 给机器人发消息，观察新事件自动出现；改变保留条数和清空显示；隐藏或离开后回到空列表；关闭或停用后核对 Host viewer 归零。可从全局队列状态核对正常接收/准入，不需要聊天历史页面。Eating 不自动向真人发测试消息。

Host 沿用会话鉴权、ownerSession/Host/Origin 检查，最多 8 个查看者；背压断开后客户端重连，每个打开流有 15 秒注释心跳，关闭即清理，重连不回放。上一轮边界证据见[日志变更](../changes/2026-10-27-QQ按需实时日志.md)。

## 停用、故障与验证

停用 QQ 断开连接并撤销工具/MCP，保留配置、账号索引、当前未交接队列与动作账本；内存队列仍受 Host 退出丢失约束。重新启用使用原实例，可手动连接，不提供 UI 删除账号配置。

鉴权错误核对两端 token；连接错误核对端点/协议端；配置损坏保留原文件不覆写；结果未知先查真实状态；同数据根第二 Host 被锁拒绝。队列拒收、超容量、设置冲突、在途清空失败均显示真实错误，不假报成功。这些是逻辑/协议边界，不等于 OS 沙箱。

复现入口为 `pnpm build`、`pnpm test`、`pnpm test:e2e`。浏览器会独立启动生产产物、临时 Host 与协议夹具。本轮最终完整构建/严格类型、Vitest 16 文件 387/387、浏览器 13/13 通过；Gateway 49 项含新增 16 项真实 SQLite 本地提交故障回归，保存失败只重试本地、不重复 sink。设置并发冲突另经独立只读复核 PASS。4 张桌面/390px 设置截图已实际读图检查，pageerror=0、无溢出、历史页签 0、MCP 9；真实迁移/安装、QQ connected 和设置 200 已核验，见[项目状态](../项目状态.md)与[验证报告](../reports/2026-10-27-投递设置与无历史队列验证报告.md)。旧正式 QQ、重组、实时日志报告保留当时功能与数字，不改写历史记录。
