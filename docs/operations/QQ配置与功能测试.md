# Eating QQ 配置与功能测试

Eating 使用 QQ OneBot v11 插件，需要已登录 QQ 并开启 OneBot 的协议端；Eating 不实现 QQ 登录协议。本轮主应用／Host／Web 0.8.0、plugin-sdk 1.6.0、ui-sdk 1.7.0、QQ 0.8.0、DSH 0.3.1，apiVersion 仍为 1。主人手动功能测试保留官方 38 公开 API 与 1 框架 quick 操作，共 39 项；受控子代理只开放各类型实际允许且主人勾选的工具。未实现空间／评论／反向连接占位已删除，实际可用性仍取决于协议端实现及 QQ 权限。完整标准目录见[OneBot 覆盖清单](../technical/OneBot标准功能覆盖.md)。

## 构建、安装与启动

要求普通 Node.js >=24.9.0、pnpm 11.28.5。Host 按已安装产物加载插件，不扫描仓库源码自动提供 QQ。新增公开契约后先完整构建 SDK、QQ、Host 与 Web：

```bash
pnpm install --frozen-lockfile
pnpm build
```

**停止使用目标数据根的 Host**，再安装并检查：

```bash
pnpm plugin install plugins/communication/qq/dist
pnpm plugin list
```

安装 CLI 与 Host 必须使用同一个 `EATING_HOME`，默认 `~/.eating`。安装器校验 SDK/API 和资源哈希，通过暂存发布、激活索引选版本；索引提交前失败保留旧版本，提交后的目录 fsync 失败返回 unknown 并保留已激活版本，需核对实际索引。插件代码与账号配置分开，见[工程结构](../architecture/工程结构与插件发布.md)。本轮不从第三方市场下载或发布 npm。

开发联合启动：

```bash
pnpm dev
```

开发页面 [Eating](http://127.0.0.1:5180/)与 [Host](http://127.0.0.1:5181/)分别在 5180/5181。生产运行：

```bash
node apps/host/dist/main.mjs
```

Host 同源提供 Web、API／MCP 与插件资源，端口由 EATING_HOST_PORT 指定，开发代理跟随；纯 Vite 不提供 Host 能力。OneBot 完整目录阶段 QQ 0.7.0 的部署、39 工具和原 6 条未交接数据核对是[历史报告](../reports/2026-10-28-OneBot完整MCP验证报告.md)的证据。本轮 0.8.0／DSH 0.3.1 已完成本地原生验证；真实数据根是否安装新版、QQ 是否连接、所选提供商是否可用，须分别核对[项目状态](../项目状态.md)与[本轮报告](../reports/2026-10-28-多代理与会话看板验证报告.md)，不能据源码或夹具结果认定已上线。

## 升级与卸载

本轮涉及 Host／Web、两个 SDK、QQ 与 DSH，应执行完整 `pnpm build`，停止 Host 后安装所用 QQ／DSH 新产物再启动，不能只替换界面。之后仅改 QQ 且已有相容 SDK 产物时，可用 `pnpm build:plugin`。版本代码位于 `plugins/<pluginId>/versions/<version>`，由 `plugins/installed.json` 激活；不支持运行中热更新或零中断升级。

首次使用新 Host 打开旧库会保全所有未交接信封，清除旧聊天正文及原始事件副本，原库压缩，不另外备份聊天。旧积压超过默认上限仍保留、提示超容量并拒新。发送防重复账本和账号配置保留；已清除的历史不会因回退代码恢复，旧 Host 也不能直接操作迁移后的新表。详细边界见[数据规范](../technical/数据目录与账号实例.md)。

卸载先停止 Host，再执行：

```bash
pnpm plugin uninstall qq
pnpm plugin list
```

重启后撤销 QQ 后台、页面和工具/MCP 入口，保留账号配置、未决动作及本地暂存模式的未交接队列。仅内存队列在 Host 退出时丢失，不能承诺卸载停机后恢复。UI“停用/恢复”只控制插件运行，与安装/卸载、清空队列分别处理。

## 连接配置

1. 打开“机器人 → QQ → 连接配置”。本版只有一个默认账号实例。
2. 填显示名、OneBot 正向统一 WebSocket 端点，例如协议端实际配置的 `ws://127.0.0.1:3001/`；示例地址不表示已有服务。
3. 若协议端启用 access token，填 Bearer 访问令牌。留空保留后台原值，勾选“清除已保存令牌”并保存才删除；公共配置不回显令牌。
4. 保存配置，文件进入 `EATING_HOME/bot/qq-bot/accounts/<instanceId>/config.json`，页面显示实际路径。
5. 点击“连接 OneBot”。实际登录号与 `online/good` 核验成功后才显示已连接。

保存会断开旧连接，“Host 启动时自动连接”影响之后启动，不代替本次核验。本版只支持一个同时承载 API/事件的正向统一端点，不支持反向 WS 或 `/api`、`/event` 双连接，不替用户安装协议端或登录 QQ。

转交选项决定收到的私聊/群消息是否加入 Harness 队列。关闭转交不会停止 OneBot 接收；未转交消息不保存正文。日志页可见时仍可观察实时接收事件，离开即清空。

## 主人、管理员与代理类型权限

在 QQ 面板的身份与代理权限区域配置多个主人 QQ 和管理员 QQ。号码按规范化十进制、安全整数范围校验，每类最多 100 个；同一号码同时出现时以主人身份为准。保存使用 policyRevision 做版本冲突检查，不重连 OneBot，也不把页面尚未保存的草稿用于授权。收到消息时按真实登录账号和发送者核对；正文、昵称或平台 sender.role 自称主人不能改配置，消息来源仍是 external。

QQ 注册 `qq.private` 和 `qq.group` 两类执行者。可勾选工具只来自各类型真实 availableTools，默认是适用的只读工具加本类型明确发送。凭据查询、无关全局工具，以及难以固定目标的通用 send_msg 和 quick 操作不提供给子代理；主人“功能测试”的 39 项标准目录保持。

主 Agent 只列出可用类型并按真实 context_ref 委派，平台动作由对应子代理执行；子代理不能自行换账号、改会话／目标或声明任意消息／资源引用。每次工具调用会再次核对当前启用列表和会话 scope；停用、断开与任务结束撤销任务令牌。子结果回主时包含 Host 本任务真实回执，普通文本或委派接纳不等于 QQ 已发送。未知动作先核对，不换 request_id 盲目重发。

通用提示词和人格中的主人／管理员变量由本地受信配置生成，支持多个号码。所有代理共用同一启用人格；可以全部停用，此时预览明确保留空人格层。旧群私消息模板若已保存，继续作为 user 输入保留，不能用于给外部消息增加 system 权限。提示词迁移细节见[Harness 设计](../architecture/Harness适配.md)。

## 全局设置：消息投递

从全局侧栏进入“设置 → 消息投递”。这些是 Host 全局设置，与 QQ 账号配置分开，两个设置分类的草稿一起保存。

| 页面字段 | 默认值 | 行为 |
| --- | --- | --- |
| 聚合静默时间 | 500 ms | 同会话新消息到达后重新计时；0 表示不等静默 |
| 最长聚合等待时间 | 2000 ms | 从同会话首条入队固定计时，不能小于静默时间 |
| 单批消息上限 | 10 条 | 达到即提前投递，不能超过队列消息上限 |
| 批次目标大小 | 32 KB | 页面 1 KB = 1024 字节，即默认 32 KiB；不能超过队列容量 |
| 投递超时 | 15000 ms | 等接收端确认的时限，超时转结果待核对 |
| 拒收重试间隔 | 10000 ms | 仅对接收端明确拒收进行有限重试 |
| 最大投递尝试次数 | 5 次 | 包含首次；耗尽后保留正文待核对 |

只在同一 `conversationId` 聚合，不跨会话混批。静默、最长等待、条数或字节任一条件达到时投递；连续新消息不会无限推迟首条的最长等待。批次目标是软阈值，单条超过目标时独立投递、不拆分，仍受队列总容量约束；它不是模型 token 数、模型请求次数或上下文长度。只提供旧单条交接接口的接收端仍按批内消息逐条调用。

只有接收端同时返回 `accepted: true`、`durable: true` 与非空 `receiptId`，并完成本地确认，才计为“已可靠交接”并删除正文。它表示接收端接管，不表示模型已读或动作完成。超时、异常、凭据不足、进程中断均保留“结果待核对”，不自动补投；明确拒收才按设置重试。DSH 已实现可靠入箱与原生子代理，并经本地模型夹具及独立产物验证；实际模型由主人在独立面板配置，当前就绪和任务状态单独核对，不沿用旧版空配置结论。

## 全局设置：队列与存储

打开“设置 → 队列与存储”：

| 页面字段 | 默认值 | 可选项或说明 |
| --- | --- | --- |
| 队列存储方式 | 本地暂存（重启恢复） | 可改为“仅内存（重启丢失）” |
| 队列消息上限 | 1000 条 | 计算全部尚未交接消息，包含投递中和结果待核对 |
| 队列容量上限 | 10 MB | 页面 1 MB = 1 MiB = 1048576 字节，默认 10 MiB |
| 队列溢出处理 | 拒绝新消息，保留现有队列 | 可改为“丢弃最旧待投递消息” |

本地暂存只保存当前未交接的规范化信封，可在重启后恢复；仅内存模式的正文不进 SQLite，Host 退出或重启就丢失未交接内容。运行中切换会迁移现有队列；保存失败保留原模式、设置和正文。

队列容量按信封 UTF-8 JSON 实际字节，**不是整个 SQLite 文件大小上限**。数据库还保存去重小元数据、设置、令牌与动作账本。原始 OneBot raw、额外 text 副本、未转交正文和终态聊天历史均不保存。

拒新时，新消息正文不入队，页面“已拒绝入队”和“最近队列错误”显示实际结果；可见实时日志带 `queueAdmission` 区分 queued / not-forwarded / rejected。收到不等于排队成功。丢旧只允许移除最旧 pending；正在投递、结果待核对受保护，没有可移除消息时仍拒新。单条大于总容量直接拒绝，不先删空原队列。

保存缩容时，拒新策略若当前不满足则 409；丢旧策略可原子裁剪 pending，但保护状态仍超容量时整次 409，不先删除一部分再报错。旧库积压超默认容量不会启动时自动裁剪，可先可靠交接或按明确策略处理。

“队列状态”显示待投递、正在投递、结果待核对、消息总数、字节占用、已可靠交接、已拒绝入队、已丢弃、超容量与最近错误。这是最近一次读取的实际快照，点击“重新读取设置”更新。

保存冲突返回 409 时，原草稿保留。先核对提示，再点击“重新读取设置”，确认放弃两个分类未保存更改后载入最新值；“放弃更改”只恢复最近读取的草稿，不修改后台。

清空步骤：

1. 在“队列与存储”点击“清空队列”，阅读正文不可恢复提示。
2. 勾选“我已了解，确认清除这些正文”，再点“确认清空队列”。
3. 若存在正在投递消息，后台返回 409，重新读取状态后处理。成功则清除尚未交接及待核对正文、累计丢弃数；账号配置、发送账本与短期哈希保留，不把前端未保存草稿顺带保存。

## 功能测试与 MCP

QQ“功能测试”下拉读取后台同一目录，当前39项＝官方38公开API＋1框架quick操作，含原消息工具、群管理／资料／成员、好友赞、好友和群请求处理、媒体／凭据查询以及OneBot维护。工具名、参数与完整限制见[覆盖清单](../technical/OneBot标准功能覆盖.md)。OneBot未支持某项时返回真实错误，不把目录存在当作已验证QQ权限。

布尔参数用“未指定／true／false”选择，枚举下拉、整数输入和JSON字段按相同schema校验。字段旁标明默认值，确认预览也显示省略时的实际值，不自动改写请求。消息可明确选择文本或结构化JSON：数组及单段对象均可，普通方括号文本不误解析；默认auto_escape=true保原文，显式false才解析CQ码。媒体file／URL／Base64交给OneBot，Eating不本机读取或下载。

所有副作用（包括群管理、请求处理、重启和缓存）逐次核对目标与参数并确认；参数／格式改变会生成新ID并取消旧确认。读消息调用标准get_msg或get_forward_msg，范围由协议端决定，不恢复Eating历史库。

所有写MCP调用必须提前保存8至128位合法稳定request_id；缺失或不合法则不发送。超时、断链或async／限速接纳仅表示结果待核对；保留原ID先查外部真实状态。原ID同参数重用已有结果或unknown，不再次向OneBot发送；新ID可能重复操作。onebot_call_mode可sync／async／rate_limited，后两种不等于已完成，set_restart本身也是异步。

快速操作需要原始事件JSON与标准operation对象，self_id必须匹配当前账号，操作字段与私聊／群消息／好友请求／群申请邀请类型对应。事件可以精简，但sender角色或正文不能当作主人授权。当前Harness事件交接仍仅私聊／群消息，标准请求工具不会自动获得历史请求flag。

Cookies、CSRF Token和QQ接口凭据只在主动查询后显示，不加入普通执行记录；离开测试页签、隐藏、pagehide或停用会清除并防止迟到回包恢复。普通面板只保最近10条执行，未知结果保留至明确核对，不持久化浏览器。MCP调用方收到敏感结果后自行保管，其原生会话可能保存，不能认为整个链路都不留存。

“MCP能力 → 查看MCP配置”仅在主动点击后获取QQ专属StreamableHTTP地址与独立Bearer，离开页签隐藏；不回显OneBot令牌，不自动修改其他Harness。新增未知可执行扩展仍需主人批准；本轮标准QQ工具已由用户授权加入。

## DSH 模型与原生会话

在 DSH 面板保存独立 endpoint／key 等模型配置后，再主动获取模型或测试连接。获取只查询已保存服务；选择返回的模型只改变页面草稿，须再次保存才生效。服务不支持模型列表时可手填真实模型 ID，不用伪造列表。测试发送最小 Ping、max_tokens=1，最多 15 秒、禁止重定向、响应上限 1 MiB；结果只表示本次 API 连通，不等同 runtimeReady、消息消费或平台动作成功。

会话看板需要手动刷新列表、选择原生父／子会话后读取内容，停机也可查看已有记录，不会为此启动模型或新会话。它通过公开原生 Cordis／persistence 只读接口沿当前 rootParentSession 树读取，默认 50 条、列表最多 100 条，响应和单条文本分别受 1 MiB／32K 上限约束，敏感字段和内部推理会过滤。运行中最近缓冲可能未落盘；状态无证据显示 unknown，更新时间缺失为空。

隐藏或离开看板会清除内容；会话读取没有后台轮询，应用既有 workspace 状态刷新仍按原有行为运行。看板不建立 Eating 聊天 archive，也不因清空 Host 队列删除 Harness 的原生上下文。分页是逻辑分页，底层可能读取整份原生日志，不保证大日志的磁盘分页性能。当前本地验证与限制见[本轮报告](../reports/2026-10-28-多代理与会话看板验证报告.md)。

## 实时日志

QQ 面板中的“实时日志”仅在页签打开、插件启用且支持日志、页面可见时订阅 Host SSE。默认最近 100 条，可选 50/100/200/500/1000，只留浏览器组件内存；缩小立即裁剪，增大不补发，选择不写浏览器持久存储或后台配置。

隐藏、离开、pagehide、关页或停用时停止订阅并清空，回到可见后从新事件开始。后台无日志缓存、文件或历史快照，无查看者不执行日志源 factory 或日志定时器。“清空显示”只清前端列表并继续监听，与全局“清空队列”不同。

行内显示时间、级别、私聊/群聊、账号/实例、会话、发送者、消息 ID 与最多 500 字纯文本预览；群号仅取明确 groupId。元数据的准入结果表明消息是否入队，不把拒收写成排队。认证字段不进入日志，预览中的当前 OneBot 令牌会替换，不承诺识别正文里所有秘密；日志通道“实时接收中”不等于 QQ 账号在线。

手动核验顺序：保持日志页签可见，使用另一个 QQ 给机器人发消息，观察新事件自动出现；改变保留条数和清空显示；隐藏或离开后回到空列表；关闭或停用后核对 Host viewer 归零。可从全局队列状态核对正常接收/准入，不需要聊天历史页面。Eating 不自动向真人发测试消息。

Host 沿用会话鉴权、ownerSession/Host/Origin 检查，最多 8 个查看者；背压断开后客户端重连，每个打开流有 15 秒注释心跳，关闭即清理，重连不回放。上一轮边界证据见[日志变更](../changes/2026-10-27-QQ按需实时日志.md)。

## 停用、故障与验证

停用 QQ 断开连接并撤销工具/MCP，保留配置、账号索引、当前未交接队列与动作账本；内存队列仍受 Host 退出丢失约束。重新启用使用原实例，可手动连接，不提供 UI 删除账号配置。

鉴权错误核对两端 token；连接错误核对端点/协议端；配置损坏保留原文件不覆写；结果未知先查真实状态；同数据根第二 Host 被锁拒绝。队列拒收、超容量、设置冲突、在途清空失败均显示真实错误，不假报成功。这些是逻辑/协议边界，不等于 OS 沙箱。
