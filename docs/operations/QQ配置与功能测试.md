# Eating QQ 配置与功能测试

Eating 使用 QQ OneBot v11 插件，需要已登录 QQ 并开启 OneBot 的协议端；Eating 不实现 QQ 登录协议。当前主应用／Host／Web0.10.0，三个共享包均3.0.0、QQ0.10.0、DSH0.5.1，插件仅接受apiVersion3。主人手动功能测试保留官方38公开API与1框架quick操作共39项标准目录，另有qq_view_received_image受控查看图片扩展，总计40项；子代理只开放各类型实际允许且主人勾选的工具。标准工具保持JSON语义，图片扩展返回真实MCP image内容。未实现空间／评论／反向连接占位已删除，实际可用性仍取决于协议端实现及QQ权限。标准目录见[OneBot覆盖清单](../technical/OneBot标准功能覆盖.md)，时间与图片能力见[ADR-0016](../decisions/ADR-0016-原生只读Web与多模态会话.md)，原样接入官方Web见[ADR-0017](../decisions/ADR-0017-原样接入DSH原生Web.md)。

## 构建、安装与启动

要求普通 Node.js >=24.9.0、pnpm 11.28.5。Host 按已安装产物加载插件，不扫描仓库源码自动提供 QQ。新增公开契约后先完整构建 SDK、QQ、Host 与 Web：

```bash
pnpm install --frozen-lockfile
pnpm build
```

首次安装可为EATING_HOME选择尚未使用的新目录；默认不兼容旧版，不自动迁移或重置旧资料。已有实例按本次明确批准的范围更新时，先停机、核对并备份目标资料，保连接配置、人格、原生UUID和Key，不清空重建。下面示例仅用于新目录，安装前停止使用该目标目录的Host：

```bash
export EATING_HOME="$HOME/.eating-current"
pnpm plugin install plugins/communication/qq/dist
pnpm plugin install plugins/harness/dsh/dist
pnpm plugin list
```

安装 CLI 与 Host 必须使用同一个 `EATING_HOME`，默认 `~/.eating`。安装器校验 SDK/API 和资源哈希，通过暂存发布、激活索引选版本；索引提交前失败保留旧版本，提交后的目录 fsync 失败返回 unknown 并保留已激活版本，需核对实际索引。插件代码与账号配置分开，见[工程结构](../architecture/工程结构与插件发布.md)。本轮不从第三方市场下载或发布 npm。

开发联合启动：

```bash
pnpm dev
```

开发页面 [Eating](http://127.0.0.1:5180/)与 [Host](http://127.0.0.1:5181/)分别在 5180/5181。生产运行：

```bash
node apps/host/dist/main.mjs
```

Host同源提供Web、API／MCP与插件资源，端口由EATING_HOST_PORT指定，开发代理跟随；纯Vite不提供Host能力。本轮恢复官方Web、图片DNS诊断及构建／验证见[新报告](../reports/2026-10-29-恢复原样DSHWeb与图片DNS诊断.md)，最终计数尚未确定；真实实例是否已停机、备份并更新完整栈以[项目状态](../项目状态.md)为准。不能只上新Web而保留旧Host／插件，也不因更新清空配置、人格或原生会话。新目录生成新账号实例／会话，不继承旧历史。

## 升级与卸载

本轮DSH补丁为0.5.1，应用／Host／Web与QQ0.10.0、共享包3.0.0及API3保持；完整栈构建与实际更新结果以本轮新报告为准。更新产物先完整`pnpm build`，停Host后核对备份、安装所用QQ／DSH新产物再启动，不能只替换界面。API3清单必须有assets数组，QQ与DSH均为空，不再交付Eating原生客户端资源，安装器仍验证全部声明路径与SHA。之后仅改QQ且已有当前SDK产物时，可用`pnpm build:plugin`。版本代码位于`plugins/<pluginId>/versions/<version>`，由`plugins/installed.json`激活；不支持运行中热更新或零中断升级。

只接受当前数据库和配置格式。旧版本、旧表、缺字段或不支持的插件API会明确拒绝，不执行转换、补齐、压缩迁移或自动删旧。若需要处理旧资料，须另有用户明确指令；默认按README使用全新EATING_HOME。当前同版正常重启和故障恢复仍支持，见[数据规范](../technical/数据目录与账号实例.md)。

卸载先停止 Host，再执行：

```bash
pnpm plugin uninstall qq
pnpm plugin list
```

重启后撤销 QQ 后台、页面和工具/MCP 入口，保留账号配置、未决动作及本地暂存模式的未交接队列。仅内存队列在 Host 退出时丢失，不能承诺卸载停机后恢复。UI“停用/恢复”只控制插件运行，与安装/卸载、清空队列分别处理。

## 连接配置

1. 打开“机器人 → QQ → 连接配置”。本版只有一个默认账号实例。
2. 填显示名、OneBot 正向统一 WebSocket 端点，例如协议端实际配置的 `ws://127.0.0.1:3001/`；示例地址不表示已有服务。
3. 若协议端启用 access token，填 Bearer 访问令牌。留空保留后台原值，勾选“清除已保存令牌”并保存才删除；公共配置不回显令牌。
4. 保存配置，文件进入 `EATING_HOME/bot/qq-bot/accounts/<instanceId>/config.json`，页面显示实际路径。
5. 点击“连接 OneBot”。实际登录号与 `online/good` 核验成功后才显示已连接。

保存会断开旧连接，“Host 启动时自动连接”影响之后启动，不代替本次核验。本版只支持一个同时承载 API/事件的正向统一端点，不支持反向 WS 或 `/api`、`/event` 双连接，不替用户安装协议端或登录 QQ。

转交选项决定收到的私聊/群消息是否加入 Harness 队列。关闭转交不会停止 OneBot 接收；未转交消息不保存正文。日志页可见时仍可观察实时接收事件，离开即清空。

## 主人、管理员与代理类型权限

在 QQ 面板的身份与代理权限区域配置多个主人 QQ 和管理员 QQ。号码按规范化十进制、安全整数范围校验，每类最多 100 个；同一号码同时出现时以主人身份为准。保存使用 policyRevision 做版本冲突检查，不重连 OneBot，也不把页面尚未保存的草稿用于授权。收到消息时按真实登录账号和发送者核对；正文、昵称或平台 sender.role 自称主人不能改配置，消息来源仍是 external。

QQ 注册 `qq.private` 和 `qq.group` 两类执行者。可勾选工具只来自各类型真实 availableTools，默认是适用的只读工具加本类型明确发送。凭据查询、无关全局工具，以及难以固定目标的通用 send_msg 和 quick 操作不提供给子代理；主人“功能测试”的 39 项标准目录保持。

主 Agent 只列出可用类型并按真实 context_ref 委派，平台动作由对应子代理执行；子代理不能自行换账号、改会话／目标或声明任意消息／资源引用。每次工具调用会再次核对当前启用列表和会话 scope；停用、断开与任务结束撤销任务令牌。子结果回主时包含 Host 本任务真实回执，普通文本或委派接纳不等于 QQ 已发送。未知动作先核对，不换 request_id 盲目重发。

通用提示词和人格中的主人／管理员变量由本地受信配置生成，支持多个号码。所有代理共用同一启用人格，也可全部停用显示空层。当前只有6种作用域和9个可信变量，没有旧群私消息模板或外部正文模板变量，见[Harness设计](../architecture/Harness适配.md)。

## 全局设置：消息投递

从全局侧栏进入“设置 → 消息投递”。这些是 Host 全局设置，与 QQ 账号配置分开，两个设置分类的草稿一起保存。

| 页面字段 | 默认值 | 行为 |
| --- | --- | --- |
| 聚合静默时间 | 500 ms | 同会话新消息到达后重新计时；0 表示不等静默 |
| 最长聚合等待时间 | 2000 ms | 从同会话首条入队固定计时，不能小于静默时间 |
| 单批消息上限 | 10 条 | 达到即提前投递，不能超过队列消息上限 |
| 批次目标大小 | 32 KB | 页面 1 KB = 1024 字节，即默认 32 KiB；不能超过队列容量 |
| 投递超时 | 15000 ms | 等接收端确认的时限，超时转结果待核对 |
| 拒收重试间隔 | 10000 ms | 仅对接收端明确拒收进行有限重试 |
| 最大投递尝试次数 | 5 次 | 包含首次；耗尽后保留正文待核对 |

只在同一 `conversationId` 聚合，不跨会话混批。静默、最长等待、条数或字节任一条件达到时投递；连续新消息不会无限推迟首条的最长等待。批次目标是软阈值，单条超过目标时独立投递、不拆分，仍受队列总容量约束；它不是模型 token 数、模型请求次数或上下文长度。接收者必须提供当前deliverBatch，不存在旧单条交接分支。

只有接收端同时返回 `accepted: true`、`durable: true` 与非空 `receiptId`，并完成本地确认，才计为“已可靠交接”并删除正文。它表示接收端接管，不表示模型已读或动作完成。超时、异常、凭据不足、进程中断均保留“结果待核对”，不自动补投；明确拒收才按设置重试。DSH 已实现可靠入箱与原生子代理，并经本地模型夹具及独立产物验证；实际模型由主人在独立面板配置，当前就绪和任务状态单独核对，不沿用旧版空配置结论。

## 全局设置：队列与存储

打开“设置 → 队列与存储”：

| 页面字段 | 默认值 | 可选项或说明 |
| --- | --- | --- |
| 队列存储方式 | 本地暂存（重启恢复） | 可改为“仅内存（重启丢失）” |
| 队列消息上限 | 1000 条 | 计算全部尚未交接消息，包含投递中和结果待核对 |
| 队列容量上限 | 10 MB | 页面 1 MB = 1 MiB = 1048576 字节，默认 10 MiB |
| 队列溢出处理 | 拒绝新消息，保留现有队列 | 可改为“丢弃最旧待投递消息” |

本地暂存只保存当前未交接的规范化信封，可在重启后恢复；仅内存模式的正文不进 SQLite，Host 退出或重启就丢失未交接内容。运行中切换会迁移现有队列；保存失败保留原模式、设置和正文。

队列容量按信封 UTF-8 JSON 实际字节，**不是整个 SQLite 文件大小上限**。数据库还保存去重小元数据、设置、令牌与动作账本。原始 OneBot raw、额外 text 副本、未转交正文和终态聊天历史均不保存。

拒新时，新消息正文不入队，页面“已拒绝入队”和“最近队列错误”显示实际结果；可见实时日志带 `queueAdmission` 区分 queued / not-forwarded / rejected。收到不等于排队成功。丢旧只允许移除最旧 pending；正在投递、结果待核对受保护，没有可移除消息时仍拒新。单条大于总容量直接拒绝，不先删空原队列。

保存缩容时，拒新策略若当前不满足则 409；丢旧策略可原子裁剪 pending，但保护状态仍超容量时整次 409，不先删除一部分再报错。当前格式中已有超容量队列不会被启动逻辑静默裁剪，仍须可靠交接或明确用户策略处理。

“队列状态”显示待投递、正在投递、结果待核对、消息总数、字节占用、已可靠交接、已拒绝入队、已丢弃、超容量与最近错误。这是最近一次读取的实际快照，点击“重新读取设置”更新。

保存冲突返回 409 时，原草稿保留。先核对提示，再点击“重新读取设置”，确认放弃两个分类未保存更改后载入最新值；“放弃更改”只恢复最近读取的草稿，不修改后台。

清空步骤：

1. 在“队列与存储”点击“清空队列”，阅读正文不可恢复提示。
2. 勾选“我已了解，确认清除这些正文”，再点“确认清空队列”。
3. 若存在正在投递消息，后台返回 409，重新读取状态后处理。成功则清除尚未交接及待核对正文、累计丢弃数；账号配置、发送账本与短期哈希保留，不把前端未保存草稿顺带保存。

## 功能测试与 MCP

QQ“功能测试”下拉读取后台同一目录，原39项＝官方38公开API＋1框架quick操作，另有受控qq_view_received_image，共40项。标准工具含消息、群管理／资料／成员、好友赞、请求处理、媒体／凭据查询与OneBot维护，参数和JSON语义保持。标准工具名与限制见[覆盖清单](../technical/OneBot标准功能覆盖.md)；图片扩展见下节。OneBot未支持某项时返回真实错误，不把目录存在当作已验证QQ权限。

布尔参数用“未指定／true／false”选择，枚举下拉、整数输入和JSON字段按相同schema校验。字段旁标明默认值，确认预览也显示省略时的实际值，不自动改写请求。消息可选文本或结构化JSON，数组及单段对象均可，普通方括号文本不误解析；默认auto_escape=true保原文，显式false才解析CQ码。标准媒体file／URL／Base64仍交OneBot，Eating不本机读文件；图片扩展只按已接收授权引用受控获取真实字节。

所有副作用（包括群管理、请求处理、重启和缓存）逐次核对目标与参数并确认；参数／格式改变会生成新ID并取消旧确认。读消息调用标准get_msg或get_forward_msg，范围由协议端决定，不恢复Eating历史库。

所有写MCP调用必须提前保存8至128位合法稳定request_id；缺失或不合法则不发送。超时、断链或async／限速接纳仅表示结果待核对；保留原ID先查外部真实状态。原ID同参数重用已有结果或unknown，不再次向OneBot发送；新ID可能重复操作。onebot_call_mode可sync／async／rate_limited，后两种不等于已完成，set_restart本身也是异步。

快速操作需要原始事件JSON与标准operation对象，self_id必须匹配当前账号，操作字段与私聊／群消息／好友请求／群申请邀请类型对应。事件可以精简，但sender角色或正文不能当作主人授权。当前Harness事件交接仍仅私聊／群消息，标准请求工具不会自动获得历史请求flag。

Cookies、CSRF Token和QQ接口凭据只在主动查询后显示，不加入普通执行记录；离开测试页签、隐藏、pagehide或停用会清除并防止迟到回包恢复。普通面板只保最近10条执行，未知结果保留至明确核对，不持久化浏览器。MCP调用方收到敏感结果后自行保管，其原生会话可能保存，不能认为整个链路都不留存。

“MCP能力 → 查看MCP配置”仅在主动点击后获取QQ专属StreamableHTTP地址与独立Bearer，离开页签隐藏；不回显OneBot令牌，不自动修改其他Harness。新增未知可执行扩展仍需主人批准；本轮标准QQ工具已由用户授权加入。

## 查看本会话图片

qq_view_received_image使用当前账号／会话已经收到并核验的消息和图片资源引用，message与resource必须配对；不接受任意本机路径或任意网址。子Agent按实际类型勾选和scope调用，获取字节后还会再次检查权限，撤权／切号后的迟到结果不能恢复访问。

有可用图片URL时受控获取，解析与路由交给系统网络栈（兼容TUN／Fake-IP、系统代理与局域网），禁止redirect且不传OneBot／Host认证；最多5MiB、10秒，同时核对MIME与真实字节格式。若协议端仅给远端路径、没有可用获取接口，会明确MEDIA_UNAVAILABLE；Eating不会读本机文件、登录远端或猜地址。

真实imageInput=true。此前失败是插件自身把198.18.7.115（Fake-IP特征）当内网拒绝，拦截发生在HTTP GET前，不是capability=false，也不需要用户改DNS。该预判已删除，QQ0.10.1改由系统网络栈取图，同一条真实消息取得image/jpeg、110000字节。不记录QQ标识、签名URL、rkey或消息正文。

该扩展返回标准MCP image，DSH原生客户端将其转成附件并送给明确支持图片的执行子Agent，主Agent先收子摘要，不默认收原图。纯文本模式应看到明确能力诊断，不能把URL／Base64普通文字当作已看图。先按下节声明当前模型输入能力；不要为验证主动向真人或付费模型试发。

功能测试预览只保临时Blob，离开时revoke，普通JSON执行记录不存Base64。Eating不新建媒体聊天库；已给模型的图片可由Harness原生附件持久化，离开预览并不删除原生附件。回环wire通过说明图像块进入请求，不代表真实提供商识图准确率。

## DSH 模型与原生会话

在 DSH 面板保存独立 endpoint／key 等模型配置后，再主动获取模型或测试连接。获取只查询已保存服务；选择返回的模型只改变页面草稿，须再次保存才生效。服务不支持模型列表时可手填真实模型 ID，不用伪造列表。测试发送最小 Ping、max_tokens=1，最多 15 秒、禁止重定向、响应上限 1 MiB；结果只表示本次 API 连通，不等同 runtimeReady、消息消费或平台动作成功。

图片输入能力单独读取／保存，原7字段连接配置与密钥保持。默认imageInput=false，只有主人确认当前实际服务支持图片后才声明；不按模型名自动勾选。保存需要停止runtime并通过revision CAS，冲突保留草稿；endpoint／model变化重置false，Key／超时变化不重置。能力声明不能让文本模型变成视觉模型，真实提供商识图仍需另行授权验证。

会话看板手动刷新、选择原生父／子会话后读取，停机也可看已有记录，不为此启动Agent／模型／新会话。公开Session及当前message projections恢复有效surface，保消息ID／turn／step／callId／source与替换关系，不平铺已失效system、不把inbox撤回当已读。平台消息显示真实sender／接收账号／私聊目标或群号，昵称有证据才带；主任务／子回报／框架通知分开，普通模型输出不等于QQ已发。系统与运行时时间独立折叠查看，内部reasoning不展示。

实例显示名是“平台-绑定登录账号-私聊／群聊-对方／群号”，如虚构QQ-10001-群聊-30003。登录号来自真实scope.accountId，不是账号实例UUID；切号区分实例，历史归属和UUID不改。默认每页50、最多200记录、列表100，响应1MiB／单文本32K，按原生日志位置分页且最多扫描2000事件。运行中缓冲可能未落盘，未知状态／时间不伪造。

在DSH面板点击“打开DSH原生Web”，主人管理操作按需取得`{url, rootSessionId}`并在新页签进入同一Eating专属DSH进程的官方鉴权入口；不连接用户主DSH，也不另起共享会话写进程。普通`runtimeStatus.nativeWeb`只有`{ready}`，删除readOnly字段，URL不进入普通status或模型上下文。挂当前官方SessionController host、client roster、Gateway和owner鉴权，完整保留官方UI／主题／侧栏／消息组件与正常会话操作；可依官方能力新建会话、发言、设置，cold follow与激活遵循官方机制。关网页不影响QQ自动处理，停Harness则Web一同关闭。

原生Web完全移除Eating自定义客户端源码／打包／模块注入、sidebar／composer／message renderer、硬编码配色、LocaleBridge、agentLabels映射及readerPeer／connection隔离／HTTP写白名单／readonlyController／冷follow拦截；DSH产物assets=[]。web的printUrl／openBrowser／surfaceContext均为false，避免污染SDK。四段名称保留为创建标签和Eating离线summary，官方页面显示依官方机制，不承诺全部旧标题外观修正。平台JSON与工具结果按官方默认组件原样显示；Eating自有面板的summary／source不注入DSH。SDK主的两个工具、受限QQ子MCP及time-context保持，官方Web创建的普通Agent不作为QQ scope child报错。

主子各一次官方time-context使用上海时区与原生600000ms，仅在已有合格step末尾追加来源明确的user运行时读数，冷恢复去重，无新时钟工具／scheduler／后台唤醒。通用与QQ默认system移除动态时间行；9个可信变量仍注册，若主人自定义再插当前时间，system仍动态变化，不能承诺缓存收益。

隐藏或离开Eating看板会清正文，不后台轮询，不建Eating archive，也不因清Host队列删Harness原生上下文。Eating离线读取底层可能解码整份原生日志，不保证大日志磁盘分页性能；官方Web的会话读取和激活保留官方机制。实际验证与限制见[本轮新报告](../reports/2026-10-29-恢复原样DSHWeb与图片DNS诊断.md)。

## 实时日志

QQ 面板中的“实时日志”仅在页签打开、插件启用且支持日志、页面可见时订阅 Host SSE。默认最近 100 条，可选 50/100/200/500/1000，只留浏览器组件内存；缩小立即裁剪，增大不补发，选择不写浏览器持久存储或后台配置。

隐藏、离开、pagehide、关页或停用时停止订阅并清空，回到可见后从新事件开始。后台无日志缓存、文件或历史快照，无查看者不执行日志源 factory 或日志定时器。“清空显示”只清前端列表并继续监听，与全局“清空队列”不同。

行内显示时间、级别、私聊/群聊、账号/实例、会话、发送者、消息 ID 与最多 500 字纯文本预览；群号仅取明确 groupId。元数据的准入结果表明消息是否入队，不把拒收写成排队。认证字段不进入日志，预览中的当前 OneBot 令牌会替换，不承诺识别正文里所有秘密；日志通道“实时接收中”不等于 QQ 账号在线。

手动核验顺序：保持日志页签可见，使用另一个 QQ 给机器人发消息，观察新事件自动出现；改变保留条数和清空显示；隐藏或离开后回到空列表；关闭或停用后核对 Host viewer 归零。可从全局队列状态核对正常接收/准入，不需要聊天历史页面。Eating 不自动向真人发测试消息。

Host 沿用会话鉴权、ownerSession/Host/Origin 检查，最多 8 个查看者；背压断开后客户端重连，每个打开流有 15 秒注释心跳，关闭即清理，重连不回放。上一轮边界证据见[日志变更](../changes/2026-10-27-QQ按需实时日志.md)。

## 停用、故障与验证

停用 QQ 断开连接并撤销工具/MCP，保留配置、账号索引、当前未交接队列与动作账本；内存队列仍受 Host 退出丢失约束。重新启用使用原实例，可手动连接，不提供 UI 删除账号配置。

鉴权错误核对两端 token；连接错误核对端点/协议端；配置损坏保留原文件不覆写；结果未知先查真实状态；同数据根第二 Host 被锁拒绝。队列拒收、超容量、设置冲突、在途清空失败均显示真实错误，不假报成功。这些是逻辑/协议边界，不等于 OS 沙箱。

复现入口为pnpm build、pnpm test与pnpm exec playwright test；完整原生实跑须显式设置独立EATING_DSH_TEST_RUNTIME，默认跳过不能记作实跑。实际构建／类型、官方原生Web与owner正常操作、图片取图修复、时间、独立产物及浏览器命令和最终总数见[本轮新报告](../reports/2026-10-29-恢复原样DSHWeb与图片DNS诊断.md)。[删除旧兼容阶段报告](../reports/2026-10-29-删除旧版兼容验证报告.md)保留当时983／53等证据，不代表本轮总数；旧回环wire成功也不代表此次真实公网图片已通。真实实例更新与配置／人格／原生UUID／Key保持以[项目状态](../项目状态.md)及本轮报告为准，不把隔离验证写成已部署。自动模型／OneBot仅回环，不向真人试发或开发代测付费API。
