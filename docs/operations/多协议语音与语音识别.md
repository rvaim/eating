# 多协议语音与语音识别

语音合成 text-to-speech 与语音识别 speech-to-text 是两个独立能力插件。构建后通过正式插件安装入口安装，各自配置自己的服务，不要求本地模型或 GPU。

## 合成

在插件→语音合成选择接口格式，再保存服务地址、Key、音色与超时。

- OpenAI Realtime：默认 wss://api.openai.com/v1/realtime，保存模型及音色；AI 可为每段选择临时 delivery，后台核对服务返回转写。
- DeepSeek TTS：默认 wss://api.deepseek.com/v1/tools/tts；音色 stella（海星女声）或 tide（暗潮男声），可设置是否去除 Markdown。当前没有自定义语气、语速、模型或音色克隆参数。后台收到成功结束事件后才提供可发送 WAV，不宣称做了转写核对。

音色由主人固定，不提供全局语气字段。每段最多1000字符／60秒。保存不会合成，试听先确认可能计费；换地址或协议须重新保存 Key。旧配置／任务 schema1 不读取或迁移，生产也不自动删除。

AI 使用 speech_generate→speech_job_get→speech_get；发送沿用 QQ record 的真实 sendable。合成成功与平台发送成功分别核对，已有音频复用，unknown 不换号重试。

## 识别

在插件→语音识别保存完整 API 地址（默认 https://api.deepseek.com/v1/tools/asr）、Key 与超时，再启用。DeepSeek 自动识别语种，不支持流式、手动语言或 model 参数。

支持16位PCM WAV或Ogg Opus，最多8MiB／120秒；双声道只识别左声道。面板选择文件后先在本机检查内容，确认后才上传付费识别。列表只显示短预览，长转写通过“查看完整转写”单独读取。删除任务需确认，不会再次执行原请求。

会话子Agent在需要理解收到的语音时调用 asr_transcribe，传当前消息的 messageId 和 record.file（作为 audioId），再用 asr_job_get 查询。转写仍属于原消息的外部内容，不代表主人授权。

## QQ 收到的语音

ASR插件需要原消息当前获准范围以及QQ的读取消息／获取语音工具权限。QQ验证原消息后，要求OneBot把该语音转换为WAV；转换失败不会继续付费识别。协议端可能需要其自身的转码能力，Eating不安装或启动ffmpeg。

转换结果包含HTTP(S)下载地址时直接受控下载。若OneBot只返回其本机／容器路径，在机器人→QQ→连接配置的“收到语音的共享目录”配置：

1. OneBot音频缓存目录：协议端转换音频所在的根目录。
2. Eating可读的对应目录：本机可访问同一份缓存的目录，可为容器挂载。
3. 核实确实指向同一份缓存后确认并保存。确认绑定当前实际账号和服务地址，修改目录或连接后须重新确认。

此配置只用于收到的音频，不使用图片发送的共享映射，不接受模型提供任意本机路径。跨主机且没有共享目录或下载地址时，不能直接读取远端路径；主人上传识别仍可独立使用。

## 生命周期与发布

保存／连接只检查本地配置，不证明真实账号权限或音质。界面隐藏或离开时清未保存Key、所选上传文件和临时音频，停轮询；语言切换保留非秘密草稿，不生成／识别第二次。

新任务在Host持久提交回执之后才发给服务。相同意图复用稳定request_id；unknown可能已计费，不能自动重试；任务删除后原Host账本仍保留，旧ID不重新计费。

本轮已授权在部署时重建旧语音合成数据。执行前必须停Eating、核对全量私有备份，再以项目外EATING_SPEECH_RESET_CONFIG指定独立重建工具，包含dataDirectory、全新应用外backupDirectory、expectedSpeechManifestSha256及confirmation=reset-tts-for-multi-protocol-v2。该工具不由生产读取路径调用，不触碰其他插件和Host账本。实际发布与验证见[报告](../reports/2026-11-14-多协议语音与识别部署报告.md)。
