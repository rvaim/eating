# 安卓手机插件（android-control 0.3.0）

`android-control` `0.3.0` 由插件在 **Eating 所在机器**直接管理本机 ADB，连接 USB 或网络安卓设备；不再提供独立的远程 HTTP MCP 执行端（`executor.mjs` 已移除）。插件不设子命令白名单，也不限制单次操作时长、每日额度或冷却时间。

## 1. ADB 与设备连接配置页

进入 **插件 → 玩手机 → ADB 与设备连接**（即使插件尚未启用或本机尚未安装 ADB，也可直接在该页完成检测、安装与配置）：

1. **顶部双状态卡片**
   - **ADB 环境**：显示 `可用／不可用`、来源（`手动指定`／`系统 PATH / SDK`／`插件已安装`）、版本与可执行文件路径。
   - **手机设备状态**：基于真实 `adb devices -l` 结果显示 `在线 (device)`、`离线 (offline)`、`未授权 (unauthorized)` 或 `未设默认设备`，仅通过 `adb version` 绝不误报“手机已连接”。

2. **ADB 环境与内置安装**
   - 检测顺序固定为：**手动自定义绝对路径 → 系统 PATH／标准 Android SDK 位置（`ANDROID_HOME`、`ANDROID_SDK_ROOT` 等）→ 插件工具目录**。
   - 填写了手动路径但文件无效／不可执行／无法运行 `adb version` 时直接报错并停止自动回退；需恢复自动检测请清空手动路径。
   - 若系统已有可用 ADB，**“安装 ADB”将保持禁用**，不会重复下载或修改系统环境。
   - 未检测到系统 ADB 时，点击 **“安装 ADB”**：插件按运行 Eating 机器的操作系统与 CPU 架构从 Google 官方仓库清单安装稳定版 Platform-Tools（当前官方支持 `macOS arm64/x64`、`Linux x64`、`Windows x64`；如 `Linux arm64` 等无官方包的架构会明确报错并引导配置手动路径）。下载文件、SHA-256 校验与运行验证通过后安装在：
     - `EATING_HOME/capabilities/android-control/tools/platform-tools/`
     - 安装记录与临时文件均位于 `tools/` 下；不写入代码包目录，也不修改系统 `PATH`。

3. **设备连接（USB／网络 ADB 与无线配对）**
   - **USB 设备**：直连插在 Eating 所在机器上的安卓手机或本机模拟器。多台在线设备时，在设备列表点击 **“设为默认设备”** 或在命令参数通过 `serial`／`-s` 显式选择，插件不会猜测第一台。
   - **网络 ADB**：输入 **主机:端口**（支持 IPv4、域名或带方括号 `[IPv6]:端口`，例如 `192.168.1.50:5555`、`[::1]:5555`）。点击 **“保存并连接设备”** 按顺序执行：保存网络地址 → `adb connect` → 复核 `adb devices -l` 状态 → 仅当确认处于 `device` 在线状态时设为默认设备。
     > 注意：`127.0.0.1` 指运行 Eating 的机器本身。若 Eating 部署在云端，请填云端可直连的设备地址，或先建立可到达云端端口的私有网络／SSH 转发。
   - **无线配对（Android 11+）**：在“无线配对”折叠卡片输入手机端显示的配对地址、6 位配对码以及（可选的）连接端口，底层调用 `adb pair`（并在提供连接地址时顺接 `adb connect`）。配对码不会保存、不写入任何日志，切离／隐藏页面即刻自动清空。

4. **高级配置与配置重建**
   - 可配置自定义 ADB 绝对路径与 Eating 所在机器上的工作目录（默认 `EATING_HOME/capabilities/android-control/workspace/`）。
   - 插件在连接状态下修改高级配置，界面会引导按 **断开运行 → 保存配置 → 重新连接** 的受控顺序执行。
   - 若磁盘中存在旧版 `schemaVersion: 1`（原远程执行端格式）或损坏配置文件，插件不会自动迁移、覆盖或将旧 `endpoint` 当作 ADB 地址，请确认后点击 **“重建连接配置”** 恢复全新 v2 格式（仅重置 `config.json`，保留工作目录、已安装 ADB 与回执账本）。

## 2. 清理插件安装的 ADB 与卸载说明

- 在宿主执行 **卸载插件** 会遵循平台“保留插件私有数据”政策，仍保留配置、工作文件、动作回执及 `tools/` 下工具。
- 如需清理插件自行下载的工具，可在连接配置页点击 **“移除插件安装的 ADB”** 并确认：插件会先停止当前占用 ADB 的运行时与进程，再**只删除** `EATING_HOME/capabilities/android-control/tools/`，完整保留连接配置、工作目录、`receipts.sqlite` 以及系统自有的 ADB／SDK 或其他软件服务。

## 3. 命令、进程、文件与截图作用域

- `android_adb_exec` 原样向选中设备传递 argv（可通过顶层 `serial` 或 `-s` 覆盖默认设备），`android_screenshot` 同样优先使用传入 `serial` 或当前默认设备。
- 每次请求的目标设备纳入后端 HMAC 意图核对；切换默认设备或设备断线重启后，旧 `request_id` 若指向不同设备会返回 `ANDROID_REQUEST_CONFLICT`，结果未知的动作也不自动换号重放。
- **文件与截图路径均属于 Eating 所在机器**（`workspace/` 与绝对路径均指宿主／插件所在主机磁盘）。需要将手机内部文件传到 Eating 机器或从 Eating 机器推入手机，请直接执行 `adb pull` 与 `adb push`。
- “提示词管理 → 插件 → 玩手机” 与 `android-control.phone` 独立手机子代理继续保持可编辑提示词，供主 Agent 与手机子代理按同一身份协作。
