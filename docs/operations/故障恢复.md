# Eating 故障恢复草案

状态：Proposed，字段与流程未冻结，未执行故障注入。来源：v0.3 §11、本轮插槽式架构确认。

| 边界 | 行为要求 | 恢复核对 |
| --- | --- | --- |
| 当前 Harness 退出 | Host/通讯模块尽量继续，停止认知投递，事件仍先持久化 | 有限退避、真实握手，按实际能力恢复原运行目标、查未知动作、补投；不自动换 Harness |
| Host 退出 | 平台能否缓存/补收因模块而异 | 恢复存储、单实例、授权、队列、注册和连接状态；不能承诺离线无损 |
| 通讯模块退出/断网 | 显示渠道不可用，有限重连；其他模块应可继续 | 平台补收/游标与唯一键，不能伪造在线，不清理其他模块注册 |
| 模块注册/界面加载失败 | 回收本模块部分注册与资源，通用管理页显示真实失败 | 校验模块版本、依赖、授权与资源归属；不因单页失败重建全局模块目录 |
| 数据库不可用 | 停止声称事件已保存，避免无证据继续动作 | 诊断/恢复持久化，保留错误与真实缺口 |
| 设备休眠/关机 | 不保证实时调度 | 核对漏发语义、外部动作和平台历史 |
| 模型服务不可用 | 有限重试、预算与错误状态 | 恢复后让当前主要认知控制者自决，不无限重新调用 |
| 记忆机制不可用 | 明确降级，不显示记忆正常，不用 Host 日志代替人生记忆 | 验证所选 Harness 可用且主人授权的插件/机制及其存储、凭据和服务 |
| 插件升级/安装失败 | 记录副作用和阶段，停止误报成功 | 按批准和回滚清单恢复；build 副作用不一定可撤销 |
| 能力检查/调用失败 | 区分 unsupported、unknown 与 error，停止依赖该能力的新动作 | 核对版本、声明与真实错误；不把失败改写为不支持，也不伪造恢复成功 |

模块失败限制在自身是设计要求，仍需验证共享服务、同进程和进程崩溃的实际影响；Cordis 作用域不提供 OS/进程隔离。模块不能擅自重启共享依赖或清理其他模块数据。

## 重启与模块停用

重启需次数上限、退避、熔断/人工恢复入口和诊断。阈值未定；不创建高频无限重启循环。正常休息、人工暂停、模块停用、资源限制和故障必须分开记录。

模块停用或移除须阻止新工作、撤销后台能力与界面注册、清理订阅/连接/定时任务并处理在途调用；撤销不能证明远端动作已取消。迟到事件或响应可用于对账，但不得恢复已撤销入口或重新启动任务。保留待投递事件、恢复映射、配置、授权审计和未决动作，数据清除遵循单独保留/删除策略，见[数据归属](../architecture/数据归属.md)。

仅恢复用户选定且仍获授权的 Harness。若旧控制者是否仍在运行未知，先核对并停妥，不为恢复可用性而再激活第二个主要认知控制者。跨 Harness 会话、插件、记忆无损迁移和运行中热切换未承诺。

## 连续性与不确定性

恢复持久会话不等于重放活跃模型生成或从任意 token 继续。适配器须分别检查真实恢复能力、Agent 配置、主映射、授权和记忆机制；不支持或未知的步骤必须明确报告。实际 Codex/Claude Code 恢复接口未核。

输入去重不能保证输出动作不重复。Harness 受理后崩溃、平台完成但回执丢失等窗口，应先查询该适配器可提供的持久记录/真实平台状态；缺乏查询能力则保留未知。结果未知时不直接重做发送、发布、支付、删除或安装，见[消息设计](../architecture/消息与投递.md)。

## DSH 适配器：恢复与调度窗口（源码分析）

DSH 的跨进程恢复使用 `resumeSession(savedId)`，仍须核对实际 sessionPersistence、Agent 配置与 SDK 不自动组合 Preset 的限制。DSH Schedule 存在 session/inbox 持久化与任务记录分开写入的窗口；session flush 后任务记录未更新可能导致重复，源码不保证精确一次。提醒回执不能等同 Agent 完成，见[源码核对](../research/DSH源码核对.md)。这些是固定版本 DSH 事实，不是通用 Harness 调度约定，尚未做 Eating 故障注入。

## 证据

保存崩溃前后时间、版本、模块/适配器与控制者标识、退出码、重试次数、实际会话/event/action 关联、能力判断证据与脱敏日志。标识、字段和状态名均为候选，见[接口契约](../technical/接口契约.md)。计划见[测试](../plans/测试计划.md)，当前所有恢复实验未开始。
