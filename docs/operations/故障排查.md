# Eating 故障排查指南草案

当前没有可运行 Eating 工程。本页是后续调查入口，候选字段与流程未冻结，不能当作已验证修复步骤。

## 排查方法

先确定故障边界和最后一个可靠证据，再查根因，不通过吞异常、复制配置或无条件重试做表面兼容。检查实际版本、Git 变化、配置来源、环境根目录、进程退出和持久记录；先只读，不直接重装插件、切换 Harness 或新建会话掩盖问题。

先分清通用 Host/共享存储故障、单模块故障与选定 Harness 故障。后台注册、管理界面注册、模块运行和操作成功是不同证据；Cordis 的逻辑作用域不能证明 OS/进程隔离，单模块失败也不应触发全局注册清空。

| 现象 | 首先核对 | 不应直接认定 |
| --- | --- | --- |
| 进程启动但不可用 | 适配器真实握手/初始化、模块装配、模型配置、日志 | 有进程即已就绪 |
| 能力缺失或查询失败 | capabilities 对应版本、证据和原始错误；区分明确 unsupported、证据不足 unknown、本次失败 error | 查询失败等于不支持，或声明支持等于调用成功 |
| 人格/工具配置不生效 | 当前适配器的真实配置接口、加载来源、授权和版本 | 所有 Harness 都支持 Preset 或会继承另一产品 UI 配置 |
| 会话恢复失败 | 主身份映射、适配器/实例、专属根、真实持久化与恢复返回值 | 创建新 ID 或换 Harness 即修复连续性 |
| 收消息但没有回复 | 队列阶段、准入/消费证据、休息/预算、Agent 自主选择 | 不回复一定是故障 |
| 定时唤醒重复或未到 | 适配器调度能力、时区、休眠、任务持久化和取消结果 | 所有 Harness 都有调度、精确一次或实时保证 |
| 模块管理入口缺失/残留 | 模块身份/版本、后台与界面分别注册/撤销、依赖、迟到响应 | 界面消失即后台停止，或后台就绪即界面加载成功 |
| 停用后仍有活动 | 新任务准入是否停止、在途调用/远端调度、实际取消能力与账本 | 撤销本地注册就已取消远端动作 |
| 插件装不上 | 精确版本兼容、包来源、build 许可、OS/运行时依赖 | 重装同版本必然解决；注册代表主人批准 |
| 记忆不可用 | 所选 Harness 实际兼容且主人授权的机制、存储范围、凭据与服务响应 | 运行日志可代替长期记忆，或更换 Harness 会自动迁移记忆 |
| 其他用户实例被影响 | 适配器的配置/数据根、共享全局配置、工作区与插件自有路径 | 仅改一个路径就已完全隔离 |

同一数据集只能有一个活跃主要认知控制者。旧控制者是否停止未知时先查运行状态与未决动作，不自动再启动另一 Harness；实际 Codex/Claude Code 接口尚未核对，不套用 DSH 命令或路径。能力语义见[接口契约](../technical/接口契约.md)，模块停用后的数据按[保留策略](../architecture/数据归属.md)处理。

## DSH 适配器：专项排查（源码分析）

| 现象 | DSH 固定版本核对点 | 不能推导 |
| --- | --- | --- |
| Persona/Preset 不生效 | 启动模式、Profile patch 顺序、SDK 不自动组合 Preset | Web 配置自动继承到 SDK Agent |
| Session 恢复失败 | 主映射、独立 home、sessionPersistence/flush、`resumeSession(savedId)` 返回值 | `session(id)` 或同 ID prompt 等于跨进程 resume |
| 定时唤醒重复或未到 | Schedule 组合挂载、时区、休眠、inbox/session 与任务记录两次写入窗口 | DSH exactly-once 或实时保证 |
| 主 DSH 被影响 | `DSH_HOME`、`DSH_AGENTS_HOME`、Profile、全局/home 级 patch、工作区与插件自有路径 | 只换 DSH_HOME 已完全隔离 |

以上只读证据见[源码核对](../research/DSH源码核对.md)，不是 Eating 运行验证或其他 Harness 的修复步骤。
