# 服务器部署与更新

## 当前授权边界

缺少运行时、项目依赖或额外工具时，先说明用途及影响并取得安装确认。只部署Eating，不自动配置HTTPS、证书、网关或防火墙，不替换服务器已有其他服务。真实连接值、端口和目录映射保存在项目外；本页只使用示例占位符。

## 代码来源

先在本地修改、验证并commit／push至GitHub，服务器再clone或pull已确认提交，不上传本地工作区或源码包，不直接编辑云端项目源码。真实私有运行配置不提交GitHub。

仓库提供[受控构建入口](../../scripts/server-build.mjs)。它不安装Node、pnpm、DSH或系统软件，只在明确批准、当前Git提交及锁文件摘要均匹配时安装项目锁定依赖，随后完整构建并执行Host／控制层相关回归。

在服务器已完成GitHub拉取后，通过项目外的私有配置指定：

```json
{
  "commit": "<已确认的40位Git提交>",
  "lockSha256": "<已确认的64位锁文件SHA256>",
  "dependencyInstallApproved": true,
  "pnpmScript": "/EXTERNAL/PRIVATE/TOOLING/pnpm.cjs",
  "packageStore": "/EXTERNAL/PRIVATE/PACKAGE_STORE",
  "logFile": "/EXTERNAL/PRIVATE/BUILD_LOG"
}
```

以上路径必须按本机真实环境填写在仓库外，不复制真实配置到本页或任何项目文件。`dependencyInstallApproved`只表达本次已确认的依赖安装，不授权额外软件；锁文件变化或新依赖应重新按当前授权确认。

```bash
EATING_DEPLOY_CONFIG="<项目外私有配置文件>" node scripts/server-build.mjs
```

构建检查源码工作区无在途修改；进程错误只显示脱敏摘要，完整构建日志留在指定的项目外私有位置。不会改变全局包管理器或系统运行时，也不修改防火墙。

## 启动与更新

保留`apps/host/dist/main.mjs`和根`dist`相对目录，使用普通Node运行生产入口。数据目录与代码分开，以服务管理器独立管理本应用；端口先检查空闲，完成时向用户说明真实监听状态及端口，不写入仓库目标清单。

Host当前默认只监听回环，且管理会话取得依赖本机访问前提；只放行防火墙不能把回环服务变成公网服务。不要为了部署静默改成公网监听或宣称已有公网登录能力。外部访问按用户选定的SSH转发或其自行维护的入口处理，不自动加装网关。

更新时先本地验证并push，云端pull对应提交、检查新增依赖授权、构建成功，再仅停止Eating、备份本应用私有数据、安装当前插件产物并恢复Eating，核对静态页面、版本和配置保留。插件同版本不同内容会被安装器拒绝，代码变化需同步递增对应插件版本；不覆盖封存产物。原有其他服务不停止、不重载、不改配置。

首次部署使用独立新数据，不自动复制本机QQ账号、模型Key、人格或同一AI会话；配置完成与实际连接／模型运行分别验证。同一AI数据集不得同时启动两个主控制者。
