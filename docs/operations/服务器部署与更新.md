## 代码来源

先在本地修改、验证并commit／push至GitHub，服务器再clone或pull已确认提交，不上传本地工作区或源码包，不直接编辑云端项目源码。真实私有运行配置不提交GitHub。

仓库提供[受控构建入口](../../scripts/server-build.mjs)。它不安装Node、pnpm、DSH或系统软件，只在明确批准、当前Git提交及锁文件摘要均匹配时安装项目锁定依赖，随后完整构建并执行Host／控制层相关回归。

在服务器已完成GitHub拉取后，通过项目外的私有配置指定：

```json
{
  "commit": "<已确认的40位Git提交>",
  "lockSha256": "<已确认的64位锁文件SHA256>",
  "dependencyInstallApproved": true,
  "pnpmScript": "/EXTERNAL/PRIVATE/TOOLING/pnpm.cjs",
  "packageStore": "/EXTERNAL/PRIVATE/PACKAGE_STORE",
  "logFile": "/EXTERNAL/PRIVATE/BUILD_LOG"
}
```

以上路径必须按本机真实环境填写在仓库外，不复制真实配置到本页或任何项目文件。`dependencyInstallApproved`只表达本次已确认的依赖安装，不授权额外软件；锁文件变化或新依赖应重新按当前授权确认。

```bash
EATING_DEPLOY_CONFIG="<项目外私有配置文件>" node scripts/server-build.mjs
```

构建检查源码工作区无在途修改；进程错误只显示脱敏摘要，完整构建日志留在指定的项目外私有位置。不会改变全局包管理器或系统运行时，也不修改防火墙。

## 本机模式与显式外部模式

Host默认仍监听 `127.0.0.1`，没有配置ownerToken时保持原本机bootstrap流程。此前“只支持回环”的说明是旧阶段范围，当前增加由用户明确选择的外部模式；不能只改监听地址而省略主人入口配置。

| 配置 | 本机默认 | 显式公网部署 |
| --- | --- | --- |
| `EATING_LISTEN_HOST` | `127.0.0.1` | `0.0.0.0` |
| `EATING_PUBLIC_ORIGIN` | 可省略 | 必填，规范HTTP(S) Origin，仅协议、主机与可选端口，无路径、尾斜线或凭据 |
| `EATING_OWNER_TOKEN` | 可省略；显式设置时启用入口核验 | 必填，随机32至256字符，仅字母、数字、下划线和短横线 |
| `EATING_HOST_PORT` | 沿用应用默认 | 从项目外私有配置指定已检查空闲的 `<HOST_PORT>` |
| `EATING_HOME` | 沿用应用默认 | 项目外独立新数据根 `<EXTERNAL_DATA_HOME>` |

外部模式缺publicOrigin或ownerToken直接拒绝启动。主人使用 `http://example.invalid:<HOST_PORT>/?token=<OWNER_TOKEN>`；根地址已有query时，如 `/?view=example`，追加 `&token=<OWNER_TOKEN>`。只接受根GET与单个有效token，成功后签发HttpOnly／SameSite=Strict入口Cookie，并303跳转删除token、保留其他query的根地址；页面再正常bootstrap取得管理session／CSRF，写API继续核验CSRF，Host／Origin检查保持。Host重启后重新使用私有入口链接。没有登录表单、账号或密码。

`/mcp/:pluginId` 和 `/mcp-services/:id` 仍需各自独立Bearer，不能用owner URL token或入口Cookie替代。官方DSH Web维持原监听与鉴权，Eating公网入口不将其回环地址自动变成公网地址，也不修改官方页面。

## 托管启动与更新

保留 `apps/host/dist/main.mjs` 和根 `dist` 相对目录，使用普通Node运行生产入口。数据与代码分开；实际端口只向用户单独交付，最终含Token链接另存本机项目外私有文件，不进入仓库／报告／截图。

[服务脚本](../../scripts/server-service.mjs)仅适用于已具备用户级systemd的Linux，拒绝root运行，不自动安装缺失工具。由 `EATING_SERVICE_CONFIG` 指向项目外私有JSON，字段如下；这些内容只在项目外填写真实值：

```json
{
  "dataDirectory": "/EXTERNAL/PRIVATE/DATA_HOME",
  "runtimeNode": "/EXTERNAL/PRIVATE/TOOLING/node",
  "runtimeDsh": "/EXTERNAL/PRIVATE/TOOLING/dsh",
  "toolingBin": "/EXTERNAL/PRIVATE/TOOLING/bin",
  "listenHost": "0.0.0.0",
  "publicOrigin": "http://example.invalid:<HOST_PORT>",
  "ownerToken": "<RANDOM_URLSAFE_OWNER_TOKEN_32_TO_256_CHARACTERS>",
  "port": "<HOST_PORT_INTEGER>"
}
```

以上为说明占位符，执行前必须在外部配置中把port填为整数，publicOrigin使用与该端口一致的规范Origin，并随机生成有效Token；不直接运行这份示例。脚本严格校验完整字段，路径均须为项目外绝对路径。服务Token、数据根与运行时路径随私有unit留在项目外，不拷入代码目录。

```bash
EATING_SERVICE_CONFIG="<项目外私有服务配置文件>" node scripts/server-service.mjs
```

脚本只管理用户级 `eating-managed.service`；拒绝覆盖同名非Eating托管unit。它仅停止已有的该托管unit，安装本实例当前QQ／DSH／表情／生图／记忆五插件，再启动该unit并检查active，不停止、重载或改写其他服务。unit、服务状态及私有配置位于项目外；active只代表服务进程就绪，页面／鉴权及业务连接另行验证。

更新先本地验证、commit并push，云端pull对应提交、检查新增依赖授权，构建成功后再按当前授权仅停止Eating、备份本应用私有数据、安装当前插件产物并恢复Eating，核对静态页面、版本和配置保留。服务脚本不代办私有数据备份。插件同版本不同内容会被安装器拒绝，代码变化需同步递增对应插件版本；不覆盖封存产物。

首次部署使用独立新数据，不复制本机QQ账号、模型Key、人格或同一AI会话。实际应用／Host／Web0.17.4、QQ0.13.6、DSH插件0.15.3；新服务器记忆0.2.0未配置时不连接，本机真实0.1.1不动。配置完成、插件安装、实际连接和模型运行分别验证，同一AI数据集不得同时启动两个主控制者。
