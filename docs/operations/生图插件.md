## 配置服务

在“插件”找到“生图”并打开面板，配置以下项目：

| 字段 | 含义 |
| --- | --- |
| Base URL | 服务的API根地址，例如 https://api.openai.com/v1。插件保留路径前缀；无参考图时追加 /images/generations，有参考图时追加 /images/edits |
| API Key | 可选，按服务要求填写；允许无Key服务。单独私有保存，留空保持旧值，明确清除才移除，不回显 |
| 模型 | 填服务实际支持的生图／图片编辑模型名，不依据聊天模型列表猜测 |
| 超时 | 一次生成及结果读取允许等待的时间，默认180秒，可设1～600秒 |
| 默认尺寸、质量 | 可选。尺寸接受正整数WIDTHxHEIGHT或服务原生标识（包括auto）；单次size可覆盖保存默认，空串不传尺寸并使用服务默认。实际支持由模型服务决定 |
| 返回格式 | 可留空，或明确选择 b64_json／url，需符合提供商与模型的实际支持 |

固定每次生成一张图。仅兼容聊天接口的服务不一定支持Images API；此插件不会自动切换到Chat Completions、Responses或其他生图协议。服务返回Base64图片或图片URL均可处理，下载图片时不传API Key或Cookie，不跟随重定向。图片编辑需要目标服务支持OpenAI Images的 /images/edits 接口；不支持时会由服务返回明确错误，不会退回文生图猜测。

Base URL或模型未配置时，面板明确提示补齐实际服务配置；Key为空不能单独判为未配置。保存或连接只检查本地配置，不会偷偷生成图片，也不能据此判断服务认证、模型、尺寸支持或余额已经验证。点击明确标注可能计费的生成按钮，或由已获MCP授权的Agent调用，才会实际请求提供商。

## 手动生成与编辑

填写画面描述后点击“生成图片”。如需改图，先在“参考图（可选）”选择一张本机图片，再填写修改要求并点击“编辑图片”。两种操作都会创建异步任务，任务被接受后显示任务编号和状态，后台处理，页面仅在可见且有活动任务时更新状态。可以离开面板，回来后查询任务和结果；这不会自动再生成。

- queued／running：已提交或正在执行，尚无成功图片。
- succeeded：图片已取得并保存到本插件资源库。
- failed：服务明确拒绝或任务确定失败。
- unknown：超时、断网、取消或重启后无法确认提供商结果，可能已经计费，不能自动重试。

重复同一个request_id及相同参数会返回原任务，不会再次扣费；改参数或参考图不能复用原ID。每次只运行一个任务，超容量时在生成前拒绝。结果未知时先去提供商核对，不能把重新生成当成无成本刷新。

图片资源列表只读元数据，单项点击才取图片预览。预览和参考图临时Blob在页面隐藏、离开或取消时撤销。语言切换保留描述和配置草稿，不重新提交生成。图片归档保存在插件数据目录，卸载插件保留配置、任务及资源。

## 受控图片来源

图片编辑支持三种来源，均不接受任意本机路径或任意URL：

- 本机上传：只在主人打开的生图面板选择，大小按“设置 → 图片大小”，默认10MiB、可配1–50MiB，支持PNG、JPEG、WebP、GIF。
- 当前会话收到的图片：Agent使用 `source={kind:"received",messageId,imageId}`，其中 `imageId` 是消息的 image 段原始 `file` 引用，不是图片URL。Host 只允许当前会话已授权消息和图片引用，来源插件必须实现受控 `readReceivedImage`。
- 之前生成的图片：使用 `source={kind:"asset",assetId}`，assetId 来自 `image_get`／资源列表，只在本插件图片库内解析。

来源图片只用于本次请求和任务摘要哈希；任务、提交账本和普通界面不保存图片payload、会话消息正文或原始图片引用。任务列表只显示来源类型、媒体类型和字节数。

## MCP工具

生图启用且connected后，默认all下当前／未来工具及类型自动可用；主人可在MCP页保存custom精确例外并恢复all，默认开放保留配置功能。普通会话的生图需求优先由main仅context_ref交绑定子独立判断、调用实际工具，不先把“不能画”猜测当事实下发。生成可能计费，缺Base URL／模型报告真实未配置，Key按提供商要求可选；连接不代表业务验证。当前规则见[ADR-0035](../decisions/ADR-0035-会话代理自主处理与默认开放可配置.md)。

| 工具 | 用途 |
| --- | --- |
| image_generate | 用稳定请求ID提交一次文生图或单图编辑任务，返回jobId，尚不代表生成成功 |
| image_job_get | 查询任务，可有限等待状态变化 |
| image_jobs | 分页查看任务状态 |
| image_list | 分页查看已生成图片的元数据 |
| image_get | 读取一张图片预览及可发送的资源引用 |

`image_generate` 可传单次 `size`，优先于已保存默认；省略沿用保存值，显式 `size:""` 表示不向服务发送size。文生图JSON与单图编辑multipart采用相同规则，合法形状不等于模型支持；服务拒绝后不自动换尺寸、模型或请求ID重试可能计费的请求。

`image_generate` 的 `source` 是可选对象：不传为文生图；传 `{kind:"received",messageId,imageId}` 编辑当前会话收到的图；传 `{kind:"asset",assetId}` 编辑本插件已有图片。工具不接受任意路径、URL、贴纸或另一个插件的私有图片。当前会话图片的 received 来源需要调用 Agent 持有该会话对应的平台子代理 scope；主 Agent 若只有通用 MCP 权限，应先委派到对应平台子代理再调用。

AI应提交后用image_job_get核对最终状态，成功后再image_get获取实际图片。已接受的后台任务不会因子Agent正常回合结束而被取消，后续可由获准的主Agent或主人查询；撤销工具权限后旧Agent不能继续查询/取图。停用插件会中止其等待并报告未知，不代表提供商已撤销计费。图片返回MCP标准image块，模型若要看图还需Harness启用并实际支持图片输入；纯文本模型也可读取任务状态与资源元数据。

资源引用形如 `eating-asset://image-generation/<assetId>`，通过宿主公开资源服务交接。AI预览仍取Base64图片；发送则取当前授权的图片资产lease，来源插件与Host核验真实字节、大小、SHA-256和MIME，可信后台可获得固定blobs内的文件能力。模型不能提供路径或选择映射。QQ在主人确认共享目录且逐图本地校验通过时使用标准file，其他情况发送前选择Base64；当前云端默认auto且没有confirmed mapping，实际仍走Base64，用户以后配置三目录并确认一次才尝试file。本地校验不等于自动证明OneBot远端路径可读，未真人probe。生图不会自动发QQ或收藏到表情库，成功与发送分别核对；unknown不换传输或ID再发一次。映射设置见[QQ操作说明](QQ配置与功能测试.md)。

## 当前边界

第一版支持文生图和单图编辑，不提供蒙版、多图参考、批量生成或在线模型市场。输入参考图和输出图片均按主人图片设置校验，默认每张10MiB、可配1–50MiB；任务最多500个、图片最多500张、总图片256MiB，列表默认20条、最多50条，提示词最多12000字符。容量不是提供商的计费配额，图片原始大小限制也不是OpenAI官方协议的统一限制。

配置及库采用各自严格schema1，版本冲突拒绝覆盖。未确认的任务不跨重启重发。用户自己的生图Base URL和模型需自行填写，Key按服务要求可选；自动测试使用独立本地夹具，不使用真实付费凭据。
