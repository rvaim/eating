## 1. 子 Agent 的实例命名

统一为：平台－创建时绑定的登录账号－私聊／群聊－对方 QQ／群号。例如虚构账号：

- QQ-10001-私聊-20002
- QQ-10001-群聊-30003

同时修正原生创建标签、会话摘要及界面标题，不能只改某一处。登录账号取协议端核验的真实账号，不使用配置实例 UUID。切换登录账号后按既有绑定规则区分新实例，历史仍显示原绑定账号；不重建已有会话、不更换 UUID。

qq.private／qq.group 保持代理类型 ID，与具体运行实例名称分开。

## 2. 对话展示与真实消息来源

不再将原始 JSON／事件列表作为主要对话呈现。优先复用原生 Web 的对话和记录投影，再补 Eating 专有消息展示：

- 平台消息：显示真实发送者 QQ、接收账号、私聊对象／群号、时间和内容；有可靠昵称才补昵称。
- 内部协作：区分主 Agent 的委派、子 Agent 的回报、框架完成通知，不能都称为“用户”。
- 模型输出：标明具体来自主 Agent 或哪个实例，不冒充已经发送到 QQ 的消息。
- 工具：以独立可折叠记录呈现调用和真实回执，明确成功、失败、未发送、结果待确认。
- 系统配置与运行时时间：独立查看，不当作 QQ 聊天气泡反复铺开；保留历史事实，正确处理原生记录的替换关系。

继续过滤内部推理，不新增一套 Eating 聊天档案。保留现有独立滚动、稳定会话导航、吸顶留白、键盘和窄屏能力。

## 3. 时间使用原生 time-context

采用负责人选定的 time-context，不另做主动取时工具，不附带提醒／调度权限。

- 默认系统模板不再包含每轮变化的实时时间，让系统规则前缀保持稳定。
- 主、子 Agent 的相应作用域挂载官方组件；默认时区 Asia/Shanghai，刷新间隔采用原生默认 600000 毫秒。
- 仅在 Agent 本来要执行合格步骤时判断是否追加读数，不后台定时唤醒模型。
- 读数作为来源明确的运行时上下文追加到历史末尾；显示为“运行时时间”，不伪装联系人发言。
- 实施前检查所有系统层的时间引用；已保存自定义正文的必要调整单列，不顺带重写人格或其他规则。

实际缓存收益取决于模型服务。验收稳定系统前缀与正确注入，不以原生日志条数推断缓存命中，也不承诺具体命中率。

## 4. 接入原生 DSH Web

首版采用独立本地页面，Eating 的 DSH 面板提供入口；暂不做 iframe 嵌入。

核心结构：同一 Eating 专属 DSH 进程同时提供 SDK 控制入口与原生 Web，共用既有主／子 Agent、会话、预设和权限。不能再启动第二个进程共同写同一数据目录，也不连接用户主 DSH 的 Profile。

具体工作：

1. 构造 Eating 专用运行组合：保留现有 SDK 与受控桥，加入官方 Web 必要服务、鉴权、前端和客户端模块；不整体套入 standard 的默认提示词与工具。
2. 处理两套启动入口和 stdio：Web 不向 SDK 的 JSON-RPC 标准输出打印普通启动信息，不自动弹浏览器；监听参数通过受控配置提供。
3. Web 入口和就绪信息交由 Eating 私有桥接，用户点击后经主人管理接口取得当前入口。端口、鉴权及生命周期随实际进程更新，不把登录凭据交给模型。
4. 网页关闭不停止 QQ 自动处理；Harness 停止则 Web 一同退出。与主 DSH 的数据及鉴权隔离。
5. 加载 Eating 消息展示插件，使原生对话能理解平台消息包、主子委派和实例身份；原生页面不会自行把 QQ JSON 变成有发送者的对话。

**首版拟定范围：查看已有主／子会话、历史、工具回执、系统和时间上下文。** 网页直接发言、新建任意会话、第二套模型／人格／权限配置入口不默认开放；如希望首版一并支持，请在确认时指出。只读限制须在后端落实，不能只隐藏按钮。

已确认官方组件和同版本前端入口存在；SDK＋Web 的具体组合尚未运行验证。先以临时数据验证，不将源码可行性当作已经可用；遇到集成阻碍及时报告，不擅自改成双进程共享会话或复用主 DSH。

## 5. 通过 MCP 让执行子 Agent 按需看图

首选增加受控的“查看本会话图片”扩展工具，已有 OneBot get_image 仍保持协议查询语义。

链路：收到的图片引用 → 取得真实图片字节 → 标准 MCP image 内容 → DSH 原生附件 → 支持视觉的模型。不是把 URL、路径或 Base64 当普通文字交给模型。

- 只准读取当前账号／会话已授权的图片引用，不接受任意本机路径或任意网址。
- 有可用图片 URL 时受控获取，检查格式、大小和超时；只返回远端文件路径且无获取接口时明确说明不可取，不猜下载地址。
- 本次不默认登录 OneBot 服务器或部署额外远端服务；若现场只有远端路径，先报告所需资源接口。
- 扩展 Eating 的 MCP 多模态结果表达，复用已核实支持图片的 DSH MCP 客户端与附件机制；不开放通用文件／Shell 权限。
- 模型必须实际支持并正确声明 image 输入。不凭型号猜能力，不靠改声明把纯文本模型变成视觉模型。
- 先让负责该 QQ 会话的子 Agent 看图并回报主 Agent；主 Agent 直接看原图、自动随消息附图或另外配置视觉服务，不默认扩展到本次。

此项需要模型线路与工具端到端验证。回环测试确认真正的图像块进入请求；真实提供商识图不在未经授权时主动调用，不把模拟通过表述为真实模型已能识图。
