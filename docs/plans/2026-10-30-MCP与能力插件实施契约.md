## 已授权范围

侧栏增加 MCP 与插件管理；通讯机器人和 Harness 都是插件类型，新增 capability 类型。两种 MCP 来源都支持：直接配置 stdio／Streamable HTTP，以及安装插件提供的 MCP。各插件独立面板、配置、数据和启停。交付表情包插件，含手动图片添加、AI 当前会话图片收藏、描述、标签、元数据分页及取用发送。

当前契约统一升级插件 API4、共享包4.0.0、应用／Host／Web0.11.0、QQ0.11.0、DSH0.8.0、stickers0.1.0。现有数据 schema 不因此修改，不保留旧运行接口或旧格式回退。旧生产代码包需停机备份后替换，新 Host 只加载 API4。

## 目录与管理 API

- `GET /api/mcp`：`McpDirectorySnapshot {protocolVersion:1,revision,services,agentTypes}`，公开类型见 plugin-sdk capabilities。
- `POST /api/mcp`：`{operation,input}`。operation 为 save/connect/disconnect/delete/save-grants。
- save：`{expectedRevision,id?,name,transport,...transportFields,autoConnect,grant:{agentTypeIds,toolNames}}`。stdio 字段 command/args/env/clearEnvKeys；HTTP 字段 url/headers/clearHeaderKeys。秘密省略保留，显式 clearKeys 才删除。
- connect/disconnect：`{id}`；delete：`{id,expectedRevision}`；save-grants：`{id,expectedRevision,agentTypeIds,toolNames}`。
- 目录展示连接状态、来源和授权，不能把安装/启用/连接/已挂载混为一谈。插件来源不可独立删除。通讯插件已有会话权限仍由自身面板管理，不能通过能力页取得无范围 QQ 权限。
- `GET /api/plugin-packages`：`{protocolVersion:1,plugins:[现有workspace插件信息]}`。
- `POST /api/plugin-packages`：preview `{sourceDirectory}` 返回 `{planId,manifest,packageBytes,digest}`；install `{planId,confirmed:true}`；uninstall `{id,confirmed:true}`。只安装本机可信构建目录，先验证不执行，确认安装同一份 snapshot。
- enable/disable 沿用 `/api/plugins/:id/enable|disable`。#plugins 显示统一目录，#plugins/:id 打开能力插件自带面板，机器人/Harness保留业务视图。

## 直接 MCP 模块

`DirectMcpConnections(dataDirectory)`：revision、list/get、save、remove、connect/disconnect、call、close。只此模块负责官方 MCP Client 与 transport，不写第二套协议。

配置私有 schema1＋revision CAS。保存不执行命令；连接才启动，stdio 不经 shell。连接/调用有界，不自动重试外部动作。公开摘要只含 env/header 名称，无秘密值；连接状态不伪造。call 返回标准 CallToolResult，由 Host 授权网关处理稳定动作标识和回执。

## 能力与资源边界

`CapabilityInvocationScope {agentId,agentTypeId,source?:AgentInvocationScope}` 由 Host 传入，不能由模型参数构造。主 Agent/普通 Harness 会话使用 main 授权；QQ执行代理使用真实类型和当前 source。主可使用获准的通用能力，QQ发送仍保持会话范围。

Host 为每 Agent、每服务签发独立短期访问凭据，仅列出已授权的工具；停用服务/插件或撤销授权立刻拒绝调用。拓扑/授权变更后停止受影响 Harness，让下次启动按新工具表挂载，明确提示，不偷偷保留旧工具。直接 MCP 和能力插件进入同一授权目录；原通讯 MCP 仍有现有账号/目标/引用守卫。

plugin-sdk 新增：

- `HostPluginContext.resources?: PluginResourceServices`。
- resources.readReceivedImage(scope,{messageId,imageId})：从真实通讯插件取得获准图片；不接受任意 URL 或文件路径。
- resources.readAsset({pluginId,assetId},scope?)：检查来源插件启用与读取工具授权，再读取插件导出的图片资源。
- `BackendPlugin.invokeCapability?(name,input,requestId,CapabilityInvocationScope)`。
- `BackendPlugin.media?:{readTool,readAsset(assetId)}`。
- `BackendPlugin.readReceivedImage?(reference,AgentInvocationScope)` 供通讯模块按现有权限公开资源。
- `HarnessHostServices.getCapabilityMcpConnections(scope)` 返回 `HarnessCapabilityConnection[]`，含 id/serverName/url/headers/tools；DSH 主/普通会话与 QQ 子按不同授权挂载。

图片资源为 `{mimeType,data}`，data 为有界 canonical base64，不是宿主本地路径。标准 image 段可使用内部 `eating-asset://<pluginId>/<assetId>` 引用，QQ在真正调用OneBot前经公开资源接口转换成标准图片数据，保持平台协议不变；原图不进入Host动作账本。

## 表情包插件

目录 `plugins/capabilities/stickers`，kind capability，API4，面板与数据归插件自身。单图<=5MiB，PNG/JPEG/GIF/WebP，验证实际文件字节；以内容 sha256 为稳定assetId，同图重复导入不覆盖已有描述/标签。数据 schema1＋revision，原子写与串行修改，坏数据不覆盖；容量有界。

item：`{assetId,description,tags,mimeType,bytes,createdAt,updatedAt}`。description必填1..1000字符，tags最多32个、各<=32字符。列表仅元数据，默认20、最多50，offset/limit/total/hasMore/nextOffset，标签AND筛选，query匹配描述/标签，createdAt降序＋assetId排序；expectedRevision可防分页期间变更。update/delete必须revision CAS。

MCP：sticker_add、sticker_list、sticker_get、sticker_update、sticker_delete、sticker_list_tags。副作用含稳定request_id。AI add输入 `{source:{messageId,imageId},description,tags}`，须scope.source，通过resources.readReceivedImage取得当前真图。owner manage add可传本地上传base64；其它管理操作复用核心。get MCP返回图像content和structuredContent的item/revision/sendable标准image段，file为内部资源引用；owner get可返回图片data供临时Blob预览。UI隐藏/离开清理Blob，不后台拉全库。
