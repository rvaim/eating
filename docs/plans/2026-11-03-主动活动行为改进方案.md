# 主动活动行为改进方案

状态：**待审方案，未实施**。日期：2026-11-03，Asia/Shanghai。

本方案针对“主动活动经常认为没什么可干，希望允许主动找人聊天”的反馈。本方案只交付文档，不实施社交动机、调度状态机、默认配置、主人配置、人格或自定义提示词调整。同轮队列与普通／主动入口会话身份修复另见[ADR-0038](../decisions/ADR-0038-空闲整批交接与统一会话身份.md)，不将其描述为本方案已实施。不部署、不读取真实凭据、不调用付费模型、不向真人发消息。后文行为优化测试均为建议验收，未因编写本方案而执行。

## 结论与证据范围

当前实现已经允许主 Agent 自主联系获准对象；“自然闲聊”不需要新增一种后台权限，也没有代码要求联系任务必须具有工作价值。问题优先从行为指引入手：现有文案反复强调可以沉默、不制造任务，却缺少明确的正向社交动机；模型一旦把“暂时没有待办”规划成 `waiting`，调度器就会停止普通定时机会，放大这次选择。

上述是静态实现可以确认的机制与风险，**尚不能证明用户这次现场反馈由其中某一项单独造成**。本次没有读取 Eating 现场模型配置、真实会话、实际模型请求或当前自主状态，不猜测现场使用的模型，也不把历史报告中的状态当作当前状态。

主 Agent 应能因为想交流而联系当前获准的人，例如问候、分享眼前想到的事、延续真实话题或轻松闲聊。聊天本身可以是自主活动，不需要先编造一个工作任务。是否联系、联系谁、何时休息，仍由同一主 Agent 根据实际上下文和人格判断；不要求每轮发消息。

## 具体原因与可信程度

### 行为文案倾向：明确允许沉默，缺少同等明确的社交选项

| 位置 | 当前规则 | 影响判断 |
| --- | --- | --- |
| [基础提示词：9](../../apps/host/src/authoring-defaults.ts#L9) | “我可以说话，也可以安静；不必每条都接，也不必为了结束一轮硬找话说。” | 是防止机械回复的合理规则，但没有明确说明无待办时也能因为交流意愿主动聊天。 |
| [主提示词：23](../../apps/host/src/authoring-defaults.ts#L23) | “不为了显得勤快制造任务，也不为了结束一轮硬发消息。” | 模型可能把主动社交也归入“制造任务／硬发消息”；这是解释上的风险，不能仅凭该句认定现场模型如此理解。 |
| [插件自主说明：141](../../plugins/harness/dsh/src/backend/adapter.ts#L141) | 活动例子为探索、创作、整理、休息、等待。 | 说明已经明确不要求先有人类任务，但没有把问候、分享、闲聊并列为正当活动。 |
| [插件自主说明：143](../../plugins/harness/dsh/src/backend/adapter.ts#L143) | “不要求每轮发消息，可以保持沉默”，并要求不重复催促未回复的人。 | 该行同时明确允许 list/contact，不能概括成禁止主动联系；需要补正向动机而非删除防催促边界。 |
| [机会指令：131](../../plugins/harness/dsh/src/backend/autonomy-runtime.ts#L131)、[132](../../plugins/harness/dsh/src/backend/autonomy-runtime.ts#L132) | 每次机会强调“按当前需要”行动、休息或等待，“无需例行发消息”。 | 在每次无输入机会中重复强化；可优先改成同时包含自主社交与合理休息的平衡指引。 |
| [活动安排：25](../../apps/host/src/authoring-defaults.ts#L25) | 已有安排还合适就保持。 | 对正确安排有用；若模型先前选择无限等待，可能延续这一选择，需把 waiting 的实际效果说明清楚。 |

这些规则是模型行为指引，不是代码硬禁令。不能为了让 AI 积极而反向规定每轮必须行动、每轮列全体联系人或固定发送问候。

### 调度确定机制：waiting 无限停止普通机会，有界休息会再醒

[准入实现：189](../../plugins/harness/dsh/src/backend/autonomy.ts#L189)在没有到期 agenda 时拒绝 `waiting` 的普通机会；[状态实现：126](../../plugins/harness/dsh/src/backend/autonomy.ts#L126)给 waiting 返回 `nextWakeAt:null`；[安排实现：214](../../plugins/harness/dsh/src/backend/autonomy.ts#L214)将该选择持久保存；[结束实现：229](../../plugins/harness/dsh/src/backend/autonomy.ts#L229)只为 active 安排下一轮。

因此，`waiting` 不是“这一轮不发消息”，而是无限停止普通定时思考机会。没有新输入或到期任务时，AI 不会再次获得普通机会来改变主意。普通外部消息仍可被处理，但处理消息本身不会自动登记 active；模型需要显式改变活动安排。[恢复实现：152](../../plugins/harness/dsh/src/backend/autonomy.ts#L152)也保留这一语义：普通 resume 保留 waiting，wake 才强制切回 active。

已有[单元测试：50](../../plugins/harness/dsh/src/backend/autonomy.test.ts#L50)明确验证无限等待；这是现行契约，不是本方案认定的调度错误。建议保留状态机，把行为指引改为：

- 暂时没有具体事情、只是想歇一会：选择 `sleeping` 到明确时间，或保持 `active` 按主人间隔再获得机会。
- 确实希望等待外部事件、在没有事件时不再定时思考：选择 `waiting`，并理解它没有普通自动重评时间。
- 约定未来办一件事：按当前授权使用 Eating agenda；到期仍受主人暂停、额度和运行时约束。

不静默给 waiting 加模型心跳，不通过原生提醒绕过 Eating 活动安排。若产品希望增加“空闲也定期再考虑社交”，应另经审查定义主人可配置节奏，优先复用已有 sleeping／active／agenda，不新增第二个认知循环。

## 建议修改点

### 第一优先：补足正向社交动机，保留现有调度和许可

1. 调整[基础／主默认提示词](../../apps/host/src/authoring-defaults.ts#L9)及[插件自主说明](../../plugins/harness/dsh/src/backend/adapter.ts#L141)：明确问候、分享、延续话题、自然闲聊本身是活动；不必等人类先给工作任务，也不必让目标先私聊。继续允许安静与休息。
2. 调整[自主机会指令](../../plugins/harness/dsh/src/backend/autonomy-runtime.ts#L131)及[必需自主规则](../../plugins/harness/dsh/src/backend/autonomy-runtime.ts#L5)：平衡“可以联系”和“可以休息”，解释 waiting 无限停止普通机会；[活动工具说明](../../plugins/harness/dsh/src/backend/autonomy-runtime.ts#L47)也应明确 waiting 与 sleeping 的区别。
3. 在[必需联系规则](../../plugins/harness/dsh/src/backend/contact-runtime.ts#L5)和[联系工具说明](../../plugins/harness/dsh/src/backend/contact-runtime.ts#L64)中明确“联系任务可以是闲聊／问候”，作为真实能力与授权合同；兴趣、频率偏好和语气仍尊重主人自定义与人格。
4. 保持[唯一 complete provider 组合](../../plugins/harness/dsh/src/backend/runtime-agents.ts#L233)及[注册：257](../../plugins/harness/dsh/src/backend/runtime-agents.ts#L257)，不另加会被 complete 抑制的普通 section。必须在实际模型 request.system 中验证送达。
5. 将防骚扰指引聚焦具体事实：明确拒绝、明确不便、已经发出尚未回复及当前频率。保持“不重复催促尚未回复的人”；不扩写成凡是无人主动请求就不准聊天。

建议文案示例，供审查后按层次拆入对应位置：

> 没有待办时，我也可以主动找当前获准的人聊聊：问候、分享眼前想到的事，或延续真实话题。聊天本身就是活动，不用编工作理由，也不用等别人先开口。我先核对当前可联系对象与工具，让对应子代理结合自己的会话历史和人格自然表达；尊重明确拒绝和不便，不连续催促没回复的人。只是暂时没想好做什么时，我可以休息到一个明确时间再看看；只有决定等真实外部事件时才登记 waiting。我不需要每轮联系别人，也不需要为了证明自己活跃而硬发消息。

主动聊天示例：当前许可允许联系好友，AI 想分享刚想到的一个轻松话题。主 Agent 读取状态及当前可联系对象，选择真实获准目标，委派“和对方自然聊聊这个话题，结合本会话历史与人格决定表达，不预写固定文案”。目标子代理自行组织内容并通过实际获准通讯工具发送；主 Agent 核对 Host 回执，再决定继续活动或有界休息。该过程不要求新的私聊入站，也不把当前群上下文冒充私聊授权。

### 参考qq-bridge后补充的社交动机（方案，未调整调度）

主人已同意参考第三方仓库中的聊天参与思路。本轮先落实普通会话的选择性接话、自然停顿与人格草稿示例；主动活动部分在本方案补足正向动机，不因此启用定时活动、改waiting／sleeping、增加联系额度或强制每轮联系。

- 有真实兴趣、想分享的见闻、想延续的约定或可披露的共同话题时，交流本身就是活动，不需要另找工作理由；内容来自实际上下文、已核实资料或获准记忆，不编造刚吃饭、刷到视频等生活经历。
- 联系前仍核对当前对象、关系、话题是否相关和主人许可；没人回时不追着发，明确不便或拒绝就尊重。先有想表达的具体内容，再决定是否联系，不用固定寒暄或例行问句凑一轮。
- 被唤醒代表有机会重新选择，不等于必须工作、必须说话或默认潜水。暂时没想法可以有界休息；真正决定等外部事件才用waiting，状态语义保持。
- 群聊已有热闹话题时优先自然加入，而不是另起主持式话题；群和私聊可以有不同语感，同一身份与人格保持，跨会话事实仍由主协调核实。

参考来源为[qq-bridge二代预设](https://github.com/Derpyu520/qq-bridge/blob/b80fa51bc03fc4d5a1ef9a4cad7029e796b8fc67/dsh/agent-presets/qq-chat-v2/agent.cordis.yml)的主体性／参与时机原则，自行按Eating当前契约编写；不采用它的固定字数／条数、强制等待、故意乱答、跨会话一律拒绝或固定鲸鱼身份。

### 可选增强：给机会提供只读机械上下文

[claim 返回：200](../../plugins/harness/dsh/src/backend/autonomy.ts#L200)当前的 limits 只有间隔、周期和连续时长信息；[机会信封：133](../../plugins/harness/dsh/src/backend/autonomy-runtime.ts#L133)没有联系额度或策略摘要。可考虑附加现有真实 `contactLimit` 和 `contactPolicy` 摘要，降低依赖旧对话猜权限的概率。

这项增强不等于推荐目标，不把 entryCount 当实际候选数，不保存聊天正文或联系人历史，不替代 list 当前实际对象，也不强制每轮查询全目录。是否需要应在提示词改进验证后决定。

### 默认与自定义的应用方式

[作者服务：133](../../apps/host/src/authoring.ts#L133)明确：基础与插件文档仅在 `updatedAt:null` 时跟随当前默认，非 null 保留主人正文。人格模板更新也不自动改变已保存人格。

后续实施必须区分“代码默认已更新”“实际 request.system 已含必需能力规则”“主人自定义仍保留旧行为偏好”。不能仅因改了默认就宣称现场人格已经改变，不能自动 reset、迁移或覆盖现有正文。若需要调整实际自定义，先给主人展示具体差异，按其后续授权保存。

## 必须保留的实际授权边界

- 主 Agent 自主选择目标与任务，受限子代理独立理解和组织表达；普通当前会话仍用 handle_conversation，跨目标仍 list/contact，不给主 Agent 全权 QQ 令牌。
- [联系轮次准入：129](../../plugins/harness/dsh/src/backend/agent-control.ts#L129)核对真实 main turn；[任务准入：151](../../plugins/harness/dsh/src/backend/agent-control.ts#L151)核对账号、对象、类型、工具、策略 revision 和额度；[MCP 有效性：176](../../plugins/harness/dsh/src/backend/agent-control.ts#L176)继续检查当前轮次、截止时间与策略。
- [联系子输入：83](../../plugins/harness/dsh/src/backend/contact-runtime.ts#L83)使用独立受信来源和 `events:[]`，不继承旧入站消息／资源权限；首次联系不能假定子代理拥有另一会话的历史。需要背景时，只提供当前允许披露的事实与交流意图，不伪造 message/resource 引用。
- 联系仍按任务数共用每小时6次默认额度，[计数位置：180](../../plugins/harness/dsh/src/backend/agent-control.ts#L180)在任务接受时计数，不能解释成仅成功发送才计数或按消息条数计数；读取状态和安排 active 不恢复额度。
- [防重：164](../../plugins/harness/dsh/src/backend/agent-control.ts#L164)保留重复 callId、pending／unknown 阻塞、每目标当前轮次32调用和绑定容量限制；unknown 不自动重发，不删除动作账本。
- [轮次结束撤权：58](../../plugins/harness/dsh/src/backend/contact-runtime.ts#L58)、策略保存撤权、主人暂停、周期取消、运行时停止、异步资源取得后和真正发送前的授权复查保持。
- `enabled`／`ownerPaused` 只控制 Eating 无输入机会及真正自主周期；普通有输入 main turn 仍可按当前策略联系。Eating 暂停不承诺冻结所有原生提醒和目标。
- 不自动开放通讯名单，不提高额度，不恢复原生功能全开，不改主人主 DSH 或官方 Web，不为行为验收使用真实凭据向真人试发。
