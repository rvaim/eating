# 安卓手机控制插件设计草案

日期：2026-11-14，修订：2026-11-15。状态：已按本草案实施并完成本地验证，尚未commit／push／部署。当前方向为完整 ADB 命令能力＋自主手机子代理；主人已否定固定游戏时长、每日额度和强制冷却的设计。

## 1. 当前方案

Eating 新增独立 `android-control` 能力插件。Harness 通过 MCP 调用通用 ADB 执行接口；执行端启动实际 ADB 二进制，原样传递命令及参数。MCP 是接入协议，不是命令白名单。

模型可以使用当前安装版本 ADB 提供的全部子命令与选项，包括任意 `adb shell`／`exec-out`、install／uninstall、push／pull、logcat／bugreport、connect／pair／disconnect、forward／reverse、tcpip／usb、reboot／root／unroot／remount、start-server／kill-server，以及帮助中新增的其他命令。不维护需要升级插件才能放行的子命令枚举。[ADB 官方命令手册](https://android.googlesource.com/platform/packages/modules/adb/+/refs/heads/main/docs/user/adb.1.md)

```mermaid
flowchart LR
  H[Harness 主／子 Agent] -->|MCP：完整 ADB 命令| P[Eating 安卓插件]
  P --> E[实际 ADB 执行端]
  E -->|USB 或网络 ADB| A[安卓设备]
  E -->|输出／进程／文件／图片| P
  P --> H
```

手机由独立的执行子代理自主操作，继续使用同一身份、人格与所选 Harness。它自行理解目标、探索应用、安排继续或休息；主 Agent 负责整体协调，继续处理聊天和其他事情，可交流进展、追加事项或中断，不逐条审批 ADB 命令。不新增手机专用规划模型或第二套 Agent Loop。快捷截图等功能可以提供，但不构成完整命令执行的前置条件。

独立手机角色需要扩展现有通用执行角色与委派入口，不伪装成 QQ 私聊／群聊子代理。使用 Harness 原生可持续、可恢复的子会话；会话可继续存在，不意味着需要无输入空转调用模型。继续、休息、结束及以后再玩的安排由主子代理结合实际情况决定。

## 2. 对外 MCP 接口

| 工具 | 用途 |
| --- | --- |
| `android_executor_control` | 查询执行端状态、释放控制或由主协调接管 |
| `android_adb_exec` | 执行完整 ADB argv；短命令返回结果，长命令返回进程句柄 |
| `android_process_read` | 查询进程状态，按游标读取有界 stdout／stderr |
| `android_process_write` | 向自己的进程写 stdin、发送终端输入或关闭 stdin |
| `android_process_stop` | 中断或终止自己的进程，回报实际停止状态 |
| `android_files` | 传入执行端所需文件、取得输出文件或查看元数据 |
| `android_screenshot` | 可选快捷工具，直接返回模型可看的 MCP 图片 |

通用执行接口示例：

```json
{
  "args": ["-s", "DEVICE_SERIAL", "shell", "getprop"],
  "request_id": "adb-getprop-example-001"
}
```

设备端 shell 脚本示例：

```json
{
  "args": ["-s", "DEVICE_SERIAL", "shell", "sh", "-c", "'pm list packages | head -20'"],
  "request_id": "adb-shell-example-001"
}
```

实际设备端 quoting 按所用 ADB 的远端 shell 语义验证；模型明确提交的 shell 程序作为命令执行，不重新解释成预设动作。执行工具说明提供经测试的 argv／stdin 示例，避免把主机参数转义与设备端 shell 语法混为一谈。

执行端固定启动配置的 adb 可执行文件，argv 不经本机 shell 二次解析。模型可以传全部 ADB 全局选项与子命令，不偷偷追加冲突的 -s 或重写目标；不得把 shell=false 宣称为设备端命令受限。

工具还接受执行等待时间、stdin 文本／二进制文件引用、是否申请终端、输出模式等通用参数。request_id 和真实调用身份由现有 Host 契约核验。没有必须提供的 observation_id，没有每次只能点一下的限制，也不要求先安装手机输入助手。

## 3. 长命令与交互

logcat、wait-for、交互 shell、长文件传输等不能被当成一次普通 HTTP 调用。执行端保存进程状态，初始调用等待一小段可配置时间；未结束则返回 process_id，由后续工具继续读取／写入／停止。

- stdout 与 stderr 保留区分，返回 exitCode、signal、running／exited／unknown 和输出游标。
- 文本输出按块读取，超出内存窗口写入有界结果文件并返回截断／保留情况，不假装已经完整返回。
- 支持 stdin、关闭 stdin、显式终端会话和终端控制；Ctrl-C 等须经实际终端／进程语义处理。
- 同一控制者可以同时运行多个进程，例如后台 logcat 与前台 shell／截图。
- 单次 MCP 等待超时只决定何时返回进程句柄，不结束手机活动或后台命令。进程运行到自然退出、代理主动停止、主人接管、真实故障或授权撤销；不为自主手机活动设置总运行倒计时。
- 关闭、重启及网络中断时保留已知进程结果；无法恢复的运行态记 unknown，不重新启动原命令。

进程句柄绑定实际执行端、调用者与原授权代次，不由模型提交 agentId／scope 冒认。实现时验证 pipe／PTY 在目标平台的行为和依赖，不以模拟 stdout 替代交互验收。

## 4. 文件与二进制结果

完整 ADB 包含执行端文件操作，不能只做文本 stdout：install／push 读取执行端文件，pull／bugreport／keygen 等会在执行端创建文件。工具返回实际所在执行端和路径／文件引用，避免把云端 Harness 文件路径当成手机旁电脑路径。

默认工作目录只是文件整理位置，不是权限沙箱。完整 ADB 对执行端文件的可读写范围由执行端 OS 账户权限决定；插件不虚称对任意 argv、设备端 shell、转发或路径实行可靠应用级隔离。若以后需要更窄范围，应单独配置执行端 OS 隔离，不用隐藏的 ADB 子命令白名单改变本次需求。

普通结果返回结构化执行信息和文本；明确请求图片输出时验证实际图片字节并返回标准 MCP image block。`adb exec-out screencap -p` 可以直接走图片输出，模型无需另读主机路径。其他二进制结果保留为文件引用，不能损坏为 UTF-8 文字。图片遵守当前 Host 大小限制，超限明确返回结果状态。[官方截图方式](https://developer.android.com/tools/adb#take-a-screenshot)

`android_screenshot` 仅为便利入口，内部复用同一执行器。截图、UI 节点、归一化坐标和中文输入助手均可作为扩展，不限制完整 ADB；模型也能自己用 ADB 安装／启动选定的工具。不能把截图的 convenience API 当成手机唯一操作路线。

## 5. 本机与云端部署

同机时，执行核心与 Eating 后台在同一电脑／小主机运行，ADB 通过 USB 或网络访问设备。

云端 Eating＋本地手机时，在手机旁电脑／常开小主机运行执行端，云端插件经私有网络或 SSH 隧道调用。家庭设备位于 NAT 后，可由本地发起反向隧道，云端访问回环映射。执行端使用自己的 ADB 进程、设备连接和文件系统，网络转发仅承载插件与执行端协议，不把手机“插在”云服务器上。

MCP 输出格式在本地／远程一致。远程执行端也必须在派发前记录 request_id，网络回复丢失时能够查询原命令，不靠云端重发猜测。

USB 调试、无线配对、设备端 RSA 确认按 Android 原生要求进行。面板可以辅助配对和登记，但模型也可通过完整命令入口执行 pair／connect／tcpip 等命令，不能再将其一律藏在 owner-only 操作里。配置执行端地址、连接凭据及启停插件仍是主人管理行为。[官方 ADB 接入说明](https://developer.android.com/tools/adb)

ADB 的具体执行能力取决于设备、系统构建和账户权限。开放 root／remount 命令不意味着插件能让原本不支持的手机自动获得 root；直接返回设备的实际结果。平台权限限制和插件自行缩减命令能力是两件事。

## 6. 自主活动、协作与主人接管

授权单位是“一台执行端上的完整 ADB 能力”。插件沿用 MCP 默认 all 与主人 custom 工具／类型配置；给 Agent 开放通用 exec 即开放完整命令能力，不再承诺按应用、单个 shell 子命令或本机路径隔离。通用 exec 和 stdin 写入不能由模型自报为 readOnly；verify 只能使用明确只读的结果查询／截图等工具。

手机子代理不设置单次娱乐时长、每日累计额度、强制休息间隔或固定操作次数，不新增对应的到额暂停和恢复流程。主子代理自主决定玩多久、玩什么、何时休息和处理其他事情。也不以“可配置默认值”的形式重新放回主人刚否定的作息限制。

现有普通子任务的 15 分钟硬截止不能直接套到持续手机活动上；手机角色需要独立生命周期，不能靠不停更换 task_id 绕过旧限时。主 Agent 的自主轮次结算也不能一直等待手机活动结束。已有主人保存的全局自主设置保持，具体关联在实现通用执行角色时明确，不在本轮修改运行配置。

完整命令可能涉及整个 ADB server、多个设备及连接管理。执行端维护真实控制者和进程归属，避免多个执行者无意交错操作；主子代理自主协调使用，同一控制者可同时启动多个命令。占用、输出与进程列表在面板可见，正常探索不强制逐条回报或人工确认；主人可以直接要求停止或接管。

模型明确调用 `adb kill-server` 时按命令执行；插件自己的“停止任务”只停止其在途进程，不擅自将全局 kill-server 当成自动清理。连接超时、取消信号和进程状态用于管理实际故障，不转化为娱乐活动时长限制。手机端已启动的后台活动单独核对，不把关闭模型／MCP 直接当成全部手机活动已停止。

能力授权、执行端配置和当前调用身份仍由后台确认，屏幕／网页／日志正文仍是数据。这里的校验用于确认谁在调用哪台执行端，不用于偷偷删减已经开放的 ADB 命令。

## 7. 回执与恢复

命令派发使用稳定 request_id。Host 与执行端分别记录原意图摘要、派发状态、进程句柄和最终结果；相同请求查询原记录，不自动重放。原始命令／stdin 可能含秘密，普通日志和 Host 动作账本不保存明文；回执摘要使用私有意图校验材料，不回显凭据。

结果区分未派发、已知失败、命令已完成与执行结果未知。exitCode=0 说明该命令正常返回，不等于对应应用的业务目标已完成。模型自行选择截图、查询或继续命令核对效果，不强制采用单步点击流程。

命令完成但截图／文件返回失败时保留原命令回执；网络恢复不重复执行 install、输入、重启或 shell 脚本。未知状态针对原请求／进程处理，不永久封锁后续独立任务或要求主人每天盯面板确认。

## 8. 面板与验收

面板提供：本机／远程执行端、连接与设备状态、完整命令测试台、进程与输出、文件输入／下载、可选截图、主人接管，以及原有 MCP 类型授权。命令台不只有固定按钮，模型和主人使用同一执行核心；不加入娱乐时长、每日配额或强制冷却表单。隐藏／离页停止 UI 轮询与 Blob 占用，不擅自结束仍获授权的后台命令。

验证重点：

1. 新的／未枚举的 ADB 子命令、全局选项及任意设备端 shell 均能到达真实 ADB，插件不靠命令名单放行。
2. install／uninstall、push／pull、连接管理、转发和重启在受控真机环境按实际结果验证；不将设备拒绝 root 误报为插件支持成功。
3. logcat／wait-for／交互 shell 支持进程句柄、stdin、终端、输出游标及明确停止；首次 MCP 返回不取消进程。
4. 文本、二进制、文件、PNG 截图均不损坏；实际 Host MCP → Harness 模型请求包含真实图片。
5. 本地主机 argv 与设备端 shell 分开验证；字面文本和用户有意提交的 shell 语法都不被错误改写。
6. 远程丢回复、插件重启、相同 request_id、主人接管及并发不会重放已派发命令。
7. 文件位置明确指向实际执行端；多进程协作和 server 级命令不被逐设备锁错误拒绝。
8. 手机子代理能持续活动并自主休息／结束；超过普通任务 15 分钟、主 Agent 收到其他消息、面板关闭等情况不会机械结束手机活动。主人明确停止仍能传达并核对真实进程状态。

设计阶段只修改草案；2026-11-15实施已完成，使用系统DSH与本机／远程执行器夹具验证，真实ADB只运行无设备version，未连接手机或commit／push／部署。完整结果见[实现报告](../reports/2026-11-15-玩手机插件本地实现验证报告.md)。固定 android_act 动作集合、强制 observation_id、配对／APK 安装仅主人可用、必须安装输入助手及后来提出的娱乐额度／冷却限制均不采用。当前评审方向是完整 ADB 能力与自主手机子代理。
