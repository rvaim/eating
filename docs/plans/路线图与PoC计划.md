## 本轮前端子实验

首次前端子实验为历史，65项业务/5浏览器证明了导航与组件机制，记录见[首版说明](../research/首版平台验证说明.md)。负责人随后要求正式开发，产品中的飞书/微信占位入口已移除，QQ已替换为真实OneBot、Host配置与能力服务。当前使用见[QQ操作](../operations/QQ配置与功能测试.md)，真实结果见[账本](../research/PoC验证结果.md)。

该子实验覆盖 P0B-02 的前端独立增删和部分 P0B-03/04 的界面撤销/保存语义，不代表真实进程/后台依赖/模拟 Harness 已验证。

## Phase 0B：插槽与 Cordis 候选

范围：正式插件依赖、停用清理与前后端能力注册。当前QQ已使用真实后台，新增平台按真实需求独立实现；协议端/失败注入/备用Harness替身仅放测试目录，不作为可配置的产品demo。

- **P0B-01 契约与归属。** 模块/账号实例/页面贡献身份、版本、能力与依赖验证。重复 ID、缺依赖、不兼容或未批准模块明确失败，不执行代码后补审批。
- **P0B-02 独立增删。** 两个模拟平台并存，移除“飞书”只撤销其后台/账号能力/页面，保留“QQ”、共享服务及通用页；不靠修改其他模块或通用平台枚举完成。
- **P0B-03 前后端注册。** 模块自有界面在真实前端运行环境注册，后台仅提供契约/元数据；界面出现不等于连接成功。覆盖当前页面被移除、空目录、后台/前端一侧失败。
- **P0B-04 清理与重建。** 重复启停、依赖消失/恢复、晚到响应、异常清理、资源泄漏、撤销后无效高权限操作；使用真实插件依赖上下文，不仅 root Context。
- **P0B-05 模拟运行时。** 验证选择、能力差异、主控制者排他、关联与停用。将能力支持证据和当次调用结果分开，不把失败当不支持，不把模拟成功当真实 Harness 支持。
- **P0B-06 底座取舍。** Node.js/TypeScript 候选下比较实际 cordis/@deepseek-ai/cordis 包与固定版本的 API、清理、前端接入成本；Cordis 上游 API 未稳定，候选不合适可替换。

成功：无平台硬编码，独立增删/撤销有证据，局部失败可见。功能解耦测试不证明进程或 OS 隔离；真实崩溃/阻塞另测。风险：框架 API 漂移、前后端生命周期不一致、同进程副作用，见[插槽](../architecture/插槽式扩展.md)与[Cordis](../technical/Cordis选型评估.md)。

## Phase 1：首个真实适配器（DSH）

1. **P1-01 发行包/握手。** 固定发布包与源码关系，核对真实导出/initialize、版本、错误和退出；不连接用户主 DSH。
2. **P1-02 隔离。** 显式 DSH_HOME、DSH_AGENTS_HOME、Profile、工作区/持久根，用 A/B 数据集 sentinel 验证不互串、不改主环境；另核插件远端存储与凭据。
3. **P1-03 主运行脉络。** 先订阅再投递，保存包含适配器/配置身份的真实 Session 映射；惰性句柄不是创建，复用不产生第二主会话。通过 Eating 契约暴露结果，不把 SDK 对象泄漏给通讯或 UI。
4. **P1-04 配置/能力。** 验证 Profile/patch 对人格和工具的贡献，证明 Preset 不自动套用；找最小正确扩展点，必要时再评估薄桥。声明真实可用能力并核权限边界。
5. **P1-05 正常恢复。** 同根显式 resumeSession，核 ID、历史、工作区与配置；缺失/占用/损坏报错，不静默创建替代。
6. **P1-06 崩溃窗口。** 受理后、事件可见后、耐久屏障后中断，测实际丢失/保留与确认缺口；SDK 无通用 history/flush 不可假装支持。

通过最小模块实验后，首个真实模型实验只做 P1-01～P1-03，不同时搭完整桌面/所有连接器。停止、预算和测试输入执行前明确。

后续 **P1-07 第二种真实 Harness**：先核官方 API/许可/能力，再在独立适配器接入，验收通讯和通用管理逻辑无需变化。Codex/Claude Code 只是候选，具体对象未定。跨运行时原生会话、记忆迁移和热切换不作为已具备能力。

## Phase 2：模拟通讯与持久桥

依赖：真实适配、运行存储与标识方案。使用已注册模拟平台/唯一主运行脉络，不先接真实即时通讯。

P2-01 接收落盘/去重与写入失败；P2-02 忙碌/休息/运行时离线投递，按能力处理；P2-03 保存未投、已接受未记账、断流重启；P2-04 模拟平台 actionId/真实结果查询，验证输出幂等；P2-05 伪造主人、重放批准与跨联系人隐私；P2-06 移除某平台时在途/积压事件的保留与重新启用。

成功：每个输入有可追踪归宿，未知确认明确记录，不盲目重复外部动作。DSH 普通 SDK 不支持 steer/inject 或历史 replay，其他运行时分别核查，不静默降级为同样语义。

## Phase 3：有预算的自主性

依赖：所选 Harness 真实满足必需能力、主人选择的兼容记忆机制、受限工具和预算/暂停。执行前定观察时长、上限与评价规则。

P3-01 无主人任务时行动或合理等待；P3-02 工具/子 Agent（支持时）；P3-03 继续/放弃/休息；P3-04 自设唤醒、休眠/漏发/重复；P3-05 经历读写/记忆失效；P3-06 同一运行时重启连续性；P3-07 成本、并行、重复无进展和暂停。

缺少必要能力时记录产品缺口/限制，不由 Host 第二套认知循环补造。DSH Schedule 写入窗口为具体实验，不能推广到别的运行时。成功需正负样例与真实时间线，短实验不证明长期可靠；低频兜底策略仍待讨论。

## Phase 4：授权与隔离

P4-01 并发请求/模糊回复/过期/撤销/重放；P4-02 未批准模块安装/激活/升级与配置；P4-03 Harness Shell/文件/子 Agent/MCP/原生安装/自动更新以及后台插件与可执行页面旁路；P4-04 批准后注册/发现/必要重启恢复；P4-05 失败副作用、依赖归属和回滚；P4-06 模块独立进程崩溃/阻塞、停止超时和凭据访问。

成功：新增能力受可信主人目标/版本/操作批准，无旁路；无关模块继续服务的范围有实际证据。Cordis scope、Preset/工具清单不是安全证明。DSH approvedBuilds 不验证主人属于已知案例，其他运行时分别核查。

## Phase 5：桌面与所选运行时分发

最小壳/Sidecar后验证 UI/Host/选定 Harness 生命周期，托盘/关窗/全退出、干净系统、批准动态扩展、单实例、升级/迁移/回退以及三平台签名/原生 ABI/包大小/启动/CPU/内存。

不自动捆绑所有 Harness；各适配器依赖、许可、安装/连接方式待定。Windows/macOS/Linux 各有证据，不从一个平台推断其他平台，也不先承诺体积小或零中断切换。
