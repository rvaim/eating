## 当前实现范围

全局“概览 / 机器人”、机器人页内平台分类和模块自有面板继续保留，前后端贡献通过 Eating 契约注册。产品仅提供正式 QQ 插件，飞书/微信占位入口已删；协议夹具只在测试目录，不能称为产品 demo。

正式 Host 使用普通 Node.js >=24.9.0、TypeScript、Node 内置 SQLite、ws 和官方 MCP SDK。开发由 `pnpm dev` 联合启动 Host 5181 + Vite 5180，前端代理 `/api`；生产 `pnpm build && pnpm start` 由 Host 5181 同源提供 `dist`、API 与 MCP。Cordis 尚未成为真实底座。

QQ 包含四个正式页签：

- **连接配置**：正向统一 OneBot WebSocket，Bearer header，令牌不回显、留空保留/显式清除；原子保存后断开旧连接，手动连接并校验真实登录及 `online/good`，有限重连。
- **功能测试**：后台 schema 动态生成，与 MCP 共用 10 项工具目录，覆盖查询、本地消息、私聊发送、群聊发送和撤回。UI 手测发送/撤回逐次确认；稳定请求 ID 和操作账本防止未知结果盲目重试。
- **消息记录**：Host SQLite 实际收到的消息，按实例归属去重，面板显示最近50条，工具接口支持before游标；不是 QQ 全平台历史。
- **MCP 能力**：插件专属 Streamable HTTP `/mcp/qq` 与独立 Bearer，官方 SDK 握手、工具发现和调用；仅显式查看配置时显示 MCP 令牌。后续注册选定 Harness，当前未自动注册。

QQ 详细边界见[QQ 与平台能力](../architecture/QQ与平台能力.md)，使用见[QQ 配置与功能测试](../operations/QQ配置与功能测试.md)，协议依据见[QQ 协议与 MCP 核对](../research/QQ协议与MCP核对.md)。

## 数据、实例与投递

统一 `EATING_HOME`，默认 `~/.eating`，已获用户允许创建；QQ 自管 `bot/qq-bot`。版本化 `accounts.json` 保存 `defaultInstanceId` 与实例列表，配置位于 `accounts/<稳定本地实例 UUID>/config.json`，实际 QQ 号从登录获取。结构预留多账号，本版仅一个默认实例，没有第二账号添加、切换或并行 UI。

共享 Host 锁、SQLite、MCP 令牌位于 `host` 子目录；POSIX 下目录 0700、文件 0600，配置原子写入、损坏拒绝覆盖、停用保留。旧浏览器原型配置不自动导入真实账号。工具可选 `instance_id`，默认当前实例，未知实例拒绝；消息、账本和事件保留 `instanceId`，外发幂等按插件 + 实例 + 实际 QQ 号隔离。见[数据目录与账号实例](../technical/数据目录与账号实例.md)。

`HarnessGateway` 已提供唯一主 sink 注册与持久 inbox，区分 `pending / accepted / uncertain`；目前没有实际 sink，消息等待投递，准入不代表 Agent 已读。本轮提供真实可接入的边界，未接入认知循环。

Host 已实现回环/Host/Origin 校验、HttpOnly session + CSRF、MCP 专用 Bearer、插件独立 scope、进程锁和插件损坏配置局部报错；不能扩大为完整恶意插件 OS 沙箱。

## 授权与未覆盖范围

本轮已授权正式 Host、QQ、数据、MCP、前端、必要依赖及集成/浏览器验证。新增未知可执行能力仍需主人明确批准；MCP 日常工具调用不逐次人工审批，UI 手测发送/撤回需逐次确认。用户主 DSH 与当前 GUI 不修改、不替换，不替用户登录，也未使用真实账号令牌或向真人发送开发测试消息。

本版不支持反向 OneBot、API/event 分离；QQ 空间发布/评论不属于 OneBot v11 标准，明确 `unsupported`，后续作为显式能力扩展研究。实际 Harness/MCP 自动注册、Cordis 真实底座、长期记忆、自主活动、任意第三方安装、完整 OS/进程隔离、Tauri、Windows/Linux 验证及多账号并行均未完成。

唯一 AI 身份、用户选择 Harness 负责认知、一个活跃主认知控制者、模块独立注册、独立 UI 与后台生命周期继续保持。跨 Harness 无损迁移、运行中热切换、多设备并发和全部能力等价未承诺。
