# Eating 项目范围

更新：2026-10-27。负责人已进入正式开发，并明确不需要聊天历史；全局设置采用二级分类，消息队列可选内存或有限本地暂存。当前基线为 `68031fc`，此前临时日志与本轮设置改动尚未提交、未推送。

## 当前实现范围

全局导航为“概览 / 机器人 / 设置”。机器人平台分类与插件自有面板继续保留，QQ为独立安装包；前后端贡献通过公开Eating契约注册。飞书/微信占位入口已移除，测试协议端不进入产品运行路径。

Host/Web/根应用0.3.0、公开SDK1.2.0、QQ0.4.0，插件apiVersion为1。Host使用普通Node>=24.9.0、TypeScript、内置SQLite、ws和官方MCP SDK。开发由 `pnpm dev` 提供5180界面与5181 Host；生产Host同源提供已构建Web、API、插件资源与MCP。QQ按[操作说明](../operations/QQ配置与功能测试.md)安装独立产物，不静态捆入应用。

QQ现有四个页签：

- **连接配置**：正向统一OneBot WebSocket，Bearer仅写入，保存与连接分开；真实登录及online/good核验成功才报告已连接，有限重连。
- **实时日志**：仅可见日志页签订阅，默认100条可选，只在浏览器内存；隐藏、离开、关闭即停止并清空，无后台日志文件、缓存或补放。
- **功能测试**：由后台schema生成，与MCP共用9项工具，覆盖账号、状态、版本、好友、群、OneBot单条消息查询、私聊/群发送与撤回。真实发送/撤回手测逐次确认，稳定请求ID防重复。
- **MCP能力**：插件专属Streamable HTTP `/mcp/qq`、独立Bearer；仅显式查看时展示注册配置，尚未自动注册至实际Harness。

不再提供本地聊天历史页面或已收消息历史MCP；OneBot标准get_msg可按消息ID读取协议端仍持有的消息。

## 全局设置与消息队列

“消息投递”配置聚合静默时间、最长聚合等待、单批消息上限、批次目标大小、投递超时、拒收重试间隔和最大尝试次数。“队列与存储”选择本地暂存/仅内存、条数/字节容量与溢出处理，并显示实际队列统计、提供明确确认的清空操作。

队列仅持有尚未完成交接的规范化信封，不额外复制原始协议事件和正文列；无需转交不保存正文。持久模式重启恢复未交接内容，内存模式不落正文盘、重启丢失；模式切换与配置版本检查为原子操作。容量和异常可见，不默称拒收消息已进入队列。

聚合按会话隔离，静默会随新消息计时，但最长等待从首条固定，条数或目标体积可提前触发；单条不拆分。只有具备可靠持久回执，才删除本地正文，接受不等于模型消费。明确拒收才有限重试，结果未知不盲目补投；短期去重只留有界标识，发送防重复记录独立保留。

实际DSH/Harness插件仍未接入。当前Gateway是投递边界，测试sink证明队列与回执机制，不能称为已完成实际模型认知。

## 数据、授权与未覆盖范围

`EATING_HOME`默认 `~/.eating`；QQ配置仍在 `bot/qq-bot/accounts/<本地实例UUID>/config.json`，真实QQ号不作目录名。插件代码在独立版本目录，账号数据与代码分开。Host锁、SQLite、MCP凭据原路径保持；本轮仅迁移消息表，保全部未交接信封，移除终态历史，不创建聊天备份。当前只支持一个默认账号实例。

回环/Host/Origin、HttpOnly会话、CSRF、MCP Bearer、scope与进程锁不等于完整恶意插件OS沙箱。新增未知可执行能力仍需主人批准，日常已授权MCP调用不逐次人工确认。开发不修改用户主DSH或GUI，不替用户登录，不向真人发送自动测试消息。

反向OneBot、API/event分离、QQ空间扩展、真实Harness及自动MCP注册、长期记忆、自主活动、任意第三方市场、运行热更新、真实npm发布、完整进程隔离、Tauri、Windows/Linux与多账号并行尚未完成。跨Harness无损迁移、热切换、全部能力相同未承诺。
