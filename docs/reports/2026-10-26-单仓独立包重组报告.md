## 独立交付与安装

[构建脚本](../../scripts/build.mjs)分别构建SDK声明/导出、Host ESM、Web与QQ产物。构建会拒绝插件导入应用源码、Host静态捆入插件。QQ产物只有清单、独立后台ESM、面板JS、CSS；清单以 `schemaVersion`、`apiVersion`、身份/版本、`backend`、`frontend`、`integrity`描述交付，后者是三入口各自SHA-256。

Host只从 `EATING_HOME/plugins/installed.json`发现激活版本，在导入可执行代码前取得工作区锁并校验包。Web读取Host返回的版本URL动态加载JS/CSS；公开UI运行时共享宿主React，避免重复React造成Hook失效。

```bash
pnpm build
pnpm build:plugin
# 安装、升级、卸载前停止Host
pnpm plugin install plugins/communication/qq/dist
pnpm plugin list
pnpm plugin uninstall qq
```

[安装器](../../apps/host/src/plugin-installation.ts)只接收已授权可信本地目录，校验API版本、合法入口、16MiB限制、符号链接/额外文件、完整SHA-256；先暂存并二次校验，再在全局安装锁与Host锁内原子发布版本及索引。同版本内容不可变，不一致须新版本号。当前激活插件间bot目录冲突、同一激活插件升级改绑目录会在发布前被拒绝，不等到Host启动才失败。

索引rename是提交点。提交前失败保留旧激活并清理本次暂存；提交后的目录同步失败明确为durability unknown，并保留已激活包。绑定检查限当前激活索引，不保证卸载后历史版本永久占有目录。

代码位于 `~/.eating/plugins/<id>/versions/<version>`，账号数据仍在 `~/.eating/bot/qq-bot`，Host公共数据仍在host。升级不移动账号，卸载撤激活并保留配置、消息、未决动作及版本文件；删除用户数据另需授权。当前停机后安装并重启生效，不提供热更新。

## 独立审查与修复

限定只读审查确认3项P2，均修复并通过相关回归，最终定向PASS。审查者回读代码/测试，执行结果由主流程实际运行，不冒称OS认证。

1. 插件初始化失败原先固定version0.0.0，与安装页面URL版本冲突，导致全目录失败。保留安装清单的版本/名称，坏配置的原文和局部错误保留。
2. 安装器接受SemVer的+build，而URL/旧前端正则不同，合法包无法开面板。统一路径和SemVer范围，真实0.2.1+local浏览器回归通过。
3. 新插件同bot目录或升级改绑会在运行后影响配置归属。改为索引事务内、发布前校验当前激活目录绑定，失败不修改旧索引/账号文件。

另补动态面板失败时清理样式并仅显示本插件错误，不让一个坏面板拖垮通用目录。
