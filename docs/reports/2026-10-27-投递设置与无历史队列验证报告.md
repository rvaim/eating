## 默认配置与真实含义

| 设置 | 默认值 | 行为 |
| --- | --- | --- |
| 队列存储方式 | 本地暂存 | 只保存未交接信封，可跨重启；可选择仅内存，重启丢失未交接内容 |
| 队列消息上限 | 1000条 | 所有待投递、在途、待核对内容均计入 |
| 队列容量上限 | 10MiB | 按规范化信封UTF-8字节计，不代表整个数据库文件上限 |
| 队列溢出处理 | 拒绝新消息 | 有拒收计数和固定错误说明；可选择移除最旧pending，不移除在途或待核对内容 |
| 聚合静默时间 | 500ms | 同会话新消息到达时重新计时 |
| 最长聚合等待时间 | 2000ms | 从首条开始，不随新消息延长 |
| 单批消息上限 | 10条 | 达到即提前投递 |
| 批次目标大小 | 32KiB | 达到即提前投递；单条过大单独发送、不拆分，仍受队列硬限额 |
| 投递超时 | 15000ms | 等待接收回执，不是等待模型完成任务 |
| 拒收重试间隔 | 10000ms | 仅明确拒收才重试，未知结果不自动重发 |
| 最大投递尝试次数 | 5次 | 含首次；耗尽停止自动尝试，保留受容量限制的内容等待处理 |

批次按会话分组，保留每条事件ID和来源，不混合不同群或私聊。批次ID按有序事件ID稳定生成。未接入接收者时只暂存，不启动模型；真实DSH/Harness插件仍未实现。

## 无历史存储与迁移

新队列表仅保留当前未交接的规范化Harness JSON，不另外保存原始OneBot事件或正文列。无需转交的消息不存正文。接收端必须给出 `accepted=true`、`durable=true` 与非空回执ID，才能删除本地正文；可靠交接不等于模型消费或任务成功。

短期去重仅保存哈希标识、状态与回执摘要，常态24小时、最多10000个。SQLite连元数据清理也故障时，原库与有界内存兜底合计最多20000个小标识，不含正文。发送防重复记录独立保留，清空消息队列不重置已执行请求。

旧库事务迁移保留全部pending/delivering/uncertain内容，在途启动后转待核对；已交接和无需转交的旧历史不保留正文。移除旧表后同库VACUUM及checkpoint回收空间，不创建第二份聊天备份。切换本地/内存模式先准备数据、事务提交后才切模式，写入失败不部分迁移；不缩容到保护状态消息无法容纳的大小。

## 定位并修正的问题

首轮全量371项中，3项日志严格字段预期未包含新queueAdmission元数据；更新预期后对应11项定向通过，最终387项全绿，没有放宽凭据/原始事件字段禁止进入日志的断言。

设置页原先重新读取时保留整个旧草稿但换新revision，可能覆盖其他页面的未修改字段。现改为有修改时先明确确认放弃，成功读取后整体替换草稿与基线；清空回包只更新队列统计，不隐式换草稿版本。真实冲突码已对齐，独立只读复核PASS。

独立复核通过真实SQLite触发器复现：远端可靠接受后本地ack失败，或拒收结果的本地状态写入失败，可能留下孤立delivering。现仅保留一个有界待提交结果，不复制正文；按重试间隔只重试本地保存，不再次调用接收端，不形成零间隔循环。busy/等待本地提交状态准确。注销后两种本地写入都失败时停止计时并保留小结果，存储恢复后重新注册或显式通知可继续；关闭只有限尝试，下一次启动仍保留待核对正文。49项网关与关联存储共90项通过，限定复核最终PASS。

周期状态统计也已改为SQL COUNT/SUM或直接累计内存元数据，不为界面轮询读取、排序和解析大队列正文。

## 影响与回退

用户可以在设置中修改实际投递规则及选择队列模式；不会再从Eating查询已完成聊天历史。当前本地暂存是为保留未交接消息的默认值，用户可选择仅内存。旧Host不读取新队列表，仍有未交接内容时不能直接降级并假设数据可见，须先安全交接或执行明确反向迁移；已按要求移除的历史正文不恢复。
