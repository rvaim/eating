# MCP、插件管理与表情包验证

日期：2026-10-30，Asia/Shanghai。开发分支：feature/mcp-plugins。决策：[ADR-0019](../decisions/ADR-0019-统一插件与MCP能力管理.md)；操作：[使用说明](../operations/MCP插件与表情包.md)。

## 功能与契约

应用／Host／Web0.11.0、三个共享包4.0.0、QQ0.11.0、DSH0.8.0、表情包0.1.0，插件统一API4。现有Host SQLite、作者、QQ、DSH业务数据schema不因此更改。开发在独立worktree进行，避免Host watch在开发过程中影响原实例。

- 侧栏增加MCP和插件。插件统一三类目录，每项动态加载自己的面板；机器人和Harness保留业务视图。
- 直接MCP支持本地stdio和远程Streamable HTTP，保存不执行。插件提供的MCP进入同一服务目录，通讯权限仍在原插件管理，不能通过总目录绕过QQ账号／会话限制。
- 插件安装预览验证同一份代码快照，确认才执行；Host内持锁安装更新，CLI仍要求停机。卸载保留数据，安装新版本可加载新面板和工具目录。
- 表情库支持本机上传、AI当前会话收藏、独立描述和标签、关键词与标签AND筛选、默认20／最大50条的元数据分页、单图预览、编辑及删除CAS。同图去重不覆盖旧资料。
- get结果把预览和sendable资源引用同时提供给模型，QQ转换为标准OneBot图片数据；列表和动作账本不带原图Base64。单次最多4张插件资源图片、总10MiB，单图5MiB。

## 开发中发现并修复的根因

1. MCP准备失败先落pending会锁住该子代理后续委派：先完成QQ与能力依赖准备，再原子提交pending；失败统一撤lease，允许依赖恢复后同callId正常准备。
2. 只关闭MCP响应不能阻止在途资源完成：lease AbortSignal贯穿Host资源、QQ发送与表情库serialized提交，在await返回和真实副作用前复查。deferred资源→撤权→释放后确认零OneBot发送／零收藏；主人无scope操作不受无关代理撤权影响。
3. JSON transport关闭不一定结束HTTP等待：撤权时销毁未完成响应，同时释放停止promise，客户端及时结束而非等工具超时。
4. 系统DSH的MCP serverName最多32字符，direct UUID直拼超限：改稳定短namespace；长工具名按当前官方64字符／身份哈希规范比较，仍保持精确工具授权。
5. DSH的MCP投影只把content文本送给模型，不能假设structuredContent会显示：sticker_get的文本明确包含元数据和实际sendable，真实模型夹具从该内容取引用，不硬拼路径绕过。

## 界面验证

新增管理浏览器11项全部通过，其中9项路由夹具和2项真实临时Host：从页面预览／确认安装表情包插件、上传PNG、建立24项库、分页20／4、标签筛选11项、编辑、卸载与重装保留；从页面保存真实stdio服务、连接、发现工具并授权。

MCP、插件目录和真实表情库的浅色、深色与390px截图均已实际读取；复用现有语义颜色变量，没有另装UI库或改变DSH原生Web界面。固定文案双语，敏感值在隐藏时清理，URL／密钥不存localStorage。

全量浏览器初次发现旧色值断言及短横屏溢出：断言改为当前语义令牌；侧栏增加定位祖先，使绝对定位的视觉隐藏文字在侧栏内裁剪，根文档不再被推高。最终全量77／77通过（约1分钟），未放松视口／根滚动断言。
