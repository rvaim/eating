# DSH 原生能力与插件管理验证

日期：2026-11-01，Asia/Shanghai。用户明确要求一次完成原生功能与 DSH 插件管理。代码与构建产物已完成，DSH 插件升级至 0.9.0；应用0.11.0、共享SDK4.0.0和API4保持。首次隔离验证完成时尚未部署真实Eating实例。用户随后反馈原地址没有新功能，现已完成原5180／5181实例的DSH0.9.0更新与资料保持核验，见[现场报告](2026-11-01-DSH原生能力现场更新与入口核验.md)。主人主DSH和当前GUI未改；未提交、推送或发布。

## 实现与根因

原有适配同时在启动 overlay 关闭原生文件/终端工具，并在主/子 Agent 处过滤继承工具。仅增加界面勾选不能改变实际模型工具。此次将模块目录、原生装配、授权、调用守卫和实际观察统一接通：

- [原生目录定义](../../plugins/harness/dsh/src/native-capabilities.ts)声明官方功能及依赖；目录读取通过实际系统 DSH 解析可用模块，不把开发依赖当作系统安装。
- [配置](../../plugins/harness/dsh/src/backend/native-configuration.ts)使用独立 schema1/revision/CAS，保存前严格校验代理类型、完整模块配置、工具名称与结构指纹；坏文件保留。私密值和带鉴权查询的 URL 不回显，保存占位符保持对应原值。
- [原生管理桥](../../plugins/harness/dsh/src/backend/native-runtime.ts)运行在系统 DSH 内，使用公开 Cordis、AgentPresets、PluginManager 和 ConfigEditor；管理通道限制随机 loopback、协议版本、nonce、令牌、请求大小与超时。
- [适配器](../../plugins/harness/dsh/src/backend/adapter.ts)在运行中复用已有实例；停止时使用短生命周期 SDK 管理进程，和正式启动/配置互斥。清理失败阻止第二个进程，写操作有稳定请求标识，未知不自动重做。
- [Agent 装配](../../plugins/harness/dsh/src/backend/runtime-agents.ts)只在当前类型 scope 加载选中功能；实例插件的工具按名称、schema 指纹和类型继承，最终调用再次复核。工具变化不会沿用旧授权，也不妨碍其他获准能力启动。QQ MCP 仍由 Host 管理会话范围。
- [面板](../../plugins/harness/dsh/src/web/NativeCapabilities.tsx)提供原生功能、DSH 插件及精确工具授权，支持搜索、JSON参数、主/子类型选择、来源检查和确认安装、模块/Bundle启停、配置替换、卸载确认与资料保留，显示保存版本及实际挂载。新安装保持停用。

决策见[ADR-0021](../decisions/ADR-0021-DSH原生能力与插件管理.md)，操作见[使用说明](../operations/DSH原生能力与插件.md)，设计与边界见[实施契约](../plans/2026-11-01-DSH原生能力与插件管理实施契约.md)。

## 最终命令与结果

普通 Node.js24.22.0、pnpm11.28.5。使用显式 `/usr/local/bin/dsh`，原生与 Host 验证均为临时资料、回环模型/OneBot或本轮构造的纯本地插件；没有真实付费模型、登录或真人发送。

## 原生系统实证

[系统集成测试](../../plugins/harness/dsh/src/backend/native-web.integration.test.ts)覆盖：

1. 停止状态读取实际模块、插件、Bundle和全局工具，模型请求数保持0，原生主会话文件仍不存在；未配置模型的真实浏览器流程也可读取和保存。
2. 文件读取、待办、网页等功能按main授权后，实际模型请求包含read/read_image、todo_write、web_fetch和基础委派工具；未开启的write和bash仍不在请求中。
3. 对当前平台每项可用原生功能逐项执行原生配置/依赖校验，不调用模型；当前平台不支持的PowerShell明确不可启用。
4. 本地DSH Bundle经原生inspect/install安装后保持停用；启用、模块配置与独立工具授权均经真实原生服务执行。纯fixture_native_echo工具被模型真实调用，返回结果进入下一次模型请求。
5. 修改该插件工具的schema描述后重启同一原生主会话，旧授权失效，下一模型请求不再含该工具，其余能力正常启动。插件配置中的canary Key未出现在目录或普通公开状态。
6. 停用并卸载该Bundle后，独立插件资料标记仍保留；系统DSH官方Web与SDK继续共享原生会话，官方会话创建/设置、明暗主题、重启持久化及自身进程清理仍通过。

[配置测试](../../plugins/harness/dsh/src/backend/native-configuration.test.ts)与[面板私密数据测试](../../plugins/harness/dsh/src/web/native-data.test.ts)核对严格当前格式、CAS、不支持文件不覆盖、类型与工具伪造、秘密脱敏/同路径保留、隐藏清理新输入秘密和损坏响应拒绝。[适配器测试](../../plugins/harness/dsh/src/backend/adapter.test.ts)覆盖相同requestId不重复修改，以及管理进程未清理时不启动第二实例或修改图片能力。

## 设计收尾复核

本环境没有可用的普通独立审阅代理入口，采用技能的降级内联复核；未声称独立代理审阅。设计上下文启动器因无执行权限未运行，经验库返回HTTP402；按已有[界面设计规范](../design/界面设计规范.md)、源码和实图继续，不更改工具权限或安装新工具。

**disposition: ship**，范围为本轮既有设置面板扩展的实现与已列截图/测试。

### persistence

通过：中文实施契约、ADR、使用说明、当前规范、状态和交接已保存。项目原先使用中文设计/产品文档，不存在根PRODUCT.md/DESIGN.md；这是既有文档组织，未把局部扩展改成视觉系统重建，也未自动修机器sidecar。

### fidelity

| 项目 | 结论与证据 |
| --- | --- |
| TYPE | match：继承系统字体，普通正文/标签层级不变；只有模块名与JSON使用代码字体 |
| MATERIAL | match：既有平面设置界面，单像素分隔、普通表单与Lucide图标，无新增摄影或装饰材质 |
| GROUND | match：浅色白绿、深色语义表面均来自既有宿主令牌 |
| 结构与交互 | match：双页签保持全范围吸顶，功能/插件/工具可切换；配置、代理范围和状态在同一展开项内 |
| 窄屏和焦点 | adaptation：390px搜索与动作换行，标签保留可访问名称，JSON区域可纵向编辑；无页面横向溢出，已有键盘/短窗/滚动回归通过 |
| 功能事实 | match：模块目录、配置与实际模型工具分别有原生测试，截图中的fixture不冒充主人数据 |

### ceiling

达到本轮Operate局部扩展的精度范围；保留宿主白绿身份和原生表单，不引入新视觉世界、额外装饰或新栅格资产。

### material_fixes

本轮收尾未发现需要继续修改的实质界面问题。首轮发现的窄屏搜索标签和默认输入样式已按既有语义令牌修正，最终截图已重读。

### keep

保持“功能/插件启用”和“代理工具授权”分离，以及“草稿/已保存/实际挂载”的区别；官方DSH Web保持原样。

设计文档核对：沿用既有调色板、系统字体、单像素分隔、44px可操作输入及固定视口/独立滚动规则；只追加本轮管理区的行为说明，没有重写既有设计tokens或sidecar。旧文档中历史数字与历史Web方案保留其当时事实，由最新ADR与本轮状态说明替代关系。
