# 2026-11-01：外部入站原生执行请求展示验证

日期：2026-11-01，Asia/Shanghai。范围：DSH 插件 0.10.3；应用/Host/Web 0.12.1、QQ 0.12.0、plugin-sdk 4.1.0 和唯一插件 API4 保持。对应[ADR-0024](../decisions/ADR-0024-外部入站的原生执行请求展示.md)。

## 需求与根因

用户要求 QQ 入站在 DSH 原生页面中，也按自主运行截图的“收到执行请求”折叠显示。

自主机会原生来源为 eating-autonomy；外部批次走 SDK HarnessSession.run，服务端固定创建 source.kind=user。官方 Web 对 user/message 的来源进行分类，普通 user 显示对话，其他实际唤醒来源显示可展开的执行请求。问题在 Eating 对 SDK 运输来源的沿用，官方 UI 没有缺少所需组件。

## 实现

- [runtime bridge](../../plugins/harness/dsh/src/backend/runtime-bridge.ts) 在公开 agent/pre-step 中等待其他准入决定，仅对当前根 Agent、被允许进入步骤且完整验证的批次消息设置 source={kind:eating-external,batchId}。
- 复用完整信封验证，核对协议、magic、当前 nonce/session/batch/digest 和真实 context/events 的 SHA-256；不识别外部正文内的伪造片段。
- 保留消息 ID、时间、role=user、全部正文及准入决定的其他字段。SDK 入箱记录仍是运输事实；flush 成功后的匹配原子 ACK 保持，来源修正只用于接纳后的原生消息事实。
- 无官方 DSH、当前主 DSH GUI 或原生客户端修改；没有 CSS、Slot、locale 或 renderer 注入。QQ 私聊、群聊共用该外部入口；自主机会、原生主人输入和主子代理来源分别保持。
- 四处插件版本同步为 0.10.3。已有配置/schema、会话 UUID、历史日志与 QQ 发送协议不迁移。

## 限制与交接

更改作用于新投递。旧消息保留原 source，不为了改变外观重写历史；全新外部触发会话也不再借 QQ 正文生成首条人类标题，官方可能显示“未命名”。模型仍接收完整 user 角色数据，来源标记不提升权限；实际 QQ 发送仍需要已授权工具回执。

原实例只验证了安装、页面加载与数据保持。真实账号的新入站展示需由主人正常启动 QQ/Harness 后观察；此次没有向真人试发，也没有做付费模型测试。

仓库原有和其他在途修改保持；本轮没有提交或 push。README、当前规范、ADR/索引、状态、交接、待确认问题与变更日志同步。
