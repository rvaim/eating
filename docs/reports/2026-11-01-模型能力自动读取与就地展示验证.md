# 模型能力自动读取与就地展示验证

日期：2026-11-01，Asia/Shanghai。用户要求模型能力从服务读取，补充配置也应位于模型名称、获取模型列表和测试连接附近。DSH插件最终升级0.9.2，并更新原5180／5181实例。

## 根因和修改

实际模型服务的/models已经返回modalities.input/output、tool_call、reasoning、context_window/context_length、max_output_tokens等字段。原[模型服务解析](../../plugins/harness/dsh/src/backend/model-service.ts)只保留id/name，丢失能力信息。修复后以[白名单归一化](../../plugins/harness/dsh/src/model-information.ts)保留图片、工具、推理、模态及容量；缺失、非法、矛盾字段保持未知，不从模型名称猜测。

[能力区](../../plugins/harness/dsh/src/web/ModelCapabilities.tsx)移动到模型名称和两个模型按钮下方、API Key之前。进入已保存模型时自动读取/models，显示服务声明；已声明图片能力时不再要求重复勾选。只有未声明时才在当前位置提供折叠手动补充，独立CAS和停止后保存保持。模型列表切换可以预览不同模型能力，保存前不写运行配置。语言切换不触发查询；读取失败、隐藏/离页和手动草稿状态均有处理。

新增[model-information.json存储](../../plugins/harness/dsh/src/backend/model-information.ts)，严格schema1，以服务地址和Key摘要绑定目录，按精确模型id读取。原model-capabilities.json及其他真实配置格式不变，不迁移或补字段。服务明确声明的图像输入、上下文和输出容量由[适配器](../../plugins/harness/dsh/src/backend/adapter.ts)写入原生模型元数据；每次输出上限继续由主人保存的maxTokens控制。未知能力沿用当前安全基线和人工补充，不虚构支持。

决定见[ADR-0022](../decisions/ADR-0022-服务声明模型能力与就地展示.md)。本次不修改网页网络策略，前轮Fake-IP问题仍单独记录。

## 验证

普通Node24.22.0、pnpm11.28.5；原生系统验证显式使用 `/usr/local/bin/dsh`、临时数据及回环模型。

```bash
pnpm build
EATING_DSH_TEST_SYSTEM_BIN=/usr/local/bin/dsh pnpm exec vitest run --maxWorkers=2
pnpm exec playwright test --workers=2
git diff --check
```

- 完整SDK/插件/Host/Web构建及严格类型通过。
- 单元/集成：61文件通过、2文件跳过；1252项通过、8项按需跳过，共1260项，46.70秒。
- 最终UI修正后重新完整构建和浏览器全量验证：87/87通过，约1分钟。8项原有按需测试未计为验证通过。
- 新增元数据白名单、显式false、矛盾/缺失未知、凭据/服务/精确id绑定、坏目录不覆盖、秘密不输出等测试。
- 新增原生系统测试，实际启动采用text/image、1000000上下文和128000输出容量，人工声明不变，初始化没有模型请求；SDK每次输出参数仍为128而不是服务最大输出。
- 浏览器核对能力区处在模型名称和API Key之间、服务声明时不出现重复勾选、模型草稿预览、语言切换不请求、未知项手动补充、CAS、读取失败与运行中禁保存。

首轮浏览器发现自动能力读取与保存操作争用Host的管理锁，以及信息刷新会让已展开的手动补充收起；已增加共享读忙碌状态，并保留展开/草稿。最终87项全部通过。本轮没有通过恢复旧接口或放松存储校验维持测试。
