# AI 定时任务验证

日期：2026-11-02，Asia/Shanghai。工作树：`main`，基线提交 `5ee7671`。本次实现应用/Host/Web0.15.0、DSH0.13.0，插件 API 仍为4。决策见[ADR-0032](../decisions/ADR-0032-AI定时任务.md)。

## 实现范围

- [autonomy-agenda.ts](../../plugins/harness/dsh/src/backend/autonomy-agenda.ts)：独立 `autonomy-agenda.json/schema1`，保存 AI 自己创建的一次性任务（id、message、dueAt、createdAt）；最多50条、128KiB、消息最多2000字符；创建只接受未来1秒至365天，独立 revision/CAS；损坏或旧格式拒绝且不覆盖。缺省读取不创建空文件。
- [autonomy.ts](../../plugins/harness/dsh/src/backend/autonomy.ts)：`scheduleTask`/`cancelTask`/`ownerCancelTask`；到期任务在 `claim` 中优先于普通间隔/休息等待，与普通自主机会共用同一 Cycle；每轮最多合并10条；任务在 cycle 持久保存后移出 agenda。暂停、故障、runtime、小时轮次和连续时长限制继续生效。
- [autonomy-runtime.ts](../../plugins/harness/dsh/src/backend/autonomy-runtime.ts)：主 Agent 增加 `eating_schedule_task`、`eating_cancel_scheduled_task`；`eating_activity_state` 返回 `agenda.revision` 和任务；到点消息通过同一 `Agent.followup`、来源仍为 `eating-autonomy`，明确不是主人指令。
- [agent-control.ts](../../plugins/harness/dsh/src/backend/agent-control.ts)与[adapter.ts](../../plugins/harness/dsh/src/backend/adapter.ts)：受信 runtime 控制通道增加 schedule/cancel；主人管理 API 增加 `cancel-scheduled-task`，按 agenda revision 单项取消。
- [AutonomySettings.tsx](../../apps/web/src/pages/AutonomySettings.tsx)、[autonomy-data.ts](../../apps/web/src/pages/autonomy-data.ts)与[双语资源](../../apps/web/src/i18n/autonomy.ts)：概览显示待执行 AI 定时任务及时间，任务卡提供取消；服务端快照严格校验 agenda 上限和形状。
- 提示词与[默认主 Agent 说明](../../apps/host/src/authoring-defaults.ts)同步说明新工具；原生 DSH Schedule 在自主周期中仍被拒绝，不放开第二条提醒链。

## 未验证与边界

- 未把代码安装到真实 `~/.eating`，未改写现有 `autonomy.json`、`autonomy-agenda.json`、联系人、代理绑定或历史；真实运行实例仍运行原版本。
- 未向真人 QQ 或付费模型发送任务消息；没有验证长期自主内容质量、休眠/关机时准确唤醒，也没有实现每日/每周/cron 重复任务。
- 到期任务从 agenda 移除与 cycle 持久写是两个独立文件写入；进程在两步之间崩溃时按 unknown 处理，不保证恰好一次。任务消息进入会话不等于模型已完成任务。
- 原生 DSH Schedule 仍是独立机制，本轮没有改变其既有主人提醒语义，也没有授权 AI 在自主周期中创建它。
