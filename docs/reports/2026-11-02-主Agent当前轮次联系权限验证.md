# 主 Agent 当前轮次联系权限验证报告

日期：2026-11-02，Asia/Shanghai。工作树：`fix/main-agent-contact-authority`，基线 `5ee7671`。依据：[ADR-0033](../decisions/ADR-0033-主Agent当前轮次联系权限.md)。本轮只在该工作树修复、验证和本地提交，不合并主分支、不推送、不改另一会话的工作区、不部署真实实例。

## 根因与实现

此前联系权限依赖 `autonomyDriver.flight.entered` 和 Host 的 `validCycle`。主 Agent 收到群消息或原生输入后，即使联系对象已获准，也因不是定时机会而不能委派私聊子代理。普通 `eating_delegate_task` 又正确地限制在当前批次，使群转私聊没有合法执行入口。

DSH 插件更新为 **0.12.1**，应用／Host／Web、SDK API4和数据 schema 保持：

- 新增 `contact-runtime.ts`，联系工具独立于定时活动驱动。真实根 Agent 的 admitted `agent/pre-step` 取得原生 turn 和 turn signal，再由私有 Host 接口签发同轮稳定随机引用；模型参数仍只有目标引用和任务。
- 普通消息、原生输入、目标续行和定时机会均可在真实当前轮次按主人联系策略委派；无输入定时 `enabled`／`ownerPaused` 不阻断普通轮次。真正定时机会的取消仍会撤销该轮联系许可。
- Host 每次核对当前轮次、策略 revision、账号／目标／类型／工具、小时额度和任务状态；子代理取得空旧消息／资源引用的新 scope，主 Agent 不取得 QQ 全权令牌。
- 正常 `turn/end`、abort、主实例销毁、bridge 初始化失败和 runtime 停止均结束许可。有界 cleanup 请求独立于已取消的执行信号；开始响应丢失时用已知原生 turn 做同版结束确认，单调墓碑拒绝迟到的旧开始，旧结束不会撤销新轮。
- 任务期限到后保持 unknown；迟到回执不能覆盖 unknown 或撤掉新任务。`proactive-bindings.json` schema1不变，原 `cycleId` 是后台联系轮次关联引用；不迁移、不恢复旧许可，遗留 pending 转 unknown，UUID／动作账本保留。
