## 变更摘要

- 必需的主委派／联系／自主规则合入唯一 complete provider，保留 owner／persona／子类型隔离。
- 先选实际行动目标：当前会话查询／回复用 `context_ref`；跨私聊／群聊用当前列表 `target_id` 联系，自动启动／恢复对应子，不要求先有新入站。
- connected 功能型 MCP 全工具、全 Agent 类型自动可用；`grant` 只作动态目录摘要，删除 save-grants 和授权勾选 UI。
- direct 连接输入无 grant，持久化严格 schema2；schema1拒绝且原文件保留。旧 `host:capability-grants` 不读／不写／不删，不从旧空名单恢复限制。
- 新 main 原生 feature 按平台默认开，files写／编辑与web.search开启；Eating官方permission默认 danger-full-access／approval never；原生 Schedule 不再由 Eating 自主周期人工阻断。既存实例经正式设置同步本次授权。
- main自动开放全部原生全局工具；所有Agent的功能型native Profile MCP及后续新工具自动可见，排除Eating／QQ受控通讯。其他子非MCP原生工具仍按精确名称／结构指纹选择，目录automaticAccess仅只读摘要，不保留无效main／全功能MCP授权勾选。tools/change后同步更新native.restrict与当前scope限制。
- 新增、连接、断开、工具目录变化及能力插件生命周期变更使用一次性重挂事务：先撤lease并停受影响Harness，await来源／目录变更完成后，仅对变更前connected、仍为同一实例且启用的Harness恢复一次。原stopped／error不自动启动，主人stop／disable优先；失败不重试、不重放unknown，返回harnessRemounts的reconnected／failed／cancelled结果。
- 通讯permissionsManagedByPlugin、精确账号／对象／资源、幂等／unknown与真正send／落库前复查保持。

最终变更范围及风险说明：待父代理复核实际差异后填写。
