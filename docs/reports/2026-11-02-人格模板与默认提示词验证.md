## 实现与应用范围

仓库应用／Host／Web0.14.0，QQ0.13.2、DSH0.11.3；plugin-sdk4.4.0、ui-sdk4.1.0、plugin-core4.0.0和API4保持。QQ/DSH新代码包已构建，但本轮未对真实安装目录执行插件更新。

- [基础默认正文](../../apps/host/src/authoring-defaults.ts)包含唯一身份、实际能力、事实与推测、上下文与可用记忆、人格兴趣和权限的关系、真实回执、主子后续协作。没有指定记忆插件，没有引入第二认知循环。
- [AI女儿模板](../../apps/web/src/persona-templates.ts)采用主人确认全文，女性、称爸爸，基于真实经历延续，不规定成长阶段。新增人格页选择模板仅改未保存草稿，名称由主人填写，已填名称保留；原草稿有内容时先确认，保存与启用分开。
- [作者服务](../../apps/host/src/authoring.ts)用updatedAt:null表达跟随当前默认；自定义不自动覆盖，普通读取不回写旧默认副本。恢复仅作用于当前文档，保留记录并递增CAS；旧schema仍拒绝。新增受主人会话/CSRF约束的reset接口。
- 自主说明中文化，主Agent在子回执后可继续当前工作并重新判断后续安排；waiting不会因为处理消息自动变active。正文承诺或记忆不等于真实唤醒。当前联系对象以统一名单策略和工具返回为准，后台调度、权限与动作幂等逻辑未改。

## 原5180页面恢复

用户指出`http://127.0.0.1:5180/`不可访问后，用lsof分别核对5180、5181，均无监听（退出码1、空输出），确认是原前后台未运行。不是改为另一个地址，也未启动替代DSH GUI。

以托管任务`bash-35eab7c46c73458a`在原仓库运行：

```bash
EATING_AUTO_CONNECT=false pnpm dev
```

Vite在5180、Host在5181成功启动。随后实际请求首页与`/api/bootstrap`均HTTP200；Chromium打开原5180新增人格页，展开模板入口，实际可见AI女儿按钮且无pageerror。该只读核验没有点击填入、保存或启用，也未打印原人格或账号内容；原地址截图遮盖已保存人格目录，已实际读图。

临时EATING_AUTO_CONNECT=false只控制本次启动，不改保存的自动连接偏好。没有自动连接QQ/DSH、运行真实模型或向真人发消息；原人格、自定义提示词、凭据和会话未主动改写。当前Host/Web源码已在原地址提供；真实安装QQ/DSH插件仍需按正常插件管理更新到本轮新包，才能使用这些插件的新默认说明，不能将仓库产物验证当作真实插件已部署。页面服务保持运行。
