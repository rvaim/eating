日期：2026-11-02，Asia/Shanghai。工作树：`fix/autonomy-proactive-state`，基于提交 `8fed468`；初始修复阶段按要求未合并主分支，主人随后授权合并并推送 main，合并验证另记于下方。决策见[ADR-0031](../decisions/ADR-0031-自主运行状态与可选能力降级.md)。

## 问题与修复范围

现场 `autonomy.json` 的旧字段 `configuration.targets` 为 `[]`，真实主动联系策略在 `proactive-contact-policy.json`（`mode: all`）；模型在 `eating_activity_state` 中看到旧字段后误报“没有主动联系权限”。同时 `maxRunMinutes` 把 01:13 到 09:00 的睡眠算成连续运行，触发 `AUTONOMY_RUN_LIMIT`；`CapabilityAccess.connections` 对已授权但断开的 OpenViking MCP 直接抛错，连带阻断 QQ 子代理委派。

本轮只修代码和文档，不迁移或改写真实 `autonomy.json`、`proactive-contact-policy.json`、联系人、代理绑定或历史。已有 `AUTONOMY_RUN_LIMIT` 仍需主人在设置页点一次“恢复”。

## 实现

- `autonomy-runtime.ts`：模型可见的 `eating_activity_state` / `eating_plan_activity` 去掉旧 `configuration.targets`；`/autonomy-snapshot` 附带 `contactPolicy` 摘要（模式、revision、保存对象数）。
- `DshProactivePolicy.summary()`：只暴露策略摘要，完整联系人仍由 `eating_list_contact_targets` 读取。
- `autonomy.ts`：`maxRunMinutes` 只累计实际活动段；`sleeping`/`waiting` 结束活动段，runtime 启动不把停机计入；状态和 claim limits 返回 `runRemainingMs`。真实连续活动达到上限仍会暂停。
- `capability-access.ts`：可选 capability 未连接时从当前任务能力集合省略，不再阻断通讯 MCP；MCP 目录仍显示 disconnected/error，工具目录漂移仍报 `MCP_GRANTED_TOOL_MISSING`。
- UI 中英文提示和操作文档同步为“只累计实际自主活动时间”。
