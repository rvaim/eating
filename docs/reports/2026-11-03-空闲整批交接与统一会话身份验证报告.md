# 空闲整批交接与统一会话身份验证报告

日期：2026-11-03，Asia/Shanghai。状态：源码修复、完整构建与隔离验证完成；未部署、未提交或推送。

## 需求与实际根因

主人要求收到消息先加入有界队列，主 Agent 繁忙时留队，空闲后一次交接所有可交接会话，由主 Agent 自行安排。另反馈同一对象存在两份对话；主动活动先不改，只给方案。

已核实的源码根因：

- Host 既有选择器以 conversationId 分桶，达到条数或体积阈值就停止取消息，且每次只交一个会话；DSH 接收层又强制单会话、最多200事件。
- adapter 的 busy 只追踪自身 SDK run 和自主周期，没有覆盖官方原生 Web／原生目标等启动的主 Agent 轮次，也缺少这些轮次结束后的 Host 唤醒链路。原生 turn/end 不等于 idle。
- 普通入站绑定与主动联系绑定各自分配 UUID，导致同一真实账号、目标及类型产生两套子会话。截图本身不作为某两个 UUID 对应关系的直接证据；独立测试已核实代码的双向重复分配机制。
- 扩大整批后，原有256引用尾截、混合记忆 scope、冷恢复未领取入箱、并发委派先 drain 后检查 pending，以及单个目标超容量毒化整批，都必须在同一交接契约内处理。

## 修改范围

Host 按完整 plugin／instance／account／conversation／kind／target 身份保序聚合；任一会话达到发送条件时一次交接全部可交接前缀。条数和体积只提前触发，不截断。冷却与 uncertain 项不自动重放；ACK、本地确认保存失败、退出和当前格式恢复保持。

DSH 主输入保留全局有序 events，以 context.conversations 给出各真实会话引用；主选择对应 context_ref 后只交该组原始事件给绑定子。原生状态通过当前 root、nonce、递增 sequence、500ms反馈及3秒本机有效期协调 Host；缺失或过期不放行，idle及本地 run 收尾均唤醒 Host。状态检查与 SDK 原生入箱之间仍有并发窗口，极短竞态由原生串行 Inbox 承接，不宣称跨进程原子“空闲时才入箱”。

普通与主动入口统一后续会话 UUID 选择。已有重复日志、历史、unknown、防重和动作账本保留，不自动合并或删除；真实 QQ 两入口均使用同一 canonical conversationId，Host 仍精确核验该字段，不提供旧别名兼容。

当前批次的消息和资源引用完整进入临时授权；持久绑定只保有界256历史。Host 对可信任务引用每类100000、两类UTF8总100MiB显式校验，超限拒绝并保原权限，不静默裁本批引用。

混合来源记忆逐组召回和采集；含糊范围显式返回 MEMORY_CONTEXT_AMBIGUOUS，不能降为主人 self 权限。原生追加输入另走 self。混合外部或需要分段的外部批次只采集各来源原文，不把主协调摘要／全轮动作复制给每个 Peer。每段最多200条，完整 messages JSON 的 UTF8预算为256KiB减1KiB预留，计入转义、元数据和标点。

主动活动行为、waiting／sleeping状态机、额度、主人配置、自定义提示词及人格均未修改；另见[主动活动行为改进方案](../plans/2026-11-03-主动活动行为改进方案.md)。普通／主动会话身份复用属于重复会话修复，不调整主动行为节奏。
