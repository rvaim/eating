# 可信图片发送定向验证报告

日期：2026-11-04，Asia/Shanghai。本报告只记录媒体子任务的源码与隔离验证；整体构建、全量测试、版本、提交、推送及云端更新由父代理的[本轮总报告](2026-11-04-官方记忆与插件能力更新验证报告.md)收口。不读取真实账号配置，不向真人或付费模型发送，不修改本机真实 Eating 或主 DSH。

## 契约与改动

- SDK 保留 `ImageResource`／`readAsset` 作为 AI 图片预览。新增 `PluginImageAsset` 的 `mimeType`、`byteLength`、`sha256`、`readBytes()`、可选 `localFile()`，以及 Host 签发的 `ImageAssetLease`。`assertActive()` 异步复核来源实际字节；`assertCurrent()` 在所有异步操作结束后同步复核当前授权，避免多来源图片之间的 await 窗口遗漏较早来源的撤权。
- Host 资源服务检查同一 caller／source／media 实例、来源 connected、当前 source readTool 权限、scope／signal 和 Host 停止状态；读取前后校验有界字节、MIME、大小和 SHA-256。路径只存在于可信后台方法中，不进入模型、普通工具结果或动作账本。
- 生图和表情库的发送资源方法直接从各自固定 blobs 取得字节，源插件每次校验资源标识、普通文件、目录、符号链接、大小、摘要与媒体类型。AI 预览继续按当前格式返回 Base64；发送不先调用预览入口。
- QQ 后台保留原始 opaque 逻辑参数用于稳定 request_id／幂等；实际 wire 独立构造。只在真实发送前决定文件映射或 Base64，单次调用只有一次 OneBot 发送，failed／unknown 后不切换模式自动重发。
- QQ 新增独立 `media-transport.json`／严格 schema1／revision CAS，保存于账号数据目录，现有 QQ 配置 schema2 保持。映射含 sourceRoot、hostMappingRoot、onebotRoot 和 ownerConfirmed，确认绑定真实连接 endpoint 与账号。设置仅由主人管理入口读取／保存，不进入公开 workspace 配置或模型工具。
- Host 可读目标须与受控源保持相对路径映射，逐图检查普通文件、无路径越界／符号链接、大小、MIME和 SHA-256。OneBot 可见根可使用不同容器目录；Windows、空格、井号与字面百分号编码有定向回归。
- QQ 面板增加自动／共享目录设置、明确主人确认与未验证边界、中英文错误、保存／冲突／草稿状态及 OneBot 先运行和登录的前置提示。语言切换不保存或重置草稿。

## 保持的限制

单图 5 MiB、最多 4 图／合计 10 MiB 保持。只有最终从可信资源实际编码的 Base64 进入后台额外预算：普通 wire 扣其字节后最多 1 MiB，额外最多 14 MiB，全 JSON 最多 15 MiB；模型参数、普通消息、入站事件、响应和 WebSocket 上限保持。正式 OneBot file／URL／Base64 参数仍原样透传。

本轮不增加媒体 URL 路由、公开下载服务、ownerToken URL、新依赖、TLS 或网关。自动模式不根据 loopback、同服务器或主人声明推断已经测试了 OneBot 远端读文件。

正式 [OneBot v11 get_image 文档](https://github.com/botuniverse/onebot-11/blob/master/api/public.md#get_image-获取图片)的 file 参数定义为“收到的图片文件名”，没有任意本地 URI 读探针的标准保证。因此没有调用它验证任意文件，也没有向真人发送测试图；主人声明与 Host 本机逐图检查不被表述为 OneBot 已实际读取。

## 夹具证明范围

真实文件发送夹具按收到的 file URI 实际读取临时映射图，并与源图字节逐项相等。其它回归覆盖默认 loopback 仍 Base64、未确认映射、不同容器根、目标大小／同大小哈希不符、符号链接／缺失／越界、源文件替换及表情删除、scope／source 撤权、读前后／发送前检查、5 MiB／10 MiB／4 图与普通消息预算、unknown 一次发送和逻辑账本无路径／原图。

这些夹具证明代码与协议运输边界，不证明实际云端 OneBot、真实容器挂载、远程目录可读性、真人发送或真实模型会自主选择同一路径。云端需使用父代理已确认提交的部署流程，逐项报告实际回执。
