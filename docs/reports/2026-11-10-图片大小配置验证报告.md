# 图片大小配置验证报告

日期：2026-11-10，Asia/Shanghai。范围：把 Eating 自带图片链路原先固定的本地 5 MiB 限制改为主人可配置，默认 10 MiB。基线为已本地提交的语音功能 `66f01c0`，本地验证完成后，主人明确要求“push 部署到服务器上”，现已授权本轮 Git 发布与云端保留数据更新。实际结果由后续部署记录收口。

## 根因与实现

原限制来自 Eating 的图片资源校验、QQ 下载／发送、MCP image 结果、生图输入／输出及表情库，并非 OpenAI／OneBot 统一规定。固定图片字节与 Base64／wire／上传响应预算同时存在，单独放开一层仍会被其他层拒绝。

新增 Host 独立 `host:image-limits`、严格 schema1／revision／CAS，主人在“设置 → 图片大小”配置 1–50 MiB 整数，缺省 10 MiB。SDK `context.imageLimits()` 提供实时不可变快照；单批原图合计 2 倍／最多 4 张，可信 Base64／wire／上传与提供商响应预算随设置计算，普通 QQ 参数保留独立 1 MiB 上限。完整计算见[ADR-0052](../decisions/ADR-0052-统一可配置图片大小.md)。

存储校验采用独立 50 MiB 支持上限，操作使用当前限额。调低不删图片、不改索引，不把历史大图判为库损坏；列表和元数据管理仍可用，超限预览／发送明确拒绝，调高可恢复读取。发送 lease 绑定设置 revision，变化后旧 lease 失效。已接受生成任务固定提交时上限，继续保存结果，不扩大请求或付费重试。

## 实际验证

环境为 Node 24.22.0、pnpm 11.28.5。所有测试使用独立临时数据、本地提供商及 OneBot 回环，无真实 Key、付费请求或真人 QQ 发送。

| 检查 | 结果 |
| --- | --- |
| 完整构建、严格类型 | 通过；六插件封存产物构建成功 |
| 全量 Vitest | 103 文件通过／2 文件条件跳过；1910 项通过／8 项条件跳过，122.22 秒 |
| 独立系统 DSH | 显式设置 `EATING_DSH_TEST_SYSTEM_BIN`，全量内运行系统集成；未启用独立 SDK 缓存条件下的 8 项不冒充实跑 |
| 表情包组件真实浏览器 | 显式设置 `EATING_STICKERS_BROWSER_TEST=1`，3 项纳入全量通过 |
| Playwright | 15 项通过，16.5 秒，含真实安装后的表情大图上传、生图、设置、滚动及面板布局 |
| 最后补充回归 | 最终构建／严格类型通过；图片策略、生图、表情存储及插件 4 文件 80 项通过，7.18 秒 |

新增策略集成用实际 10 MiB／12 MiB PNG，验证本地下载、表情上传、提供商结果读取、正式 MCP `image_get` 图片块、Host asset lease 以及双图发送到真实 OneBot WebSocket 回环；逐图原始字节一致，提供商 POST 及真实发送各一次。调低到 2 MiB 后，旧 lease 失效、超限预览拒绝；重启仍可列出旧图、原 blob 不变，调高后生图和表情均重新可读。设置缺省不补写、严格格式、CAS、非法范围、主人 session／CSRF 也有验证。

QQ 共享目录回环使用 12 MiB 文件，验证映射校验没有残留默认 10 MiB 截断，来源／挂载字节一致且逻辑动作不包含实际文件路径。无法验证映射时仍在发送前选 Base64，unknown 不二发。

全量后统一参考图错误 code 为既有双语入口，并让表情配置摘要报告当前操作限额而非存储支持上限；最终补充回归覆盖 2 MiB 配置摘要和原图保留，随后完整重建及严格类型通过。未把补充回归宣称为第二次全量。

真实表情管理页默认成功上传 10 MiB，页面打开期间调到 12 MiB 后成功上传 12 MiB，调低到 2 MiB 后拒绝 3 MiB；覆盖文件选择与最终上传转换均读取当前策略。设置页覆盖默认值、保存、CAS 冲突保草稿、重读确认、语言切换保输入及刷新持久化。

已实际查看 1440×1000 和 390×844 设置截图，输入、说明、按钮及手机换行正常；原滚动和页签浏览器回归通过。设计钩子报告的表情包 17px 标题／4px 标签圆角均来自未改动的既有组件样式，属于本次扫描上下文误报，保留现有视觉层级，不添加忽略配置；既有 DESIGN 与 sidecar 时间差也未引入本轮变更。

首轮全量有 3 项失败：QQ 下载 mock 尚未接收新 `maxBytes` 参数，发送预算断言仍写死 14 MiB，表情文件转换测试仍以 5 MiB 判超限。已统一到当前策略，文件转换也显式传当前限额，不恢复旧限制。另修正生图启用测试把正常的“未配置模型”状态提示当错误的断言，保留状态提示并只断言无 error alert。最终全量及浏览器均通过，不隐去这些中间失败。
