## 预览根因与改动

原预览节点位于图片资源列表与分页之后。点击任务中的“查看图片”或资源行只读取并替换这个节点，长列表下预览始终在列表末尾。1100px 以下任务与资源改为纵向排列，更需要滚动寻找预览。

改为插件内的原生 modal dialog：

- 两个入口均在当前视口居中打开，加载提示立即出现；图片保持比例，并展示描述、格式、大小和生成时间。
- 关闭按钮、Escape、点击外侧遮罩均可关闭。关闭后保持列表滚动位置，焦点回到原入口。背景表单在弹窗打开时不能取得焦点。
- 关闭或页面隐藏取消在途预览并撤销 Blob，清空所选图片和错误；旧请求的 finally 只处理自己的 controller，避免取消后干扰下一次预览的加载状态。离页保持原有清理。
- 沿用现有主题令牌，支持桌面、390px 窄屏和中英文。只按点击读取，不预加载整页图片，不改变生成流程和图片设置。

验证中发现共享 ActionButton 在 disabled 且带说明时由 button 改为 span 包裹 button，会更换原按钮节点，原生 dialog 因而无法恢复该入口的焦点。预览打开时背景已由原生 dialog 置为不可交互，因此移除两处不再需要的 previewLoading 禁用，保持入口节点稳定；未修改共享组件。

## 图片 JSON 误发的实际证据

按用户截图中的资源标识在实际 Eating 专属 DSH 原生日志中定位，未输出原始聊天正文、账号、Token、连接值或私有目录。当天以下五次调用均发生于同一子会话，工具为 qq_send_private_message：

| 上海时间 | message 实际类型 | 字符串内容的结构 | 工具结果 |
| --- | --- | --- | --- |
| 20:44:55 | string | 序列化的 image 段数组 | 非错误，返回 message_id |
| 20:45:55 | string | 序列化的 image 段数组 | 非错误，返回 message_id |
| 20:46:10 | string | 序列化的 image 段数组 | 非错误，返回 message_id |
| 20:49:51 | string | 序列化的 image 段数组 | 非错误，返回 message_id |
| 20:50:47 | string | 序列化的 image 段数组 | 非错误，返回 message_id |

此前 image_get 已成功返回 item／sendable 和图片附件。上述发送都省略 auto_escape；现有 QQ 调用层会填入 true。成功 message_id 只能证明本次文字消息被接受，不能证明图片已发送。

当前实际主代理 owner-policy.systemPrompt 已包含“不能 JSON.stringify”规则和 image 段示例。源码的 QQ 默认类型规则、消息 schema 描述和生图工具描述也已说明对象／数组用法。这次未采集模型 HTTP 原始请求，因此不把当前主提示文件当作每个历史子轮次实际 system 的证据。

### 源码链路

1. `plugins/communication/qq/src/message-schema.ts` 的 oneBotMessage 合法类型包含普通字符串；该字符串不违反现有 JSON Schema。
2. `backend/operations.ts` 的 prepareOneBotCall 保留字符串内容，省略的 auto_escape 设为 true。
3. `backend/media-transport.ts` 的 containsQQImageAssets／resolveQQImageAssets 仅识别结构化的 image 段及 node.content；普通字符串不会触发图片 lease 解析。
4. `src/server.ts` 的 invokeFor 以零图片预算把原文字交给 OneBot，正常返回文字发送回执。

本地使用现有 prepareOneBotCall 和 resolveQQImageAssets，传入仅含示例资源的 JSON 字符串，得到：校验通过、message 仍为 string、auto_escape=true、detectedAsset=false、imageBase64Bytes=0、字符串不变。未调用网络。生图 image_get 本身同时返回标准图片 content 和结构化 sendable，问题发生在后续发送参数组织及发送边界放行。

## 建议的约束方案（尚未实施）

在 QQ 公共发送准备／校验路径增加明确的内部图片引用使用约束，并在动作登记和 OneBot 调用前执行：普通 message 字符串、text 段、快速操作 reply、合并转发 node.content 中，误作为聊天正文使用的内部图片引用或相应序列化图片消息段应返回明确错误，outcome=not-sent，提示 message 直接传 image 对象／数组并复用已有资源。

保持正常 OneBot 字符串／CQ 能力、结构化图片、原授权和媒体 lease 校验。不得把错误字符串自动解析成图片并发送，不做隐藏格式修补；不得因错误重新生图，亦不得自动换请求号重发 unknown。改正参数时遵守既有 request_id 与参数一致性要求。

这能强制阻止已定义的错误格式发给用户，但不能保证模型收到错误后一定成功纠正；真实图片发送仍应核对 image 段调用及相应回执。继续增加人格或提示词中的同义提醒不构成强制保证。该方案将扩展 ADR-0047 当时仅提示词的决定，需要作为单独的发送契约变更实现和验证。
