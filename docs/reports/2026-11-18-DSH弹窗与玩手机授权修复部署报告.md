## 二、问题根因与修复要点

1. **点击“打开 DSH Web”新标签闪一下即关闭（`plugins/harness/dsh` `0.23.3`）**：
   - **根因**：`NativeWebButton.tsx` 同步执行 `window.open('about:blank', '_blank')` 后，真实浏览器会立即聚焦新标签，导致原 Eating 页面 `document.hidden` 变为 `true` 并触发 `visibilitychange`；组件原把 `visible` 纳入 `available` 并通过 `useEffect` 在 `!available` 时执行 `cancel()`，从而在 `open-native-web` 请求尚未返回时就把刚打开的 `popup` 关闭。
   - **修复**：将按钮初始可点击门禁 `canOpen`（`operational && visible`）与在途弹窗存活条件 `operational`（`enabled && ready && !blocked`）解耦；聚焦新标签导致的 `document.hidden = true` 不再误杀在途开窗请求，仅在 DSH 停用／未就绪／面板切离卸载／`pagehide` 或开窗失败时取消并关窗；补充 `target.document?.body` 缺失时回退至 `target.location.replace(result.url)` 的防御。同步更新 `tests/browser/native-web-ui.spec.ts` 覆盖“聚焦隐藏仍完成导航”与“离开面板取消并隔离凭证”。
2. **玩手机插件 `ANDROID_ACCESS_REVOKED`、`ANDROID_EXECUTOR_BUSY`、`ANDROID_IMAGE_PENDING` 及面板在途请求误中止（`plugins/capabilities/android-control` `0.3.1`）**：
   - **根因 A（永久封锁 `agentId` 与 `takeover`/`release` 缺陷）**：DSH `ExecutionControl` 按 `(parentId, agentTypeId)` 跨任务复用同一个 `android-control.phone` `agentId`；任务结束／中止调用 `revokeAgentAccess` 后，`server.ts` 触发 `engine.revoke(actor)` 将该 `agentId` 永久写入 `blocked` 集合，新任务持有 Host 签发的新非中止 `AbortSignal` 租约仍被拒绝；同时 `op="takeover"` 先调用 `active()` 后才删 `blocked` 导致无法自救，且 `takeover()` 调用 `revoke(holder)` 反而永久封禁前任占用者，`op="release"` 也直接调用 `revoke(actor)` 封禁自己。
   - **修复 A**：在 `server.ts` 按 `WeakSet<AbortSignal>` 去重绑定中止监听并将 `scope.signal` 传入引擎；`engine.ts` 通过 `activateLease`、`leaseSignals` 与 `revokedSignals` 将吊销严格绑定到具体租约信号——旧已吊销租约继续被拒绝并按信号精准清理残留进程，新非中止租约对复用 `agentId` 自动恢复激活；`release` 仅释放 `controlled` 标记与控制权而不自封；`takeover` 在核验当前调用方未吊销后清零控制权并停止前序占用者活跃进程，不将前序占用者列入 `blocked`；已被直接吊销且无新有效租约的调用仍被 `takeover` 拒绝。
   - **根因 B（命令退出后写控制锁永久滞留）**：`android_adb_exec` 等调用 `active(actor, true)` 占用 `controller` 后，命令正常退出（`exited`）却从未释放 `controller`，导致无活跃进程时后续不同代理继续触发 `ANDROID_EXECUTOR_BUSY`。
   - **修复 B**：仅当 `actor` 仍有 `controlled === true` 的活跃进程留在 `live` 表时保留写控制权，进程退出即通过 `releaseControllerIfIdle` 自动释放，`android_files` `put` 同步写完亦即时释放空闲锁；真正有活跃阻塞／交互进程运行时仍严格维持互斥与 `ANDROID_EXECUTOR_BUSY`。
   - **根因 C（`android_screenshot` 固定 10s 超时）**：`android_screenshot` 硬编码 `wait_ms: 10000` 且不接受参数，跨公网虚拟局域网传输逾 1MB 原图时未完成即返回 `ANDROID_IMAGE_PENDING`。
   - **修复 C**：默认并将可配置上限提升至 `wait_ms: 30000`（高速连接下进程结束即返回、不空等），并在工具描述中明确遇到 `ANDROID_IMAGE_PENDING` 时可通过 `android_process_read(process_id, output="image")` 继续等待取图。
   - **顺带发现并修复的前端与集成测试缺陷**：`plugins/capabilities/android-control/src/web/panel.tsx` 的 `[loadConfigurationSnapshot, enabled, saved]` 副作用清理函数原会触发 `abortRef.current?.abort()`，工作区轮询刷新 `saved` 时会误杀在途 `invoke` 请求引发未确认报错；现拆分为仅卸载时终止用户请求。同时修正 `apps/host/src/android-control.integration.test.ts` 遗留自 v0.3.0 重构的夹具 JSON 断言形状（`{ serial, argv }`）。
