# 2026-11-23 消息即时交接与防滞后重组织验证报告

## 根因定位

1. **10 秒默认聚合冷却**：`DEFAULT_DELIVERY_SETTINGS.aggregationWindowMs` 原默认为 `10000` ms，且云端已保存配置为 `10000` ms，用户每发消息需先等待 10 秒才开始交接给 Harness。
2. **活跃子代理期间追加消息绕行主代理**：原有 `appendWhileBusy` 将同会话后续消息仍送回主代理，经过主代理记忆召回与 1–2 轮 LLM 推理再手动调用 `eating_task_control(message)`，叠加显著额外延迟。
3. **发送前与分段发送缺乏新消息门禁及安全流式抢占**：核对 DSH 运行时源码（`@deepseek-ai/dsh-subagent`、`@deepseek-ai/dsh-agent-loop`、`@deepseek-ai/dsh-tools`、`@deepseek-ai/dsh-session`）后确认：
   - `sendMessage` 默认投递到 `next-step` 队列，不能中止当前正在流式输出的 LLM 响应；
   - MCP 发送工具为串行 `exclusive` 执行，执行前经过 `tools/pre-execute` 钩子；
   - `cancel` 仅在显式 `keepInbox: true` 且正确触发 `wakeRequested` 时可在不销毁子代理激活和租约的前提下切入下一轮。

## 修改内容

- **即时交接与会话序号追踪（`packages/plugin-sdk`、`apps/host`、`apps/web`）**：
  - 将 `DEFAULT_DELIVERY_SETTINGS.aggregationWindowMs` 默认值由 `10000` 调整为 `0`（保留 `0–300000` ms 配置能力及拒收退避冷却）。
  - Host `HostStore` 新增会话级最新入站序号与订阅监听；`HarnessDeliveryService` 新增 `flushConversation` 即时释放聚合等待；`AgentAccessRegistry` 追踪子代理已见入站序号并在非只读工具调用作用域附加不可枚举的 `hasNewerInboundMessage` / `onNewerInboundMessage` 钩子。
- **DSH 同会话活跃子代理热通道与安全流式抢占（`plugins/harness/dsh`）**：
  - 单会话活跃 `reply` 子代理在途时，同会话新批次直接校验租约并投递至该子代理，通过 `@deepseek-ai/dsh-session` `appendPluginRecord` 持久化 `plugin:eating/fast-track-delivery` 并在重启恢复时按已受理收尾、不重放给主代理；非热通道批次仍经主代理并在 `agent/pre-step` 注入 `eating_active_tasks` 摘要。
  - 当子代理处于纯 LLM 流式推理且尚无已提交助手文本或活跃工具调用时，采用「先 `sendMessage` 入队 → `interrupt(keepInbox: true)` → 哨兵 `next-turn` 唤醒并移除哨兵」顺序安全中止过时草稿，立即开启下一轮整合新消息。
  - 在 `reply` 子代理挂载 `agent/pre-step`（推进已见入站序号）和 `tools/pre-execute` 发送门禁：发消息前检测到未读入站消息即调用 `/check-inbound` 触发 `flushConversationNow` 并等待热通道送达，以 `NEW_INBOUND_MESSAGE_PENDING`（`outcome: 'not-sent'`）拦截过时发送。
- **QQ 发送端与分段发送新消息门禁及提示词更新（`plugins/communication/qq`、`apps/host`、`plugins/harness/dsh`）**：
  - QQ 发送工具在执行前及正则分段发送间隔内检测新入站消息；未发出前直接返回 `NEW_INBOUND_MESSAGE_PENDING`（`not-sent`，不写 `unknown`），分段发送中途立即唤醒止损并返回确定的 `parts_sent` / `parts_held` / `held_messages` / `interrupted_by_new_message: true`。
  - 同步更新主子代理协调规则与默认提示词，要求子代理在收到新消息或发送被拦回时重新评估先前内容是否仍需发送并重新组织语言。
- **版本同步**：应用／Host／Web `0.29.0`、`@eating/plugin-sdk` `4.17.0`（`@eating/plugin-core` `4.0.0`、`@eating/ui-sdk` `4.4.2` 与 `pnpm-lock.yaml` 不变）；`dsh` `0.28.0`、`qq` `0.22.0`，其余 6 个插件按封存插件规则递增补丁版本（`stickers` `0.4.3`、`image-generation` `0.8.2`、`openviking-memory` `0.4.3`、`text-to-speech` `0.3.4`、`speech-to-text` `0.2.4`、`android-control` `0.3.5`）。

## 后续故障根因与 0.29.1 修复部署

### 现场根因

1. **`AgentAccessRegistry` 范围污染导致 `append-task` 触发 `403 AGENT_SCOPE_VIOLATION`**：上一轮子任务发送 QQ 分段消息后，`AgentAccessRegistry.invoke` 把全部 `message_ids` 记入 `actor.returnedMessageIds` → `actor.scope.messageIds`，而 `DshAgentControl /actions` 仅收集单个 `message_id`（遗漏分段后的 `message_ids[1]`）。同进程内下一轮任务启动时，`AgentAccessRegistry.issue` 将 `previous.scope.messageIds`（含旧 `returnedMessageIds`）混入新任务的 `actor.baseScope.messageIds`；随后热通道触发 `append-task` → `extendAgentScope` 时因缺少旧分段 ID 直接拒绝。
2. **热通道发送前未回退主代理与轮询未快速止损**：`tryFastTrackToActiveChild` 未对发送前 `not-sent` 控制错误回退主代理；`append-delivery` 失败后 `adapter.ts` 立即将 `runtimeReady` 置 `false` 且仍轮询等待 15 秒超时，将队首消息 `1570`（批次 `a398d098`）标为 `uncertain` 挂起后续消息，同时令 11 秒后子代理完成唤醒主代理的轮次触发 `[CONTACT_TURN_INVALID]`。
3. **未确认批次导致重启误报 `SESSION_RECOVERY_FAILED`**：`runtime-bridge.ts` `inspectStoredSession` 对 `deliveries.json` 中尚未确认的 `accepted: false` 预期批次缺失同样抛 `SESSION_RECOVERY_FAILED`，而非汇报 `recovery: 'absent'`。
