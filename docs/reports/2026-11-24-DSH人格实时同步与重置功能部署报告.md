# 2026-11-24 DSH 人格实时同步与重置功能部署报告

## 根因定位

### 一、切换人格后 DSH 提示词仍停留在旧人格

1. **宿主修改人格/提示词后未向运行中的 DSH 实时推送**：`apps/host/src/app.ts` 的提示词保存/重置、人格修改/激活、外貌图片增删改序及插件配置更新路由只写回宿主存储，未通知已连接的 Harness 重新下发 `bridge/owner-policy.json`。即使已切换到新人格，运行中的 DSH 仍继续读取上次启动时写入的旧 `owner-policy.json`。
2. **双外貌人格切换未重新挂载外貌能力**：`syncPersonaAppearanceTopology()` 仅在“有外貌图片 ↔ 无外貌图片”边界翻转时调用 `changeCapabilityTopology()`。当从“有外貌图片的人格 A”切换到“同样有外貌图片的人格 B”时，旧工具能力不会重新发布，DSH 侧持有的仍是旧人格的外貌描述与配置。
3. **DSH Web 手动新建的非根交互会话未挂载主人系统提示词**：`plugins/harness/dsh/src/backend/runtime-agents.ts` 的 `onAgentCreated` 仅给根主会话和受管任务子代理安装系统提示词，对在 DSH Web 中直接新建的非根交互会话遗漏了 `eating:owner-system` 段落。

### 二、DSH 插件“删除历史会话”首次必败且需要重启后二次操作

1. **与宿主 `manage` 互斥锁死锁（409 `PLUGIN_BUSY`）**：旧版 `withStoppedForRestart` 在 `POST /api/plugins/dsh/manage` 执行期间，宿主已将 `mutations.get('dsh')` 标记为 `'manage'`；随后 DSH 插件在内部自行调用 `connect()` → `registerSink()` 尝试恢复运行，直接触发宿主 `PLUGIN_BUSY` 并发保护失败，导致首次操作半途报错并遗留停止态。
2. **重复收集待删除文件导致提交阶段 `ENOENT` 中断**：旧版 `deleteSelected` 重复调用 `sharedFiles()` 并把同一路径两次压入删除列表，首次执行在提交阶段遇到第二个重复路径时抛出 `ENOENT` 中断，导致后续 `session.json`、`bridge/*` 与 `session.v4.jsonl` 未清理干净。
3. **POSIX 文件锁残留导致活跃状态误判**：DSH 依赖 `flock(2)` 持锁，进程退出后 `session.lock` 文件按设计保留在磁盘上；旧逻辑仅凭锁文件存在即误判 `live: true`。

## 修改内容

### 一、人格与提示词实时同步

- **`packages/plugin-sdk`（`4.17.0` → `4.18.0`）**：
  - `BackendPlugin` 新增可选回调 `onOwnerConfigurationChanged?(): void`。
  - `HarnessHostServices` 新增 `readQueueSummary?()` 与 `coordinateReset?()`，供宿主统一编排重置生命周期。
- **`apps/host`（`0.29.1` → `0.30.0`）**：
  - `apps/host/src/app.ts` 新增 `notifyOwnerConfigurationChanged()`，在提示词更新/重置、人格修改/激活、外貌图片新增/重排/改名/删除以及非 Harness 插件配置与启停变更后立即通知当前 Harness。
  - 修复 `syncPersonaAppearanceTopology()`：在两个都带有外貌图片的人格之间切换时同样触发 `changeCapabilityTopology()`，确保外貌能力描述与引用同步刷新。
- **`plugins/harness/dsh`（`0.28.1` → `0.29.0`）**：
  - `adapter.ts` 实现 `onOwnerConfigurationChanged()`：DSH 运行中时立即重写 `bridge/owner-policy.json` 并热更新运行时提示词策略；DSH 未运行时跳过写入、待下次启动统一生成。
  - `runtime-agents.ts` 在 `onAgentCreated` 中为 DSH Web 直接创建的非根交互会话挂载 `eating:owner-system`（`mainSystemPrompt`）。

### 二、将“删除历史会话”替换为“重置 DSH（保留 Eating 配置）”

- **宿主协调重置与队列处理（`apps/host/src/harness.ts`、`apps/host/src/app.ts`）**：
  - `HarnessDeliveryService` 新增 `drain()`，在清理投递队列前先等待已中止的在途投递安全收敛。
  - `harnessServices(id)` 实现 `readQueueSummary()` 与 `coordinateReset()`：由宿主统一执行「停止运行时 → 执行重置 → 按用户决定保留或清空投递队列 → 若重置前处于运行态则切换互斥态为 `'connect'` 并自动重启」，避免 `PLUGIN_BUSY` 死锁，同时不削弱普通并发 `manage` 请求的互斥保护。
- **重置引擎与安全边界（`plugins/harness/dsh/src/backend/session-history.ts`、`adapter.ts`、`launch/dsh-system.mjs`）**：
  - 新增 `DshResetEngine` 及 `preview-dsh-reset` / `reset-dsh` 操作，配备严格路径/符号链接越界守卫（`Guard`）及 `dsh-reset-receipt.json` / `dsh-reset-lock.json` 幂等锁与回执。
  - **保留范围**：Eating DSH 插件全部配置文件（`config.json`、`model-capabilities.json`、`model-information.json`、`native-capabilities.json`、`autonomy.json`、`autonomy-agenda.json`、`proactive-contact-policy.json`）以及 `dsh-home/profiles/**`（DSH 原生已安装插件与 Profile 配置）。
  - **清理范围**：Eating 创建的 `workspace/*`（遇到符号链接仅安全 unlink 链接本身、不触碰外部目标）、`dsh-home/*`（除 `profiles`）、`agents-home/`、`runtime-home/`、`bridge/*`、`native-management/`、`session.json`、`*-bindings.json` 及旧版 `session-history-*` 残留。
  - 放宽优雅停机等待窗口（`shutdownTimeoutMs: 2500`、`disposeEofGraceMs: 2000`、`disposeGraceMs: 2000`、`closeTimeoutMs: 10000`）并加固 `launch/dsh-system.mjs` 子进程退出清理。
- **双语重置面板与队列门禁（`plugins/harness/dsh/src/web/{SessionHistory.tsx,history-data.ts,history-i18n.ts,history.css}`）**：
  - 将 DSH 插件第三页签升级为「重置 DSH / Reset DSH」，明确展示将清理范围与将保留配置、4 栏当前运行状态摘要、原生定时任务提示、预览令牌倒计时及显式确认勾选。
  - 当投递队列存在待发或不确定消息时，向用户弹出交互式处理选项：取消重置、保留队列消息仅重置 DSH、或一并清空队列并重置 DSH；页面隐藏时自动清理临时敏感确认状态；样式全部使用主题设计令牌（零硬编码颜色）。
