# 2026-11-24 自主运行超时自动恢复与流式超时修复部署报告

## 1. 背景与根因结论

本次排查覆盖 Eating 自主运行模块与系统 DSH 依赖源码（`@deepseek-ai/dsh-llm-pi-ai`、`@deepseek-ai/dsh-agent-loop`），证实了导致自主运行频繁触发 `AUTONOMY_CYCLE_TIMEOUT` 并永久中断的三大根因：

1. **DSH `llm-pi-ai` 未接收请求与流式空闲超时参数**：`plugins/harness/dsh/src/backend/adapter.ts` 的 `createRuntimePatch` 未向 `llm-pi-ai` provider 配置传入 `timeoutMs` 与 `streamIdleTimeoutMs`。依赖默认 `streamIdleTimeoutMs = 300000`（5 分钟）且未设置请求超时，Eating 配置的 `timeoutMs`（60 秒）未生效；上游模型连接卡死或限流重试挂起时会拖满 120 秒单轮上限，直接触发整轮超时。
2. **单轮超时误按 `unknown` 结算并永久冻结自主运行**：`plugins/harness/dsh/src/backend/autonomy-runtime.ts` 在普通单轮超时（非连续执行预算耗尽）时无条件按 `outcome = 'unknown'` 结算，绕过 `maxConsecutiveFailures` 并在首次超时即置位 `ownerPaused = true`；同时 `autonomy.ts` 在连续失败达阈值时也永久置位 `ownerPaused = true` 且不自动恢复，导致后续所有自主活动中断直至人工点击恢复。
3. **自主轮次超时取消后滞留 `agent.inbox` 导致永久繁忙**：部署前现场核查进一步发现，若自主轮次运行期间有外部消息通过 `append-delivery`/`steer` 进入 `agent.inbox`，随后自主轮次因超时调用 `agent.cancel({ kind: 'user' }, { keepInbox: true })`，`@deepseek-ai/dsh-agent-loop` 因中止阶段 `wakeRequested = false` 在回合结束回到 `idle` 后不会自动唤醒驱动消费队列，导致外部消息长期滞留且 `runtimeStatus.busy` 锁死为 `true`。

## 2. 根因修复内容

- **运行源码提交**：`46ea7eb`（含前置核心提交 `39cbd43`；文档收口提交不改动运行代码）。
- **版本变化**：应用／Host／Web `0.30.0 -> 0.30.1`，`dsh` 插件 `0.29.1 -> 0.29.2`；`@eating/plugin-sdk 4.18.0`、`@eating/ui-sdk 4.4.2`、其余 7 个插件（`qq 0.22.1`、`stickers 0.4.4`、`image-generation 0.8.2`、`openviking-memory 0.4.4`、`text-to-speech 0.3.5`、`speech-to-text 0.2.4`、`android-control 0.3.5`）及 `pnpm-lock.yaml` 保持不变。
- **关键改动**：
  1. `plugins/harness/dsh/src/backend/adapter.ts`：`createRuntimePatch` 为 OpenAI 兼容及 Google Gemini 协议透传 `timeoutMs` 与 `streamIdleTimeoutMs`，使卡死的流式请求可在单轮内快速超时并由 DSH 重试。
  2. `plugins/harness/dsh/src/backend/autonomy-runtime.ts`：普通单轮超时（`!budgetLimited`）按 `failed` + `AUTONOMY_CYCLE_TIMEOUT` 结算，子代理动作仍沿用既有 ADR-0062 回执核对与隔离；冷却期保持心跳观察与自动认领；`cancelFlight` 调用 `agent.cancel(..., { keepInbox: true })` 后登记 `resumeInbox`，主 Agent 回到 `idle` 时移除残留 `eating-autonomy` 并沿用 `plugin:eating-recovery` sentinel 立即唤醒消费未认领外部消息。
  3. `plugins/harness/dsh/src/backend/autonomy.ts`：保持 `schemaVersion: 3` 存储契约不变（零迁移）；单次超时或模型失败按 `minIntervalSeconds * failures` 退避自动续跑；连续失败达到 `maxConsecutiveFailures` 时进入有界指数退避冷却（`reason = 'cooldown'`，`ownerPaused = false`，冷却上限 60 分钟，定时任务不穿透冷却），冷却结束自动重试并在成功后清零失败计数；真实 `unknown`、`AUTONOMY_RUN_LIMIT`、控制/持久化故障仍严格硬暂停并要求核对；同步修复长轮次结算后心跳瞬间误报 `status-unavailable` 的问题。
  4. `apps/web/src/pages/AutonomySettings.tsx` 与 `apps/web/src/i18n/autonomy.ts`：新增 `cooldown` 中英文横幅文案、状态代码与下次重试时间展示，并提供「立即唤醒」与「暂停运行」操作。
