## 前端平台子实验：2026-10-26

- 环境：macOS arm64；普通 Node 24.22.0，pnpm 11.28.5。
- 固定依赖：React/react-dom 19.3.1、TypeScript 7.0.2、Vite 8.3.5、plugin-react 6.1.2、Vitest 5.0.5、Playwright 1.64.1、lucide-react 1.61.0；精确解析见[锁文件](../../pnpm-lock.yaml)。
- 服务：[本地 Eating](http://127.0.0.1:5180/)，独立于 DSH GUI，仅绑定回环地址。
- 实现与复现命令：[首版说明](首版平台验证说明.md)。

| 检查 | 实际结果 |
| --- | --- |
| `pnpm build` | TypeScript 严格检查与 Vite 生产构建通过；无真实后台参与 |
| `pnpm test` | 3个文件、65项通过：注册表16、持久配置26、工作区23 |
| `pnpm test:e2e` | Chromium 5场景通过：两级导航/自有字段/刷新保存；微信注册/独立移除/恢复；全移除/取消/空态；损坏存储不覆盖；390px无横向溢出 |

- 独立设计复核：首轮fix，M1输入边界对比不足；修正为3.254:1，并修正S1错误方位文案、S2移除/取消焦点。最终修复评分 **ship**，三项resolved、remaining clear，仅对该修复清单作结论，不宣称整站/后端认证。
- 额外脚本验证：取消后移除按钮获得焦点、QQ/飞书移除后目录标题获得焦点，均为true；八种实际截图已读取有效。

初次浏览器测试4通过1失败：损坏 JSON 被统一归类为存储访问失败提示。已区分 JSON 解析错误与浏览器读权限错误，复跑5/5通过，原记录仍未覆盖。初次构建发现 ES2022 类型目标不提供 toSorted，改为复制排序，后续构建通过。

## 开发环境根因记录

DSH bundled Node 24.21.0 启用 macOS hardened runtime；Rolldown 的 Darwin arm64 原生模块虽正确安装，仍因不同 Team ID 被 library validation 拒绝。WASI 缺失是后续 fallback，不是缺少平台原生包的根因。

未改 DSH 签名、沙箱或依赖版本。按工具要求仍可用提供的 Node 执行 pnpm，保持项目工具子进程通过现有 PATH 使用普通 Node 24.22.0，已真实构建/测试通过。使用普通 Node 启动 Eating 的标准命令见说明；不要求产品最终依赖用户开发环境。
