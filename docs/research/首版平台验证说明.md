# Eating 首版平台验证说明

> 历史说明：以下描述基线6da6044的纯前端版本，不是当前运行方式。旧插件源码见[历史索引](源码历史索引.md)，当前正式QQ见[配置与测试](../operations/QQ配置与功能测试.md)，不要按旧步骤导入真实账号。

当前可运行的是 **React 本地网页验证版 0.1**，不是完整桌面产品。入口：[本地 Eating](http://127.0.0.1:5180/)。预览进程停止后需按下文重启；它独立于 DSH Web GUI。

## 当前能验证

- 全局左栏按“概览、机器人”排列。
- 机器人页内分类从已注册插件目录生成，插件自己提供配置组件。
- QQ/飞书默认注册；微信从“注册插件”目录加入，分类和面板同时出现。
- 中文字段校验、保存、纯格式的本地校验、刷新恢复。
- 移除需要确认，仅撤销注册；保留配置，不影响其他平台。重新注册可恢复配置。
- 全部移除后的空状态、未知历史模块保留、损坏存储/写失败的真实错误。
- 桌面两层左栏，窄屏保留全局入口并将页内分类改为可滚动横向导航。

平台均明确“本地示例/未连接”；本地校验没有网络请求。不会登录真实账号、收发消息、启动模型、使用长期记忆或创建 Harness。配置不要填真实密钥。

## 结构

| 层 | 实现与边界 |
| --- | --- |
| 纯业务注册 | [registry.ts](../../packages/plugin-core/src/registry.ts)，只管声明验证/目录/撤销/订阅，不依赖 React/平台名称 |
| 本地数据 | [历史persistence.ts](https://github.com/rvaim/eating/blob/efbd70e/packages/plugin-core/src/persistence.ts)，版本校验、读写错误，不覆盖损坏记录 |
| 工作区 | [workspace.ts](../../apps/web/src/state/workspace.ts)，先持久化再更新界面，分插件保存、移除保留 |
| 前端契约 | [contract.ts](../../packages/ui-sdk/src/contract.ts)，界面组件位于前端贡献，不进入纯业务核心 |
| 模块发现 | [catalog.ts](../../apps/web/src/plugins/catalog.ts)，Vite 构建期发现本地模块入口，通用页面不枚举平台 |
| 实际插件面板 | [QQ/飞书/微信旧入口](源码历史索引.md)，当时分别声明字段/校验/默认值/组件 |
| 页面 | [App.tsx](../../apps/web/src/App.tsx)、[Robots.tsx](../../apps/web/src/pages/Robots.tsx)、[Overview.tsx](../../apps/web/src/pages/Overview.tsx) |

这是业务插件目录与浏览器组件注册，不是 Cordis Host 的动态代码加载。所有示例代码随当前构建提供，面板“注册”不从网络安装新包，也不替代未来可信安装审批。

新增本地示例可在现有 `plugins` 根下添加自己的目录和 `entry.tsx`（代码文件名是工程接口）。导出符合契约的模块后重新构建，由自动发现加入目录；不需要改 QQ、飞书、通用导航或配置条件分支。任意外部包安装/热加载/权限控制尚未实现。

## 本地运行

要求普通 Node.js >=22.12.0（本次实际验证为 macOS arm64 / Node 24.22.0），pnpm 11.28.5。版本固定在[包配置](../../package.json)和[锁文件](../../pnpm-lock.yaml)。

```bash
pnpm install --frozen-lockfile
pnpm dev
```

默认地址 http://127.0.0.1:5180/，占用时明确失败，不偷偷换端口。打开根地址为概览，`/#robots` 为全部平台，`/#robots/qq` 为一个示例面板路由（实际 ID 仍由插件目录提供）。

```bash
pnpm build
pnpm test
pnpm exec playwright install chromium
pnpm test:e2e
```

浏览器测试需预览服务正在运行；Playwright Chromium 第一次需安装到其缓存。当前没有要求或实现 CI 自动启动脚本。

本次工具用提供的 Node 执行 pnpm，但**开发工具的子进程使用已有普通 Node**。DSH 签名的 hardened Node 直接加载 Rolldown 原生模块会因 Team ID 不同被 macOS 拒绝，原因已确认；不重装碰运气、不改签名、不降低 DSH 安全。可用普通 Node 启动项目，见[验证结果](PoC验证结果.md)。

## 数据与限制

本地存储键 `Eating.prototype.workspace.v1`，仅属于当前来源/浏览器。记录已注册 ID、按 ID 分开的已保存配置、最近20条实际手动操作；不编造初始活动。清除站点数据会丢本地示例配置。多标签并发合并、正式备份/迁移/密钥存储未实现。

损坏/未来版本/权限读取失败时保留原记录，进入浏览模式；保存明确失败，不假装成功。没有在 UI 提供破坏性一键清空。后续可设计明确导出/修复流程，当前请勿将真实重要数据存入示例。

当前导航切换会卸载未保存表单草稿；“有未保存的更改”可见，但尚无离开页面的统一保护。已保存值不会因此丢失。错误边界只隔离组件渲染错误，不提供恶意 JS、进程/OS 或网络执行隔离。
