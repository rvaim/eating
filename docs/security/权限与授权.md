# Eating 权限与主人授权

状态：2026-10-29。当前应用／Host／Web0.10.0、三个共享包3.0.0、QQ0.10.0、DSH0.5.1，仅接受API3。分层人格与代理范围继续按[ADR-0014](../decisions/ADR-0014-分层提示词与受控子代理.md)，默认不兼容按[ADR-0015](../decisions/ADR-0015-默认不兼容旧版.md)，时间与图片沿用[ADR-0016](../decisions/ADR-0016-原生只读Web与多模态会话.md)；官方原生Web的完整owner功能按用户最新授权及[ADR-0017](../decisions/ADR-0017-原样接入DSH原生Web.md)。本轮验证与图片DNS诊断见[新报告](../reports/2026-10-29-恢复原样DSHWeb与图片DNS诊断.md)。这些是源码与服务端逻辑授权，不等于OS沙箱、任意恶意插件隔离或三平台完整验证。

## 目标与主体

已授权普通操作允许自主使用；新增可执行扩展需可信主人明确批准；付款、重要删除等动作按实际风险保护，不默认每步人工确认。固定人格和审批数据由可信Host／主人入口控制。

| 主体 | 允许 | 必须限制 |
| --- | --- | --- |
| UI／模块页面 | 通过受控Host接口提交配置／操作 | 直接持有运行时内部或其他模块权限 |
| 主Agent／子Agent | 使用已授权工具、申请扩展 | 改核心人格、伪造批准、绕过安装入口 |
| 通讯模块 | 接收／发送并标明平台真实身份 | 用正文声明获得主人权 |
| Harness适配器 | 在授权范围管理选定运行时，提供官方owner入口 | 越权访问主DSH或泄露运行时鉴权入口 |
| 插件底座／注册表 | 核对身份／版本／归属、装配／撤销 | 将注册成功等同可信授权 |
| 安装执行者／脚本 | 执行批准绑定的来源／版本／操作 | 任意扩大权限、访问Host授权凭据 |

## 当前正式实现

QQ／Host建立回环绑定、Host／Origin／跨站校验、本地会话＋CSRF、每插件MCP专用Bearer、QQ令牌只写不回显、POSIX受限配置、稳定request_id和账号作用域unknown保护。主人手动功能测试保留原39项标准OneBot目录，新增1项受控图片扩展，共40项；所有副作用经显式确认。缺稳定动作键时返回not-sent，不随机补键发送。

受控子代理遵循以下边界：

- QQ主人／管理员只从当前完整配置读取并由本地主人入口保存，每类最多100个规范化、安全整数QQ号码，policyRevision CAS，owner优先。更改身份和工具权限不重连，不补缺失权限默认值。接收时核对真实登录账号与sender，正文、昵称或平台sender.role不能改变主人配置，source仍external。
- 系统层只从受信主人配置／已注册来源装配。作者6种作用域、9个受信变量，scope／source必填；模型和MCP没有固定人格、核心提示词或批准数据的写入口。正文、附件、引用与任务保留user数据，主人／管理员变量只由Host本地配置生成。
- Eating SDK主Agent只有列类型和受控委派两个原生工具，不挂全权QQ MCP。子只获得当前类型availableTools中已勾选、可固定会话范围的能力，不再委派；凭据、无关全局维护、通用send_msg和quick不向子开放，子不追加原生文件、Shell或安装工具。这些约束属于Eating SDK主子执行链，官方Web的正常owner功能按已授权官方机制提供。
- Harness只有deliverBatch；getMcpConnection必须带完整scope，readAgentActions与revokeAgentAccess必需，不能回退主人令牌或缺省成功。委派只收类型、真实context_ref与任务。目录和invokeScoped共同核对启用、账号、会话、目标及引用；消息／资源引用各最多256项，资源单值最多2048字符，不能任意遍历其他会话。
- 每任务轮换内存子令牌，finish、断开、停用撤销；调用重读动态权限，旧令牌或迟到调用不能恢复权限。代理身份与稳定request_id经SHA命名空间隔离账本；同参复用已知结果，改参拒绝，unknown不盲目重做。本任务动作集合不混旧任务。
- 子结果向主返回摘要与Host实际动作回执，摘要不冒充成功；普通finalResponse不自动发QQ。flush＋匹配ACK只表示可靠入箱接管，不代表模型消费、任务或平台动作成功。

显示身份以注册pluginName、实际scope.accountId、私聊／群聊和targetId组成，不从instanceUUID或旧label猜账号。切号区分新实例，历史UUID与归属保留；外部正文中的同名字段不能伪造native source。原生agent-message、subagent-settled和time-context各有独立来源，模型输出不冒充平台已发送消息。

## 图片读取与多模态结果

API3工具必须声明resultFormat=json或content；原39项OneBot保持json，qq_view_received_image声明content并返回真实标准MCP image。图片扩展只按当前账号／会话收到的message与resource配对读取，不能用两份独立白名单授权交叉引用，不接受任意本机路径或任意网址。

网络获取先核对启用状态、scope和引用，结束返回前再次复核；切号、撤权或任务结束后迟到字节不能重新授权。公共DNS校验并固定公网地址，拒本地／私网目标、禁止重定向，不传OneBot／Host认证头。上限5MiB／10秒，MIME与字节格式同时校验；只有远端路径而没有可用获取接口时返回MEDIA_UNAVAILABLE，不登录远端、不读本机文件、不猜地址。

本轮真实图片主机multimedia.nt.qq.com.cn经dns.lookup仅返回198.18.7.115，符合Fake-IP特征；SSRF对198.18/15保留段的拒绝发生在HTTP GET前。当前imageInput=true，不归因于能力关闭；未确认具体代理来源，不记录QQ标识、签名URL、rkey或消息正文。本轮图片／网络策略不改，仅说明用户网络DNS层恢复真实公网解析，或未来显式授权的受信图片代理；不全局放行198.18／私网或开放目录，不据旧报告声称真实公网图片已通。

Host普通JSON执行记录不保存Base64，浏览器预览用临时Blob，离开时revoke。Eating不新建聊天媒体库；已给模型图片由原生附件机制负责持久化，工具调用方／原生会话可能继续保存其结果，不能承诺整条链路无留存。

模型输入能力由主人通过管理入口单独声明，初始imageInput=false，revision CAS且只停runtime可保存。endpoint／model改变重置false，Key／超时不重置；不能凭型号自动授予image能力。纯文本模式拒绝实际图片，视觉模式也只表示已声明输入能力，不证明真实提供商识图准确率。原图按需给授权执行子Agent，主先收摘要，不默认将全图交主。

## 模型、时间和会话读取权限

模型获取／测试只由受控管理入口使用已保存endpoint／key，选择只改草稿。测试最小Ping、max_tokens=1、最多15秒、禁重定向且响应1MiB；成功只证明本次API连通，不代表运行时或业务成功。

官方time-context仅在主、子各自ctx挂载一次，依赖agents／sessionProjections，Asia/Shanghai与600000ms原生默认；仅已有合格step追加source.kind=time-context的user context，冷恢复按原生日志去重。没有时间工具、scheduler或后台模型唤醒。通用／QQ默认提示移除动态时间行，9个可信变量仍可由主人自定义使用；若自定义system再次使用当前时间，缓存影响据实说明。

Eating看板手动读当前专属root的真实parentSession树。公开Session.fromRestore与当前message projections恢复有效surface，保来源／关联ID／替换关系，inbox编辑或撤回不充当已读消息，不把当前binding revision赋给历史。默认50条、列表100、每次最多扫描2000个原生日志位置、响应1MiB／单文本32K；过滤秘密与reasoning。隐藏／离开清正文，不后台轮询，停机可读且不启动Agent／模型／新会话。缓冲未落盘时不伪造状态或更新时间。

## 同进程官方原生Web与owner入口

原生Web与SDK共用同一个Eating专属DSH进程、注册表与原主子会话，不连用户主DSH，不启动第二个共享目录写进程，不修改官方npm源码。挂载当前官方SessionController host、client roster、Gateway和owner鉴权，保留完整官方UI、主题、侧栏、消息组件及会话操作。用户已明确授权create／prompt／settings等正常官方能力，冷follow及会话激活按官方机制处理，不增加Eating根树限制。

主人主动调用open-native-web取得`{url, rootSessionId}`，由“打开DSH原生Web”按钮在新页签进入127.0.0.1合法端口的官方鉴权入口。普通`runtimeStatus.nativeWeb`只有`{ready}`，删除readOnly字段；入口与鉴权不进普通status或模型上下文。web的printUrl／openBrowser／surfaceContext均为false，避免污染SDK控制通道。关闭页面不停止QQ，Harness停止即关闭Web。

移除Eating readerPeer、connection隔离、HTTP写白名单、readonlyController及冷follow拦截；删除src/native-client源码、打包和模块注入，不通过隐藏按钮限制官方功能。不注入Eating sidebar／composer／message renderer、硬编码配色、LocaleBridge或agentLabels映射。平台JSON按官方默认组件原样呈现，标题显示依官方机制，不保证旧标题一律外观修正；Eating离线summary与source仍留在Eating自有面板。SDK两工具与受scope约束的QQ子MCP保持，原生Web创建的普通Agent不按QQ scope child校验或报错。

## 格式、产物与真实数据保护

清单、后台入口与实际实例kind必填一致，唯一API3；assets为必填readonly string[]，当前QQ与DSH均为空数组，integrity继续覆盖全部基础文件与声明assets，不再交付Eating自定义原生客户端资源。安装前验证资源树、重复／路径／哈希，完整独立复制，不依赖源码邻接目录。SHA只证明与清单一致，不证明发布者可信或建立OS沙箱。

作者schema2、QQ wrapper schema2、DSH绑定schema2、独立模型能力schema1和各当前存储形状在写入前验证；旧API2或缺字段明确拒绝，不推断权限或自动转换。坏配置局部报错，不渲染可写空表单。

默认不兼容不授权清空真实资料。本轮真实实例更新须按已批准范围停机、核对完整栈、备份并保配置／人格／原生UUID／Key；实际执行与摘要以[项目状态](../项目状态.md)及验证报告为准。不能把隔离测试写成已部署，也不能用新EATING_HOME冒充保留原身份。当前PATCH、空Key保持、正常重连、同版恢复、ACK重建和幂等继续存在。

## 执行边界、扩展与撤销

Preset、工具过滤、prompt、Cordis scope和Eating注册表是逻辑机制，不是完整OS沙箱。同用户任意Shell／文件可能改安装目录与批准配置；进程独立、Profile或双home本身不等于权限隔离。低权限身份、配置／网络／安装入口与OS沙箱仍须独立验证。

新增Harness／通讯模块、可执行前端、MCP、未授权预装模块激活或远端执行纳入主人审批；不能先执行插件再申请。贡献项绑定所有者／版本／权限，撤销后迟到请求不能复活入口。同进程第三方JS与共享页面的真实访问范围仍需验证，不以Error Boundary声称隔离恶意代码。

批准绑定可信主人、请求、精确来源／版本／操作／数据身份及有效状态。安装、启用、卸载和删除资料分别授权；停用／卸载保配置、未决动作和历史，不能默认删共享依赖。DSH原生plugin-manager参数不替代Eating主人授权，其语义不自动推广到其他Harness。

## 验收

实际SDK、官方原生Web与owner正常操作、时间、既有图片wire及图片DNS诊断、浏览器验证统一见[本轮新报告](../reports/2026-10-29-恢复原样DSHWeb与图片DNS诊断.md)，本页不重复最终计数或预填部署结论。原生实跑须显式设置独立EATING_DSH_TEST_RUNTIME；跳过不能写实跑。回环wire只证明当时图像进入请求，不证明本次真实公网图片已通或识图准确率。

本轮核对官方UI与主题／侧栏／会话功能原样接入、官方owner鉴权、普通Agent与QQ scope child区分，以及SDK工具scope／引用配对、撤权后迟到结果和assets=[]独立产物。Eating离线看板的树边界不套到官方Web。OS凭据／文件隔离、恶意插件、真实提供商与三平台另行验证。见[威胁模型](威胁模型.md)、[插槽设计](../architecture/插槽式扩展.md)和[待确认问题](../待确认问题.md)。
