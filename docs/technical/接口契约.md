## OpenViking记忆（2026-11-01）

当前记忆能力见[ADR-0027](../decisions/ADR-0028-OpenViking记忆能力与自动采集.md)。plugin-sdk4.5.0新增可选BackendPlugin.memory及HarnessHostServices.memory，定义在[公开记忆契约](../../packages/plugin-sdk/src/memory.ts)。MemoryProvider.recall/capture/flush由插件实现，Host当前回合服务begin/append/finish/end仅保存RAM上下文；CapabilityInvocationScope.memory由Host动态补充，不从模型入参取得Peer/主人标记。Host复核通讯插件owners与真实批次，跨会话权限仅主人私聊/原生主人操作；普通自动召回当前＋全局。

DSH0.12.0在所有准入钩子之后追加历史参考上下文并采集主回合终态，子代理不重复采集。当前工具返回只记录名称和returned/failed/unknown，不保存参数/结果正文；记忆故障不撤原生交接ACK。SDK/API版本、配置和状态schema独立，无旧格式自动迁移。插件MCP工具memory_search/read/save/scopes沿用既有精确授权；自动采集开关独立。配置面板GET/POST configuration完整CAS，manage提供snapshot/test-connection/flush/search/read/delete，删除需confirmed=true及精确当前记忆文件URI。记忆0.2.0要求配套协议1扩展：capabilities声明增量提取和历史分段，Session incremental-memory接受request_id、expected_sequence、本轮messages和archive_max_bytes，持久回执包含[from_sequence,to_sequence)、状态、真实changes与可为空的archive_uris；普通提取无需归档。配置/状态schema2，manage增加retry(jobId)，仅对服务证明未进入应用的失败重试原请求，不重发消息；unknown拒绝。更多字段见[操作说明](../operations/OpenViking记忆插件.md)和[扩展协议](../../integrations/openviking-incremental/README.md)。

## 自主运行与当前轮次联系（2026-11-02）

当前整合版本为应用/Host/Web0.15.0、plugin-sdk4.5.0、ui-sdk4.1.0、plugin-core4.0.0、QQ0.13.2、DSH0.13.1，记忆源码0.2.0保持，插件仍API4。公开[自主契约](../../packages/plugin-sdk/src/autonomy.ts)提供 BackendPlugin.autonomy 的 snapshot/configure/control；通讯 proactive 提供 channels/scope。无输入定时协调要求 readProactiveChannels/prepareProactiveScope/hasPendingMessages，缺接口明确报不支持。`enabled`／`ownerPaused` 只控制无输入定时机会，不阻断普通有输入主轮次的联系；真正自主机会取消时撤销该轮许可。

主人 GET /api/autonomy 返回 protocolVersion1、Harness 能力／配置状态、agenda（AI定时任务）和当前通讯通道；POST 仅接受 {harnessId,operation,input}。configure 使用完整配置＋expectedRevision；pause/resume/wake 使用 expectedRevision＋expectedActivityRevision；acknowledge-contact 要求 confirmed=true、当前配置 revision 和精确 agentId/taskId；cancel-scheduled-task 要求当前 agenda revision 和 taskId。Session/CSRF/Origin、插件启用与 mutate 锁保持，模型不能调用管理 API。

主 Agent 使用 `eating_schedule_task`／`eating_cancel_scheduled_task`，按 agenda revision 创建／取消 `autonomy-agenda.json/schema1` 中的未来一次性任务；`eating_activity_state` 同时返回 agenda。最多50条、每条2000字符、未来1秒至365天，到期每轮最多合并10条为同一自主机会，来源仍为 `eating-autonomy`，明确是过去的自己安排的任务。任务到期可打断sleeping/waiting，仍受主人暂停、额度、runtime和周期检查；cycle持久登记后移出agenda，中断按unknown处理，不重放已进入会话的任务。当前无重复规则，自主周期中仍禁止创建／修改原生DSH Schedule。

真实主 Agent 的原生当前 turn 均可使用 `eating_list_contact_targets`／`eating_contact_target`，覆盖QQ群／私聊、原生主输入、目标续行、定时唤醒，无需目标先发私聊。联系入参仅为当前列表返回的 target_id 和 task，后台构造账号／类型／目标及工具交集；主 Agent 自主决定，受限子代理执行。普通 `eating_delegate_task` 仍绑定当前批次 context_ref 和消息／资源 scope，群 context 不能冒充私聊，跨目标走联系策略且不继承旧资源引用。

getMcpConnection 的 Host 内 ScopedAccessPolicy 只含精确 toolNames 和 active 闭包，不可序列化或由模型提供，与插件当前类型工具政策取交集。准备、真实调用、异步资源取得后及发送前复核真实主 turn、账号／对象／工具和撤权；内部控制以 nonce／随机令牌及主 Agent 身份校验，不信正文 source。当前 turn 结束、abort、销毁或 runtime 停止撤权；保存联系策略也撤旧许可。主 Agent 不取得 QQ 全权令牌，readAgentActions/revokeAgentAccess 与真实动作账本仍必需。

所有联系任务共用 maxContactsPerHour；公开原生 callId 防重，每目标当前轮次最多32引用，重复／pending／unknown 拒绝，迟到回调不能改 unknown。proactive-bindings.json 保持 schema1，cycleId 沿用为内部轮次引用，不迁移、不恢复旧许可；新 runtime 将遗留 pending 转 unknown。内部定时来源仍为 eating-autonomy，外部 deliverBatch／ACK 不变。

定时任务按[ADR-0032](../decisions/ADR-0032-AI定时任务.md)，当前联系按[ADR-0033](../decisions/ADR-0033-主Agent当前轮次联系权限.md)，状态与恢复见[数据规范](数据目录与账号实例.md)。原DSH0.13.0定时任务验证见[当时报告](../reports/2026-11-02-AI定时任务验证.md)；独立工作树DSH0.12.1的1422项及四项真实联系回环见[联系报告](../reports/2026-11-02-主Agent当前轮次联系权限验证.md)，当时真实目标续行和Web浏览器输入控件未单独端到端验证，未部署。DSH0.13.1整合验证、提交/push与部署待[本轮整合报告](../reports/2026-11-02-定时任务与当前轮次联系整合部署.md)记录。以下旧阶段工具数量不定义当前集合。

## 包与插件

[后台SDK](../../packages/plugin-sdk/src/index.ts)定义BackendPlugin、BackendPluginEntry、Host上下文、来源、工具、批次与回执；[代理契约](../../packages/plugin-sdk/src/agents.ts)定义类型、范围与回执／会话摘要；[作者契约](../../packages/plugin-sdk/src/authoring.ts)定义当前提示词和确定性组合。界面经[公开契约](../../packages/ui-sdk/src/contract.ts)与[受控API](../../packages/ui-sdk/src/api.ts)接入。

插件只导入公开SDK，不引用Host／Web内部或兄弟插件。BackendPlugin与Entry必须声明kind，且与已安装清单一致；不默认communication。清单schema1、API4，身份／版本／种类／声明目录／后台／前端及assets必填；assets为readonly string[]，当前QQ与DSH均明确给[]。integrity覆盖原3个基础文件与全部声明assets；路径、树、重复项和SHA-256在执行前校验，旧API2及缺字段不补齐。加载只用验证后的安装产物；[发现器](../../apps/host/src/discovery.ts)和[安装器](../../apps/host/src/plugin-installation.ts)落实核对。

DSH不再交付Eating自定义native-client资源，完全移除其源码、打包及模块注入，使用Eating专属运行时内的官方Web服务与client roster，不修改官方npm源码。具体交付布局见[工程结构](../architecture/工程结构与插件发布.md)。OneBotConfig属于QQ插件，普通连接PATCH与持久完整配置是不同输入，不把专有字段塞通用SDK。共享类型没有旧prototype持久化API或转发入口。

## 管理与MCP

- GET /api/bootstrap建立会话与CSRF；GET /api/workspace返回当前目录、真实状态及贡献。
- POST /api/plugins/:id/configuration、connect、disconnect、enable、disable、invoke、mcp-registration是主人受控入口；manage只路由明确operation与input，不进入模型工具目录。
- 作者GET /api/authoring、当前文档CAS保存、人格管理与已保存组合预览由[Host](../../apps/host/src/app.ts)验证；旧提示词ID／字段不接受。
- /mcp/:pluginId使用官方StreamableHTTP初始化／list／call及Bearer，不是伪REST。主人手动令牌与子代理任务scope令牌分开，Harness不能请求全权令牌。

Session、CSRF、Host／Origin、体积及结构均校验，本地地址不等于可信。副作用要求调用方预先提供稳定8至128位request_id；缺失／非法not-sent，服务端不补随机副作用键。相同账号范围的HTTP／MCP共用幂等账本，超时不等于外部未发生。

PluginToolDefinition.resultFormat是必填判别字段，取json或content。json保JSON业务回包；content返回PluginContentResult，content含标准MCP text／image块及可选structuredContent，图片必须有受支持mimeType和真实Base64字节。Host不得把整份content结果再次JSON编码成普通文本。原39项OneBot工具声明json，新增qq_view_received_image声明content；通用MCP保持多模态结果，普通JSON操作记录不保存图像Base64。

## 来源和交接

HarnessEvent标明插件／实例／真实账号／会话／发送者、接收时间、结构化content/text及source.external。可按插件声明提供角色／目标／消息与资源引用；这不使正文成为系统指令。QQ按真实连接账号和已保存身份核验，Host规范化队列保这些字段，不凭文本授权。

HarnessMessageSink只有必填deliverBatch(batch, signal)，批次含稳定ID、同会话事件和触发原因；可选isReady负责忙碌就绪，不存在逐条deliver。只有accepted＋durable＋receiptId并本地确认才转移正文所有权，不表示模型消费或外部动作完成。明确拒收有限重试，未知保留；本地确认失败只重试本地。

同一数据集只允许一个主要接收者。当前故障恢复、原生flush／ACK核对与unknown防重保留；旧接口、旧schema自动转换删除。数据版本、队列和幂等细节见[数据规范](数据目录与账号实例.md)。

## Harness私有服务与代理

HarnessOwnerConfiguration必须提供当前prompts、activePersona、agentTypes、pluginInstructions和bindings。PromptDocument.scope/source必填，source仅owner／plugin，旧legacy集合与外部模板变量拒绝。

getMcpConnection(pluginId, scope)必需完整可信范围；readAgentActions与revokeAgentAccess必需，不缺省空成功。Host只向已批准Harness暴露服务，通讯插件不能取得这些私有接口。

普通 eating_delegate_task 只收类型／真实context_ref／任务，联系委派只收当前列表的target_id／任务；均不允许模型任意提供system／tools／persona／scope。普通委派保持当前批次和资源范围，跨目标联系按真实主turn及当前策略签许可。平台预绑定来源，目录过滤与逐次执行校验并用。TaskID来自公开原生callId，索引必需taskId／taskRefs；同一批可查询后再委派，重复／pending／unknown与迟到回调受保护。

成功／失败／未知和本次实际动作分开；子摘要不充当回执，主final不自动发送。工具scope／Preset只是逻辑边界，不是OS沙箱。创建标签与Eating离线summary使用真实注册pluginName或canonical pluginId、scope.accountId、中文私聊／群聊和targetId；不改变绑定key、稳定UUID或历史归属，官方Web显示依官方机制。

## 管理操作与模型能力

QQ save-agent-policy使用完整身份／两类型工具字段与expectedRevision，CAS冲突保原配置，不重连；持久化只收完整wrapper schema2，UI不可补默认空表单假装可编辑。

DSH list-models／test-connection只用已保存连接。图片输入能力通过主人管理操作单独读取／保存，与原7字段连接配置和密钥分开；持久化为schemaVersion1／revision／imageInput，初始false，保存须runtime停止且expectedRevision匹配。endpoint／model改变重置false，Key／超时不重置，不按型号自动声明视觉。标准图片结果由原生MCP附件进入明确支持image的执行子Agent；文本模式必须明确拒绝，不把文本URL当作实际图像输入。

主、子各一次挂载官方time-context，依赖agents／sessionProjections，Asia/Shanghai及原生600000ms默认；只在既有合格step向末尾追加source.kind=time-context的user context，原生日志恢复去重。默认系统正文不再含动态时间行，9个可信变量仍注册；自定义正文使用当前时间仍会改变system，不能承诺缓存收益。没有时间工具或调度权限。

## 官方原生 Web 入口

DSH 插件不再提供自有会话看板和 list-sessions／read-session。会话的列表、分页、投影与操作由同进程官方 Web 提供，不另建离线投影或旧入口回退。

主人调用`manage('open-native-web', {})`按需取得`{url, rootSessionId}`，Eating的“打开 DSH Web”按钮在新页签打开同一专属DSH进程的官方入口。URL校验为127.0.0.1合法端口与官方鉴权交换；`runtimeStatus.nativeWeb`仅`{ready}`，删除readOnly字段，入口不放进普通status或模型上下文。

服务组合挂当前官方SessionController host、原生client roster、Gateway和owner鉴权，保留官方完整UI／主题／侧栏／消息组件及create／prompt／settings等正常操作。web的printUrl／openBrowser／surfaceContext均为false，避免污染SDK。移除Eating readerPeer、connection隔离、HTTP写白名单、readonlyController与冷follow拦截，原生会话操作及冷激活按官方机制运行，不加Eating根树限制。

删除Eating src/native-client源码、打包和模块注入，不替换sidebar／composer／message renderer，不硬编码配色、不挂LocaleBridge或agentLabels映射。DSH0.10.3按[ADR-0024](../decisions/ADR-0024-外部入站的原生执行请求展示.md)在公开agent/pre-step将当前完整匹配nonce/session/batch/digest的SDK外部消息标记为source={kind:eating-external,batchId}，保留ID、时间、role和正文；SDK入箱及flush/ACK不变。官方Web默认折叠为“收到执行请求”，展开仍呈现原始JSON；自主机会eating-autonomy和主人原生user输入各自保持，不改写已有日志。四段名称用于创建标签，官方UI显示依官方机制，不承诺全部旧标题外观修正。SDK主的受控委派及当前轮次联系工具、按任务受限QQ子MCP和time-context保持；官方Web创建的普通Agent不当作QQ scope child报错。操作参数和错误以[适配器](../../plugins/harness/dsh/src/backend/adapter.ts)为准。

## 变更规则与证据

接口变化同步类型、调用方、负向拒绝测试、README、ADR、规范与交接。默认不设计旧版迁移／回退；任何例外或真实数据处置须用户明确要求。不静默忽略未知字段或以旧私有方法补齐必要能力。

本轮官方原生Web、构建／类型、验证与图片取图修复统一见[恢复原样DSHWeb与图片DNS诊断](../reports/2026-10-29-恢复原样DSHWeb与图片DNS诊断.md)。真实imageInput=true；取图已删除DNS预判与地址固定，改由系统网络栈解析和路由，同一条真实消息取得image/jpeg、110000字节。仍保授权引用、无重定向、不传认证头、5MiB／10秒与MIME／字节校验，详见[QQ架构](../architecture/QQ与平台能力.md)。实际部署以[项目状态](../项目状态.md)为准；其他Harness、OS隔离与三平台仍须独立核对。

## MCP和插件管理（API4）

插件统一kind communication/harness/capability，API4，前后端公开契约由当前plugin-sdk提供。新增管理端点：GET/POST `/api/mcp` 和 GET/POST `/api/plugin-packages`。请求、来源、CAS、秘密保留及图片资源形状见[实施契约](../plans/2026-10-30-MCP与能力插件实施契约.md)，各层最终类型以公开SDK和当前代码为准。

Harness新增getCapabilityMcpConnections(scope)，返回每服务短期代理连接和精确工具名；scope是Host/适配器可信参数，不作为LLM工具入参。插件新增invokeCapability/media/readReceivedImage，与通用资源服务配合。直接MCP工具的副作用信封使用arguments/request_id，上游只收原arguments；旧API3不继续运行。

表情包sticker_list按query/tags/offset/limit分页，只有元数据；sticker_get返回实际图片和文本可见sendable。写入用request_id及必要revision，当前会话来源由scope.source验证；手动管理add为本机上传独立入口。
