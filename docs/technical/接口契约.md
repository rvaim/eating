## HTTP前端安全请求标识（2026-11-03）

按[ADR-0044](../decisions/ADR-0044-HTTP前端安全请求标识.md)，公开 `@eating/ui-sdk` 提供同步 `createRequestId(): string`；始终以 `globalThis.crypto.getRandomValues(new Uint8Array(16))` 取得安全随机字节，设置UUIDv4 version／variant位，返回小写 `8-4-4-4-12` RFC UUIDv4。无randomUUID调用或fallback，无Math.random／时间／计数器，无新增依赖；缺getRandomValues明确失败，不生成弱随机标识。

应用workspace、QQ panel、image panel、DSH NativeCapabilities、memory ranges只从公开SDK引用。分配时机保持：同一意图复用原ID，unknown只核对原号、不自动换号重发；Node后台UUID实现及存储schema不改；表情包功能保持，仅共享SDK产物字节变化按封存规则升0.1.2。公网HTTP非secure缺randomUUID是面板崩溃根因；前次localhost隧道secure=true掩盖API缺失，回归须真实 `eating-http.test` 映射127并断言secure=false，不mock crypto API。源码验证与云端保留数据更新完成：修复提交 `ab19cbb` 经本地commit／push后由云端GitHub取同提交构建运行；完整构建／类型、全量1743项通过／8跳过及最后4项浏览器通过。真实公网HTTP secure=false、randomUUID缺失、getRandomValues可用，QQ配置可见且UUIDv4切tab复用，页面／UUID异常0、无POST mutation、Token已去URL；12受保护文件哈希、Host settings／数据库、插件配置摘要与ownerToken保持。见[本轮报告](../reports/2026-11-03-公网HTTP面板修复与保留数据更新验证报告.md)。本次补足当前HTTP平台契约，不移除安全随机、不强制HTTPS；0043的鉴权、Git发布、安装确认与项目外隐私边界保持。

## 公网Token入口与监听配置（2026-11-03，前轮事实）

按[ADR-0043](../decisions/ADR-0043-公网Token入口与Git发布部署.md)，本轮应用／Host／Web0.17.4，QQ0.13.6、DSH插件0.15.3保持，源码、隔离及实际服务器部署验证完成（[报告](../reports/2026-11-03-服务器Git拉取与Token入口部署验证报告.md)）；当时release `6afda68` 经本地验证push后由云端GitHub拉取构建／回归并运行。实际IPv4公网监听及入口／管理鉴权通过，防火墙由用户放行，未证明WAN直连已打通；五插件仅表情connected，其余unconfigured，未迁本机资料或连接真实QQ／模型。`ServerAccessOptions` 为可选 `listenHost`／`publicOrigin`／`ownerToken`；环境变量为 `EATING_LISTEN_HOST`／`EATING_PUBLIC_ORIGIN`／`EATING_OWNER_TOKEN`，监听端口仍用 `EATING_HOST_PORT`。listenHost仅 `127.0.0.1` 或 `0.0.0.0`，默认前者；外部必须publicOrigin＋ownerToken。Origin仅规范HTTP(S)协议、主机及可选端口，无路径、尾斜线、凭据、query或fragment；Token随机32至256字符，仅 `[A-Za-z0-9_-]`。dataDirectory由项目外私有服务配置提供、运行时使用 `EATING_HOME`，真实值不进仓库或报告。

启用ownerToken后，仅根 `GET /?token=<OWNER_TOKEN>` 可交换权限，已有query以 `&token=` 追加；重复token、错误值、非根及非GET拒绝。成功设置独立随机 `EatingOwnerAccess` Cookie（HttpOnly／SameSite=Strict／Path=/，HTTPS Origin另带Secure），303到删除token但保其他query的根地址，响应no-store及no-referrer。入口Cookie受Host进程生命周期约束；后续页面／插件资源及bootstrap必须持有效入口Cookie，bootstrap另建原管理session与CSRF，写API继续核验CSRF。默认本机不配置ownerToken时流程保持；无登录页、账号或密码。

`/mcp/:pluginId` 与 `/mcp-services/:id` 继续独立Bearer及原scope，owner URL token、入口Cookie不能代替。Host／Origin／跨站检查保持；官方DSH Web监听与鉴权不改。用户本轮选择HTTP直连，传输不加密，不增加HTTPS／证书／网关或防火墙规则。服务脚本只管理用户级 `eating-managed.service` 及新数据五插件；本地验证commit／push后云端GitHub拉取对应commit构建、缺依赖先询问安装，详见[部署说明](../operations/服务器部署与更新.md)。实际服务器Token／管理鉴权及重启验证完成，源码全量1732项通过／8跳过、136项针对性及脚本32项离线检查通过，详细证据见本轮报告；用户仍需自行放行防火墙和配置插件，WAN连通未验证。

## 自主运行与当前轮次联系（2026-11-02）

当前源码为应用／Host／Web0.18.0、plugin-sdk4.8.0、ui-sdk4.2.1、plugin-core4.0.0、QQ0.14.0、DSH0.16.0、生图与记忆0.3.0、表情0.2.0，插件仍API4。公开[自主契约](../../packages/plugin-sdk/src/autonomy.ts)提供 BackendPlugin.autonomy 的 snapshot/configure/control；通讯 proactive 提供 channels/scope。无输入定时协调要求 readProactiveChannels/prepareProactiveScope/hasPendingMessages，缺接口明确报不支持。`enabled`／`ownerPaused` 只控制无输入定时机会，不阻断普通有输入主轮次的联系；真正自主机会取消时撤销该轮许可。

主人 GET /api/autonomy 返回 protocolVersion1、Harness 能力／配置状态、agenda（AI定时任务）和当前通讯通道；POST 仅接受 {harnessId,operation,input}。configure 使用完整配置＋expectedRevision；pause/resume/wake 使用 expectedRevision＋expectedActivityRevision；acknowledge-contact 要求 confirmed=true、当前配置 revision 和精确 agentId/taskId；cancel-scheduled-task 要求当前 agenda revision 和 taskId。Session/CSRF/Origin、插件启用与 mutate 锁保持，模型不能调用管理 API。

主 Agent 使用 `eating_schedule_task`／`eating_cancel_scheduled_task`，按 agenda revision 创建／取消 `autonomy-agenda.json/schema1` 中的未来一次性任务；`eating_activity_state` 同时返回 agenda。最多50条、每条2000字符、未来1秒至365天，到期每轮最多合并10条为同一自主机会，来源仍为 `eating-autonomy`，明确是过去的自己安排的任务。任务到期可打断sleeping/waiting，仍受主人暂停、额度、runtime和周期检查；cycle持久登记后移出agenda，中断按unknown处理，不重放已进入会话的任务。当前Eating agenda无重复规则；按[ADR-0034](../decisions/ADR-0034-主Agent自主决策与功能能力默认开放.md)移除自主周期对原生DSH Schedule的人工阻断。Eating暂停只控制其无输入机会／真正自主周期，不冻结main或暂停所有原生提醒。

真实主 Agent 的原生当前 turn 均可使用 `eating_list_contact_targets`／`eating_contact_target`，覆盖QQ群／私聊、原生主输入、目标续行、定时唤醒，无需目标先发私聊。联系入参必填当前列表返回的target_id、task和显式mode，后台构造账号／类型／目标及工具交集；主Agent先理解请求、判断事实充分性及实际目标；当前普通会话用eating_handle_conversation的真实context_ref、mode及必要context_notes交绑定子核实或回复，明确任务或用户明确逐字内容用eating_delegate_task固定reply，跨私／群用list/contact，工具自动启动或恢复对应受限子，无需新入站。群context不能冒充私聊，跨目标不继承旧资源。某子scope不足不等于主无能力，群发送成功不等于私聊成功。

getMcpConnection的Host内ScopedAccessPolicy含精确toolNames、active闭包及可选readOnly，与AgentInvocationScope.readOnly共同限制工具；只在RAM，不可由模型提供或写入持久策略。verify仅允许tool.readOnly===true，目录和真实调用均检查，并与插件当前类型工具政策取交集。准备、真实调用、异步资源取得后及发送前复核真实主 turn、账号／对象／工具和撤权；内部控制以 nonce／随机令牌及主 Agent 身份校验，不信正文 source。当前 turn 结束、abort、销毁或 runtime 停止撤权；保存联系策略也撤旧许可。主 Agent 不取得 QQ 全权令牌，readAgentActions/revokeAgentAccess 与真实动作账本仍必需。

所有联系任务共用 maxContactsPerHour；公开原生 callId 防重，每目标当前轮次最多32引用，重复／pending／unknown 拒绝，迟到回调不能改 unknown。proactive-bindings.json 保持 schema1，cycleId 沿用为内部轮次引用，不迁移、不恢复旧许可；新 runtime 将遗留 pending 转 unknown。内部定时来源仍为 eating-autonomy，外部 deliverBatch／ACK 不变。

定时任务按[ADR-0032](../decisions/ADR-0032-AI定时任务.md)，当前联系按[ADR-0033](../decisions/ADR-0033-主Agent当前轮次联系权限.md)，状态与恢复见[数据规范](数据目录与账号实例.md)。原DSH0.13.0定时任务验证见[当时报告](../reports/2026-11-02-AI定时任务验证.md)；独立工作树DSH0.12.1的1422项及四项真实联系回环见[联系报告](../reports/2026-11-02-主Agent当前轮次联系权限验证.md)，当时真实目标续行和Web浏览器输入控件未单独端到端验证，未部署。DSH0.13.2整合验证、提交/push与部署已在[本轮整合报告](../reports/2026-11-02-定时任务与当前轮次联系整合部署.md)记录。以下旧阶段工具数量不定义当前集合。

## 管理与MCP

- GET /api/bootstrap建立会话与CSRF；GET /api/workspace返回当前目录、真实状态及贡献。
- POST /api/plugins/:id/configuration、connect、disconnect、enable、disable、invoke、mcp-registration是主人受控入口；manage只路由明确operation与input，不进入模型工具目录。
- 作者GET /api/authoring、当前文档CAS保存、人格管理与已保存组合预览由[Host](../../apps/host/src/app.ts)验证；旧提示词ID／字段不接受。
- /mcp/:pluginId使用官方StreamableHTTP初始化／list／call及Bearer，不是伪REST。主人手动令牌与子代理任务scope令牌分开，Harness不能请求全权令牌。

Session、CSRF、Host／Origin、体积及结构均校验，本地地址不等于可信。副作用要求调用方预先提供稳定8至128位request_id；缺失／非法not-sent，服务端不补随机副作用键。相同账号范围的HTTP／MCP共用幂等账本，超时不等于外部未发生。
