# Eating 接口契约草案

状态：协议版本1的平台Host/QQ/MCP已实现，未来Harness适配仍可修订。实际[平台契约](../../packages/platform-contract/src/index.ts)定义后台、实例/账号、工具和Harness sink；[前端贡献](../../apps/web/src/plugins/contract.ts)仍独立。受控管理HTTP、独立Bearer MCP、实际参数和限制见[QQ能力架构](../architecture/QQ与平台能力.md)，旧前端验证只作历史。

## 已实现的正式入口

管理接口：GET `/api/bootstrap`建立本地会话与CSRF；GET `/api/workspace`返回版本1真实状态；POST `/api/plugins/:id/configuration|connect|disconnect|enable|disable|invoke|mcp-registration`，详见[Host实现](../../services/host/src/app.ts)。配置/工具仍由插件声明并验证，不向前端开放任意高权限命令。

每插件 MCP `/mcp/:pluginId` 使用专用Bearer和官方StreamableHTTP协议，初始化/list/call不是普通伪MCP REST。副作用工具必须由调用方预先提供稳定request_id；缺失/无效拒绝not-sent，不允许服务端补随机键后执行。HTTP测试面板预生成并保留同键，跨接口共用持久账本。

`instance_id`是本地账号实例路由，省略用当前默认实例；实际QQ号另字段。当前单账号，未知实例明确拒绝，不静默发送到默认号。事件、消息索引和动作范围包含实例，后续多账号不改变字段含义。

## Host 边界

UI 到 Host、通讯模块到 Host、Host 到选定 Harness 适配器、Agent 到 Eating MCP/安装申请入口分别定义权限，不共享一个任意命令通道。传输用 IPC、本地 socket、stdio 或 HTTP 尚待选择；若用 HTTP，不将“本地”视为自动可信。前端仅调用 Host 的受控入口，界面可见不代表拥有后台权限。

所有跨进程操作应带协议版本、requestId、身份/来源、结构化参数、超时和关联结果。错误需区分输入非法、未认证、未授权、状态冲突、模块停用、Harness 离线、能力不支持、能力未知、超时、持久化失败、依赖不可用、结果未知和版本不兼容。重试语义按操作定义；超时/调用失败不等于外部动作未发生。

## 候选数据职责

| 类型 | 必要信息 | 信任规则 |
| --- | --- | --- |
| 外部事件 | eventId、模块/平台/账号/会话/发送者、时间、内容引用、来源级别 | trust 字段由 Host 生成 |
| 投递回执 | eventId、attemptId、适配器/控制者及实际会话/message/event 关联（若提供）、阶段、时间 | 区分受理/持久化/消费，不能伪造缺失证据 |
| 外部操作 | actionId、模块、目标会话/资源、幂等键、尝试与平台结果 | 工具完成不代替平台确认 |
| 安装申请 | requestId、来源、精确版本/commit、校验、权限和副作用 | Agent 只能申请，不能批准；含通讯/Harness 与可执行页面等新增能力 |
| 授权决定 | 可信主人 ID、requestId、绑定目标、批准/拒绝、有效范围/期限 | Host 验证；正文不能充当签名 |
| 运行状态 | Host/模块/接口阶段、健康、队列积压、主要控制者、记忆能力、成本与故障 | UI 不把猜测状态当事实，后台与界面分别报告 |
| 模块注册贡献 | 模块标识/版本、类别、依赖、后台能力、管理界面、资源归属与撤销关联 | Host 校验命名空间、兼容和授权；模块不能越权覆盖其他贡献 |
| Harness 能力描述 | 适配器/实现版本、能力范围、支持证据、探测时间和最近结果 | 声明支持不等于已授权、运行健康或本次成功 |

具体字段和 JSON schema 在协议 PoC 阶段确定；v0.3 示例不是正式 API。运行队列、映射和账本用于可靠性，不作为 Eating 的第二套人生记忆。

## 模块注册与撤销

Eating 定义平台无关的扩展接口与前端注册机制，通讯、Harness 等模块自行声明/注册其后台能力和自己的管理界面，通用管理页读取经过 Host 校验的目录。QQ、飞书等同类模块只依赖通用契约和声明的共享服务；新增/移除模块主要局限自身，不能要求修改其他模块或通用管理逻辑。后台入口不直接依赖 React/浏览器，界面贡献单独处理版本、路由、可见权限和加载失败。见[插槽式扩展](../architecture/插槽式扩展.md)与 [ADR-0007](../decisions/ADR-0007-插槽式模块与界面注册.md)。

注册须有稳定归属、版本/兼容检查、依赖检查、冲突处理与撤销机制。部分注册失败时只回滚本模块贡献和资源，不清空全局注册表。停用先阻止新调用，再撤销后台/工具/页面入口，清理订阅、连接和任务；不能误删共享依赖或其他模块数据。实际取消不支持或失败时保留在途记录，迟到响应只用于对账，不得恢复已撤销入口或重启任务。

运行准入、停用/移除与用户数据删除分别处理；保留队列、游标、配置、授权审计与未决动作等必要证据，按[数据策略](../architecture/数据归属.md)执行。新增可执行能力仍须可信主人明确批准，注册成功不能代替批准或证明沙箱成立。

Cordis 仅为优先验证的 Node/TS 后台插件底座（Proposed）；版本未选定，其内部 Context/scope 不自动成为 Eating 对外协议。作用域只表示逻辑资源管理，不是 OS/进程隔离，模块注册和失败隔离都尚未运行验证，见[Cordis 评估](Cordis选型评估.md)。

## Harness capabilities 与调用结果

适配器需如实描述创建/恢复运行上下文、事件投递、受理/持久化/消费证据、忙碌排队、steering、取消、调度、子 Agent、记忆机制及配置/数据范围等能力。具体能力粒度与 `capabilities` 这一字段名都只是候选，不要求所有 Harness 具备相同能力。实际 Codex/Claude Code 接口未核；不能把 DSH Agent 内部方法抄成通用或远程 API。

| 候选标记 | 表达的事实 | 处理要求 |
| --- | --- | --- |
| supported | 指定版本与条件下有支持声明/证据 | 仍需校验授权、运行前提和本次结果，不自动承诺成功 |
| unsupported | 已明确不提供该能力 | 不调用该能力，不伪造回执或用 Eating 自建认知循环补齐 |
| unknown | 未核、未探测、证据不足或相互冲突 | 显示未知及原因，不能按 supported 或 unsupported 使用 |
| error | 本次探测或调用失败，属于操作结果 | 记录原因、关联和结果不确定性；不能据此反推 unsupported |

支持状态与本次操作结果是不同维度：探测失败可以保留此前支持证据并标明时间/适用条件；没有证据时仍是 unknown。必要能力未满足时不能宣称相应功能就绪，可选能力缺失则显示实际降级。异常、预算限制、人工暂停和自主休息分别报告。长期记忆仅由选定 Harness 可用且主人授权的插件/机制提供；不可用必须可见。

同一数据集只允许一个当前活跃的主要认知控制者。候选契约需关联选定适配器、实例与主身份映射，并防止旧控制者未停妥时激活新控制者；子 Agent 是委派执行者。跨 Harness 会话/插件/记忆无损迁移、全部能力等价和运行中热切换均未承诺，见[Harness 适配](../architecture/Harness适配.md)。

## DSH 适配器：官方接口与 Eating 契约的区别（源码分析）

DSH 是首个具体技术验证对象。固定源码中 SDK wire 暴露的 `session/prompt` 使用 `source: {kind: 'user'}`；SDK 不提供任意 role/source 参数。Host 必须在外围验证来源，不能伪造系统角色或把 SDK 的 user 来源当可信主人身份。

公开 prompt 是 followup；中途 steer/inject 未在公开 SDK 暴露，持久确认或取消的实际能力以[源码矩阵](../research/DSH源码核对.md)为准。Host 内 Agent 方法不能直接写成远程 SDK 能力。源码结论尚非 Eating 运行验证，其他 Harness 需单独核对。

关联 eventId、重放判断、授权和动作幂等是 Eating 自己的基础设施契约；不能只在 prompt 里写一个 ID 就声称 DSH 支持幂等准入。SDK 回执也不能代替耐久、消费或平台动作成功。

## 变更与兼容

正式实现前给契约版本、校验规则、状态迁移与兼容策略；变化同步类型、测试、ADR、状态和交接。涉及数据格式时记录升级和回滚，避免新旧 Host/模块/适配器不匹配后静默丢事件；不将 Cordis 或某个 Harness 的内部格式冻结成通用持久契约。
