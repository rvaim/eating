# Eating 数据目录与账号实例规范

状态：账号路径、临时队列与原始历史移除保持原规范；2026-10-28 的多代理实现增加 DSH 原生子代理绑定文件、主人／管理员与类型策略、作者配置 v1→v2 内存迁移和按需原生会话读取。已完成本地原生验证，精确结果见[本轮报告](../reports/2026-10-28-多代理与会话看板验证报告.md)；独立 Harness 数据根和最小 DSH 首版证据保留在[历史验证](../reports/2026-10-28-DSH最小Harness验证报告.md)。

## 根目录

`EATING_HOME` 指定数据根，默认用户目录下 `.eating`，支持 `~` 展开，不依赖项目或安装目录。QQ账号、Host锁与数据库文件路径保持；先前消息迁移只改变数据库内部结构，新增DSH目录不移动QQ资料。

```text
~/.eating/
├── plugins/                    # 插件代码版本区
│   ├── installed.json          # 安装/激活索引
│   └── <pluginId>/
│       └── versions/<version>/ # 完整可加载产物
├── host/
│   ├── host.lock
│   └── Eating.sqlite           # 临时队列、短期去重、动作账本、Host设置/MCP令牌
├── bot/
│   └── qq-bot/
│       ├── accounts.json       # 实例索引与默认实例
│       └── accounts/
│           └── <instanceId>/
│               └── config.json
└── harness/
    └── dsh/
        ├── config.json        # 独立模型配置，密钥只写不回显
        ├── session.json       # 主原生会话UUID与小批次元数据
        ├── agent-bindings.json # schema1，仅子代理绑定ID，不存正文
        ├── runtime/           # current.json及版本化npm运行时/完整锁
        ├── dsh-home/          # 专属DSH_HOME，原生sessions归Harness
        ├── agents-home/       # 专属DSH_AGENTS_HOME
        ├── workspace/
        ├── runtime-home/      # 子进程HOME/XDG环境
        └── bridge/            # 受信策略、当前预期、就绪与仅元数据ACK
```

SQLite 运行中可出现同目录 WAL/SHM。队列硬容量只计信封 payload，不是数据库、WAL、动作账本或整个工作区磁盘配额。数据、令牌与消息不进仓库，忽略规则不能代替权限。

插件代码版本、稳定账号实例和真实 QQ 号分别标识，升级不能把账号配置移动到代码版本目录。安装/升级/卸载先停止 Host 后重启，卸载撤销代码入口并保留账号配置、动作账本和本地暂存队列；仅内存正文受 Host 退出丢失约束。安装布局与生命周期见[工程结构](../architecture/工程结构与插件发布.md)。

## 三类标识

| 标识 | 含义 | 稳定规则 |
| --- | --- | --- |
| pluginId | 插件种类，例如 qq | 不因账号数量变化 |
| instanceId | Eating 本地账号配置实例 | 初建 UUID，重启不变，不采用 QQ 号或显示名 |
| accountId | 协议端真实登录账号 | 核验后获得，不因为有配置就伪造 |

未连接也能配置本地实例；换号码不搬配置目录，真实账号变化仍参与事件与动作范围，不能把旧账号结果当新账号成功。

## 索引、配置与权限

账号索引 schemaVersion=1，含 defaultInstanceId 和 instances（instanceId、label、createdAt）。结构可表达多个实例，但本版只创建并运行一个默认实例，无添加、切换或并行第二账号 UI/服务。

每实例配置 schemaVersion=1，含 updatedAt 与 configuration（显示名、端点、访问令牌、超时、启动连接/转交选项）。QQ 0.8.0 增加主人／管理员号码列表与按类型工具策略，使用 policyRevision 做 CAS；每类号码最多 100 个，规范化且须在安全整数范围内。身份／类型策略单独更新不重连 OneBot，不改变实例 ID。默认项由索引决定，重复 ID、穿越、版本损坏或默认项缺失拒绝，不新建覆盖。新的通讯插件声明合法 `<name>-bot` 目录，Host 检查当前激活目录冲突并拒绝同 ID 升级改绑；不把卸载后的目录归属永久锁定给旧插件。

配置写临时文件、同步后同目录原子替换，失败保留完整旧文件并清本次临时文件。POSIX 目录 0700、配置和索引 0600；公共响应不回显访问令牌。Windows ACL 与崩溃持久性需另测。当前不接系统钥匙串或全盘加密，复制完整数据根涉及敏感资料；网页不将令牌放 localStorage，OneBot 与 MCP 令牌分离，后者只在显式查看时展示。

Host 全局投递设置不写入 QQ config。SQLite settings 内 `host:delivery-settings` 保存 values/revision，`host:delivery-queue-state` 保存无正文累计计数和固定错误说明；启用状态和 MCP 凭据仍归 Host。

### 提示词与人格配置

`host:authoring` 保存主人提示词与候选人格，不提供模型／MCP 写入口；最多启用一个人格，也可以全部停用。v2 持久化三份基础层、实际改过的插件覆盖、原有人格与可选 legacy group／private 输入，不复制插件未改默认或人格正文到每个角色。协议快照仍为 protocolVersion=1，配置 revision 与文档 CAS 版本保留；总量 5 MiB、单正文 50000 UTF-16 字符、候选人格 100 个，注册贡献与保存的插件覆盖分别最多 256 份。

旧 schemaVersion=1 必须先完整严格校验，旧 main 逐字归 common，旧群私正文及所有人格／名称／ID／revision 原样保留。读取只做内存迁移，读取与同内容保存不写原 JSON；首次实际主人修改才原子写 v2。原配置损坏或超限则拒绝覆盖，写失败保留此前文档。旧 group／private 仍只能渲染为 user 输入，不能直接升级成系统模板。

覆盖以稳定的 `agent:<角色ID>`／`plugin:<说明ID>` 保存来源和默认正文。插件升级时未覆盖项使用新默认，主人已改正文优先；停用保留编辑并撤执行权限，卸载后保留覆盖、来源不可用时只读。展示翻译 localizedTitles 只从当前注册元数据透传，不存覆盖、不改主人名称／正文、不进入 system。插件启停／默认变化不增加主人 CAS revision，运行端应每任务重读实际贡献。

## 浏览器语言偏好

界面语言仅以eating.locale保存到浏览器localStorage，可选zh-CN/en-US，不写Host业务配置或插件账号目录。存储不可用时保持当前页面可切换，跨标签页使用storage事件同步。该偏好不含认证信息、消息正文、提示词或人格内容；切换语言不改写任何业务数据。

## 临时队列与短期去重

`delivery_queue` 只持有当前未交接信封：sequence、event_id、规范化 harness_json 一份、UTF-8 payload_bytes、pending/delivering/uncertain、尝试数、下次尝试时间和入队时间。不保留原 OneBot raw_json、额外 text 列或不转交消息的正文。信封内 content/text 属于公开规范化输入，不另外复制到历史表。接收时核验的 source 角色分类、目标与消息／资源引用纳入持久字段白名单，重启不能因遗漏这些字段改变委派授权；source 仍是 external，外部正文不获得系统权限。

persistent 默认将信封临时放 SQLite，重启可恢复；memory 仅在 RAM，普通退出/重启丢失未交接正文。模式与 revision 始终为 Host 设置，内存模式也可持久保存无正文设置、计数、短期哈希与动作账本。

仅接收端 `accepted: true + durable: true + 非空 receiptId` 且本地确认成功后删除对应 payload。`event_dedup` 只存 event_id 哈希、observed_at、短状态和 receipt_hash，固定 24 小时，常态磁盘与故障内存缓存合计最多 10000 个。SQLite 连清理也持续失败时，旧磁盘最多 10000 加内存后备最多 10000，合计最多 20000 个小标识；无正文，内存后备不能保证跨重启。

短期哈希过期或达上限可移除，但尚在队列的 event_id 继续阻止重复准入，不因 24 小时过期再次入队。可靠交接、显式丢弃和不转交仅保留上述短期元数据与累计计数，不构成可查询消息历史。

## 容量、切换与清空

默认 1000 条、10 MiB，全部 pending/delivering/uncertain 都计入条数和规范化 UTF-8 JSON 字节；原库体积、页开销、settings、去重或发送账本不计入这个队列限制。持久快照以 SQL COUNT/SUM 分状态聚合，内存直接累计 Map 元数据，不为周期统计搬运正文。

- reject-new 达上限则新正文不保存，返回 `inserted: true / queued: false / admission: rejected`，递增 rejected 并显示最近队列错误，平台实时日志仍能记录接收准入。
- drop-oldest 只移最旧 pending，保留 delivering/uncertain；单条超总字节直接拒绝，不先清空原队列。没有足够可移除 pending 时也拒新。
- 缩容按明确策略预计算；拒新策略不满足、或丢旧后保护状态仍超限，整次 409，模式、revision、正文和计数不部分提交。
- persistent → memory 先准备 RAM，再原子提交设置和 SQL 正文清理；memory → persistent 事务写完全部存活信封与设置才切换 RAM。写入失败保持原模式与内容。
- 清空需用户勾选确认；只要有 delivering 就 409。成功删除其余未交接正文、累计 discarded，保留账号配置、短期哈希和发送账本。清空不改变未保存的设置草稿。

新库启用 incremental auto_vacuum 与 secure_delete，正常正文移除执行增量回收和 WAL checkpoint；只有旧历史迁移做一次完整 VACUUM。容量拒收或清理失败都必须可见，不吞错伪造已排队。磁盘全面故障时，拒收计数和故障 hash 尽力持久化，不能承诺不可写磁盘仍跨重启保存。

## 旧库迁移

首次打开旧 `incoming_events` 时同一事务执行：

1. 保留全部 pending/delivering/uncertain 的有效 Harness 信封，维持顺序、尝试数和来源；启动 delivering 转 uncertain，避免盲目补投。
2. accepted/not-forwarded 只可留下未过期的小哈希/回执摘要，不读取其正文到新队列。任何未交接信封损坏或事务写失败都取消迁移、保留原表，不静默跳过。
3. 删除旧正文、原 raw/text 副本和整张旧表，设置 schema `user_version=2` 与一次压缩标识；提交后于同一数据库 VACUUM/checkpoint，不生成聊天全量备份文件。
4. 旧 backlog 超过新默认容量也全部保留，显示 overCapacity、拒绝新准入，交由可靠交接或明确用户策略处理，不在迁移中隐式丢旧。

账号索引、QQ 配置、插件安装信息、MCP 凭据、Host 锁与 `actions` 发送账本不迁移或清空。用户要求删除的历史不可承诺恢复，memory 退出丢失也无法回滚恢复。旧 Host 依赖旧表，不应直接降级并假定能看到新队列；回退须先安全交接或按明确反向迁移处理。

## 实例与动作隔离

接收信封含 instanceId，conversationId 含账号和私聊/群目标；去重键包含本地实例、真实账号、会话和平台消息 ID，只存其哈希。内部诊断按实例过滤，只返回未交接信封，raw 为 `{}`，不向 QQ 页面或 MCP 提供聊天历史。

主人手动发送账本按 pluginId、instanceId、accountId、稳定 request_id 隔离。子代理另外对 agentId＋原 request_id 生成 SHA 命名空间，防止不同代理相同请求键互相占用；同一代理原请求同参数复用已知结果，参数变化拒绝。running／unknown 不重做，进程中断 running 转 unknown。其参数哈希和持久动作结果用于阻止重复真实发送，不能随清空队列、日志列表或旧历史正文一起删除。

工具可带 instance_id，省略仅指默认实例；未知实例明确拒绝，不偷偷改发给默认账号。未来多账号须扩展连接、选择与权限，不改变现有字段含义。

## Harness的运行与会话责任

`kind: communication` 使用bot目录，仍要求合法的`<name>-bot`声明；`kind: harness` 使用harness目录，DSH声明`dsh`。同插件跨kind升级必须显式迁移，不能静默改绑。插件代码、运行时依赖与稳定数据三者分别管理，卸载不删任何业务数据。

DSH的配置目录0700、配置/控制文件0600；显式安装只在专属版本目录解析固定公开npm依赖并保留锁文件。两个DSH home、workspace和子进程HOME分别指定，环境仅允许必要系统变量与Eating独立配置的模型/QQ MCP凭据，不使用主DSH。

桥的ready仅代表工具与持久能力就绪；入箱事件经公开sessions.flush成功后才原子写当前批ACK，Eating本地确认后删除队列正文。下一批元数据成功保存后移除上一批ACK，不建永久ACK历史、后台清理轮询或消息日志；失败时保留当前恢复证据。原生会话JSONL属于所选Harness，为上下文和恢复所需，Eating不复制第二套可查聊天历史，也不把本地队列清空当作删除Harness原生会话。runtime安装目录失败或旧版本保留，不等于无限安装尝试或自动更新。

### 原生子代理绑定与只读会话

`harness/dsh/agent-bindings.json` 使用 schemaVersion=1，只保存插件／账号实例／登录账号／会话／类型与原生 UUID 的绑定标识，不存消息正文或另建聊天记录。映射最多 100 项、文件最多 1 MiB；写入前预检容量，同目录原子保存成功后才提交内存状态，失败不留下仅存在于内存的可执行绑定。稳定映射用于同一会话跨任务与整 Host 重启复用 UUID，不同会话隔离。引用缓存只保留最近 256 份、每份最多 2048 项；子代理任务令牌和本任务 action 集合不写入永久绑定文件，任务结束、断开／停用即撤销，新的回执集合不混旧任务。

原生 sessions 仍位于专属 DSH_HOME，属于 Harness 自己的上下文／恢复数据。看板只在手动 list／read 时经公开 Cordis＋persistence 读取 rootParentSession 的树，不启动模型或新会话、不生成 Eating archive；停机读取已有文件前后 SHA 保持。运行中最近缓冲可能未持久化，状态／时间无证据按 unknown／空值返回。默认 50 条、会话列表最多 100 条、响应 1 MiB 和文本 32K 上限是接口边界；底层可能整文件解码，逻辑分页不保证大日志的磁盘读取复杂度。

旧版本迁移的本地夹具已单独核对旧 root UUID、user／tool 原生记录与配置密钥字节保持，不复制用户真实数据或凭据；精确命令和范围见[本轮报告](../reports/2026-10-28-多代理与会话看板验证报告.md)。原生会话不是 Host 队列，清空队列不删除它，回退也不应直接用不识别作者配置 v2 或新绑定格式的旧产物覆盖。

## 停用与迁移设备

停用断开平台并撤销工具，保留账号配置、动作结果及当前未交接队列；仅内存模式仍受 Host 生命周期约束。代码卸载与删除账号资料分别处理。实时日志只有可见页签打开时的浏览器内存，隐藏/退出清空、Host viewer 归零，不产生目录或文件。

旧网页原型配置不自动导入为真实认证。发现旧单文件而尚无实例索引时应提示明确迁移需求，不猜归属覆盖。换设备先停止原 Host，核对密钥和协议环境；同数据根只允许一个 Host，不支持两主实例。跨 Harness 原生会话与长期记忆迁移不在本规范保证范围。
