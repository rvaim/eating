# Eating 数据目录与账号实例规范

状态：用户已明确确认根目录和 bot 分类，以及“设计多账号、本版只做一个账号”。既有账号路径结构与读写在正式 QQ 阶段已实现测试通过，不代表多账号运行已实现。本轮新增插件代码版本区，2026-10-27 已完成安装/升级/删除构建源后重启/卸载数据保持验证，账号索引与配置文件逐字未变，证据见[重组报告](../reports/2026-10-26-单仓独立包重组报告.md)。

## 根目录

`EATING_HOME` 指定平台数据根，默认用户目录下 `.eating`。支持 `~` 展开；不依赖项目或安装目录。此前暂定各OS标准应用目录的方案由明确要求取代。本次单仓重组不迁移 QQ 账号、Host 锁或 SQLite。

```text
~/.eating/
├── plugins/                    # 本轮新增，插件代码版本区
│   ├── installed.json          # 安装/激活索引
│   └── <pluginId>/
│       └── versions/<version>/ # 完整可加载产物
├── host/
│   ├── host.lock
│   └── Eating.sqlite           # 事件/待投递、幂等动作、启用状态、MCP令牌
└── bot/
    └── qq-bot/                 # QQ插件声明并管理，位置保持
        ├── accounts.json       # 实例索引与默认实例
        └── accounts/
            └── <instanceId>/
                └── config.json
```

插件代码版本、稳定账号实例与实际 QQ 号分别标识，代码升级不能把账号配置搬到某个版本目录。安装/升级/卸载要求 Host 停止后重启，卸载撤销入口并保留 `bot` 账号数据、消息和未决动作。安装路径与暂存发布是本轮实施选择，不表述为负责人逐项确认，细节见[工程结构与插件发布](../architecture/工程结构与插件发布.md)。

SQLite运行时可能出现同目录WAL/SHM文件。数据目录、令牌与消息不进入仓库；忽略规则只是提交保护，不替代权限。

## 三类标识

| 标识 | 含义 | 稳定规则 |
| --- | --- | --- |
| pluginId | 插件种类，例如 qq | 不因账号数量变化 |
| instanceId | Eating 本地账号配置实例 | 初建生成UUID，重启不变，不采用QQ号或显示名 |
| accountId | 协议端实际登录的QQ号 | 真实核验后获得，不因为有配置就伪造 |

即使未连接账号也能配置本地实例。后续换号码不移动配置目录；实际账号变化仍参与消息与动作范围，不能把旧账号回执当新账号成功。

## 索引与配置

索引schemaVersion=1，记录defaultInstanceId和instances（instanceId、label、createdAt）。格式允许表达多个实例以避免将来重写单例结构；本版仅创建并使用一个默认实例，没有添加/切换/并行第二账号的UI或服务。

每实例配置schemaVersion=1，含updatedAt和configuration（显示名、端点、访问令牌、超时、启动连接/转交选项）。默认实例由索引决定，不假设数组第一项或目录名等于账号。重复ID、穿越、损坏版本或丢失默认项拒绝，不静默新建覆盖。

新建插件声明自己的合法 `<name>-bot` 子目录；Host 对当前激活插件校验目录冲突，并拒绝同一激活 ID 升级改绑；此绑定不建立卸载后的历史永久归属，插件自行管理内部格式。Host公共队列/授权不写进QQ配置，QQ也不清除其他插件目录。

## 保存与权限

写临时文件、同步并同目录原子替换；失败保持完整旧文件，清理本次临时文件。POSIX目录0700、配置和索引0600；访问令牌不通过公共配置响应回显。Windows ACL与崩溃持久性须单独运行验证，不能用POSIX测试替代。

配置是受限本地文件，当前未接系统钥匙串或全盘加密设施。复制完整home视为复制敏感资料。网页不把令牌放localStorage，MCP令牌仅在显式查看时展示，和OneBot令牌分开。

## 实例隔离契约

接收消息与Harness事件包含instanceId；实际conversationId还含账号/私聊或群目标。去重键含实例，读取按实例筛选。发送账本按pluginId、instanceId、accountId与稳定request_id隔离。

工具可带选填instance_id，省略仅指当前默认实例；显式未知实例会拒绝，不偷偷改发给默认QQ。未来多账号要扩展连接实例映射/选择与权限，不改已有字段含义。

## 停用、迁移与删除

停用断开连接并撤销工具，保留索引、配置、消息和未决动作。卸载程序不等于清理历史。用户重要数据删除需独立明确操作。

旧网页验证配置未自动导入为真实端点/认证。发现旧根 `qq-bot/config.json` 而尚无实例索引时提示明确迁移需求，不猜测归属、不覆盖。用户正式 home 在首次正式 QQ 阶段创建；本次重组保持原账号实例与文件，无旧账号文件被迁移。

换设备前停止原Host，复制/迁移需要核密钥与真实协议环境；同一home取得Host锁才运行，不支持同时两主实例。跨Harness记忆与会话迁移不在此规范保证中。
