## 工程迁移与包边界

- Host 已从旧服务目录物理迁至 [apps/host](../apps/host/)，[apps/web](../apps/web/)保留；两者各有包配置，根 pnpm workspace 聚合开发、构建和测试。
- 公共后台契约迁为 [plugin-sdk](../packages/plugin-sdk/src/index.ts)，前端契约与 API 客户端迁为 [ui-sdk](../packages/ui-sdk/src/index.ts)。公开包名 `@eating/plugin-sdk`、`@eating/ui-sdk`，当前包版本 `1.0.0`、契约 `apiVersion` 为 `1`，不能混同版本含义。
- QQ 迁至 [communication/qq](../plugins/communication/qq/)，独立包 `@eating/plugin-qq` `0.2.0`。后台[入口](../plugins/communication/qq/src/server.ts)、[协议与工具](../plugins/communication/qq/src/backend/)、[前端入口](../plugins/communication/qq/src/web/entry.tsx)、[面板](../plugins/communication/qq/src/web/panel.tsx)分开；[OneBotConfig](../plugins/communication/qq/src/config.ts)归 QQ，不再放公共 SDK。
- 插件对 Eating 的依赖只走公开 SDK，不导入 Host/Web 私有源码；QQ 面板不再导入 Web 内部文件。主程序不捆 QQ，按安装产物加载后台和界面。
- [plugin-core](../packages/plugin-core/)保留纯注册与旧持久化测试；本轮不是删除所有旧核心测试。旧路径不留 shim，完整映射见[迁移表](architecture/工程结构与插件发布.md#迁移映射)。

QQ 独立交付后台 ESM、界面 JS/CSS 与清单；清单实际使用 `schemaVersion`、`apiVersion`、`id`、`version`、`backend`、`frontend` 和 `integrity`，后者记录各交付文件的 SHA-256。后台导入已通过仓库外产物回归；Web 动态导入 Host 提供的资源，公开界面 SDK 和 React 共享宿主实例。

## 插件安装生命周期

本轮从本地产物目录安装；代码放入 `EATING_HOME/plugins/<pluginId>/versions/<version>`，`plugins/installed.json` 保存安装/激活索引。Host 安装 CLI 先核对兼容和哈希，通过暂存/原子发布切换激活版本。

**安装、升级、卸载均需先停止 Host，完成后重启。** 升级只改目标插件；卸载撤销后台、页面、工具/MCP 入口，保留账号配置、消息与未决动作。代码卸载与数据删除分别授权，不提供热更新或零中断保证。本轮不做任意第三方市场下载、真实 npm 发布或完整 OS 沙箱。

CLI 已确定：根 `pnpm build` 分别构建 SDK/QQ/Host/Web，`pnpm build:plugin` 仅构建 QQ；停 Host 后以 `pnpm plugin install plugins/communication/qq/dist` 安装或升级，`pnpm plugin list` 查看，`pnpm plugin uninstall qq` 卸载。生产入口为 `node apps/host/dist/main.mjs`。完整顺序见[QQ 操作说明](operations/QQ配置与功能测试.md)，本轮已完成这些入口的安装产物回归，详情见[重组报告](reports/2026-10-26-单仓独立包重组报告.md)。哈希与版本兼容不能代替主人批准。

## 正式 QQ 功能与数据保持

产品仅 QQ 真实插件，飞书/微信占位已删；测试协议端只在测试目录。QQ 面板继续提供连接配置、功能测试、消息记录、MCP 能力四页签：

- 仅正向统一 OneBot WebSocket，Bearer header；令牌不回显，留空保留、显式清除。原子保存后断开旧连接，手动连接并核验真实登录与 `online/good`，有限重连。
- 功能测试从后台 schema 动态生成，与 MCP 共用 10 项工具；UI 手测发送/撤回逐次确认，稳定请求 ID，unknown 不盲目重发。
- 消息记录来自 Host SQLite 实际接收历史，按实例去重，面板最近 50 条、工具支持 before 游标；不是 QQ 全平台历史。
- QQ MCP 为 `/mcp/qq`，独立 Bearer、官方 Streamable HTTP；令牌仅显式查看配置时展示，未自动注册到实际 Harness。已批准 MCP 的日常工具调用不逐次人工审批。

QQ 空间发布/评论不在 OneBot v11 标准，本版 `unsupported`，不伪造能力。详见[QQ 架构](architecture/QQ与平台能力.md)与[协议依据](research/QQ协议与MCP核对.md)。

统一 `EATING_HOME` 默认 `~/.eating`。原 `bot/qq-bot/accounts.json` 与 `bot/qq-bot/accounts/<稳定本地实例 UUID>/config.json`、`host` 内锁/SQLite/MCP 令牌不迁移。实际 QQ 号由登录获取，不作目录名；本版只一个默认实例，没有第二账号添加、切换或并行 UI。新增插件代码区和 `bot` 数据区分开。

工具可选 `instance_id`，省略指当前实例，未知实例拒绝，不静默回退；消息、事件和账本含 `instanceId`，外发幂等按插件+实例+实际 QQ 号隔离。配置原子保存、损坏拒绝覆盖、POSIX 0700/0600、旧浏览器配置不自动导入等规则见[数据规范](technical/数据目录与账号实例.md)。

## Harness、安全与 ADR

`HarnessGateway` 的唯一主 sink 和持久 inbox 已有实现，`pending / accepted / uncertain` 不变；没有实际 sink，`accepted` 仅准入，不代表 Agent 已读或采取行动。Eating 不建设第二套 Agent Loop 或人生记忆。MCP 可用不等于已接入认知。

回环/Host/Origin 校验、HttpOnly session + CSRF、插件 MCP Bearer、scope、锁与局部损坏处理不构成完整恶意插件 OS 沙箱。Cordis 仍为候选，Tauri、真实 Harness、长期记忆、自主活动、三平台与多账号并行未完成。
