## 首次使用

1. 安装并启用 DSH 插件产物后，在“Harness → DeepSeek Harness”保存 OpenAI-compatible API 基础地址、精确模型名称和主人独立 API Key；Key 只写不回显，留空保留，清除需勾选保存。
2. 当前运行时已预装，可跳过安装；新安装时点击“安装运行时”并等待后台完成。异步 started 不等于安装完成，首次下载可能需 1–3 分钟；10 分钟上限，可取消并终止安装子进程。
3. QQ 必须已连接并向 Harness 转发；群消息还受接收群聊设置控制。点击“启动 Harness”，核对运行时就绪、固定 session ID 与忙闲状态。
4. 保存模型配置会先停止旧运行时，需重新启动；可选择 Host 启动时自动启动。启动成功不证明服务商认证或推理成功，错误、结果未知按实际状态处理。

首版只有配置、运行状态与会话 ID，没有原生 SDK Web 会话页。普通模型文本不会自动发 QQ，回复须由模型选择 QQ MCP 工具。真实提供商地址、模型、Key 尚未配置，不得写生产已在线。

## 关键实现与恢复边界

[适配器](../plugins/harness/dsh/src/backend/adapter.ts)使用 npm 官方 rc.4 的精确固定 SDK 版本和匹配运行时/provider/MCP 三包；版本以包清单为准。新安装的依赖实际解析 pi-ai 1.4.0（上游范围 ^1.1），不套用旧研究仓库 lock 中 1.3 的补丁假设。

专属根为 `EATING_HOME/harness/dsh`，包括 `config.json`、固定会话元数据、`dsh-home`、`agents-home`、`workspace`、`runtime-home` 及桥目录。目录 0700、配置 0600；运行时装到 `runtime/versions/install-<UUID>`，三包版本/lockfile 校验后原子发布 `current.json`。保留安装 lockfile、禁安装脚本，spawn 不经 Shell；仅确认进程不存在的 ESRCH 才回收旧安装锁。SDK 环境白名单不继承主 DSH/Profile/模型 Key。

主人主提示词和当前人格组合成可信 system，群/私模板与完整逐条信封只进 external user 数据。每次新批次读取主人配置，修改后下一请求生效但 session ID 不变。运行时实际工具仅 9 项 QQ MCP，无原生文件/Shell/资源/安装/人格写工具；独立 home 和工具收窄不构成 OS 沙箱。

ready 校验 QQ 工具和持久化接口，不能当作当前批次可靠回执。批次只在 `sessions.flush(session) === true` 后原子写 ACK，Host 核对 nonce、session、batch、digest 才返回 durable 并删除队列正文。首次空 session 的 session-ready 标记也须跨屏障，再写 created。重启使用公开持久记录扫描 flush 成功但 ACK 未写的窗口，重签新 nonce，不重新 prompt；未知仍保留待核对，不承诺 exactly-once。

忙时 `isReady=false`，Gateway 暂停投递、不增加尝试次数；已有本地待提交结果优先完成。stop/reconnect 恢复同会话，不额外发 prompt 或消息。桥策略/控制文件不复制批次正文，ACK 为恢复保持有界并在后续批次清理。DSH 会话 JSONL 是所选 Harness 原生上下文，不是 Eating 新建聊天历史。

## Host 与通讯边界

`HostPluginContext.harness` 仅给 Harness entry：只读 owner 配置、已批准通讯 MCP 私有连接、唯一 sink 注册与 wake；通讯插件拿不到该服务。运行时安装通过 owner session/CSRF 的 manage API，模型工具列表不含安装入口。停用/停止/关闭主动撤销 sink，即使 disconnect 抛错也不留下入口。

QQ 0.5.0 的规范化信封补可选 messageId/targetId；机器人自身回声不转投，避免循环。仍只保存有界未交接信封、可靠交接后删正文，动作账本保持；日志只在可见页签订阅、浏览器内存有界，不增加后台日志缓存。
