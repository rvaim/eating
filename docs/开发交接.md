## 正式 QQ 能力

产品仅提供 QQ 真实插件，飞书/微信入口已删；测试夹具仅位于测试目录。QQ 面板有四个页签：

- **连接配置**：仅正向统一 OneBot WebSocket，不支持反向或 API/event 分离；Bearer header，令牌不回显，空值保留、显式清除。原子保存后断开旧连接，用户手动连接，实际登录与 `online/good` 都成功后才显示已连接，支持有限重连。
- **功能测试**：动态读取后台工具 schema，10 项工具与 MCP 共用目录，覆盖登录、状态、版本、好友、群、`get_msg`、本地消息、私聊发送、群聊发送和撤回。UI 手测发送/撤回逐次确认，稳定请求 ID 用于追踪与幂等；未知结果不盲目重发。
- **消息记录**：Host SQLite 收到的实际消息，按实例归属去重，面板显示最近50条；工具接口支持before游标；不是 QQ 全平台历史。
- **MCP 能力**：插件专属 Streamable HTTP `/mcp/qq`，独立 Bearer，官方 SDK 握手、工具发现与调用；仅点击查看配置才显示 MCP 令牌。尚未自动注册到 Harness。日常 MCP 工具调用不要求逐次人工审批。

QQ 空间发布/评论不在 OneBot v11 标准，本版明确 `unsupported`，不伪造实现。细节见[QQ 与平台能力](architecture/QQ与平台能力.md)、[协议与 MCP 核对](research/QQ协议与MCP核对.md)。

## 数据与账号实例

`EATING_HOME` 统一数据根，默认 `~/.eating`，已获用户允许创建。插件自行管理 `bot/qq-bot`；版本化 `accounts.json` 保存 `defaultInstanceId`（稳定本地 UUID）及 `instances`，配置位于 `accounts/<实例 UUID>/config.json`。实际 QQ 号从登录获取，不用作目录名。

设计为可扩展账号实例，本版仅一个；未实现第二账号添加、切换或并行 UI。工具可选 `instance_id`，省略使用当前实例，未知实例必须拒绝，不能错误 fallback。消息、账本和事件带 `instanceId`，外发幂等 scope 为插件 + 实例 + 实际 QQ 号；结果 `unknown` 不自动重试。

共享 Host 锁、SQLite、MCP 令牌位于数据根的 `host` 子目录。POSIX 目录 0700、文件 0600；原子写入，损坏拒绝覆盖，停用保留。旧原型浏览器配置不自动导入，不为旧配置伪造 OneBot endpoint。详细布局与恢复约束见[数据目录与账号实例](technical/数据目录与账号实例.md)。

## Harness 与安全边界

`HarnessGateway` 已有真实类型和唯一主 sink 注册机制，持久 inbox 使用 `pending / accepted / uncertain`。目前没有任何实际 sink，收到消息持久等待；`accepted` 仅表示准入，不代表 Agent 已读、完成认知或采取行动。后续 Harness 模块需显式接入，MCP 也需后续注册。

Host 有回环地址、Host/Origin 校验、HttpOnly session + CSRF、MCP 专用 Bearer、插件独立 scope 和进程锁；单插件损坏配置只使该插件报错。不能据此保证完整恶意插件 OS 沙箱。Cordis 尚未成为真实底座，Tauri、真实 Harness、长期记忆、自主活动、Windows/Linux 和多账号并行均不在本轮已完成范围。
