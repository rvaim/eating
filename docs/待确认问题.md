## 本轮已确认

旧格式明确拒绝且原文件不转换、不覆盖；删除兼容代码不授权删除或重置真实 ~/.eating。新 EATING_HOME 是新实例与新会话，不能描述为已迁移。坏配置在对应页面显示错误，不生成可写空表单或补权限默认值。当前格式细节见[数据归属](architecture/数据归属.md)，入口见[README](../README.md)。

## 最小 DSH 首版结论（历史）

以下保留最小 DSH 阶段的结论与版本；本轮已完成的身份、原生委派和看板范围以下节及各问题“当前”说明为准。

2026-10-28：Q-01在DSH首版已解决，公开systemPrompt.section的complete/interpolate/text回调承载主人主策略与启用人格，实际下一请求system更新而会话不变；不用SDK自动Preset假设。Q-02的最小可靠接管以公开sessions.flush成功后的原子ACK和公开persistence只读恢复实现；入箱/idle不是fsync，无exactly-once承诺，其他Harness仍需独立核。

Q-06的QQ账号与OneBot实际已连接，QQ0.5.0升级后connected，原3待交接、配置与发送账本摘要保持；开发未向真人试发。当时主人通讯身份授权绑定尚未完成；本轮已实现本地多主人／管理员及真实来源核对，但仍不能因 QQ 可收消息就认定任意发送者是主人。

Q-10已选公开npm rc.4精确匹配SDK和三包运行时，真实安装锁定依赖图，普通Node24.22.0/macOS本地验证；完整三平台打包、原生ABI与第三方notices仍未全部核验。Q-12已有持久真实UUID和完整Host重启resume证据，混合联系人披露策略仍须后续按授权处理。Q-13的DSH vendor Cordis仅随该运行时依赖安装，不等于Host已选定Cordis底座。

Q-14在该历史阶段的SDK1.4.0/API1、QQ0.5.0与DSH0.1.0已按独立产物运行，额外Harness类型/数据根/管理入口及失败撤销验证已完成，历史重组数字保持下文证据原样。Q-16首版明确只开放QQ工具，不暗示长期记忆、完整自主调度、第二Harness或OS沙箱已实现。

## QQ 标准工具目录阶段补记（历史）

2026-10-28用户已明确授权完整OneBot标准MCP与提交，38公开API＋1框架quick操作共39项已实现；空间／评论及反向连接占位已删除。版本0.7、653项／34浏览器和当时部署见[历史报告](reports/2026-10-28-OneBot完整MCP验证报告.md)，不再将新增标准QQ工具列为待批准。实际各 OneBot 实现／账号权限／媒体转换、request／notice 向 Harness 交接及专有扩展仍独立核验；本轮多主人／管理员与来源绑定的已实现范围见 Q-06。QQ凭据标准查询已接入，调用方原生会话可能保存结果，不作全链路不留存保证。

## Q-01：DSH 适配器怎样绑定人格/能力

- 问题/重要性：人格与工具必须在实际模型请求和调用中生效，不能只验证配置页预览，也不要求其他 Harness 使用 DSH Preset。
- 当前已解决：DSH 用公开原生 Agent 创建钩子、Agent Preset 与工具 scope 装配主／子代理；主仅列类型／委派，子使用当前类型勾选的会话范围工具。四层／统一人格每任务重读，在同一 UUID 下应用新配置，已有本地原生证据。
- 后续：其他 Harness、更多原生旁路与 OS 隔离分别验证，不把逻辑权限等同沙箱。决定者／期限：技术 Agent 提适配证据，重大边界变化由负责人决定；每个新适配器开放前核查。

## Q-02：各适配器的确认与断线补查

- 问题/重要性：准入不是耐久/消费/平台成功。
- 当前已解决：DSH 用公开 sessions.flush＋原子匹配 ACK 和 persistence 只读恢复处理可靠接管；原生子任务受理、入箱持久与实际动作结果分别核对。未知任务／动作不自动重传，不承诺 exactly-once。
- 后续：其他运行时及更多断线窗口独立核验，不能用看板读取或入箱事件代替可靠交接证据。决定者／期限：技术 Agent；重大上游改动由负责人确认，每个新适配器开放前。

## Q-03：Host 语言和本地协议

- 问题/重要性：影响多运行时适配、Cordis 与分发。
- 已知：本轮已采用Node.js/TypeScript独立Host，管理HTTP+会话/CSRF、插件StreamableHTTP MCP+Bearer；普通Node>=24.9.0。三平台分发和最终后台服务形式仍待验证。
- 建议：按当前接口演进，不为候选底座强建双Host。决定者/期限：当前实现见ADR-0010，重大替换需新ADR。

## Q-04：通用执行能力与新增能力审批

- 问题/重要性：同用户任意 Shell/文件可能绕过安装入口。
- 已知：Preset/Cordis scope 不是沙箱；DSH 原生安装参数不验主人。备选：低权限进程/OS 沙箱、受控配置/执行/网络/安装者，边界未证实。
- 建议：明确脚本、页面、MCP、远端执行、激活/升级范围并验证。决定者/期限：负责人确认权限取舍，技术 Agent 实现证据；广泛执行开放前。

## Q-05：首个记忆插件/机制与失效策略

- 问题/重要性：成长和连续性需真实可用记忆。
- 已知：由主人选择与所选 Harness 兼容者，Eating 不建第二库；未选提供方。备选本地/远端，隔离/导出/迁移/失效策略未测。
- 建议：先测实际读写与故障可见；不默认跨 Harness 通用。决定者/期限：负责人，Phase 3 前。

## Q-06：首个真实主人通讯渠道

- 问题/重要性：需真实身份验证、接收与主动联系。
- 当前已解决：QQ／OneBot v11 已是真实接入平台；本轮提供多主人／管理员规范号码列表、policyRevision CAS、接收时实际账号／sender 核对和 owner 优先规则。消息仍标 external，正文自称不授予配置权；身份／类型策略更改不重连。
- 后续：真实账号环境的主动联系、不同 OneBot 的来源可靠性与真人动作仍按主人授权分别验证；开发不向真人自动试发，也不把面板配置成功当作远程身份认证完成。

## Q-07：唤醒/休息与资源阈值

- 问题/重要性：避免永久停摆/无界推理并尊重休息。
- 已知：各 Harness 能力不同，DSH Schedule 有漏发/重复窗口。备选自主调度/外部事件、可选兜底；阈值和意外结束判定未验证。
- 建议：受限观察后定策略，不能 Host 生成新生活任务补缺。决定者/期限：负责人确认体验/预算，技术 Agent 提数据；实验前定上限，长运行前定策略。

## Q-08：托盘还是独立后台服务

- 问题/重要性：关窗与 UI 进程退出不同。
- 已知：不靠 React 页面保活；第一版可先托盘。备选独立后台/系统服务，各平台未验证。
- 建议：先确认实际生命周期期望。决定者/期限：负责人，Phase 5 前。

## Q-09：运行存储、保留与单实例

- 问题/重要性：队列/审批/动作账本和模块归属需事务、锁与隐私策略。
- 已知：本轮Node内置SQLite已实际采用并验证，EATING_HOME默认~/.eating、bot/qq-bot多实例结构与当前单账号范围已由用户确认；程序停用保留数据，主实例锁已实现。
- 后续：确认保留期限、导出备份与加密／ACL，不把当前 POSIX 测试推广到三平台。默认不兼容已由 ADR-0015 确认；只有收到明确迁移或回退指令时才另行设计，不把发布作为自动增加兼容功能的触发条件。决定者／期限：负责人确认隐私与具体数据处置范围，相关功能实施前落实。

## Q-10：每个运行时的发行与许可证

- 问题/重要性：源码 SHA 不等于可安装制品，不应把所有 Harness 自动捆绑。
- 已知：DSH 固定源码 Node 下限/MIT 有证据；其他运行时、精确 Node/原生 ABI/notices 未核。
- 建议：分别评估内置/外接、固定版本与许可，干净系统验证。决定者/期限：技术 Agent 提证据，重大分发负责人决定；每适配器测试前定包，Phase 5 前锁清单。

## Q-11：独立 UI 组织与最终框架

- 问题/重要性：首版已确定并实现两层导航与浅色界面，最终桌面/更多管理功能仍需确认。
- 已知：React／TypeScript／Vite 浅色两层导航、正式 QQ 面板及手动 DSH 原生会话看板已实现；DSH 自带 vendor Cordis 用于原生接口，Host 最终 Cordis 底座与 Tauri 桌面仍未接入。
- 建议：当前先审阅运行版，再评估桌面/后台交互，不默认引入双 UI 框架。决定者/期限：负责人确认体验，后续阶段按证据扩展。

## Q-12：主运行脉络和联系人隐私

- 问题/重要性：唯一身份不等于单个 native Session 已可行。
- 当前已解决：eating-main 是历史候选别名，DSH 现在持久保存真实主 UUID，并按插件／实例／登录账号／会话／类型保存最多 100 项原生子 UUID。跨任务更新 common／人格／工具及整 Host 重启复用已验证，子代理只在绑定会话 scope 内操作。
- 后续：主代理可能获得多个联系人摘要，跨联系人主动披露规则与长期记忆共享仍需产品与权限审查；逻辑子会话隔离不能代替这些规则。其他 Harness 的 ID／恢复语义单独核验。

## Q-13：Cordis 最终包、版本与维护方式

- 问题/重要性：上游与 DSH vendor 名称/版本/API 不可默认兼容。
- 已知：上游 4.0.0-rc.12 与 DSH vendor @deepseek-ai/cordis 4.0.5 是不同对象。后者已随专属 DSH 运行时安装并用于公开原生接口；Host 最终 Cordis 包／版本仍未选定，不能将插件内依赖当作 Host 选型完成。
- 备选：上游、DSH 维护版、必要时其他底座；建议依真实依赖/清理/发布和维护成本选，不提前 Fork。
- 决定者/期限：技术 Agent 提 P0B 结果，负责人确认最终选型；业务插件 API 冻结前。

## Q-14：前后端注册与产物加载验证

- 已确认：单仓、主程序/SDK/插件独立发包、按产物加载，插件仅依赖公开 SDK，见 [ADR-0012](decisions/ADR-0012-单仓独立包与插件加载.md)。不再将构建期静态打包作为当前候选。
- 历史重组实施：公开 SDK 1.0.0／API 1、QQ 0.2.0；本地产物安装先停止 Host 后重启，UI 动态加载 Host 资源，升级仅改目标插件、卸载保留数据。现版应用／Host／Web 0.9.0、plugin-core／plugin-sdk／ui-sdk 2.0.0、QQ 0.9.0、DSH 0.4.0，仅 API2；旧 API 与历史升级路径不构成当前支持，实际部署另核。目录、清单与安装布局是实施细节，不表示负责人逐项确认。
- 已有证据（2026-10-27）：构建/严格 TS、280 项单元集成、8 项浏览器及四包 pack；SDK 兼容/摘要、暂存失败、停机/不可变版本/并发/当前 active 数据目录冲突与改绑、仓库外升级重启及卸载数据保持已回归。索引提交后目录同步失败返回 unknown 并保留已激活版本；目录绑定不建立永久历史归属。完整范围见[重组报告](reports/2026-10-26-单仓独立包重组报告.md)。
- 后续：热更新、第三方市场与完整权限隔离另行设计，不将当前本地安装扩大为这些能力完成。

## Q-15：Harness 选择／切换与默认不兼容

- 问题/重要性：不能因可选运行时就悄悄丢会话/记忆或启动第二主控。
- 已确认：Eating 默认不兼容任何旧版，只有用户明确指令才设计例外，未来发布也不改变此规则。可选择 Harness 已确认；跨 Harness 无损迁移、热切换与能力等价仍未承诺，第二种真实 Harness 尚未选定／核验。
- 后续：先验证停止旧主控、数据根排他与不兼容提示；新实例不冒充原会话恢复，保留原生文件也不表示新版可读。没有通用转换或迁移功能承诺。
- 决定者／期限：负责人确定具体切换体验与任何例外范围，技术 Agent 提供事实；开放第二适配器前分别验证。

## Q-16：运行时最小能力集与差异展示

- 问题/重要性：可适配不等于满足持续生活所有需求。
- 已知：能力证据和调用结果需分开，不支持/未知不伪造成功；具体最小项未冻结。
- 备选：按功能依赖禁用/降级，或关键缺失时拒绝用作主控；建议逐项映射需求，记忆/恢复/权限缺口明确报告。
- 决定者/期限：技术 Agent 给可行性，负责人确认可接受产品限制；适配器对用户开放前。

## Q-17：多账号实际管理与运行

- 已确认：平台/插件种类、本地instanceId、实际账号分别标识；版本化accounts.json与每实例配置目录已实现，本版只操作一个默认账号。
- 未完成：添加/删除第二账号、切换/并行连接、每账号工具授权、MCP账号选择与UI列表；不能因为索引允许多条就声称已经支持。
- 建议：当前可选instance_id显式校验不回退，后续按已存实例格式扩展连接映射/权限，而不是重写单config格式。
- 决定者/期限：负责人下一阶段确认多账号交互，开放第二实例前做并发、停用、去重/幂等与数据隔离验证。
