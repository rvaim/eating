# Eating 项目状态

更新：2026-10-30，Asia/Shanghai。当前新增统一插件／MCP管理和表情包能力，系统DSH与官方Web继续保留。功能、接口、验证与现场结果见[本轮报告](reports/2026-10-30-MCP插件与表情包验证.md)与[ADR-0019](decisions/ADR-0019-统一插件与MCP能力管理.md)。

应用／Host／Web0.11.0、三个共享包4.0.0、QQ0.11.0、DSH0.8.0、表情包0.1.0，唯一插件API4；原QQ/DSH/作者/Host数据schema保持。新能力不代表已连接任何真实ADB或浏览器服务。

## 当前能力

新增生图能力实现见[ADR-0020](decisions/ADR-0020-独立OpenAI生图能力.md)和[使用说明](operations/生图插件.md)，实际验证与部署结果将在[本轮报告](reports/2026-10-30-生图插件验证.md)记录。平台及共享SDK不变，新插件0.1.0/API4，不改QQ发送。


- 插件页统一通讯／Harness／能力三类，可预览、确认安装、更新、启停和卸载，各有独立面板；卸载保留数据。
- MCP页同时管理直接stdio／StreamableHTTP和插件来源，连接、工具、授权分别报告；按代理类型与精确工具选择能力，授权变化撤旧lease并停止相关Harness。
- 表情库手动上传／AI当前会话收藏、描述标签、query与多标签AND筛选、默认20最大50条分页；列表只有元数据，取用后经公开资源引用发送。库去重、CAS、防重及撤权竞态已有实际回环。

- 通过系统 dsh 启动 Eating 专属 SDK＋官方 Web 进程，数据、配置与工作区位于 Eating 自己的目录，不共享用户主 DSH 数据。插件只附带启动转交层，不额外安装 Web 或运行时。
- 运行时就绪、消息可靠交接和模型处理结果分别报告；模型限流显示 HTTP 429、原生错误码与脱敏后的提供商原因，成功回合清除旧错误。
- QQ既有主子受控工具、稳定UUID与四段创建标签保留。自有会话看板和离线读取接口已移除，配置页通过“打开 DSH Web”进入同一个实例的官方页面；鉴权入口按需返回，公开状态只含就绪标记。
- 官方time-context上海／600000、默认system稳定；MCP图像与独立能力声明、40项QQ工具保持。本轮不改图片网络策略。

## 图片现实限制

图片取图已修复：原先插件自行解析DNS并把198.18.7.115（Fake-IP特征）当内网拒绝，导致TUN／系统代理／局域网部署都取不到图。现只校验URL形态，解析与路由交给系统网络栈；仍保会话授权引用、无重定向、不传认证头、5MiB／10秒与MIME／字节校验。QQ0.10.1，同一条真实消息已验证取得image/jpeg、110000字节，不需要用户改DNS。

原生Web修复在独立工作树验证；实际构建、官方明暗主题／原生操作、SDK回环和页面结果以[修复报告](reports/2026-10-29-恢复原样DSHWeb与图片DNS诊断.md)记录，不以旧1149／70或旧自定义只读截图作为此次结论。
