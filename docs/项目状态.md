## Harness 与最小使用流程

全局新增“Harness”，二级提供“DeepSeek Harness”配置页；机器人只列通讯插件。DSH 页面管理独立 OpenAI-compatible API 地址、精确模型名称和 API Key、请求超时、输出 token、可选 Host 启动时自动启动。Key 只写入不回显，留空保留，勾选并保存才清除；保存配置会先停止旧运行时。

1. QQ 已连接，并开启“向 Harness 转发”；群消息还需允许接收群聊。
2. 在“Harness → DeepSeek Harness”填写模型配置，点击“保存配置”。真实服务商的地址、模型与独立 Key 由主人提供。
3. 当前实例运行时已预装，可跳过安装；新安装时点击“安装运行时”并等待后台完成，首次下载可能需 1–3 分钟，受网络影响。
4. 点击“启动 Harness”，核对运行时、固定主会话及忙闲状态。启动只说明工具与持久化能力就绪，不代表模型认证或本轮处理已成功。

首版不提供原生会话/聊天历史查看页，也不接入用户主 DSH、Profile、现有凭据或当前 DSH GUI。生产模型认证和真实模型费用链路尚未验证。

## 消息、人格与可靠交接

Eating 仍只有同一个 AI。主提示词与主人当前启用的人格组合成可信 system 策略，群/私聊模板和逐条来源完整批次放在外部 user 数据；修改策略或切换人格在下一请求生效，固定 session ID 不变。原有三份正式默认策略、空人格初态、最多 100 份人格/最多一个启用、11 项变量与 CAS/损坏保护保持，见[阶段二变更](changes/2026-10-27-提示词与人格管理.md)。

DSH 模型自主决定是否回复，并调用实际 QQ MCP 工具发送；普通文本和 `finalResponse` 不由 Host 自动转发。实测工具目录只有 9 项 `mcp__qq__…`，没有原生文件、Shell、资源、安装或固定人格写入工具；这项能力收窄不等于 OS 沙箱。

忙时 `isReady=false` 暂停新投递、不消耗尝试次数；已有本地待确认结果优先完成。ready 只证明工具和持久化接口可用；只有桥确认 `sessions.flush(session) === true` 并原子写入匹配批次 ACK，Host 才可靠交接并删除队列正文。首次空会话也须经持久屏障才能标记 created；重启扫描公开持久记录，可恢复 flush 后、ACK 前窗口，不重复 prompt。缺少调用方幂等保证，仍不承诺 exactly-once。

QQ 0.5.0 为规范化信封补充可选 messageId/targetId，机器人自身回声不转投 Harness，避免自我触发。按需日志、无历史临时队列与外发防重复账本继续保持；可靠交接不等于模型完成，结果未知不盲目重发。

## 数据与运行边界

DSH 数据位于 `EATING_HOME/harness/dsh`：配置文件 0600、专属目录 0700，`dsh-home`、`agents-home`、`workspace`、`runtime-home` 分离。官方运行时安装到 `runtime/versions/install-<UUID>`，校验三包同版与 lockfile 后原子发布 `current.json`；依赖安装禁脚本、子进程不经 Shell，取消/超时会终止安装子进程。

Host 仅向 Harness 插件提供只读主人配置、已批准通讯插件的私有 MCP 连接和唯一 sink 注册/wake；通讯插件拿不到这组服务。安装运行时属于 owner session/CSRF 管理操作，不是模型工具。停用、停止和关闭均撤销 sink，即使插件断开抛错也不保留投递入口；跨 kind 升级拒绝隐式搬迁数据。

DSH 原生会话上下文 JSONL 属于所选 Harness 数据；Eating 不再复制聊天历史。桥控制文件保存策略和交接元数据，不保存消息正文副本；ACK 仅为当前恢复保留并在后续批次清理，不能变成无限账本或后台日志。环境采用白名单，只传独立模型 Key 与该插件获授的 QQ MCP 凭据。
