## 已完成

- 保留 React/TypeScript/Vite、普通 CSS、lucide-react 和中文“概览 / 机器人”导航；平台分类和面板从注册目录生成。飞书、微信入口已从产品移除，协议夹具仅位于测试目录。
- QQ“连接配置”：正向统一 OneBot WebSocket，Bearer header 认证；令牌仅写入，留空保留、显式清除。原子保存配置后断开旧连接，手动连接并取得真实登录信息及 `online/good` 状态后才显示已连接，支持有限重连；不支持反向连接或 API/event 分离。
- QQ“功能测试”：从后台工具 schema 动态生成，与 MCP 共用 10 项工具目录，覆盖登录、状态、版本、好友、群、`get_msg`、本地消息、私聊发送、群聊发送和撤回。UI 手测发送/撤回逐次确认，并保留稳定请求 ID。
- QQ“消息记录”：展示 Host SQLite 实际收到并持久化的消息，按实例归属去重，面板显示最近50条，工具接口提供before游标；不宣称覆盖 QQ 全平台历史。
- QQ“MCP 能力”：专属 Streamable HTTP `/mcp/qq` 与独立 Bearer，使用官方 SDK 验证握手、工具发现和调用；仅显式查看配置时显示 MCP 令牌。尚未自动注册到 Harness。
- `HarnessGateway` 提供唯一主 sink 注册契约及持久 inbox，区分 `pending / accepted / uncertain`。目前没有实际 sink，消息等待投递；`accepted` 仅表示准入，不表示 Agent 已读。
- Host 已有回环地址与 Host/Origin 校验、HttpOnly session、CSRF、MCP 专用 Bearer、插件独立 scope 和进程锁；单插件损坏配置局部报错，不拖垮宿主。上述措施不构成完整 OS 恶意插件沙箱。

## 运行与数据

普通 Node.js 要求 >=24.9.0，实际验证为 24.22.0，pnpm 11.28.5。`pnpm dev` 通过开发脚本启动 Host 5181 + Vite 5180；正式生产运行 `pnpm build && pnpm start`，由 Host 5181 同源提供 `dist`、`/api` 和 `/mcp/qq`，不能用纯 Vite 预览替代生产 Host。

统一位置由 `EATING_HOME` 指定，默认 `~/.eating`，已按用户允许创建。QQ 数据位于 `bot/qq-bot`：版本化 `accounts.json` 保存 `defaultInstanceId` 与实例索引，单账号配置位于 `accounts/<稳定本地实例 UUID>/config.json`；实际 QQ 号从登录结果获取，不作为目录名。本版仅一个实例，未实现第二账号添加、切换或并行 UI。

共享 Host 锁、SQLite 和 MCP 令牌位于 `host` 子目录。POSIX 下目录 0700、文件 0600，配置原子写入、损坏拒绝覆盖，停用保留数据。旧浏览器原型配置不自动导入真实账号。工具可选 `instance_id`，默认当前实例；未知实例拒绝，不回退。消息、操作账本和事件带 `instanceId`；外发幂等按插件、实例和实际 QQ 号隔离，结果未知不自动重试。

运行细节见[QQ 配置与功能测试](operations/QQ配置与功能测试.md)、[数据目录与账号实例](technical/数据目录与账号实例.md)。

## 当前架构与 ADR

唯一身份，可替换 Harness；Host 不重写认知、人格决策或长期人生记忆。模块与面板独立注册，新增可执行能力需主人批准。MCP 日常工具调用不要求每次人工审批，UI 手测发送/撤回仍需逐次确认。

当前 11 份 ADR：0001/0002 Superseded；0003/0004/0005/0008 Proposed；0006/0007/0009/0010/0011 Accepted。正式 Host/QQ 与数据实例决定见 [ADR-0010](decisions/ADR-0010-正式Host与QQ能力服务.md)、[ADR-0011](decisions/ADR-0011-统一数据目录与账号实例.md)及[ADR 索引](decisions/项目说明.md)。Cordis 仍是待核对的后台候选，尚未成为真实运行底座。

## 已知限制与后续

QQ 空间发布/评论不属于 OneBot v11 标准，本版明确 `unsupported`，后续通过显式能力扩展研究。反向连接、分离 API/event、多账号并行、实际 Harness 注册/认知回路、真实 QQ 账号联调、长期记忆、自主活动、任意第三方安装、完整恶意插件隔离、Tauri 及 Windows/Linux 验证均未完成。

后续按负责人安排进行真实 OneBot 配置或 Harness 适配；不能把协议夹具通过写成真人 QQ 已验证，也不能把消息持久化写成 Agent 已读。旧 DSH hardened Node 原生签名限制已定位，开发使用普通 Node，不修改用户 DSH 签名或现有 GUI。
